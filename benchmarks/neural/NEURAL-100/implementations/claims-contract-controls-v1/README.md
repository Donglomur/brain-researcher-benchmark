# Maintained NEURAL-100 scientific-claim controls

The investigation component includes a numerical report and a separately graded
typed interpretation. Its public portability checks authenticate source and
reject a missing complete export. The earlier scientific-claim controls were
recorded as historical engineering evidence, but their test scripts were not
included in the public source projection. This suite makes the claim semantics
independently runnable in an ordinary checkout.

It loads the actual hash-pinned `claims.py`, `report_contract.py`, and
`artifact_io.py`; it does not copy or replace their implementation. Its 19 tests
use invented dictionaries with all 47 recording identities, 41 mice, the 39/8
area partition and eight conditions. Six mice have repeated A1 recordings, so
recording-weighted and mouse-weighted aggregation can be distinguished. No
recording array, onset estimator, scientific bootstrap or model is run.

The tests cover missing repeats and complete-cohort withholding, observed-only
versus full-cohort labels, sign and null interpretation, nonfinite or internally
inconsistent reference results, candidate-independent projection, shared
bootstrap support, zero-touching intervals, missing first-spike evidence,
complete recording/condition coverage, the pointwise rather than simultaneous
significance interpretation, and the difference between malformed
submissions and valid but scientifically wrong claims. Wrong claims produce
mismatch paths without releasing private expected values. An absent support
count remains ungradable rather than being inferred from other fields.

Run from the repository root using Python 3.11 or later:

```sh
python3 -I -S -B benchmarks/neural/NEURAL-100/implementations/claims-contract-controls-v1/test_claims_contract.py
```

The optional `--source-root` argument points to the same three pinned source
bodies when testing a private construction copy before integration. It does not
permit arbitrary versions: changed body identity requires an explicit review
and pin update. Numerical imports, sockets and subprocess creation are refused
during this suite; no generated fixture files are written.

The first pooled execution passed the original 18 tests in 0.236475 seconds of
total wrapper time, with 29,786,112 bytes reported as peak child RSS. Independent
review then requested an explicit pointwise-versus-simultaneous significance
regression. That one new test passed separately in 0.148818 seconds; the earlier
18 passing tests were not replayed. These observations establish only generated
software-contract behavior. The formal bootstrap
identifier and every fixture value are invented; no actual draw schedule or
biological measurement is authenticated by these controls.

The suite has no effect on the original task definition, selected runtime,
source bindings, evaluation authority or qualification status. Integration still
needs explicit enrollment of this test command in the repository's component
checks. It does not add a benchmark, a model result, a viewer condition or a
native-understanding claim. The complete operator export, physical timing and
anatomy validation, cohort reconciliation and empirical execution remain
separate requirements.
