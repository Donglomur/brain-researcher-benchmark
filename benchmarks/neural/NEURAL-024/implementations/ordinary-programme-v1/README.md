# NEURAL-024 ordinary programme admission

This component accepts one precommitted Python programme over the **existing, fully prepared NEURAL-024 causal count-forecasting case**. It provides ordinary scoring and a separate, strict calibration-rate control condition. It is a source package; no ordinary participant has been executed by this change.

The previously executed disclosed calibration control completed all 22,100 predictions and matched the frozen calibration reference exactly across 390 scalar fields, with zero gain. That establishes operational baseline parity. It is not an AI result, native neural understanding, improved performance, or a new benchmark ID.

## Data and scientific contract

The candidate receives the same source 18,700/calibration 3,000 × 96 count-only banks and the previous-bin observation after its prediction has been durably committed. There are 22,100 requests: 10 required warm-up predictions and 22,090 × 96 scored cells. Native intervals and all 96 channel identities are retained. The source-controlled `CASE_IDENTITY.json` binds the exact two public banks, four private prepared files and three provenance records. The operator supplies their locations through `examples/case-custody.template.json`; paths may move, identities may not.

No bank projection, preparation, reference fitting, dataset acquisition or copying of prepared inputs is performed. A user of this source package must already possess the exact prepared artifacts and their provenance. This repository component does not publish those data or claim that another arbitrary dataset is equivalent.

The unchanged scorer reports signed Poisson log-likelihood gain in bits per spike against calibration-rate and comparisons with all six frozen references. A complete ordinary score may be negative, zero or positive. It has no accuracy floor and does not require calibration parity. The `calibration_rate` mode requires the original exact source/method bytes and exact parity/zero gain; switching only the unreviewed mode does not authorize another condition.

Ordinary programmes may maintain state and learn from source, calibration and the revealed prefix under the original task. Candidate fit counts and authorship remain unknown; method text is a declaration. Trusted grader fit/API counters are not claims about candidate training. This is a tools/programme condition, not a direct/viewer/native-understanding condition.

## Completion and failure

The causal loop retains write→flush→fsync→Gate.commit→feedback→next observation. Candidate/attach absence precedes private grading. Ownership recovery uses the exact same custody map and immutable create IDs. A failed launch after durable activation still stops its group and checks its resource journal.

`operation_result.json` remains pending external exit: the operator must independently verify the recorded outer group is absent and its native lease is free. A valid ordinary result has `ordinary_programme_scored_pending_outer_exit`, full 22,100 commits/22,090 × 96 support, six reference arms and known cleanup. Its signed score is retained without a positive-score gate. Invalid/incomplete submissions, missing custody, ownership uncertainty, interrupted or failed publication stay nonqualified. A bounded stage/type stderr diagnostic covers outer failures; absent result files are never success.

A whole-benchmark-ready claim and any native-understanding or scientific-performance claim remain separate. This source component requires later registry/CI integration and a separately selected participant/run; neither is silently implied by construction.
