# Shared image identity repair

The preserved issuer checks 12 exemplars per concept for each person and one per
session. Those marginal counts can still pass after swapping two concepts in one
person's session. The same image would then acquire different category targets
across people. Its visual row lookup also accepts an extra repeated image ID,
because conversion to a dictionary hides the duplicate and can leave an index
beyond the 22,248-row array.

`source_identity.validate_roster` checks the complete 108,192-row source roster,
the shared 22,248 experimental images across all four people, a single
image-to-concept/path mapping, and exact extraction-manifest or visual-row joins.
It reads no measurements or category membership values. It retains the original
88,992 experimental rows and exclusions; it does not replace the scientific task.

The versioned `adapter.extract` and `adapter.feature_issuer` functions perform
these checks before dispatching to the preserved preparation and issuer APIs.
They have the same arguments as the original `preparation.extract` and
`views.FeatureIssuer`. Put this directory on the operator's import path and use
the adapter entrypoints in a separately selected preparation protocol. The
predecessor source hashes are checked on dispatch. The original source files,
registration and canonical understanding contract are unchanged. This adapter
has not been enrolled in the central runtime.

The existing authorization checks and qualification prerequisites still apply.
The repair neither authorizes native preparation nor authenticates an external
roster merely because its internal identities agree. An identical error in all
four people's metadata still requires independent original-source verification.
Release/derivative provenance, image content, ocular clock alignment, annotation
joins, full reference execution and participant transport remain unqualified.
No model performance or direct/viewer interpretation result is claimed.

Source scope is inherited from the registered [THINGS-data preprocessing
revision](https://github.com/ViCCo-Group/THINGS-data/tree/5e0eccac51eac78b57045f5b90b4f53814f56c32/MEG),
[THINGS-MEG dataset](https://openneuro.org/datasets/ds004212), and the current
task/understanding contract. No fresh scientific source acquisition occurred.

`test_source_identity.py` contains generated metadata controls, including
counterexamples that preserve the predecessor's marginal counts, order
invariance, missing/duplicate image identities, and adapters refusing malformed
joins before native dispatch. Run it only through the coordinated lightweight
test pool during this revision. Generated controls do not qualify authentic data.

All 13 generated controls passed in the shared pool. No authentic data were
prepared and no model was run; central runtime enrollment remains pending.
