# Exploratory complete-condition viewer

This is an additive, source-only restricted observation and collection route for
the existing NEURAL-037 endpoint. It is **not an admitted native-understanding
study**. Dense prediction of released condition-mean trajectories can measure
numerical reconstruction without establishing neural understanding. In
particular, the complete output obligation is large and provider feasibility is
unresolved; a transport fitting in a file does not make the study practical.

The route preserves all six acquisitions, both ABC/CBA directions, 1,132 original
ROI rows, 2,264 query-row occurrences and **509,360 explicit predicted values**.
Acquisitions 1–4 retain all 240 native frames and 5–6 all 200. All eleven visible
conditions remain accessible in each query: one opposite order from that
acquisition and both orders from the other five acquisitions. ROI identities
match only within an acquisition. There is no condition/cell/frame subset.

## What the participant sees

Each broker loads exactly one original 32-file selected view, authenticates its
input descriptor and all 22 training mean/count arrays, and never opens query
targets or masks. It uses the unchanged original context validator and the
accepted NPY/JSON readers. Native source numeric values are 50-trial finite means,
not raw trials. A zero count indicates unavailable support; its zero mean is a
placeholder and produces a gap in the plot. No smoothing, deconvolution,
interpolation, normalization or hidden-condition statistic is added.

`observe` selects an authorized acquisition/order and original ROI key. It
returns that entire native-frame mean/count row, a fixed lossless PNG, and its
axis/availability legend. PNG axes use native frame index and source numeric
units with an explicitly unknown physical convention. Straight display segments
between adjacent observed samples are not resampled source observations.
Physical timestamps, onset windows and animal/session identities are unresolved.
Exact numeric readout is intentional: this is **viewer-mediated observation with
numeric readout**, not visual-only perception or a no-tools condition. Pixel
quantization is not claimed to preserve the information of raw float arrays.

The broker cannot fit a model, run arbitrary code, retrieve the source dataset,
copy an observed trajectory into an answer or fill a missing prediction. The
participant must supply every answer value. The initial description includes
the permitted training-only normalization scale and original case geometry.
The participant receives INSTRUCTIONS.md and this typed display, rather than
the programme view's mounted support scripts and supplied reference code.
Identical cases and scoring therefore permit a capability comparison; they do
not isolate a causal effect of tools or establish equal information/access
budgets. Exact readout, plotting and immutable row commitments are declared
representation and interaction differences.
The source checkout, wrapper, authority/capture files and imports must remain
operator-controlled and stable. Captured dependency hashes are integrity checks,
not an untrusted-code-loader sandbox.

## Complete response and feasibility contract

`submit` commits exactly one full query ROI trajectory. Its complete ASCII JSON
action includes `action`, `cell_key` and `values`; all 200/240 numbers must be
explicit, finite JSON numbers, with no booleans, duplicate keys or nonstandard
constants. The original strict integer-token limit is 18 characters; larger
finite float64 values can use finite decimal/exponent notation. Shortest
round-trip decimal float64 spellings fit the row envelope. Truncation, a duplicate
committed row, invalid action or premature `finish` fails the session. There is
no automatic retry, interpolation or replacement. `abstain` ends the whole
context explicitly. A row commitment protocol is a delivery constraint; it is
not claimed equivalent to a programme's one-shot answer process.

The unchanged endpoint permits reordered complete context/row records. The
collector joins their exact identities and emits the original ordered schema;
it never reassigns predictions by array position. All twelve captured sessions
are required even when one abstains. Existing public-only `scorer_core.admit`
checks the complete panel before export. Grading remains a separate operator
action through the accepted `condition-endpoint-v1/score.py`; it loads targets
only after complete admission and returns no subset score on abstention.

The prospective output reservations are distinct:

- **8,192 ASCII bytes per complete action**, including its JSON envelope and
  newline when served over JSON-lines. Across 2,264 accepted answer actions this
  is 18,546,688 bytes; invalid attempts cannot trigger an automatic retry.
- **8,192 externally reserved output tokens per row**, or 18,546,688 tokens over
  the panel. The numerical coincidence with bytes is not a conversion rule.
  This source neither measures nor enforces provider tokens. This very large
  provisional allowance is not an attractive primary-study budget.
- The original **64,000,000-byte complete prediction file cap** remains
  independent. It does not cover input/images, session artifacts, transcripts,
  receipts, or cumulative filesystem writes. Each session artifact is capped
  separately at 4,500,000 bytes.

For the compact original schema, one-character numeric lexemes require at least
1,101,181 bytes. For mean numeric lexeme length L, its serialized size is
509,360*(L+1)+82,461 bytes before a final newline: 8,741,581 bytes at L=16 and
12,816,461 at L=24. These are serialization calculations, not predictor choices,
token estimates or measured provider outputs. Actual generated serializer sizes
are recorded separately in external test evidence.

Each session allows twice its complete number of authorized training ROI rows
as `observe` actions, enough to reach every permitted row without selecting an
easier subset. This allows 49,808 observations across all sessions. Each full
observation JSON is bounded at 2,000,000 bytes, including base64 PNG and numeric
readout: the conservative full-panel observation-traffic ceiling is therefore
99,616,000,000 bytes. This is a large upper envelope, **not measured traffic**;
descriptions/acknowledgments and provider image-token accounting are separate.
PNG generation is on demand and images are not written by the broker. External
transcript storage and cumulative traffic need their own actual allocation.
The loader holds roughly one complete 4.53–4.85 MB original input view plus
Python/NumPy/rendering/serialization overhead. This is an input-byte statement,
not a measured authentic RSS guarantee.

Tokenizer, per-turn output, context capacity, input/image tokens, cumulative
cost, latency and externally enforced fresh model state must be qualified before
an authentic study. The source provides no such qualification. A provider
unable to satisfy complete support remains unsupported; the endpoint must not
be shrunk or silently filled by a programme.

## Reciprocal contexts and operator route

The hidden condition in one query is training in another. Freeze the participant
protocol and weights before exposure; preserve continuing state within a context,
then use a fresh externally isolated model conversation/process/filesystem for
each of the twelve contexts. Fresh Python broker objects alone cannot prove
that external model memory was reset. Dataset/publication exposure also remains
a contamination concern. Runtime and scientific qualification remain false.

`source/LOCK.json`, `source/context_contract.py` and `source/PANEL.json` are
byte-identical original metadata/source, containing no fluorescence arrays or
target values. SOURCE_BINDINGS.json binds them and the accepted31c05 array/JSON
reader and corrected complete-condition scorer. Existing source/export metadata
and stat inspection found all 330 prepared files at their declared extents
(61,420,252 bytes), including all 285 selected view descriptors. Array bodies were
not reopened or rehashed during this source revision. Use the existing isolated
view stager; never mount the union of prepared reciprocal contexts for a
participant. The new code does not duplicate the existing programme controller.

After a separately approved authentic protocol and resource qualification, the
operator broker command has this form:

```sh
python -I -B serve.py --view /custody/one-original-view \
  --context acquisition_1_ABC --output /custody/new-session.json \
  --seconds SELECTED_SECONDS
```

The code accepts an explicit 1–86,400-second broker deadline from its initial
entry and uses POSIX interval timers after trusted source bootstrap. External
supervision must bound that initial bootstrap too. The selection is prospective, not a claim
that a provider can finish in that time. External supervision still owns Python
startup, host CPU/RAM/disk, final natural exit and provider usage. A retained
session file alone proves none of those. Physical I/O, process isolation and
host/runtime feasibility are not qualified by source tests. The operator must
capture each successful session's exact bytes after observed closure; failures
retain partial evidence and cannot authorize continuation.
Standard error and internal exceptions are operator-only diagnostics; a provider
integration must expose only the declared JSON display/action interface.

The collector consumes an operator-owned JSON list of all twelve
`{context_id,path,bytes,sha256}` capture descriptors:

```sh
python -I -B collect_cli.py --captures /custody/all-twelve-captures.json \
  --output /custody/new-submission.json
```

It authenticates each captured buffer, binds the same protocol/source/input
identities and calls the unchanged public admission. Hashes or reported counters
do not prove how a model produced those bytes. No target read, evaluation
feedback, score, provider call or automatic cross-context state transfer occurs.

## Source controls

```sh
python -I -B test_viewer.py
```

Controls reuse one complete invented fixture, all twelve query geometries and
all 509,360 response slots. They check restricted observations, unavailable-frame
rendering, exact response collection, capture joins and malformed/partial
refusals. Original numerical tests are not replayed. Generated counts/means and
answers establish software behavior only; authentic observations, providers and
models are not executed. Source-only status adds no new benchmark registration.
