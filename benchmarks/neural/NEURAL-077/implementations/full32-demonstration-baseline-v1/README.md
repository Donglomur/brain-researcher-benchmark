# Four-demonstration ERP reference programme

This component provides a deterministic reference programme for NEURAL-077's existing full32 numerical comparison. It derives its parameters from the same four labeled demonstrations presented to the direct arm. It is a candidate for a later paired study; its accuracy and probability calibration on ERP data have not been measured.

The existing condition contains 6,400 event-locked queries from 32 participants. Each input includes complete Cz/Pz waveforms with 1,024 samples per channel. The target is experimental target-versus-standard event identity, not physiological P3 presence. The source recipe already applies its reference and first-256-sample baseline correction. This programme preserves those supplied inputs and does not introduce another packet transformation, display-delay correction, participant split or target definition.

The programme uses no additional participant data, supplied fitted coefficients, cohort prevalence, query labels, query identity features or cross-query state. The four demonstrations are the only source for its class templates and nuisance estimates. Their numerical parameters are recomputed from the identical supplied demonstrations inside each fresh process; they are never updated using query outcomes. The opaque query ID is returned only to preserve the response ABI.

## Frozen method and interface

The method is frozen in `METHOD.json` and the programme configuration before generated controls. It averages 24 contiguous 32-sample bins from samples 256:1024 in each channel, yielding 48 features. These coordinates follow the released marker; the physical display-delay calibration remains unresolved.

Each channel is normalized using only the pooled baseline RMS of the four demonstrations. The scale has a floor of 1e-6 times their global RMS; all-zero demonstrations use scale 1. The two class templates are their feature centroids. Pooled within-class diagonal residual variance uses two degrees of freedom, 50% shrinkage toward the mean feature variance and a 1/32 ridge. With squared regularized distances D0 and D1, the programme maps `(D0-D1)/96`, clipped to [-12, 12], through a sigmoid. This equal-prior map is a fixed scoring choice, not empirically calibrated probability. Both classes must occur among the four demonstrations; no cohort prevalence is supplied.

The programme finds one exact four-demonstration JSON list and one subsequent exact query object in the bounded prompt. It rejects ambiguous/malformed structures; it does not assume undocumented prose delimiters. The existing authenticated participant-bundle interface supplies configuration and launches the module's `main()` entrypoint. The programme consumes one complete framed prompt and emits one framed query-ID/probability response. It does not supply a new runner or grader.

A later operator must capture the complete source/configuration bundle with the existing bundle interface before opening study queries and use the existing programme arm. Set the existing provider-pair freeze specification’s `programme_root` to this component’s `programme/` directory and its `programme_manifest` descriptor to `BUNDLE_MANIFEST.json` (123 bytes, SHA-256 `97017c646f461fedd26163a01cbadcc2a5bef69629059ad40f083467e6078be3`). The existing `bundle.capture(root, manifest)` and `bundle.verify(frozen)` interfaces produce the standard launcher; it injects immutable `neural077_config.CONFIG` before calling `erp_template.main()`. The module is intended for that launcher, not standalone invocation. Configuration changes require a new explicit source/method commitment. The unchanged paired admission requires both complete 6,400-case arms before protected labels open. This component neither selects a smaller pilot nor relaxes that requirement.

## What the source controls establish

Four generated controls assess whether separated signals produce different predictions, complementary demonstration labels reverse the decision, demonstration order leaves the prediction unchanged, and changing only the opaque query ID leaves probability unchanged. Generated fixtures assess these computational properties. The original prompt and packet were not exercised, so these controls do not establish actual EEG execution compatibility. They do not estimate EEG accuracy, benchmark difficulty, physiological specificity or calibration.

Source tests support a bounded external `ARTIFACT_DIR` and keep generated outputs disjoint from source/dependency trees. Final source metadata records the exact Python compilation identity, control results and qualification limits. No original EEG arrays, demonstrations, private labels, model calls or paid provider connection are used in source construction.

The [provider-pair component](../full32-provider-pair-v1/README.md) retains its separate capture/admission requirements. This reference programme does not qualify an LLM's tool restrictions, hidden context, provider identity or native neural understanding. A meaningful direct-versus-programme performance comparison still requires independently answered matched arms and protected grading.
