# Full32 visual interpretation and image-matched programme source

The explicit `erp-full32-visual-v1` profile extends the existing viewer, provider capture and frozen-programme route to all 6,400 queries from the 32-person ERP CORE packet. The paired conditions are `visual_direct_four_demo` and `visual_program_four_demo`. This is a source extension, not a new benchmark registration, completed visual delivery, provider qualification or model result. The historical `legacy400` visual default and the full32 numerical default remain separate.

## Matched information and scientific scope

Both arms can inspect the same four complete labelled demonstrations and one unlabelled query as images through the declared actions. The trusted viewer uses the existing lazy packet consumer; it does not derive records by parsing numerical prompts or repeat signal preprocessing. The solver receives neither numerical arrays nor the packet manifest, participant roster, grouping, source timestamps, trial indices, shard/order metadata, private answers or operator paths. The same display specification and action limits apply to both arms. Every initial raster must match byte for byte; the same subsequent actions produce equivalent pixels. Independently chosen action trajectories may differ.

The structured source is Cz/Pz, 1,024 samples at 1,024 Hz, using the existing released-marker source coordinates and half-open offsets [-256,768). The event target is experimental target-versus-standard identity. It does not establish physiological P3 presence, calibrated amplitude units or a physical 26 ms display-delay correction. No averaged-ERP exclusion is imported. The cohort remains finite and nonrepresentative; hidden prior exposure and model pretraining contamination are unknown.

Programme authoring is explicitly image-only. The frozen exposure declaration must deny raw numerical demonstrations, held or pooled query access, private targets, provider outputs, test-wide feedback, natural-class-prior use and the exposed six-person training material or fitted coefficients. Authoring may use the same four demonstration images and declared viewer actions. The complete programme, interpreter, source closure, public manifest descriptor, static display commitment and limits are frozen before query dispatch. An operator declaration cannot prove hidden lifetime exposure.

There is no retry, replacement, truncation or reduced cohort. The full32 macOS sandbox construction reuses the metadata allowlist in `full32-paired-runtime-v1/profile_successor.py`, including its literal `/Library` ancestor permission. Source-policy checks do not establish live native enforcement. The legacy 400-query policy remains historical.

## Existing executable interfaces

No new sender, runner, scorer or bootstrap engine is introduced. The existing provider `run` command accepts `--profile erp-full32-visual-v1` and `--manifest-pin` containing the exact JSON `{bytes,sha256}` descriptor. It retains its explicit model, credential descriptor, interpreter, query/campaign deadlines and request/response byte allocations. No model or provider is selected by this document.

The existing image `pair.py freeze` command takes the same profile and manifest descriptor, an image-only exposure file, programme bundle manifest, interpreter, protected roots and exact viewer limits. `run-programme` derives the profile from the authenticated frozen contract. `compare` takes both complete arm receipt descriptors, the frozen contract and an explicit evaluation-limits file with `work_seconds`, `read_bytes` and `write_bytes`; the existing minimum write allocation is 4 MiB. Collection alone is not full provider custody admission. A programme episode must use the maintained programme adapter, not the direct-provider collector.

The existing protected join and per-person metrics are reused. Primary comparison is direct-minus-programme participant-macro balanced accuracy at p >= 0.5; secondary log loss is natural-log, equally weighted by participant, with metric-only clipping at 1e-15. The existing bootstrap accepts `--profile erp-full32-visual-v1` with `VISUAL_BOOTSTRAP_POLICY.v1.json`. It retains 10,000 paired 32-person resamples, NumPy PCG64 seed 20261119, 95% percentile intervals, linear quantiles and the same draws for the primary difference and explicitly secondary unadjusted intervals. The numerical profile remains the default. No empirical interval was computed here.

Repeated source/capture authentications remain charged. Named conservative reserves cover source/runtime startup, bounded NPZ validation and the unchanged private loader after public gates. The counter describes logical reads, not physical disk traffic. A metadata inventory cannot substitute for body authentication or authorize more reads.

Complete HTTP history can still dominate retention. Compression is lossless, but generated fixtures do not establish an actual-cohort compression ratio or throughput.
