# ERP image-matched programme condition

This condition asks whether a frozen programme can interpret the same rendered EEG information available to the restricted viewer agent. It adds an experimental condition to NEURAL-077's existing 400-case viewer comparison. It does not add a dataset, an independent benchmark, or an AI performance result.

The existing visual-provider comparison pairs image inspection with a programme that receives numerical waveforms. That remains a separately named comparison. This condition instead keeps the observation representation matched: the programme receives the same initial raster and scientific metadata, with access to the same four demonstration records, viewer actions and action budgets. It may compute from the visible pixels. It may not obtain the original numerical observations or private answers through another interface.

The programme and viewer agent may choose different legal actions and therefore inspect different later views. Matching the available information and action semantics does not require identical adaptive trajectories, computation, latency or resource use. The condition records these distinctions rather than treating them as equal by assumption.

## Image and permission identity

The scientific prompt and initial observation retain their original content. The programme condition changes only the explicit permission concerning computation from permitted images. It preserves the original prohibition on external retrieval, other-query memory, unexposed files and raw observations.

The existing provider client may losslessly recode a rendered PNG before transmission. Original-raster and transmitted-image custody hashes remain distinct. The existing codec audit establishes identical decoded RGB pixels; it does not establish identical compressed PNG or HTTP bytes. The provider's later image preprocessing and perception remain unknown.

## Evaluation protections

Programme source, permitted dependencies, configuration, runtime identity and declared authoring exposure must be frozen before held evaluation. A programme frozen after the direct arm has begun its query campaign is ineligible for this paired condition. Each programme query uses a fresh process and the existing bounded viewer protocol. The first final response is terminal.

Both complete arms must pass public admission before the protected comparison opens private labels. The original cases, label joins and numerical scoring functions are reused. Missing, duplicated, misaligned or incomplete responses cannot be reported as a complete comparison. The existing image-versus-waveform and full32 routes retain their own identities and evidence.

The executable interface is `pair.py`: `freeze` creates the durable programme commitment and frozen contract; `run-programme` consumes an exact contract byte count and SHA256; `compare` requires exact direct-arm, programme-arm and frozen-contract descriptors. Freeze declares finite viewer, campaign and artifact limits and protected filesystem roots. The programme route requires the existing macOS sandbox policy; `protocol_only` is not an admissible programme condition. The same-host operator clock records freeze ordering and is not an external timestamp attestation.

The additive adapters bind authenticated existing transport and scoring source in private namespaces. They change the explicit permission and condition metadata, and record donor and derived identities. Existing modules are not globally patched. Numerical scoring mathematics and the ordering of public validation before protected label access are retained.

## Interpretation limits

The target is the released experimental event label, not physiological P3 presence or seizure detection. The four visible demonstrations are deliberately balanced, and their fraction is not the natural class prevalence. No full-training prevalence is supplied. A predictor using a prevalence learned from protected evaluation labels would receive additional information.

Source freezing constrains subsequent changes; it does not establish an author's earlier exposure or a model's pretraining history. Those remain declared or unknown as appropriate. Participant and case structure, uncertainty and reference comparisons must be reported with any future measured result.

Generated controls test construction and refusal behavior. They do not qualify an actual provider, demonstrate operating-system confinement, prove universal process containment, or measure neural understanding. Runtime restrictions and their evidence must be stated separately from instruction-only restrictions. This source contribution includes no live provider call, scientific evaluation, or readiness promotion.
