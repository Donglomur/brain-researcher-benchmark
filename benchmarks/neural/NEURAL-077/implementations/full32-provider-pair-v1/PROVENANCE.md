# Source provenance and limits

This additive source component supplies a full32 direct-provider producer, frozen-programme producer and separate paired admission. It is not an independently answered EEG experiment. The full32 scientific condition, source projection, target join and metrics remain in the existing authenticated repository components.

`SOURCE_BINDINGS.json` names and pins the complete runtime source closure using repository-relative paths. The new modules are `pair.py`, `broker.py`, `client.py` and `bridge.py`. Existing numerical projection and grading come from `full32-paired-benchmark-v1`; programme sandbox/episode primitives come from `full32-paired-runtime-v1`; bounded provider HTTPS/custody primitives come from `waveform-provider-v1`; framing and owned-process closure reuse their existing repository interfaces. No private evidence-tree loader is a public runtime dependency.

The request bridge enforces one complete prompt, an explicitly selected model/output allocation and disabled tool/retry/truncation policies in captured requests. Provider admission preserves the first original response and authenticates raw request/response custody. These checks establish consistency conditional on a trusted capture host. They do not independently qualify a remote provider's hidden state, no-tools behavior or capacity. Both full 6,400-case public arms must admit before the private-material descriptor and labels are opened. Generated source controls test refusal boundaries and never stand in for a complete scientific arm.

The target remains target-versus-standard event identity, not physiological P3 presence. The split excludes local training participants and the two exposed development participants; pretrained exposure is unknown. The freeze captures authoring inputs and an operator declaration, not proof of hidden prior exposure or absence of learned constants in arbitrary programme code.

An initial private syntax-check handoff reported Python 3.11.5 from a different executable. That observation is preserved privately and is not relabeled. Final source syntax compilation and the finite generated-fixture campaign use the selected Python 3.11.6 executable; their observed identities and results are recorded in `SOURCE.json`. No original EEG payload, protected target, live provider connection, model query or scientific score is part of this source phase.

Private authoring receipts, local paths, credentials and generated campaign artifacts are excluded from the public source allowlist. The test script can create its own bounded generated fixtures outside the repository, optionally under an external `ARTIFACT_DIR`. A later live study needs separate connection, resource, spending, programme and scientific review choices; this source publication does not authorize a live run or promote benchmark readiness.
