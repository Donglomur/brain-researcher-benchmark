# Fixed-reference ERP evaluation

This component evaluates the unchanged four-demonstration deterministic reference on NEURAL-077's existing 6,400 queries from 32 participants. It provides a separate reference-only contract, prediction collection and protected scoring path. Its outputs describe a deterministic programme baseline; they are not direct AI responses or a paired direct-versus-programme comparison.

The scientific target remains experimental target-versus-standard event identity. It is not physiological P3 presence. Inputs, the four permitted demonstrations, participant grouping and the original balanced-accuracy and natural-log-loss definitions remain unchanged. The reference's method and configuration are pinned to the existing four-demonstration baseline component. That programme previously passed one authentic-input compatibility diagnostic without opening the answer. The unchanged reference has since completed a separately selected full-cohort evaluation; its measured results and limits are reported below. It is not an optimized or qualified strong comparator.

Neither analytic comparator was executed as a new model run, and the reference was not retuned after scoring. Its probability calibration remains unqualified.

This measurement establishes an initial deterministic reference for experimental event-label classification. It does not measure a frontier LLM's difficulty, native neural understanding, paired direct-versus-tools performance, physiological P3 detection, paper improvement or SOTA.

## Information and completion rules

The source/configuration bundle, input manifest and full roster, supported runtime, authoring exposure and metric policy must be frozen before evaluation queries or protected labels are opened. A prior ungraded compatibility query is part of the exposure history; it does not authorize tuning this frozen method on the evaluation cohort.

Prediction collection uses one first response for each declared query. A complete reference requires the exact 6,400 unique case identities, finite valid probabilities, immutable input/output commitments and authenticated known process closure. A failure, missing case, duplicate, changed commitment or unresolved process remains incomplete. Such evidence is retained and cannot silently become a completed reference by dropping cases.

The private label descriptor is lazy. It may be opened only after complete reference admission. Scoring uses the existing authenticated private participant join and original per-participant metric computation. Both classes are required for each participant; missing or undefined participant metrics cause refusal rather than exclusion. Results retain all per-participant metrics and their equal-participant macro averages. This source does not add a trial-independent uncertainty estimate or a new endpoint.

## Operator interface

`reference.py` exposes three separate operations:

1. `freeze --spec PATH --spec-bytes N --spec-sha256 HASH --output FRESH_DIR` authenticates a provider-free specification and writes `CONTRACT.json`, `PROGRAMME.json`, `EXPOSURE.json` and the frozen full `ROSTER.json`. The specification binds public manifest/roster descriptors, baseline source/manifest, exposure declaration, supported interpreter/sandbox and finite work/read/write limits.
2. `run-reference --contract PATH --contract-bytes N --contract-sha256 HASH --output FRESH_DIR` executes the complete programme reference. It retains the initial case inventory, first responses, per-case closures and collected predictions. A complete output has an `ARM.json` receipt; failed or partial output does not acquire completion merely because some predictions exist.
3. `evaluate-reference --contract PATH --contract-bytes N --contract-sha256 HASH --arm ARM_DESCRIPTOR_JSON --private-material PRIVATE_DESCRIPTOR_JSON --output FRESH_DIR` validates the single reference and then loads private material lazily. The arm descriptor contains only its output root and authenticated receipt. The protected result is `RESULT.json` with the unchanged original participant metrics.

All destinations must be fresh and disjoint from selected source, data and evidence operands. The source/read/write/runtime contract is finite. Each additional authentic execution requires its own selection and admission. The source controls remain generated-only; the separate measurement above is actual fixed-reference evidence.
