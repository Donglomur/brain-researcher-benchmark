# NEURAL-067 causal row and action journal primitives

This source component restores the operator-side row reader and durable action journal from the exact lifecycle source named by the registered runtime manifest. It adds a failure fix: a partial write, failed fsync or post-write deadline cannot leave a journal open for a retry at the same ordinal. Initial append deadlines also permanently close the journal. Header-write/sync failures during construction, initial or post-write append deadlines, action-write/sync failures, and failures during complete sealing permanently close the journal logically and attempt descriptor closure. An OS close failure records unknown descriptor state and preserves the original error as primary with cleanup failure chained. Malformed append arguments and incomplete-seal precondition refusals leave an otherwise valid journal usable; they do not write an action or produce a successful seal. Failed files are preserved.

The prepared cache format is the existing `<176Hdq` layout:176 unsigned16-bit count slots, one float64 timestamp and one int64 trial identity. Counts must be at most255. This is the locally declared prepared representation, not a claim that every raw FALCON file contains176 units. Preparation must authenticate the actual NWB unit order, count conversion, timestamps and source masks. Seven actions retain the existing coordinate order `tx,ty,tz,rx,g1,g2,g3` and native source units.

`Rows` exposes only the selected arm's permitted fields. Clock fields use elapsed run time and observed segment age; query length and raw trial identity stay outside observations. `Journal` stores seven actions plus observation and predecessor hashes in4096-byte-header/160-byte-record files. Append progresses only after successful fsync and the final deadline check. A journal that suffered an I/O/deadline failure is permanently closed logically and cannot issue a successful seal. Logical closure is set before attempting `os.close`. On failure, `close_error` retains the attempted descriptor, error type and unknown descriptor state; this does not prove resource retirement. The enclosing controller must resolve that obligation. The journal never retries an ambiguous descriptor close.

These are operator primitives, not a participant runtime or isolation mechanism. A caller can invoke `Rows.next()` repeatedly; an enclosing trusted controller must enforce one committed response before the next observation is released.
