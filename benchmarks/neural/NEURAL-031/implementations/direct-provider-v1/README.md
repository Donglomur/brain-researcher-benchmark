# Complete NEURAL-031 direct-provider arm

This sibling package connects the unchanged numerical observation, first supplied
response capture and complete collector to a trusted provider transport. It
creates forty separate requests, preserves each original provider response and
admits all 1,548 predictions together. It supplies no model result or scientific
qualification. No authentic inputs, provider, credentials or model were used in
its generated source controls.

The condition remains direct numerical observation of processed morphology and
coactivity measurements. The twenty mice, 774 requested rows per information
view, 731 observed ratios and 43 requested unavailable targets are unchanged.
Baseline has four columns and neural has six; common missingness and permitted
training labels remain identical. Direct versus programme access is a separate
axis from baseline versus neural information. This is not raw microscopy,
waveform understanding, the source paper's pooled correlation, a causal tool
effect or an independent experiment for each overlapping training fold.

## Complete presentation and independent requests

`prepare` first commits the selected source/model/resource specification, then
calls the existing numerical `Engine.present` for each original authenticated
export. No new serializer, row selection, feature rounding or target conversion
is introduced. The preparation pins each complete `OBSERVATION.json` and its
operator presentation receipt in `CONTRACT.json`. Preserve the returned contract
descriptor externally before dispatch. Only the observation text and response
schema enter the model request. The support, other contexts, receipts, paths,
credentials and private query targets do not.

Every fold/view receives a new trusted client process and one independent
Responses request. There is no conversation or previous-response link. The
constructed request explicitly supplies `tools: []`, `tool_choice: "none"`,
`parallel_tool_calls: false`, `store: false`, `stream: false`,
`background: false` and `truncation: "disabled"`. Another fold's training labels
disclose this fold's answers, so a persistent multi-context conversation would
invalidate the condition. The trusted operator must also account for attempts
and access outside this controller.

The complete observation cap remains 512 KiB and the answer cap 128 KiB. These
are byte bounds, not tokenizer or model-capacity proof. A later selected model
must support the whole request and sufficient answer allocation. Size overflow,
context-length errors, refusals, incomplete output, wrong model/policy, tool
outputs or multiple final messages fail the assigned attempt. There is no
shortening, replacement model, second response, automatic retry or partial arm.
An actual endpoint's support for this strict request/response schema remains
unqualified by generated tests.

## Original response custody and complete admission

The client reuses the exact pinned N077 HTTPS `Sender` and exclusive `Custody`
primitives. Its fixed endpoint, TLS verification, one-call refusal, bounded raw
capture and no-redirect/no-retry behavior remain unchanged. The donor HTTP
receipt retains its `neural077_https_binding_v1` name as source provenance; it
does not identify this arm as EEG. The task-specific bridge accepts the N031
request identity and all ordered ratio rows instead of EEG scalar probabilities.

Credentials enter an inherited anonymous pipe supplied by a separately
authorized operator application. They are not argv values, environment settings,
configuration files or prompt content. The sender retains bounded raw request
and response bodies before answer parsing/emission. The parent pins all four raw
custody records in each exclusive `END.json`; the complete arm pins those ends.
A failed or malformed first answer remains a failed original exchange. Raw
failure prefixes, including unresolved timeout evidence, remain in its directory.
Literal credential echoes are refused under the existing donor policy; broader
semantic secret disclosure and complete memory erasure are not proven.

The single-thread broker uses the unchanged `owned_exit` primitive. It creates
a new session, observes exit without reaping, then performs the sole owned group
stop/reap. It requires normal exit, pipe EOF and known group absence. It does not
claim containment of escaped descendants, malicious-host isolation or remote
cancellation/billing cessation.

Each successful original provider answer is passed to the unchanged numerical
capture. Its existing provider/fresh-context/no-tools fields stay false.
`run` records the entire planned roster before dispatch, preserves first failures
and unattempted counts, and only calls the original complete collector after all
forty exchanges pass. It writes no partial `ARM.json`. An independently selected
`admit` invocation authenticates the external contract and arm descriptors,
reconstructs every complete request, checks all raw first responses and unique
provider response IDs, joins every unchanged capture, and verifies the complete
original submission/support and collection. It opens no private target and calls
no scoring function.

Transport admission reports captured request-policy consistency and original
response consistency under trusted local custody. It does not set remote
context/tool-policy or scientific qualification true. A self-consistent set of
receipts cannot prove a dishonest operator's behavior or unseen server state.

## Later operator use

All commands require a separately selected study and finite resource allocation.
They do not authorize network/model spending. Use an existing Python environment
with NumPy for preparation/collection; the one-request client uses the standard
library. `SOURCE.json` authenticates this package and its unchanged relative
dependencies before loading them. The already executing launcher, Python/NumPy,
standard library, OS and operator remain trusted.

The exact preparation specification has these keys:

- `schema`: `neural031_provider_spec_v1`.
- `input_root`: absolute root containing the original `foldNN/baseline` and
  `foldNN/neural` exports; each has its authenticated manifest and NPZ.
- `support_path`: absolute path to the original pinned public support JSON.
- `provider`: exact `model` identifier and integer `max_output_tokens`.
- `interpreter`: absolute `path`, `bytes` and `sha256` of the existing executable.
- `limits`: `episode_seconds`, `cleanup_seconds`, `arm_seconds`, `read_bytes`
  and `write_bytes`. Whole-arm limits include every dispatch and collection;
  an episode must leave its cleanup and failure-finalization time.
- `authoring_exposure`: bounded declaration of known authoring/prior access;
  it is not an attestation of hidden lifetime or pretraining exposure.

Byte counters conservatively reserve bounded source/metadata, file reads and
child/collector writes; they are not measured syscall I/O or a live-run cost
estimate. Initial bounded CLI/source preflight and emergency failure records
also require outer operator supervision. Only resource adequacy for the
generated fixtures is observed. Provider token usage is recorded, but no input
tokenizer, monetary budget meter or hidden-provider compute meter is supplied.

Use fresh output directories outside the input, freeze and repository trees.
Their parents must already exist. Paths and receipt hashes are trusted operator
operands, never participant-selected. Preserve failed directories; resubmitting
the same assigned attempt in another directory is forbidden by the study
protocol, not prevented against an unrestricted operator.

```text
python -I -B provider.py --source-sha256 SOURCE_SHA prepare \
  --spec SPEC.json --spec-bytes N --spec-sha256 SHA --output FRESH_FREEZE

python -I -B provider.py --source-sha256 SOURCE_SHA run \
  --freeze FRESH_FREEZE --contract-bytes N --contract-sha256 SHA \
  --credential-fd 3 --output FRESH_ARM

python -I -B provider.py --source-sha256 SOURCE_SHA admit \
  --freeze FRESH_FREEZE --contract-bytes N --contract-sha256 SHA \
  --arm FRESH_ARM --arm-bytes N --arm-sha256 SHA
```

The credential descriptor must already be provisioned privately; writing `3`
does not create a pipe. Do not place credential values in commands or logs.
Freeze a common scorer and matched direct/programme design separately before
any scientific comparison. The historical fixed ratio-1 programme control,
original programme batch budget, scorers and old outcomes remain unchanged.

first responses, capacity/overflow/incomplete/timeout failures and no replacement
or retry. Temporary fixtures are removed with cumulative artifact counts reported.

Actual authentic presentation custody, supported endpoint/model behavior,
complete input/output token capacity, remote independent-context operation,
