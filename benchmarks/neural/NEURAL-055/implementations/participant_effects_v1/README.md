# Ten-person endpoint retention

The existing paired report retains grand means and resampling intervals but omits the ten participant effects required by `understanding.v1.json`. This operator-side extension publishes each person's scores and matched contrasts under their existing opaque case ID. Seeds and 200 shared images remain repeated observations within ten people.

`endpoint.participant_endpoints(reporting, system, expected, terminals, outcomes, pairing, contrast_registry, registry=registry)` consumes the protected operator's already-scored outcomes. It calls the preserved `reporting.complete_conditions` to retain the original query identity join and within-person replicate averaging. A missing required cell makes the whole condition unavailable. It validates that each person retains one case across all conditions and that distinct people do not alias one case. It emits no query IDs, individual query outcomes, source-person IDs, or targets.

The endpoint now requires exact equality with `registry.campaign(system)`, all 960 unique expected cells, and an exact matching terminal roster before aggregation. Removing a seed from `expected`, or replacing it with extra cells under another condition while retaining the same count, cannot turn missing evidence into a complete denominator. The new required keyword `registry` is the authenticated original registry module pinned in `SOURCE_BINDINGS.json`; it is supplied explicitly rather than imported from an unselected environment. This is an API change: callers must pass that module and bind its source before using the extension. The endpoint checks the canonical cell definitions and seeds; it does not itself authenticate the supplied module's source.

Valid raw outcome rows must retain exactly 200 unique query IDs and 200 values for each original metric; extra rows or metrics cannot disappear during identity indexing or averaging. Missing outcomes still make their condition unavailable, while joint query/value permutations retain the original identity join.

`endpoint.paired_report(reporting, system, expected, terminals, outcomes, pairing, schedule, contrast_registry, interpretation_records, guard, registry=registry)` is the explicit successor reporting API. The first argument is the authenticated original reporting module. It calls the original report once, preserves every existing field, and adds `participant_endpoints`. The original 32 contrasts, F/I and T0/T1 conditions, neural-control arms, independent-query comparison, infinite-loss conventions, and fixed-panel interpretation remain unchanged. Positive-infinite NLL remains infinite; infinity minus infinity remains undefined.

This component is callable source, not a newly selected campaign runtime. An integration owner must bind the added source and this explicit call in a successor protected runtime manifest before scientific use; the preserved `protected.py` still calls its original report. No manifest, canonical contract, history, target, or prior result is changed here. This extension cannot establish direct/viewer interpretation, native containment, author-baseline competence, or any of the outstanding scientific gates.

The generated standard-library controls exercise the actual original aggregation and contrast functions over the complete 960-cell registry. Their arithmetic expectations are hand-computed. The adapter test replaces only the expensive bootstrap-bearing report call and checks that original numerical fields survive unchanged; it does not qualify bootstrap numerical agreement. Run `test_endpoint.py` through the coordinator's reviewed two-slot pool.

Source bindings are recorded in `SOURCE_BINDINGS.json`. No authentic EEG, image payload, checkpoint, private target, fitting, solver trial, or model call is used by this component's controls.
