A semantic nonmatch, incomplete close or failed receipt custody cannot become a confirmed runtime control. Semantic failure does not erase separately proved cleanup.

All six controls and all three host-context closures are required for complete success. Each call uses a fresh container. The runtime attach cap is 512 KiB; the unchanged flood control still exercises the full 2 MiB backend limit.

## Source controls

The final source has 16 distinct generated control groups across these files:

- `test_fresh_runtime_state_v1.py`: six authored custody, grammar, source and condition groups.
- `test_fresh_runtime_boundaries.py`: three independent body and closure boundary groups.
- `test_fresh_guard.py`: three exact-admission and cancellation groups.
- `test_fresh_driver_boundaries.py`: three independent orchestration and receipt-custody groups.

Run each with Python 3.11 and `-I -S -B`. These tests use the standard library and committed generated fixtures; they do not require Docker, NumPy on the host, original EEG, a provider or an API key. The complete-flow test creates a small temporary generated staging directory under its current working directory and removes it. Its evidence and report bodies, including the 2 MiB flood, remain in memory.

The complete flow exercises the real backend orchestration, command meter, fresh adapter, frozen parser/predicate and exact report serialization with simulated daemon/process receipts. It produced six attach calls, three context closes and 43 commands. Its final report was 63,989 bytes against the unchanged 65,536-byte cap. The fresh receipt was 8,285 bytes and the generated runtime output was 139,820 bytes, testing output larger than the old 64 KiB recorder cache. This is generated source evidence, not actual process custody or isolation qualification.

A preceding full-flow check exposed a 71,643-byte report-cap failure. Its source/result and costs are preserved outside Git. ## Operational limits

The prospective retained-image run uses six sequential containers across three host contexts, with two read-only input file mounts, an immutable selected image, read-only root, network and IPC modes `none`, all capabilities dropped, no-new-privileges, private bounded tmpfs and no candidate Docker socket or credentials.

The selected network condition is necessary, not a universal isolation claim. It checks the captured flags, addresses, scoped route forms and process capabilities against the inspected configuration. It does not establish an atomic snapshot, firewall or policy-routing-rule coverage, cross-namespace invariants or arbitrary hostile-code security.

The exact proposed native bounds remain 600 seconds under the external supervisor, a combined 1 GiB host/candidate RAM declaration, one thread, 64 MiB explicit worker file reads and a 4,390,912-byte cumulative artifact envelope. Host RAM is declared rather than an OS hard limit; the candidate has inspected cgroup limits. Modeled owned CPU allowances and explicit file/command accounting exclude shared Docker daemon, VM and kernel costs. Failed and unknown charges are retained.

No new native qualification, model call, authentic EEG read, scoring run, image pull, install or benchmark-readiness increment is established by this source directory.
