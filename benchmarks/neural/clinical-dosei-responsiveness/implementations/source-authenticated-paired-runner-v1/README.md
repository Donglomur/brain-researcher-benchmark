# Authenticated paired workflow connector

This package connects the accepted DoSEI metadata and on-demand observation reader to the existing paired controller, code backend, prediction sealer and ordinal scorer. It preserves all 7,345 assessment slots and 171 recording groups. It introduces no model, target, split, baseline or scientific result.

`release_admission.admit_release` accepts complete immutable metadata bodies and checks fixed accepted hashes for each role. It joins every observation to the private case index, recording receipt, source clock, array identity and common disclosure. The public controller receives only opaque case IDs and observation hashes. The accepted saved proof establishes historical completion; this code does not pretend to inventory the current source directory. The existing reader checks current array identities before and after each actual slice read.

`dependencies.load_dependencies` authenticates named inherited source files before compiling them. A trusted caller must also authenticate this new package through its frozen source manifest. Supplied Python modules, callbacks and objects remain trusted host state; neither class names nor matching digest strings prove custody or isolation.

`assembler.build_runner` reauthenticates the complete fixed release and the accepted six-control engineering proof before constructing an ordered delivery factory. Construction opens no arrays and invokes no participant. `run()` projects each case once, compares the exact canonical packet and each fresh default image to their accepted byte hashes, then delivers viewer and code conditions in the frozen order. The arms have separate viewer state. The code backend receives the same packet and explicitly uses `owned_process_v2`; the viewer arm has no numerical export or code capability. Code assistance limits and tool declarations are part of the common prospective budget.

The factory retains host-private projection, setup and closure originals. It closes capabilities irreversibly, rejects out-of-order or repeated delivery, retains cleanup uncertainty and refuses a successful pair when custody or cleanup fails. Array-read counters remain available after failure. Projection receipts include new cumulative read counters, so they are not claimed to reproduce historical receipt hashes.

Prediction collection, `seal(result)` and `score(sealed)` are separate operations. Targets enter only the post-collection sealer and scorer. Existing grouped MOAAS categories, nullable labels, full denominators, ordinal loss, abstention policy and descriptive recording summaries are unchanged. Recordings are not established independent patients; the task is retrospective marker-associated source responsiveness, not clinical diagnosis.

The explicit `build_generated_runner` route uses fictional metadata, scripted participants and code stubs. Its output is marked `generated_only` and cannot enter the fixed authentic admission function. Full-cohort generated controls use a counting evidence sink and a signature-only image stub. Small controls retain generated originals. These checks establish source connections and failure handling, not durable complete-cohort custody, actual plotting, model ability or general isolation.

An authentic execution still needs a selected real participant worker/configuration, original provider delivery and usage evidence, hard adapter deadlines, and a prospectively admitted aggregate resource budget. The shipped provider transport elsewhere in the task has only a fake worker; it is not silently upgraded here. Accepted observation manifests contain hashes rather than all packet bodies, so actual execution must budget fresh array reads and rendering. Six checked runtime controls do not establish scientific readiness or qualify arbitrary hostile programs. This package supplies no automatic execution, download, installation, API call or supervisor.
