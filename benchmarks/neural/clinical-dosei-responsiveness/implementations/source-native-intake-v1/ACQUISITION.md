# Native source acquisition and preparation handoff

The original signal archive has **not** been acquired for this component. This is a staged protocol proposal, not an execution receipt. The small metadata/static/artifact archives were authenticated separately; their pins are in `PROVENANCE.json`.

The exact original is [`data.zip` in immutable Zenodo record 22145442](https://zenodo.org/api/records/22145442/files/data.zip/content): **724,356,077 bytes**, publisher MD5 **`b98c8a81d2e866085f9e7ac75a950754`**. Full SHA256, ZIP expanded size, exact member paths and member hashes remain unknown. Source documentation describes `10-XXX.csv` names; an enclosing `data/` path is not yet authenticated. Use the fixed record, not a floating concept/latest URL.

1. Check approved local source locations for the exact size/MD5 before downloading. A matching filename is insufficient. Reserve the archive, one partial file, bounded receipts, and future scratch/output storage separately. An interrupted body must not lead to an unaccounted second copy.
2. Download through verified HTTPS with an allowlisted Zenodo host, no more than three HTTPS redirects, a 10-second connection timeout and a 180-second attempt deadline. Stream to one exclusive partial path; cap body bytes at 724,356,077 and headers separately. Do not automatically retry. Require exact completed size and MD5, then retain SHA256. Any resumption requires validated Content-Range and stable object identity.
3. Inspect the central directory without extracting. Retain every name, compressed/expanded size, compression method, CRC and relevant flag. Refuse traversal, absolute/duplicate names, symlinks, encryption or unsupported methods. Require an explained exact mapping to all 171 authenticated metadata IDs. Never discard unknown files or omit an ID merely to reach an expected count.
4. Before signal parsing, freeze an actual preparation allocation from the inspected inventory. Proposed administrative ceilings are one CSV at a time, each <=1 GiB and <=4,000,000 rows, <=32 GiB expanded across the archive, one CPU thread, <=1 GiB RAM, <=180 seconds per bounded invocation. These are refusal limits, not source-size estimates; an over-limit member requires a reviewed protocol revision, not truncation. A regular temporary file is needed by the current hash-bound CSV interface; reserve its full expanded size and remove only owned completed scratch after retaining provenance. Do not extract all recordings to disk at once.
5. Perform an evaluator-private header/annotation pass before freezing source grammar. Recover exact native unit suffixes, null spellings, EVENT tokens/separators, sparse MOAAS/SOC spelling, source timestamps and per-record counts. Preserve source rows, disagreements, ambiguous/null labels, version changes and residual-error annotations. The current `scan` command retains every nonempty EVENT/MOAAS/SOC row but calls derived MOAAS rows **candidates**. It cannot establish full original-EVENT parity by itself.
6. Reconcile all 171 recording IDs and source events against v2 metadata, retaining the 7,345/1,132 aggregate alongside the legacy 7,328/1,129 declaration. Select no successor denominator before original-event identity and exclusions are reviewed. Keep actual repeated-procedure grouping explicit and biological-person identity unknown until authoritative evidence exists; do not link people by demographic similarity.
7. Freeze the retrospective `native_marker_relative_30s_v1` candidate manifest and its protected targets separately. Use the exact original marker and all native grid rows in `[marker−30 s, marker)`. `candidate-packet` can produce a full waveform for an admitted coded candidate, with no clinical fields or released artifact mask in the participant projection. It does not certify complete census, original EVENT identity or canonical eligibility. Preserve incomplete windows and ambiguous labels in coverage rather than dropping them.
8. Generate packets lazily or reserve their complete output size explicitly. Overlapping 30-second windows should not cause an unplanned full-data duplication. Released offline artifact masks stay private; future-dependent annotation/QC cannot silently enter participant input. The historical pre-challenge/onset condition remains unavailable.

After the source census and biological grouping are resolved, review a successor scorer-policy adapter, reference qualification and participant transports. No source-processing step here authorizes training, a model API campaign, additional downloads or a clinical performance claim. The original ordinal scorer and its inherited count checks remain unchanged.
