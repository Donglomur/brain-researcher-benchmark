# NEURAL-095 prospective cross-access comparison

This private source component compares **restricted viewer interpretation** with
an **agent-authored frozen prediction programme** on the same original DMFC
timing task. It does not register a benchmark, qualify an execution environment,
or report an AI result. Its source is additive; the old four-cell scored owner
and existing viewer remain unchanged.

The four comparison products are viewer/cue-only, viewer/neural,
frozen-programme/cue-only and frozen-programme/neural. Each has the same complete
258 query trials and access to all 748 training trials from Haydn20161211. The
neural information is forty held-in units in four 50 ms bins strictly before
Set, with the original cues, elapsed clocks, training labels and folds. These are
spike counts, not continuous waveforms. The target remains released `tp_ms`;
the original five fixed references, MAE/RMSE, forty conditions, eight contexts
and context-macro MAE remain unchanged.

The viewer exposes typed navigation, metadata and lossless count-table PNGs.
All training examples are available; a participant need not view every example.
Its within-view state and navigation are distinct from the programme's original
TRAIN-only preparation and single frozen full-query numerical call. The latter
may construct a learned tool using the training data. Neither route is renamed
`case_adaptive`. The old four-cell experiment still compares frozen and adaptive
programmes separately. Identical input commitments do not make representation,
learning, inference method or resource budgets identical, and do not identify a
causal effect of tool access alone.

## A prospective programme collection

The old owner issues success only after protected scoring, so its receipt cannot
establish the required prospective comparison. `frozen_owner.py` assembles a new
explicit `frozen_pair_ungraded/v1` source deployment in memory. It reuses the
original Cell, ActorBackend, frozen actor, numerical ABI and process/resource
cleanup. It selects only the two frozen cells and six numerical units: preparation,
one complete-batch tool call and export for each view. The collector constructs
no PairedEvaluator and opens no protected query target or reference report.
Authenticating source descriptors that name the existing scorer is not executing
the scorer or reading those protected operands.

The new collection's opaque submissions are not represented as publicly
validated. Its distinct outer receipt requires actual completion and cleanup of
the controller, both actor families and all six numerical units. It cannot be
created by renaming an old scored result, accepting two old COMMIT files alone,
or recovering unfinished processes during comparison admission. The original
per-cell limits and conservative 4,800-second whole-operation allowance remain
prospective; this source grants no execution or fresh cumulative-cost allowance.

An independently selected source map supplies exact byte-count/SHA256 descriptors
for `frozen_owner.py` and `frozen_collection.py`. The selected deployment root,
configuration, source freeze and final outer receipt are separate operator
inputs. Self-authored receipt hashes are not independent approval or proof that
a source/procedure review occurred.

## The comparison barrier

`cross_mode.dependencies()` authenticates and executes captured dependency bytes.
Its single transport bootstrap substitution injects the captured original viewer
module; its original source manifest and reported source identity stay bound to
those captured bytes. Public data capture and participant checks remain the
original functions.

`cross_mode.evaluate_paths()` is the concrete operator entry point for a future
admitted study. It constructs the original public packets and original protected
loader closures, then calls the adapter. Constructing those closures does not
open their protected operands. The adapter:

1. Reuses the participant transport's closed-view audit and the viewer's exact
   replay/collection validation, including its typed completion receipt.
2. Authenticates the new programme's independently selected source/configuration
   and full closed ungraded operation.
3. Joins the complete ordered query roster and all five original input-file
   commitments for each view. These bind training targets/folds, query cues and
   clocks, counts, units, schema and task contract.
4. Matches distinct selected viewer/programme method policies and validates both
   programme NPZs with the unchanged public validator. Complete programme NPZ row
   permutations are accepted and aligned by case ID; reordered declared rosters,
   missing cases and changed commitments are rejected.
5. Snapshots all four finite prediction vectors before calling either protected
   loader. It loads the original references and targets once, joins their exact
   case order and cues, and uses the unchanged reference scorer and corrected
   paired arithmetic. Cue-minus-neural differences are reported separately for
   each access mode, with their original sign and no invented improvement margin.

The full source map and frozen handoff identify the exact accepted API, controls
and dependencies. Passing a policy after collection does not prove prospective
cross-access preregistration. Existing viewer cleanup also explicitly leaves
descendant absence, real provider context/reset, and external no-tools enforcement
unqualified. These limitations are retained in the comparison output.

## Evidence limits

Generated controls use invented complete case rosters and predictions. Adapter
controls explicitly stub viewer/programme custody boundaries while exercising
the original NPZ validator and score arithmetic; owner controls separately cover
the actual new source/closure logic with native infrastructure substituted. They
are software checks, not participant runs or neuroscience results.

The earlier authentic fixed-800 ms rendering/replay preparation does not qualify
the newer participant transport and is not evidence for these four participant
products. No authentic inputs, models, providers, fits, containers, downloads or
native scientific runs are used in this construction. A later complete study
requires separately reviewed operational inputs, environment and resource
admission. One exposed animal/session supplies no unseen-animal generalization
claim. Previously exposed reference group scores also mean operationally withheld
targets are not necessarily contamination-free secrets.
