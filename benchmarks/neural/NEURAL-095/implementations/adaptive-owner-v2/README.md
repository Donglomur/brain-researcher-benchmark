# NEURAL-095 stateful investigator owner successor

This source assembler connects the existing `case-investigator-v1` actor to the
actual protected four-cell owner. It closes the old configuration gate's refusal
of the stateful policy. The two adaptive cells receive one identical, reviewed
callback embedded in the original actor template. Each cell runs a fresh actor;
callback globals and observation history persist across its complete 258 cases.
The full unlabeled query batch remains available through the numerical tool.
Observations may change later tool requests and predictions. TRAIN-only fitting
finishes first; fitted artifacts stay frozen after queries open.

The frozen-program branch retains the exact original offline actor and its one
full-batch numerical call. It receives the same reviewed numerical program and
method as the adaptive branch. The original backend enforces that frozen output
equals the first full-batch result. Historical offline runs are not relabelled as
adaptive experiments. A Python callback is not a model/provider connection or
evidence of native neural understanding.

## Construct a prospective source deployment

Use Python 3.11 or later. Supply the original portable runner's fully populated
operator declaration, one numerical program, its complete METHOD.json, one
`def decide(context)` callback and an independently reviewed JSON source/procedure
record (start from the deliberately unapproved `REVIEW_TEMPLATE.json`). The numerical ABI is the original TRAIN-only `prepare` followed by `tool`;
`arguments={}` must return the unchanged complete frozen batch. Other declared
argument dictionaries may return permitted numerical observations for the actor.
Tools must never fit on query data. The callback interface is documented in
`../case-investigator-v1/README.md`.

The review schema is `dmfc-stateful-investigator-review/v2`. Required fields and
checks are enforced in `configuration_gate.py`: exact byte-count/SHA256 pins for
callback/program/method; substantive findings for all twelve original method
fields; an identified reviewer, findings, all eleven procedure checks; decision
`source_and_procedure_reviewed_for_original_contract`; and both
`execution_authority` and `matched_method_proven_by_grader` set to false. No
positive review or execution request is generated. A named reviewer in JSON is
attribution, not cryptographic authentication.

```sh
python3 -I -B configure.py --operator operator.json --destination /srv/dmfc-v2 \
  --callback decision.py --callback-sha256 EXACT_CALLBACK_SHA256 \
  --program numerical.py --program-sha256 EXACT_PROGRAM_SHA256 \
  --method METHOD.json --method-sha256 EXACT_METHOD_SHA256 \
  --review REVIEW.json --review-sha256 EXACT_REVIEW_SHA256
```

Choose a fresh, ordinary, sufficiently short deployment path to satisfy the
original Unix socket bound. The command authenticates the fixed source templates,
parses candidate code without executing it, assembles the callback, replaces the
deployed configuration gate, and updates the complete source closure. The paired
worker's new pin propagates through delivery manifest, producer, live adapter and
closure. Original repository packages and public scientific inputs are untouched.
`DEPLOYMENT.json` records every rendered source; `CONFIGURATION_PAYLOAD.json`
contains no request. Keep their exact SHA256 values. Partial writes on filesystem
failure are preserved; do not reuse their destination.

Provision original inputs as specified by the original runner's PROVISIONING
instructions; this helper never reads or downloads them. A responsible operator
must separately select the complete operation and issue the original current
request/capacity witness described by
`../neural-095-four-cell-runner/OPERATOR_ADMISSION.md`. This successor's own
`admit.py` attaches that existing request and delegates to the unchanged owner;
the historical external-candidate gate intentionally continues to refuse it.

```sh
python3 -I -B admit.py --root /srv/dmfc-v2 --deployment-sha256 EXACT_DEPLOYMENT_SHA256 attach \
  --payload /srv/dmfc-v2/CONFIGURATION_PAYLOAD.json --payload-sha256 EXACT_PAYLOAD_FILE_SHA256 \
  --request /srv/dmfc-v2/operator/REQUEST.json --request-sha256 EXACT_REQUEST_SHA256 \
  --output /srv/dmfc-v2/operator/CONFIGURATION.json
python3 -I -B admit.py --root /srv/dmfc-v2 --deployment-sha256 EXACT_DEPLOYMENT_SHA256 run \
  --configuration /srv/dmfc-v2/operator/CONFIGURATION.json --configuration-sha256 EXACT_CONFIG_SHA256 --dry-run
```

After separate operational admission, omitting `--dry-run` replaces this helper
with the original entrypoint. The original owner then checks request freshness,
capacity, exact daemon/image, source closure, limits and recovery. Dry-run/source
bootstrap success does not authorize execution or certify runtime readiness.

including rejection of an intentionally incomplete owner request. It calls the
actual controller composition, ActorBackend and Study over four complete cells:
1,032 generated predictions, four fresh real actor subprocesses and six numerical

count observation, and all four actors close before validation/scoring barriers.

container/IPC operations. The numerical observations are computed from complete
invented 748/258 arrays, including all 4×40 count features. The evaluator's private
unit is a generated stub; no authentic target/reference score is claimed. Tests
also bind unchanged scientific descriptors and the exact mounted arithmetic.

No authentic packet, model/API call, container run, scientific result, runtime
qualification or new benchmark ID is produced by this package. One exposed animal
session cannot establish cross-animal generalization, causal neural contribution,
SOTA, contamination-free testing or scientific matchedness from source hashes.
