# NEURAL-097 indexed endpoint revision

`metrics.evaluate(targets, predictions)` computes the existing protected endpoint with strict participant and stratum identities. The preserved scorer accepts `False` as participant 0 and `0.0` as an integer index. It also accepts a stratum with extra elements, then silently excludes that case during cell matching. This revision rejects those malformed inputs before producing scores. It indexes the target universe once instead of scanning it for each of 2,970 arm/cell combinations.

The numerical endpoint and report structure are unchanged for valid inputs: five identical case sets, all 33 participants, two relevance strata, nine duration/orientation cells per participant, face-positive classification at `p_face >= 0.5`, equal class/cell/participant weighting, natural-log losses clipped at `1e-15`, balanced Brier, and the separately retained prevalence-weighted legacy loss. Both held image halves must already have been pooled once by the existing protected controller. Missing class support propagates null balanced metrics; an empty cell also nulls legacy loss. No participant or cell is dropped or reweighted.

The module uses the Python standard library and imports no source readers, candidate code, native launcher, fitting routine or protected roster. It accepts a target map with nonempty string case keys and rows containing `person_index`, `y`, and `stratum`; additional trusted metadata is ignored and never returned. Each prediction arm is a map from the exact same case keys to finite, nonboolean numeric probabilities in [0,1]. The return value retains the predecessor's structure, including its explicit lack of scientific qualification.

This is an operator-side mathematical component, not a participant submission route. Call it only after the existing target-last controller has admitted prediction identities, source/case lineage, source-panel binding and all required execution receipts. It cannot authenticate those properties. Importing this component into an unqualified runtime does not establish admission, competence or an empirical result. The historical runtime, contracts, source pins, mode claims and task definition remain untouched; selecting this revision for the registered runtime is an integration decision that requires pin updates and review.

The source design is a prospective sensor-summary adaptation. It is not the original paper's source-space pseudotrial analysis. No authentic data, protected targets, cohort roster, reference fits, candidate trials or source downloads were used here. Full source/census preparation, all 22 qualification gates, competent references, direct observation, typed viewer and investigator delivery remain unresolved. No new evidence for neural interpretation is claimed.

`tests/test_metrics.py` uses generated data to check exact predecessor parity on unequal cells/classes/participants, independently calculated endpoint values, class-balanced versus prevalence-weighted losses, missing/empty support, chance thresholds, arm separation, malformed identities and probability refusal. These are software controls, not simulated scientific evidence. Use the shared two-slot test pool for these checks in the parallel revision wave; the direct child command is `python3 -I -B tests/test_metrics.py` from this directory.
