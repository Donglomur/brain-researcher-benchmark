This additive restricted transport connects the three [matched modality projections](../modality-viewer-controls-v1/README.md) to fresh local participant processes. The original combined-only transport and its authentic execution receipt remain unchanged. This successor supports `combined_calcium_behavior_v1`, `calcium_only_v1` and `behavior_only_v1` on the same seven held-mouse folds, 120 available labeled training windows and twenty queries per fold, with 140 required probabilities per condition.

The operator selects the condition before any image or metadata calculation. Participants receive the existing binary JSON-plus-PNG framing and typed actions, with explicit condition and visible-modality fields. They cannot switch modality, see query labels or receive raw packets. The combined pixels, included-lane geometry, canvas, time support, gain range, labels, case identities, original scoring and six historical benchmark-authored reference streams remain unchanged. Conditions do not create new tasks or independent biological cases.

Each macOS episode starts a new process with a scrubbed environment, closed inherited file descriptors, a fresh empty read-only working directory, and no network or child-process permission. The byte-identical captured client executes from a separate opaque read-only code directory under resolved `/tmp`; it does not execute from the operator's output directory. Both temporary roots ignore `TMPDIR`, `TEMP`, `TMP` and the operator's cached temporary-directory choice. Thus `argv` and `__file__` expose only the opaque code path. The operator retains `client.py` as evidence, authenticates the executed copy, and records removal of both temporary directories before success.

`run_fold` binds condition, source, input, client hash, interpreter path, episode, workspace/code paths and budgets. It sends `controls.Session` projections directly and streams requests, responses and hashes. A successful history is written only after all twenty first-final responses, finish, clean client exit, no trailing output and completed cleanup. Errors, partial output, exhausted budgets and failed cleanup retain failure evidence and cannot enter the collector. There is no shared mutable condition state and no substitution into the old combined viewer replay.

`audit_transport` reconstructs the selected session and compares every captured request, response hash, image byte and complete history. It performs one replay per session. `collect` requires seven matching restricted sessions and returns one original-format 140-row probability file. `collect_matched` checks all 21 boundaries before rendering: exactly the three declared conditions, the same client bytes/interpreter path/source/budgets, and distinct episodes, workspaces and code paths. It then produces three 140-row files and a matched receipt. Old transport histories, operator-only modality histories and protocol-only diagnostics are refused by restricted collection.

Use the existing framework interpreter explicitly; `/usr/bin/python3` is not an admitted substitute. A fold invocation has this form, after separate input and execution admission:

```sh
python3 -B transport.py fold \
  --condition calcium_only_v1 --fold 0 --packet AUTHENTIC_PUBLIC_FOLD \
  --output FRESH_EXTERNAL_DIRECTORY --client scripted_client.py \
  --python /Library/Frameworks/Python.framework/Versions/3.11/bin/python3.11 \
  --sandbox macos --max-actions 161 --max-images 140 \
  --max-output-bytes 67108864 --wall-seconds 900
```
