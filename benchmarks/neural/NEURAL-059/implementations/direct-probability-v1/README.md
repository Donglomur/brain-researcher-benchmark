# Direct probability collection source

This additive component supplies the missing numerical direct-response collection
path for NEURAL-059. It validates the complete prepared 29-session roster using
the existing original-slot validator, then calls the existing feature projector
unchanged. It does not alter the scientific target, scorer, four information
conditions, or the separate F/I process package.

`DirectCollection` is trusted operator code. Construct it from the full protected
preparation with four explicitly selected byte ceilings. Obtain operator handles
with `channel(session_index, condition)`. Only returned JSON bytes may be sent to
a participant; never give a participant the Python handle or protected operands.
Each channel offers every available labeled train/validation case individually,
its calibration counts, and the current held observation. Calibration use is
optional. SH/SHN omit block-prior features; SH/SBH omit all neural features.
Neural channels retain the full original unit axis and exact log1p count values.
No raster, feature selection, rounded numbers or subsampling is introduced.

A response is UTF-8 JSON with exactly `case_id`, `observation_sha256` and
`p_left`. The hash is SHA256 of the actual observation bytes received. Probability
must be a finite non-Boolean number in [0,1]. Duplicate keys, missing or additional
fields, changed observation identity and duplicate/invalid submissions fail the
collection permanently. Predictions are immutable. All four conditions must
commit a trial before any condition sees the next trial's lawful preceding-trial
history. This matters because that history can disclose the preceding outcome.
Every session must finish; a supported subset cannot produce a complete artifact.

The operator must maintain **separate participant contexts for every session and
information condition**. These Python objects cannot enforce process, filesystem,
model-conversation or tool isolation. No executable participant/provider is
supplied. This is a numerical direct-response protocol component, not proof of
native understanding, a visual EEG/raster task, or an admitted no-tools run.
The existing controller, source-generation discrepancy, authentic extractor and
all scientific gates remain unresolved. No original recordings or targets were
opened to construct this component.

`finish()` produces a capture artifact only after full support is collected. Its
records preserve actual observation and response byte hashes and keep score null.
They are explicitly marked `complete_capture_source_only_unqualified`. They are
not relabeled as F, I or a reference method to pass the existing scorer. A future
reviewed direct-condition grading adapter and an admitted external participant
boundary are still required. No task/contract readiness status is changed.

The source loader authenticates seven existing dependency files, executes its
captured preparation and support bytes, and temporarily binds the legacy support
helper during trusted bootstrap. It restores that import name afterward. Treat
construction as single-threaded trusted operator startup, not as a general
untrusted Python module loader. The retained scorer dependencies keep their
existing loader and qualification limits.

`test_delivery.py` uses the existing tiny generated full-roster fixture. It tests
the full four-condition capture, lawful-history barrier, restricted projections,
held-target omission, exact response identity, terminal failure, support omission
and immutable operands. It does not run existing tests again or load recordings.
