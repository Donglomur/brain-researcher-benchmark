## Future operator invocation

After separate input, resource and runtime admission, use absolute ordinary
paths and a fresh output directory:

```sh
python3 -B benchmarks/neural/NEURAL-014/implementations/full-header-export-v1/export_headers.py \
  --task /operator/task.json --author-csv /operator/source-description.csv \
  --archive /operator/t15_copyTask_neuralData.zip \
  --scratch /operator/allocated-private-scratch --out /operator/fresh-header-export
```

The archive is opened once, checked for ordinary-file identity/extent and hashed
before ZIP parsing. Its hash and descriptor/path identity are checked again
after all members. Every expected member has its exact declared compressed and
expanded extent; the directory permits only the expected files and ordinary
parent directory entries. Unexpected, duplicate, linked, encrypted or unsupported
entries refuse the export.

One member at a time is streamed into a private temporary file. The ZIP CRC,
expanded extent and staged SHA256 are checked before HDF5 opens. The staged
file is hashed again after headers and its descriptor identity must remain
unchanged. Only ordinary, singly linked root trial groups are visited. The three
native scalar attributes `session`, `block_num` and `trial_num` are read; group
names must retain their native trial syntax. No dataset is indexed, read_direct
called, or transcript/token/neural value loaded. Duplicate native identities
across files and malformed identities refuse the entire export. Empty members
remain present with empty trial lists; count disagreements are reported by the
unchanged consumer instead of becoming acquisition failures or invented trials.

`HEADERS.json` has the exact `neural014-trial-header-census-v1` schema and
`all_source_members` coverage. `COMPARISON.json` is produced by the unchanged
consumer, including exact Train versus combined Val/Test semantics and explicit
discrepancies. `CUSTODY.json` independently binds input/output identities and
observed read/staging counters; the consumer's own authentication flag stays
false by design. A future operator must retain and independently review the
custody record, not accept a self-produced file as external attestation.

Output files are exclusive and the custody file is written last. A failure
retains `FAILED.json` and any partial outputs for diagnosis. Success requires
process exit0, all three complete matching files and no failure marker; directory
existence or a partial census alone is insufficient. Scratch is transient owned
storage; its full cumulative writes still count. Host files are owner-writable,
not immutable. Ordinary execution in an operator-exclusive namespace is required;
this code is not an adversarial concurrent-process sandbox.

## Resources and limitations

Opaque archive/member hashing and container parsing read protected payload bytes,
even though neural/label datasets are never decoded. This is not metadata-only
byte access. The archive read ceiling is `3*archive_bytes +4MiB`; each staged
member's file-object read ceiling is `4*member_bytes +65536`. Member staging writes
sum to the full declared12,916,863,318 bytes, with one largest member retained
at a time; the original archive must also remain. Header/comparison outputs each
have an8MiB ceiling. Parser/library RAM, elapsed time, filesystem allocation and
future full workload remain separately admitted and unmeasured. The caller must
budget all source, scratch, failed work and retained outputs before execution.

The public entry checks h5py3.13.0 and NumPy2.2.6, matching the retained original
preparation dependency declaration; no installation or authentic compatibility
claim follows. Generated engine controls use the available Python3.11,
h5py3.16.0/NumPy2.4.6 environment, recorded at execution. They do not qualify the
original runtime or execute the full original public input route. The source
