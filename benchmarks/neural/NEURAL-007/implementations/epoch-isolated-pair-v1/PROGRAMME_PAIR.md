# Epoch-isolated same-signal programme and protected pair

This additive package introduces `epoch_isolated_raw_viewer_zero_shot_v1` and
`epoch_isolated_raw_programme_zero_shot_v1`, paired under
`epoch_isolated_same_epoch_v1`. It does not replace, relabel or pool results
with the historical whole-person or pending full-history provider conditions.

Every one of the 5,450 registered 30-second targets remains: 2,780 epochs in
development-001 and 2,670 in development-002. These are **two already exposed
people**, not 5,450 independent people or an unseen-population evaluation.
Neighbouring signal context and prior answers are removed. Each target has a
fresh visual context and a fresh programme container, volume and scratch space.

## Exact information and shared prior policy

`contract.EpochPacket` contains only an immutable NPY byte stream with the
original three channels, 3,000 samples per channel, float64 little-endian volts,
at 100 Hz, plus that target's identity and three original clock fields. It keeps
no parent Packet, array, path or access method that can read another epoch.
`project_epoch` asks the authenticated original Packet for exactly
[index*3000,(index+1)*3000) and all three channels. No filtering, resampling,
feature engineering, YASA output, training person, reference prediction or label
is added. The visual condition retains a complete three-channel overview on
every request; detail windows cannot remove that overview.

Both arms bind identical canonical `sleep007_epoch_shared_knowledge_v1` bytes:
provider, model, revision, policy `shared_declared_base_agent_prior_only`, and
an empty external-assets list. The visual sender checks the actual model against
this declaration. A programme is frozen before target access and binds the same
declaration and any separately supplied programme-generation provenance.
Neither a declaration nor a source hash proves hidden pretraining or the origin
of embedded knowledge. The original image digest alone also does not prove that
the image lacks task-trained assets. Its complete image/source boundary audit
and exposure are external operator prerequisites; this source does not create
those approvals. Matched-agent/prior, runtime and scientific qualification stay
false in these source receipts and reports.

Matching the signal samples, channels and clock scope does **not** establish
information equivalence between numerical arrays and raster views. Reports call
this same-epoch signal-access pairing under a declared prior policy, not a proven
causal tools-only effect.

## Programme isolation and first answers

`epoch_programme.prepare_programme` freezes one bounded UTF-8 source file, the
shared knowledge descriptor, exact local source freeze, immutable image and any
external generation-provenance descriptor. The callable never opens scientific
inputs. `make_mounts` admits precisely six single-file bindings:

- /input/case.json and /input/signals.npy for the current target;
- /program/program.py and /trusted/PROGRAMME.json;
- /trusted/epoch_producer.py and /trusted/contract.py.

No whole packet, implementation tree, training data, labels, prior outputs,
other target, host directory or Docker socket is passed to participant code.
The unchanged canonical Provider supplies the actual fresh Docker isolation:
read-only image and host binds, no network, dropped capabilities, private
namespaces and bounded fresh scratch/output. Its canonical request and exposure
validators are called before dispatch and again during admission. The pinned
external boundary-audit bytes, complete image inventory identity, exact mount
set and image/source/command binding are checked. Input inventories must match
before/after; producer closure precedes capture; all owned container and volume
resources must be absent before acceptance. No participant callable is imported
or executed in the trusted Packet or grading process.

The programme ABI is
`python -I -B /program/program.py --input /input --out /output`.
It emits exactly `prediction.json`, containing only condition, epoch_id and
five probabilities in W/N1/N2/N3/R order. The trusted wrapper applies the original
float64 probability tolerance and adds the canonical transport envelope.
The first externally captured valid output is immutable. Extra files, wrong
targets, failed/partial phases, reused resources and replacement answers fail.

`execute_programme_collection` is a finite all-target operator loop. It requires
the entire projection/exposure roster up front and a complete original campaign
deadline; it does not retry or resume a failed target. Actual execution remains
separately selected and qualified. The per-phase resource map is the existing
canonical ABI, supplied explicitly. The whole-run phase allowance must cover
5,450 times setup+producer+capture+cleanup seconds. This is a prospective bound,
not an observed feasible whole-cohort runtime. Journal bytes/count, Provider
reads/writes, input projection storage and original-packet reads need explicit
future resource admission.

## Complete evidence and protected score

Both collection files have schema `sleep007_epoch_arm_collection_v1`, exact
new arm condition, shared knowledge/source descriptors, all 5,450 ordered
target IDs with immutable per-target record descriptors, and one complete
original-format predictions NPZ. No subset, padded row, revised answer or
historical-condition collection is admitted.

`epoch_admission.admit_pair` validates both public submissions and original
reference identities. It opens each original person Packet once, reconstructs
each exact epoch projection, replays the visual request/response custody, checks
programme source/exposure/closure custody, and compares every submitted vector
with the first accepted answer. Visual sessions and response identities cannot
be reused; native resources cannot persist across targets; one pre-input
programme definition and shared prior declaration apply to the entire panel.

`coordinate_compare` completes this admission before launching a separate
trusted grader. The worker repeats admission before opening the private-location
manifest or target arrays. Only then does it call the unchanged original
candidate adapter's target checker, score and difference functions. Private
masks, five-class macro-F1, equal-person weighting, first-class ties and supported
balanced accuracy are retained. The original YASA/RF references are reported as
richer-information references, not matched epoch arms. The report explicitly
rejects pooling with whole-history results and makes no SOTA, population or
benchmark-completion claim.

## Source and portability

Publish these program fragments alongside the visual fragments in
`benchmarks/neural/NEURAL-007/implementations/epoch-isolated-pair-v1/`.
All imports use that co-located package; operator source/data locations are
explicit runtime arguments. No private preparation path is embedded in code.

The installed dependency state is the already accepted prior nine-file
integration: finite-workflow SOURCE_BINDINGS SHA23d951b6..., unchanged common and
grading, plus the existing canonical Provider, original viewer and metric.
Private preparation may pass the authenticated accepted binding directory through
`load_runtime(implementations_root, finite_bindings_root=...)`; this changes no
workspace file and does not copy a second old operator.

Runtime source freeze schema `sleep007_epoch_source_v1` requires exactly
contract.py, epoch_programme.py, epoch_producer.py, epoch_admission.py,
epoch_visual.py, epoch_provider.py and SOURCE_BINDINGS.json. The old whole-person
source and historical evidence remain untouched.

Generated controls are construction evidence only. They may exercise finite
same-epoch projections, request/custody and rejected exposures using synthetic
samples and fake transport. They do not qualify original per-frame/token
capacity, real provider isolation, a native programme image, hidden priors,
whole-cohort resource sufficiency or AI performance.
