# NEURAL-075 complete paired numerical controls

This executable control suite exercises the existing paired grader with all 60 generated cases and the unchanged, source-authenticated scorer. It fills the public package's numerical verification gap: the predecessor's portability suite deliberately prohibits NumPy and does not call admission, metrics or evaluation. No numerical implementation or historical source is changed.

The suite loads the actual installed operator, authenticates its entrypoint against the existing public inventory, authenticates the immutable grader source manifest, and loads the scorer through its fixed source pins. Invented scores, opaque IDs, categories, protected NPZ bodies and a deliberately invented `ClosedPair` enter the documented `grade_verified_pair` numerical test seam. The fixture bypasses production capture and **does not demonstrate producer closure, permission, native execution, source-data preparation or scientific performance**.

It checks:

- The full original geometry: five people, three arms, two phases, two accesses, 50 categories, 500 imagery and 1,750 perception rows; all 3,375,000 score entries pass admission before any protected callback.
- Exact ties: flat 50-category scores yield fractional Top-1 of 0.02, midrank 25.5 and half-tie pairwise score 0.5, while the preserved historical strict-greater diagnostic yields 1.
- All five signed participant effects, including adverse B-minus-A effects; imagery means stay separate from the larger perception phase. No-neural and training-permuted arms remain in the complete evaluation.
- A malformed score at the very last row of the 60th case prevents even a design read. A locally valid reversed final-case trial order fails the design join before any target read. Altered protected bytes fail their pinned descriptor without returning a partial grade.
- A separate numerical counterexample distinguishes private category score-vector averaging from averaging trial accuracies: 0.1 trial Top-1 and 1.0 category Top-1. A hand-calculated four-category example checks the four rank/tie statistics independently.

Only in-memory generated observations and targets are used. There is no decoder fitting, candidate invocation, raw fMRI, historical target access, author inference, data acquisition or network connection. Network and subprocess APIs are forbidden while controls run. These are software controls, not model or human results. Direct observation, typed viewer and case-adaptive tool conditions remain undelivered.

Run with an already available NumPy environment, from any working directory:

```sh
python -I -B /absolute/repository/benchmarks/neural/NEURAL-075/implementations/numerical-controls-v1/test_numerical_controls.py
```

The parallel construction wave runs this command only through its reviewed two-slot pool with one numerical thread, a declared 1 GiB ceiling and 180-second timeout. The suite adds no dependencies to the repository and leaves the closed predecessor inventory intact. It is a new numerical verification component, not an alternate public scoring route or readiness layer.

The source protocol remains `neural075-v1`, the exact installed source manifest is 1,589 bytes at SHA-256 `2f7efbaa03fd83449038d83700efd7e187a4ce440073735ea90f7b3efd8c1dd9`, and the numerical scorer stays bound by `paired-grading/paired_grading/pinned_scorer.py`. Current `task.json`, `understanding.v1.json`, historical definitions and private-target boundaries are unchanged. Integration may enroll the suite as a NumPy software check; no admission status should change from these results.
