# Initial evaluator v1: sequence recurrence and trajectory components

This package adds executable scientific construction components for `PAPER-ROOT-ADD-007`. It recomputes clusters and task/phase counts from per-neuron burst latencies, performs a prospective matched-phase template recurrence comparison across all four registered mice, and separately exposes a Poisson trajectory replay kernel. **Native paper reproduction and scientific qualification remain held/unknown.** Template recurrence is not the paper's decoded spatial replay endpoint. No original contract, historical source, registry or task count is changed.

The implementation is [pfc_evaluator.py](../implementations/initial-evaluator-v1/pfc_evaluator.py); immutable identities and all 16 exact source asset filenames are in [source_contract.json](../implementations/initial-evaluator-v1/source_contract.json). The input contract is pinned to SHA256 `5b90d33727d900a940a6e7bb01bd614b91fa7d7756c18c922bc6f51f040b4466`.

## Safe input and native conversion hold

The CLI reads JSON only. It never deserializes pickle, imports author code or accepts supplied cluster IDs. Top-level keys are exactly `schema_version: 1`, `provenance`, `mice`, `events`. `mice` maps each filename identity `478`, `481`, `483`, `485` to a unique list of registered cell IDs; this preserves filename identity without newly verifying biological identity. Every mouse must have Task, Arena and Sleep observations. This validates declared-packet coverage; proof that a native converter omitted no events remains held. `provenance` has exactly `kind` (`generated_control` or `trusted_conversion_pending_validation`), nonempty `conversion_receipt` and `mask_mapping` strings. These strings are disclosures, not authenticated proof; accepting the second kind never clears native admission.

Each event has exactly:

```json
{"id":"478-learning-outward-L-1", "mouse":"478", "context":"Task",
 "session":"s1", "trial":"trial1", "phase":"learning",
 "condition":"outward_L", "correct":true, "speed_pass":true,
 "onsets_s":{"cell1":0.05,"cell2":0.15,"cell3":0.25}}
```

Contexts are `Task`, `Arena`, `Sleep`. Task conditions are `sampling_L/R`, `outward_L/R`, `reward_L/R`, `inward_L/R`; phase is `learning` or `learned`. Rest context phase is null and condition is `rest`: the evaluator never invents rest phase labels. Onsets are distinct finite seconds in a 500 ms burst, with at least two registered neurons. Tied single-event onsets are rejected because resolving their order requires an upstream scientific decision. Mean template onset ties use a disclosed lexical cell-ID tie break. Task sessions cannot cross learning phases; trial correctness must be consistent within a session. Trial identities cannot cross phases. Unknown fields, missing mice/contexts, duplicate IDs and nonfinite values fail validation.

A future trusted converter must verify the 16 payload hashes against the retained local receipts, record its own conversion code/hash, inspect original pickle types in an isolated approved environment, and map each exact unusual `Sesseion` filename. It must align per-neuron observations, corrected-cell masks, burst/session/phase/condition/correctness/speed masks, and longitudinal cell registration before writing JSON. Preserve all retained/excluded observations with reasons and reconcile native counts. Source arrays may be waveform-valued rather than latency-valued; choosing onset/center-of-mass extraction and handling native ties remain explicit conversion holds. ## Computations and prospective policies

The [pinned author source](https://github.com/HamedShabani/PFC_sequence_analysis/tree/039228a3f1e079f5230fbb2bd794a714ab264b5c) and [paper methods](https://elifesciences.org/reviewed-preprints/106981v3) motivate the following independent implementation:

1. Restrict two ordered sequences to common neurons and calculate Spearman correlation. Fewer than two shared neurons is undefined. Calibrate an upper-tail rank test with complete permutations through seven neurons, or 10,000 seeded draws above seven, using plus-one Monte Carlo p values. The supplied draw count controls engineering tests; all settings are recorded.
2. Recompute longitudinal clustering from **all Task observations**, including correct/failed and speed mask strata. Ward linkage uses Euclidean distances between binary significant-correlation profiles, cut at the maximum pair distance (`fac=1`). Initial template quality uses within/across significant-match ratio at least one. Within-cluster matches use a leave-one-event-out template and require at least two distinct session/trial blocks, so singleton self-matches cannot manufacture recurrence; this is a prospective support guard, not native-source equivalence. Templates sort mean per-neuron latencies. Significant template pairs with standardized correlation above 2.5 merge iteratively and recompute quality at ratio .1. No outside-cluster comparator means quality is undefined and the template is rejected. A graph with no significant edges is kept as singleton candidates, then quality-filtered, rather than treating an empty graph as one biological cluster.
3. Return every original Task event's computed label and cluster × phase × condition × correctness × speed counts. Rejected templates remain separately visible; assigned cluster labels alone are not evidence of a valid biological template. These are descriptive selectivity counts, **not a calibrated significance test of selectivity**. Native Skaggs spatial information, rate/occupancy maps and selective-cell classification remain held. Per-cell Task participation fractions expose the source caution about neurons active in over half of bursts; no automatic exclusion rule is inferred.
4. For the prospective phase comparison, select correct, speed-admitted outward bursts; match learning and learned event counts separately for each goal arm using a fixed seeded sample. Both arms require at least two bursts in each phase. Return all selected IDs and available/selected counts. Refit separate phase template banks. This differs from the source's combined learning-plus-subsampled-learned fit and 50-repeat analysis; it is not claimed to reproduce Figure 4G.
5. Score both template banks against the **same complete declared-packet Arena/Sleep event set**. The mouse effect is learned minus learning fraction matching any retained template. Report raw Task expression by condition and phase as a diagnostic; outward observations overlap fitting and are explicitly flagged. Sampling/reward values are descriptive and no unbalanced reward-minus-sampling inference is made. A missing template bank gives an unavailable contrast; missing mice are never dropped from the macro statistic.
6. Generate one cell-identity permutation per mouse/context/session/draw and reuse it for every event in that group and both phase banks. This preserves within-session structure, counts and event masks. It tests cell-identity alignment, **not pure temporal-order specificity**. Return every null draw and plus-one two-sided tails. Summarize four mouse contrasts with equal weights, all 256 empirical animal bootstrap resamples, and all 16 sign flips. The latter requires a symmetric-effect null; with four mice its smallest two-sided p is .125. No event-level precision is substituted for animal uncertainty.

The author `shuffle()` helper stores a raw-correlation percentile, while `check_template()`/`allmot()` compare standardized correlations with the threshold column (`mtools.py` source lines 118–154, 264–321, 1171–1254). The notebooks instead load saved `nrm.npy`, whose calibration was not inspected. This is a **helper-domain inconsistency, not proof that native saved normalization is wrong**. The explicit permutation-p policy avoids silently guessing its meaning; it prevents a native-equivalence claim. Source notebook parameters `fac=1`, initial ratio 1, merge ratio .1 and z threshold 2.5 were verified in two fully read pinned notebooks. Their exact byte hashes are in the source manifest. No author source is redistributed.

## Separate Bayesian trajectory component

`poisson_decode(counts, rates_hz, bin_seconds)` accepts nonnegative integer `[time,cell]` counts and nonnegative `[cell,position]` rate maps in Hz. It uses the independent Poisson log likelihood, including silence and factorial terms, and a uniform position prior. It returns normalized posteriors and maximum-likelihood position indices. Impossible likelihood rows or tied maxima produce null positions, never an arbitrary spatial trajectory. Exact zero rates are respected; this is an explicit prospective numerical policy different from the source's small log epsilon.

`trajectory_session(event_counts, rates_hz, bin_seconds, seed=0, draws=499)` recomputes decoded trajectories under one shared rate-map cell permutation for every burst in a session/draw. It reports time-versus-position rank correlation, permutation z score when variance is nonzero, and forward/backward plus-one tails at .025. Events require at least five active count bins; undefined observed or null trajectories hold significance instead of dropping unfavorable null samples. All supplied time bins enter rank correlation; silent-bin exclusion and neighbor handling are not inferred. `trajectory_replay` is a single-event convenience call and must not replace session grouping for multi-event inference.

This component does not build source rate maps, reproduce outward-run burst/neighbor exclusion, decode native recordings, infer position units or establish figure agreement. Caller rate maps must be fit independently of assessed bursts and their declared neighbors; this primitive cannot verify that provenance. The initial assessment reported a cell-index null in the paper methods and inspected only a bounded notebook prefix. A later [complete retained-source inspection](replay-active-source-recovery-v1.md) found an **active temporal-permutation branch in source cell27**, in addition to the commented alternatives. This prospective cell-identity kernel therefore does not implement that active notebook null. Final-paper correspondence, native rate-map/mask lineage and exact reference targets remain held. This kernel is not wired into the recurrence CLI or conflated with its result.
