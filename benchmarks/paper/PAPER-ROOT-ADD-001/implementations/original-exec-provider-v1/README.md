# Explicit exec-reset provider baseline

This is the Linux `exec_reset_bwrap_v1` option, with no default execution mode or practical full-campaign claim. It connects one authenticated feature and one permitted compact response/maps bundle to a freshly executed frozen Python candidate. The source has only generated/mocked controls. No Linux namespace, bubblewrap, cgroup, child-process, authentic neural-array or model execution has qualified it.

`NativeProvider(config, admission, evidence_root=...)` opens one exclusive lifecycle JSONL journal. `prepare_feature(path, spec, rows=...)` authenticates a readonly source NPY, makes one owned ordinary readonly staging copy, and returns an opaque owned handle. Each `run_request(handle, bundle, descriptor)` independently recomputes the exact compact identity; `descriptor` contains immutable `public_json` and `public_id` attributes or exactly those two dictionary keys. It launches a new participant address space and namespace, captures bounded raw NPY bytes, requires natural zero exit and absence of the entire owned cgroup, retires request inputs, writes its closure record, then releases raw bytes and the existing packed-join closure. `release_feature` removes the one-job staging file. `finish` closes all owned descriptors and returns journal identity and counters. The separate full-task coordinator owns canonical session/job/held order, durable authorities, the packed writer/reader, original scoring and full-panel completeness.

The candidate file is `/candidate/candidate.py` and exports `predict(train_x, train_y, query_x, context)`. The separately mounted minimal `participant_entry.py` recovers the original equality partition and row order, including signed-zero qid bits, from compact bytes. It has no author estimator, private-store reader, original repository import or held response. Generic scientific runtime and assistance artifacts are separately frozen trees. For paper+data, the runtime/assistance trees must not contain the author implementation. Manifest hashing cannot determine this semantic property: the operator's reviewed information-condition manifest remains required. Candidate stdout is reserved for one primitive finite NPY prediction; Python-level candidate prints are redirected to stderr, and lower-level stdout contamination is rejected later by the unchanged packed parser.

## Execution-mode comparison

The original callback traversal is 58,926 feature jobs and 6,776,076 software requests, yielding 224 result arrays over 14 sessions/eight people. These are not AI API-call counts. Context is candidate-visible, so identical response support does not justify output reuse across feature jobs or contexts.

The source fold exclusion is the scientific requirement; a fresh OS process is this provider's mechanism for enforcing it for arbitrary stateful candidate code. It is not a requirement of the paper. A trusted stateless estimator/DSL or audited batched kernel could calculate every fold in one operator process while applying the same exclusion, but that is a more restricted programme condition. A resettable VM snapshot is another possible state-reset implementation with its own qualification and transfer costs. A persistent unrestricted callback cannot simply be substituted: successive training sets reveal the union of responses, including responses held in another request.

| Route | Reusable state | Fresh work per request | Present status |
| --- | --- | --- | --- |
| Explicit exec-reset bubblewrap | One readonly feature staging file per job; globally frozen public trees | Child, exec, runtime/candidate imports, namespaces, cgroup, permitted-bundle staging and return collection | Implemented source; native qualification pending; no practical-default claim |
| Clean preloaded supervisor | Only declared generic library state in an ancestor that has never executed participant code or received/mapped request Y | Fresh child before request FD delivery, fresh private tmp/PID/network/mount boundary and exclusive cgroup, participant import/call | Design comparison only; rejected as an unsupported provider mode |
| Fork private coordinator/cache | Would inherit private response and prior request memory | Closing FDs does not clear inherited address space | Prohibited |

A persistent bubblewrap containing an ordinary forkserver is not by itself the second route: shared `/tmp`, process visibility, inherited FDs, namespace capabilities and prior-candidate state still need a concrete qualified boundary. A clean preloader could remove interpreter/import work only if the child retains that clean address space while creating the new boundary. Executing bubblewrap after the clean fork clears the preload benefit. Its implementation and cost/closure proof are separate work, not an inferred optimization here.

At an assumed, unmeasured 100 ms per start, 6,776,076 starts alone would take about 7.84 days. The baseline must be costed before any full-task admission. The saved source census gives 2,219,912,453,304 permitted bundle bytes across requests; bundle production/freeze and dispatch can require separate traversals. Staging each of 58,926 job features once is 18,379,809,168 bytes; the feature content logically visible across requests is 3,494,433,054,768 bytes. Actual parent cache behavior, imports, prediction computation and repeated candidate reads add costs.

The feature is an ordinary file because bubblewrap 0.11 `--ro-bind-fd` resolves and verifies a real host source. All staging write handles close before its readonly FD is used. This is qualified trusted-host custody, not an immutable inode against hostile same-UID host mutation. Bundles and descriptors use sealed memfds and `--ro-bind-data`, which copies them again inside the namespace. `staging_bytes` and `sandbox_copy_bytes` account for these two copies separately; the latter is charged prospectively even if launch fails. One ephemeral feature file is reused within a job; no per-request evidence files are retained. The single journal still grows with 6,776,076 invocations and needs an explicit aggregate cap.

## Required native preparation

No native admission or qualification receipt is supplied by this directory. Future execution needs Linux with pidfds, memfd sealing, unprivileged user/PID/mount/network/IPC/UTS/cgroup namespaces, bubblewrap **0.11.0**, and an existing delegated cgroup-v2 domain with memory, CPU and pids controllers and `cgroup.kill`. The frozen host qualification must bind the actual kernel and bubblewrap ELF dependency closure, child reaping ownership, descriptor semantics, tmpfs and namespace setup, cgroup membership before exec, cleanup on failures/parent death, and trusted immutable staging/runtime custody. This implementation does not authenticate arbitrary host dynamic loader libraries or claim a kernel-security proof from a JSON boolean.

The trusted coordinator must remain single-threaded (including native library threads), retain default SIGCHLD ownership and own all child reaping. Candidate code runs only after `execve` resets the private parent address space. Before waiting on its pipe gate, the trusted child arms `PR_SET_PDEATHSIG(SIGKILL)`, checks that the original parent still owns it, and sets `PR_SET_NO_NEW_PRIVS`. This closes the parent-death window before bubblewrap installs its own protection. The parent obtains a pidfd and moves that exact unreaped child into the exclusive cgroup before releasing the gate. Cleanup uses the owned cgroup and pidfd, never a reused numeric PID/process group. Entire cgroup emptiness and natural exit are required before raw predictions reach the scorer. A root admission binds the complete canonical config digest, finite expiration, reviewed protocol and separately retained native qualification; these are trusted operator assertions, not signatures or self-contained OS attestation.

The exact config schema is checked by `config_snapshot`. It requires the explicit mode, candidate/provider/store/schedule identities, frozen condition, runtime/candidate/assistance manifests, exact bubblewrap executable, delegated cgroup path, runtime interpreter and every key in `CAPS`. `provider.identity()` binds this provider, the minimal public entry and the unchanged operator-side compact codec. Admission schema is checked by `admission_snapshot`. Passing a differently named mode or an expired/mismatched admission fails before any native work.

Each tree manifest is canonical JSON with `schema: language-frozen-public-tree/v1`, `kind`, `condition`, sorted `directories`, and sorted `files` entries containing `path`, `bytes`, `sha256`, `mode`. Runtime condition is `generic`; candidate and assistance conditions must equal the run arm. All paths are relative, ordinary, single-link, on the root filesystem and readonly; directories are mode 0555, files 0444 or 0555. The conservative first profile rejects symlinks, hardlinks and unlisted files, so a runtime must be prepared accordingly. Runtime `/usr/...` contains the selected interpreter and generic dependencies. It also contains empty mount-slot directories `input`, `candidate`, `artifacts`, `executor`, `tmp`, `proc`, `dev`, and exactly zero-byte files `input/features.npy`, `input/responses.bin`, `input/request.json`, `executor/entry.py` within those reserved slots. No benchmark checkout or host home directory is an allowed runtime substitute.

Resource caps cover cumulative source reads, staging, namespace copies, logical input visibility, stdout/stderr, kernel-control metadata, journal bytes, jobs and requests; per-invocation cgroup memory/swap/pids/CPU, tmpfs, CPU time and stdout/stderr caps; logical parent work; and finite per-request/whole-run deadlines with cleanup reserve. Read charges include bounded EOF probes; separately reported observed source/kernel bytes count actual returned bytes. Logical visibility is not total participant memory or physical I/O: a candidate can reread the same mounted data. Cgroup memory/CPU/time limits bound execution, and their native effectiveness is unqualified here. Parent work estimates exclude Python/kernel/library overhead and caller-owned values. The coordinator must account for its own cache, authority, packed-output and scoring costs in addition.

Thirteen authored generated methods cover source callback operand/bit parity, finite formats, information-bound mounts, readonly staging and one-job reuse, raw-output custody, exact request identity, whole-run admission, pre-I/O caps, streaming tree enumeration and mocked cgroup/exec-parent ownership. The lifecycle tests inject a fake backend or mock process/kernel functions; they do not execute a child candidate, bubblewrap, namespaces, cgroups, pidfd signals or `prctl`. Fixture-path and fixture-cleanup failures were retained and corrected; successful unchanged controls were not repeatedly rerun. Independent review also required FD cleanup, pre-read transport admission, binary working admission and idempotent closure repairs before source acceptance.

## Official source basis

Flags were checked against the [bubblewrap 0.11.0 manual source](https://raw.githubusercontent.com/containers/bubblewrap/v0.11.0/bwrap.xml) and [0.11.0 implementation](https://raw.githubusercontent.com/containers/bubblewrap/v0.11.0/bubblewrap.c). The manual's `--unshare-all` includes optional user/cgroup variants, so this provider separately requires `--unshare-user` and `--unshare-cgroup`. It uses `--disable-userns`, `--cap-drop ALL`, `--clearenv`, `--new-session`, `--die-with-parent`, readonly binds, bounded tmpfs and readonly proc/device mounts. The C implementation confirms `--ro-bind-fd` identity checks and the separate copy semantics of `--ro-bind-data`. Cgroup membership, populated-state, hard limits and kill semantics follow the [Linux cgroup-v2 interface documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html). These source readings establish intended interfaces, not a successful local native experiment.
