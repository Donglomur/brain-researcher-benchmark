# Original Figure 3b author pairing

This additive component connects the existing selected task to a competent,
separately identified author reference and two participant information conditions.
It retains all 14 sessions/eight people, layer 5, lag indices 17–19, 42 jobs and
5,685 held-qid requests per programme. Full 224-array reproduction and the
provided-author reference remain separate and unchanged.

The three pieces are:

- `author_programme.py`: the standalone `predict(train_x, train_y, query_x,
  context)` programme. Package its exact bytes as the sole `candidate.py` in
  the operator reference tree. It executes literal `Ridge(alpha=0.01)` with the
  original defaults and requires NumPy 1.24.3, sklearn 1.2.2 and SciPy 1.10.1.
  No current-stack fallback, scaler, alpha tuning or estimator reuse is added.
- `executed_reference.py`: verifies complete source/held-row lineage and the
  fresh-exec lifecycle-to-packed-transport/closure join, then invokes unchanged
  original raw-prediction recovery. A supplied aggregate cannot become a sealed
  executed reference. Reference calibration is neither participant condition.
- `paired.py`: authenticates the exact component and external admissions,
  preflights all three material trees, and calls the existing provider,
  collection and recovery APIs. It compares each independently executed
  participant against the same executed reference using the original NumPy
  reductions. It adds no supervisor or alternative sandbox.

The real-learning mode requires one qualified fresh-exec invocation for **each
held qid**, including the author estimator: 126 jobs and 17,055 invocations for
the three-role campaign. The earlier 42-worker time-only reuse is rejected.
These are programme executions, not necessarily AI API calls. No such campaign
has been executed or admitted by constructing this source.

Both participant arms have identical source inputs, runtime, resource limits,
feedback rules and scorer. Their assistance manifests must differ only by the
declared author-code files and necessary directories. The reference has a
separate calibration role and empty assistance tree; its legacy code-bearing
transport label does not count as an AI `paper_data_author_code` result.
All programmes are globally frozen before final evaluation, with no feedback
or state accumulation across held exclusions.

Recovery requires identical per-job context, target and feature identities,
qid/time maps, support class and every ordered held-row/request/bundle binding.
Lifecycle records must show the exact pinned fresh-exec provider's
`open; (start, closed) × 5685; finish` sequence and agree with packed closure and
transport hashes. These are authenticated attributed records, not independent
OS qualification. The existing provider still needs its separate Linux
namespace/FD/cgroup qualification and exact root admission.

The entrypoint requires `--source-sha256`, `--protocol`,
`--protocol-sha256`, `--admission` and `--admission-sha256`. It has no default
runtime, roots, budgets or native admission. Every real call requires an
external hard deadline in addition to cooperative checks. Material preflight,
collection, lineage recovery and scoring have explicitly additive read/time
allowances; they are not one shared meter. Nine selected-store reader
traversals are declared across the complete campaign. Existing prepared input
storage is reused, without a copy or another original-archive preparation.

Continuous paired deltas preserve all sessions and nulls, with eight-person
contributions and leave-one-person-out diagnostics. No practical-effect margin,
binary win, population inference, historical numerical parity or current SOTA
is supplied. Public-source exposure, retrospective PCA/centered smoothing and
the 567/579 biological identity distinction remain explicit limits.

Twenty generated controls cover literal mocked estimator calls, permitted
operands, source lineage, lifecycle joins, condition/material differences,
numeric reduction equivalence, null propagation and the thin entrypoint's
ordering. The entrypoint ordering control mocks orchestration; estimator
controls mock numerical modules. No original arrays, real fit, participant
process or native qualification is exercised.
