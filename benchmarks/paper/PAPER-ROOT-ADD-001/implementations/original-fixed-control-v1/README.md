# Fixed programme control of the complete selected language task

This is an engineering control for the original Figure 3b input, prediction and scoring route. It is not an AI evaluation, a fitted model, an author prediction replay, or evidence that the paper has been reproduced or improved. Execution requires a separately reviewed exact protocol and root admission; construction tests never launch a child process or open authentic response arrays.

The selected task retains all 14 sessions from eight people, zero-based layer 5 and lag indices 17–19: 42 source jobs and 5,685 held-query callbacks. Original provided PCA features, population responses, retrospective centered smoothing, source qid grouping, row order and pooled out-of-fold Pearson calculation are unchanged. Full 224-array reproduction remains a separate route. The 567 versus 579 unit-identity question, historical preprocessing exposure, public-source exposure and same-stack author-computation parity remain unresolved.

`time_worker.py` is one globally frozen standard-library programme. It receives only the complete public time-index vector for a job and emits `(time % 17 - 8) / 8` as canonical float64 NPY. It receives no feature values, qids, training responses or held-out responses. These exact dyadic outputs exercise a nonconstant prediction path without learning anything about the neural task.

`fixed_provider.py` runs that programme in 42 fresh interpreter processes, one per source job, and derives each of the 5,685 original held-query responses by exact row selection. The identical time vector and source-proved time-only computation justify this specific reuse. This is not permission to batch an arbitrary participant that could accumulate other folds' targets. The trusted operator still constructs the original permitted-response bundles to exercise the cache and request identities; those labels never enter the fixed worker. Each query closure is attributed to its already closed job producer. The private journal records three entries per successful job (launch attempt, closed producer, completed derivations), one configuration entry, and an ordered request/output/closure hash chain; it never represents 5,685 process launches or API calls.

`fixed_control.py` joins the authenticated selected store, original private cache, fixed provider, packed predictions and unchanged original scorer. Collection and recovery use separate readers, read allowances and deadlines. Recovery retains every one of the 42 correlations, including undefined values, without selecting favorable cases. Its result explicitly denies author replay, independent reproduction, AI execution, scientific qualification and improvement.

The child boundary is suitable only for this pinned trusted programme. It uses verified source bytes, an existing pinned interpreter, isolated Python flags, closed inherited file descriptors, finite pipes, a new process group and owned-child cleanup. It does not qualify arbitrary hostile participants, an OS namespace, a hostile trusted host or parent-death containment. Worker processes have their own sessions; an outer supervisor cannot claim to kill every descendant. Cooperative driver interruption and owned worker cleanup remain required.

`supervise.py` supplies a prospective finite outer deadline without changing the shared generated-test pool's 180-second ceiling. It authenticates the exact protocol, admission, interpreter and driver bytes before spawning the driver, preserves bounded logs and a closure receipt, and is itself protocol-pinned. Its longer native envelope requires root admission. The first full fixed-control attempt is not implied by the source tests.

The released result archive contains correlations for the selected condition, but no matching saved raw predictions for these three lags. Its prediction-named files belong to a swapped-embedding lag −10 condition. Aggregate correlations cannot reconstruct the missing per-row predictions; this control does not substitute those other outputs.

The conservative metadata-derived accounting includes 548,752,368 bytes of cache reads and up to 2,431,404 response-file opens, plus separate store/scorer/provider reads. Repeated bundle construction, feature authentication, transient pipes and receipts are separately admitted. Wall time is unmeasured before the exact attempt; a finite limit is an attempt bound, not a performance claim. Prepared input storage is reused without copying it.
