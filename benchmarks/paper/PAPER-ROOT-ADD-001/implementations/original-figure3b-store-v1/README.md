# Original Figure 3b input store

This separately versioned store supports the adopted Figure 3b improvement task: all 14 original sessions and eight people, contextual PCA layer 5, and original lag indices 17, 18, 19. It contains 42 source jobs and 5,685 held-qid software prediction requests. It does not replace the complete 224-array reproduction task or declare a new scientific result.

The original-scope reader reports `original_figure3b_improvement`. Generated controls report `generated_figure3b_store_control`; they cannot qualify original completion or use the old full runner's engineering-fixture scope as an authentic task.

## What is preserved

The exact original `smooth_targets`, `format_words` and `lag_rows` functions generate only the selected layer and three negative lags. Generated controls compare their output bytes to the corresponding jobs in the complete 4,209-job session iterator. The supplied 30-PC features, word timing/order, sentence qids, speaker mask, mean-before-smoothing population response, original padding and lag convention are unchanged. No PCA refit, lexical/family substitution, favorable session selection or extra feature union is introduced.

Each job is checked against the authenticated original support census. The unchanged complete-store `derive_lineage` verifies row/qid hashes, the full held-group roster, and byte-exact target recovery from the accepted Stage B population base and private source-row map. One feature object is reused across the three negative lags only when its full X bytes and accepted feature key agree. Response classes remain separate because their response-row lineages differ.

The complete original metadata, all source input receipts and original weight-header provenance are retained. The selected score uses equal-session aggregation; the 579 weight rows are not substituted for the 567 continuous response channels or used to reweight this endpoint. Their biological identity correspondence remains unresolved.

## Bounded output

The selected original store has exactly:

- 14 feature arrays, 42 response classes and 5,685 response-shard arrays;
- 84 qid/time map arrays;
- 14 private population bases and 42 private source-row maps;
- 5,783 candidate object specifications, 5,839 total arrays and 5,913 total files.

Source-metadata-derived logical output is **13,912,816 canonical array bytes** plus at most **7,026,717 metadata bytes**, totaling **20,939,533 bytes**. These are planned output bounds, not an observed original store. Filesystem blocks, directories/inodes, failure remnants and later execution artifacts require separate capacity. The largest selected session's existing cache constructor preflight is 8,560,640 bytes. Other simultaneous reader/cache/collector/provider allocations still need a joint admission.

The layout uses the accepted complete-store writer's exclusive opaque UUID paths, private directories, readonly single-link files, canonical 128-byte NPY headers and bounded JSONL records. Private source bases/maps are outside the candidate specifications. Before publishing `STORE.json`, the producer checks complete source cardinality, selected array extents, logical output and total file count. Failures preserve partial output without a successful completion marker.

The smaller output does **not** imply a 21 MB input read: the actual preparation seam currently uses the unchanged full 13-input-member session loader and reauthenticates all original archives and weight headers. Its source read counter and joint preprocessing budget include those full operations. No original payload has been reread to validate this component.

## Preparation and private reader

`prepare_original` has the same argument names as the complete-store producer: output root, original archive paths, census/preparation paths, exact admission bytes/SHA and finite read/working/output/metadata limits. Its distinct admission schema is `language-figure3b-store-preparation-admission/v1`; it binds the selected scope and root selection SHA, this producer, its unchanged complete-source dependency, original metadata, NumPy version, paths and limits. Actual preparation requires separate root storage/process/deadline admission. This source does not authorize a payload read or run.

`prepare_generated` accepts only explicitly generated source metadata. It always materializes the three fixed selected cells of its generated session roster; its historical input-plan prefix flag cannot narrow or promote the selected scientific scope.

`StoreReader(root, expected_store_sha256=..., read_limit=..., working_limit=...)` exposes `scope`, `store_sha256`, `metadata`, `weights`, `iter_sessions()`, `private_metrics()` and `close()`. Each session exposes `root`, `session`, fresh `specs`, `iter_jobs(include_targets=False, contexts=None)` and `close()`.

The default job iterator authenticates all three job records before the first map read and then opens only allowed qid/time maps. Each returned job contains the original primitive context, existing typed feature job, readonly maps, private target/support binding, and selected feature path/specification. `include_targets=True` privately reconstructs and verifies exact original population targets for later scoring. It is not a participant interface.

An optional list/tuple of up to three exact primitive context dictionaries can select already materialized cells for a trusted coordinator. The entire selector is verified before map reads; output order remains canonical. This convenience never changes the store's complete 42-job contract or permits a partial benchmark result.

Read authentication, stable cached identities, immutable array backing and cumulative read/EOF charges reuse the accepted complete-store reader. Session initialization failure releases retained index reservations and latches the reader. The trust assumption is an immutable operator host, not protection against a hostile host. Caller-retained yielded arrays and other components require separate live-memory accounting.

No binary win, whole-paper improvement or current SOTA follows from this input-store construction.
