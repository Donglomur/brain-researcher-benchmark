# Original MEG stimulus-decoding accuracy

This component scores the original paper's **mean test-fold accuracy and population
fold SD** from supplied out-of-fold probabilities. It also imports the pinned
author classifier's stimulus-decoding CSV and reports matched differences for
every declared cell. It does not fit a model, create folds, select a best measure,
or produce a whole-paper win decision. The earlier `nested-connectivity-v1`
component and its prospective split/metric remain unchanged.

The source endpoint is category decodability among consciously seen stimuli.
It is not consciousness detection. Known-category averaged regional MEG inputs
remain the source observation type; this scorer does not make them single-trial
or label-independent inputs.

## Source-specific calculation and support

The author classifier at revision
`cab648bbe2eab7093f9ab7b9a5fcddabf28e60a0` uses six directed ROI pairs,
two relevance conditions, two stimulus periods and six binary comparisons among
face, false font, letter and object. The code labels false font `false`. These
are **144 endpoint combinations**, each carrying the supplied eligible measures.
The 246-measure domain must be established externally; it is not recovered from
the 284-row metadata file or generated by this code.

Source feature-quality screening occurs before the six class-pair loops within
each region/relevance/period block. `expected_cells(measure_ids, eligibility)`
therefore requires all 246 measure statuses in every one of the 24 blocks. The
status is `None` for inclusion or a nonempty exclusion reason. Every retained
measure must occur in at least one block, every block must remain represented,
and each included measure expands to all six class pairs. This records supplied
QC decisions; it does not authenticate them or substitute a new screening rule.
Without exclusions, the matrix has 35,424 cells. Directed ROI reversals remain
separate, even when a particular measure is symmetric.

`score_cell(observations, probabilities, pair)` accepts an operator-owned list of
`{"id": ..., "participant": ..., "label": ..., "fold": ...}` and a separate
observation-ID-to-probability mapping. Fold numbers are integers 0 through 9.
Probabilities represent the lexically second stimulus class. A probability of
exactly 0.5 predicts the first class, matching the source logistic classifier's
binary decision at zero. Both orders of a stimulus pair identify the same
comparison and use this fixed probability orientation.

The scorer requires every published participant identifier, both stimulus classes
for each participant, every fold, exact prediction support, unique observation IDs
and one held-out fold per participant. This preserves the paired participant
support of the selected Figure 3c/3a result declared in
[reproduction.v2.json](../../reproduction.v2.json). Keeping all 94 participants
while omitting a category, even for just one participant, is incomplete support
and is refused before any score is returned.
It reads the existing pinned public 94-ID roster from the sibling implementation
and checks its SHA-256 before use. It never reads private source targets. The
supplied observation ledger must independently preserve the authentic row support,
order and labels: these checks cannot detect fabricated values or missing repeated
observations when both classes still remain for each participant. Multiple
observations per participant/class are supported without silently changing their
weight; the scorer neither deduplicates them nor assumes exactly 188 rows.

For each fold, accuracy is correct predictions divided by observations. The
primary accuracy is the unweighted arithmetic mean of the ten accuracies; SD is
the population standard deviation (`ddof=0`). Pooled accuracy and per-participant
accuracy are explicitly descriptive. Neither balanced accuracy nor AUC replaces
the source primary metric. Fold SD is not a standard error or an inferential
uncertainty estimate: the training sets overlap.

`score_complete_matrix(cells, cell_inputs)` consumes an iterable of
`(cell_key, observations, probabilities)` triples, checks the full lattice and
returns only after all expected cells have been scored. The seven-field key is
`(measure, ROI_from, ROI_to, relevance, period, class0, class1)`. Missing,
duplicate or foreign cells cause refusal. `score_cell` remains useful for a
single cell, whose result does not imply complete-family coverage.

`read_author_matrix(text_stream, cells)` reads exactly the author's columns:
`SPI,classifier,meta_ROI_from,meta_ROI_to,relevance_type,stimulus_presentation,`
`stimulus_combo,accuracy,accuracy_SD,AUC,AUC_SD`. It requires the
`Logistic_Regression` comparator, the full expected support, fractions in [0,1],
and finite metrics. Python tuple syntax in the stimulus column is parsed with
`ast.literal_eval`, never executed. Reversed class aliases cannot create duplicate
cells. Cross-task or relevance-decoding files have different schemas and refuse.
This is summary import, not an author rerun or recovery of its fold predictions.

`compare_matrices(candidate, reference)` checks identical complete cell support
and returns each accuracy difference. Here measure IDs identify reference
comparison slots; the function does not constrain the candidate architecture or
how its probabilities were obtained. It cannot verify that candidate and reference
used identical physical inputs, folds or permitted observations. A future
protected harness must bind those execution records. There is deliberately no
best-cell selection, cross-cell scalar, significance test or paper-win threshold.

## Use and validation

This is a dependency-free Python API. Import `score.py` using the application’s
module loader. Obtain `cells = expected_cells(measure_ids, eligibility)` from
an independently authenticated QC ledger, then call the functions above with
operator-controlled inputs. Input iterables and in-memory dictionaries are not
an untrusted-file sandbox or a physical resource admission system.

Run the adjacent generated controls through the shared test pool:

```sh
python3 -I -B test_score.py -v
```

The tests use artificial values attached to the public roster identifiers, with
no authentic samples or predictions. They exercise unequal fold sizes, population
versus sample SD, class orientation and ties, participant-by-class completeness,
retained repeated-observation weighting, identity support, all 144 endpoint
combinations, explicit QC exclusions, strict author CSV import and complete
matrix comparison. They do not execute source models or access private targets.

## Remaining scientific requirements

The empirical Zenodo v1/v2 join, corrected-supplement identity, authentic ordered
246-measure domain, original row ordering and realized participant folds remain
unresolved. No source archive was downloaded or prepared here. No author model,
candidate model, solver trial, paper improvement or current-SOTA comparison was
run. A full-family comparison rule, meaningful effect, participant-level paired
uncertainty and exposure/resource protocol are still required. This source-style
scoring component completes neither that admission nor the original paper task.

Exact cached source identities and the code locations supporting these semantics
are recorded in [SOURCE.json](SOURCE.json).
