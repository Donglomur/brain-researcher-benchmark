## What is checked

The externally selected paired source manifest and every member are authenticated before
the pure panel contract is compiled. Its unchanged participant-roster reader
uses already captured, authenticated roster bytes. Neither submitted code nor
the official-code capsule is imported or executed.

The externally selected `PREPARED.json` and paper pins bind an exact tree:

- Both frozen three-file programme capsules, the fixed wrapper and canonical
  programme manifests; nonempty submissions and original preparer size limits.
- The seven source-pinned official code/config files for the code-assisted
  condition, the paper, and exact participant instructions; no extra payloads.
- The single NPY bank, all ten context files, the private source/category ledger,
  and the record declaring both programmes frozen before preparation.
- Exact owned private/public modes, regular single-link files, no symbolic
  links, and no paths outside the prepared root. Public trees have
  explicit read-only file/directory modes, including under a private process umask.

All ten contexts are rebuilt from the private panel and compared in full. This
checks label membership, group separation, held queries, opaque row order and
equal inputs for both conditions. Every `[4,1000]` bank row must be finite,
little-endian float64 and match its tensor commitment. Wrong byte order,
truncation, extra payloads and a rehashed row swap fail. Captured file identities,
owners, modes, link counts, extents and modification/change times are checked
again before report publication without rereading the bank.

This operation intentionally sees the private ledger **before delivery**. It
must run as the trusted evaluator, with no participant process present. It is
separate from the runner's later rule that scoring targets remain unopened until
all twenty prediction phases close. The verifier's own report stays private.

## Provenance and remaining limits

Tensor commitments establish internal correspondence. They do not independently
rederive the original CSV-to-prepared scientific transformation or prove that a
self-consistent anonymous bank came from the real source data. The accepted
94-person preparation, exact selected preparation source and its successful
execution remain external provenance. Likewise, a frozen-programme declaration
does not independently observe authorship history or establish which assistance
the authors actually saw.

The filesystem checks assume an evaluator-controlled host. Final observations
are sequential, not an atomic immutable snapshot and not a defence against a
malicious host administrator. The subsequent owned Provider must still check
actual mounted bytes before and after every phase. Historical folds, publication
and corrected-supplement joins, reference agreement, AUC companions and a
meaningful selection-aware improvement decision remain separate qualifications.

[`CACHE_DECISION.md`](CACHE_DECISION.md) explains why immutable-original reuse
could not be established. The original uncached programme route remains intact.

## Finite invocation

On an independently admitted operator, use the already existing preparation;
do not rerun its source ZIP conversion:

```sh
python -I -B verify.py \
  --prepared-root /private/existing-meg-delivery \
  --prepared-pin-json /private/selected-prepared-pin.json \
  --paper-pin-json /private/selected-paper-pin.json \
  --paired-manifest-pin-json /private/selected-source-manifest-pin.json \
  --output /private/new-audit/delivery-report.json \
  --read-limit 134217728 --write-limit 65536 --seconds 60
```

The output parent must already be owned and private; the report must not exist
or lie inside the prepared tree. All three pin files have exactly `bytes` and
`sha256`. Their tiny bootstrap reads reject FIFOs, devices and links before payload
access; changed file identity is rejected before acceptance. The admitting supervisor must bind their own
identities and the source/interpreter closure.

The limits above are a **prospective profile, not an execution admission**.
Logical payload reads are reserved before each operation, including failed
attempts and EOF probes. Preparation arrays outside the delivery are never
opened. Captured roster rereads occur in memory. Interpreter/library/bootstrap
I/O, physical disk I/O, aggregate CPU and process-tree memory are outside those
counters and require separate supervision. The verifier allows at most 256 MiB
logical reads, 1 MiB report allocation and 300 seconds; a caller must choose
smaller finite limits appropriate to its admitted operation.

The persisted report is always `provisional_structural_check`. If final fsync
crosses the deadline, the operation fails and leaves that provisional file.
Standalone acceptance additionally requires observed successful process exit
within the original deadline and an externally recorded final report hash.
Inside the runner, admission instead observes the actual fresh function return
and pinned retained report before constructing transport. The complete campaign
still requires its external successful-exit/deadline observation.
Partial outputs are preserved, existing reports are never overwritten, and no
failure is retried automatically.

the CLI. A generated report cannot qualify authentic preparation, runtime,
