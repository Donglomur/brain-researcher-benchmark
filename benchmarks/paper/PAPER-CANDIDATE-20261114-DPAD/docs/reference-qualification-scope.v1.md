# DPAD reference qualification: current scope clarification

This note clarifies the distinction between qualifying a source-method reference and attributing an execution to the historical Figure 6h–i run. The current [improvement contract](../improvement.v1.json), [reproduction contract](../reproduction.v1.json) and generated blocked reports retain the bundled historical wording about preparation, caller, environment and sanitization. Those documents have not been rewritten. Read that wording with the claim-specific distinction below; it does not make exact historical software identity a separate prerequisite for a qualified reimplementation.

A prospective reference may use an independently reviewed paper-method implementation or the pinned author method in a recorded compatible runtime. Qualification still requires the source algorithm, complete architecture and state-dimension selection procedure, preprocessing, original validity and aggregation conventions, and independent execution on the authenticated original observations and folds. Recovering the original caller is one way to establish these semantics; its absence does not by itself disqualify independently supported source-equivalent semantics. A current evaluator file, compatible environment or matching mean alone cannot establish them.

Exact historical caller/runtime identity remains unresolved for attribution to the historical execution. Original saved predictions are not categorically required when an independently executed, qualified reference produces predictions on the same authenticated support. They remain material if they are the only evidence that can resolve source masks, selection or comparison. A new source-method run must be labeled as such. It does not establish historical replay or automatically satisfy the retained published-versus-reproduced baseline comparison. Any distinct source-method rerun claim must use its separately reviewed supported contract; this note does not select one.

The scientific requirements remain unchanged:

- Preserve the original joint one-step-ahead neural/behavior prediction problem, monkey I's exact seven wideband sessions, the wideband-to-session crosswalk, the selected 32 electrodes and 77–99-unit membership. A local roster cannot supply missing biological identity.
- Preserve the original five-fold temporal support and training-only inner architecture/dimension selection. Authenticate the realized folds; a newly chosen split or held-session extension cannot substitute for them.
- Qualify source-equivalent 10 ms bins, Gaussian smoothing, 50 ms downsampling, alignment, boundary handling and the exact channels. Changing symmetric/causal filtering changes the input condition. Resolve original invalid-row/channel inclusion, sanitization and aggregation before claiming scorer equivalence.
- Retain the full seven-method, two-coordinate frontier, all 35 session-fold outcomes, channelwise Pearson correlations and the source aggregation and paired comparison rule. Published numbers or their copied means do not qualify a reference fit, source masks or prediction outputs.
- Qualify a competent reference and protected evaluation, training-only selection, meaningful joint-effect criteria, valid uncertainty and concrete access/compute budgets. Both information conditions retain identical original data and folds; author-code access is their sole information difference.

This note does not resolve a source hold, admit execution, change a criterion/tolerance, bind new data or author artifacts, or promote readiness. It preserves all existing evidence, flags, counts and unqualified outcomes. Numeric-source updates, if separately reviewed, must retain their own evidence and cannot be inferred from this clarification.

The [current task](../task.json) and [paired outcomes](../outcomes.v1.json) remain authoritative for their unchanged declarations. The [pre-improvement task](../historical/task.pre-improvement.v1.json) and [pre-outcomes task](../historical/task.pre-outcomes.v1.json) remain immutable historical context. Shared [reproduction reference rules](../../../../src/neurobench/paper_reproduction_v2.py) allow operator reconstruction, while the [improvement engine](../../../../src/neurobench/paper_improvement.py) separately defines the source-method rerun route. Those permissions require independent scientific qualification; this note supplies none.
