# Bounded native trial-index decoding

This source component fills one input gap in the existing Consensus task. It
decodes a narrowly specified OCaml integer-list serialization and compares the
result with supplied companion indices. It preserves repeated and omitted
source trial identities. It does not run the author model, load neural arrays,
parse NPY files, or establish original Figure 2b reproduction or improvement.

The pinned author fitting entrypoint creates trial indices as a list and writes
them through `Misc.save_bin`. That helper uses `Marshal.No_sharing`; its loader
uses OCaml unmarshalling. This Python component instead recognizes a limited
inert byte grammar. Source observations and limitations are in [SOURCE.json](SOURCE.json).

## Accepted profile

The owner must supply the expected raw SHA256 and source trial count from a
separately authenticated source manifest. A hash supplied by the same untrusted
source is not authentication of the deposit. The declared count must be 1–10,000,
matching the existing occurrence adapter's engineering limit. The body is at
most 40,021 bytes and must contain exactly one small-header Marshal value:

- A 20-byte header with matching payload extent, zero shared blocks and
  exactly three heap words per declared list cell on both architectures.
- Exactly the declared number of tag-zero, size-two cells, each containing a
  canonically encoded nonnegative integer smaller than the source trial count.
- One compact empty-list terminator, then EOF.

Only compact integers and signed 8/16-bit integer encodings are accepted. These
cover every allowed index. Other encodings, objects, references, custom values,
code pointers, nested lists, large headers, truncation and trailing objects are
refused. This is not a general Marshal reader or a version-independent native
compatibility claim. The selected OCaml 4.14 format documentation is a reference
profile, not evidence that the paper used that compiler release.

## Owner-local use

```sh
python3 -I -S -B native_indices.py \
  --native /external/data/animal/trial_ids_0 \
  --source-trial-count 123 \
  --expected-sha256 EXPECTED_LOWERCASE_SHA256 \
  --companion-json /external/owner/supplied-companion-list.json
```

The optional companion file contains a JSON list of integer or exactly integral
finite numeric values, as accepted by the existing occurrence adapter. It is
**not the NPY file**. Exact NPY decoding and byte-to-deposit provenance remain
separate prerequisites. The record reports disagreement without changing either
sequence; `native_indices` can populate the corresponding owner-supplied fold
record for [the occurrence adapter](../trial-occurrences/README.md).

The CLI reads only the explicit, bounded ordinary files and prints owner-private
JSON to stdout. It rejects final-component symlinks. Parent-directory traversal
and filesystem containment are not sandboxed. Output includes trial identities;
do not place authentic output in participant packets or public artifacts without
the applicable task policy. No automatic acquisition or execution is enabled.

## Controls and remaining work

`python3 -I -S -B test_native_indices.py` exercises generated byte fixtures,
including a literal repeated-index example, encoding boundaries, unsupported
types, corrupt headers, truncation, companion disagreement and CLI refusal.
Run it through the repository's existing bounded test pool. No control invokes
OCaml or reads an authentic scientific input.

This component is ready for source review only. It does not authenticate the
seven-animal/three-fold collection, the original NPY companion, conditions,
trial-axis alignment, row ordering across native processes, active-cell census,
PSTH selection, historical model configuration or final Figure 2b reduction.
All existing task eligibility and readiness statuses remain unchanged.
