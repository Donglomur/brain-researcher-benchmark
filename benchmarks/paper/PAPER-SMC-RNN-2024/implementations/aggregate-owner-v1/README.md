# SMC aggregate owner

This additive source composes the existing durable process owner and pidfd CLI
custody with a persistent delegated cgroup for each producer condition. It
supports the prospective aggregate episode's matched 8 GiB/six-thread setting;
it does not change the historical single-process route or repeat the accepted
author references.

**Execution is unavailable until the sibling aggregate episode's source-pinned
deployment binding is resolved and independently qualified.** The accepted
matched 8 GiB/six-thread material pair is selected. No scientific image,
delegated Linux hierarchy or producer PID ceiling is selected. Caller arguments and
`qualified=true` assertions cannot fill those gaps. Generated controls exercise
source logic with fake kernel/process observations; they are not runtime proof.

The public execution entry is `runner.py execute`. The public grading entry is
`runner.py grade`; the sibling episode refuses direct grading. The grader first
authenticates controller and CLI closure, natural and post-controller cgroup
proofs, raw CPU/memory counters, producer attachment, Docker-only resource
closures, and final group removal. It opens private scientific targets only
after those checks.

Reproduction retains 75,000 aggregate producer CPU seconds and 86,400 wall
seconds per access condition, including both causal and noncausal outputs.
Improvement retains 7,200 CPU and 10,800 wall seconds. Both use a prospective
8 GiB ceiling, six numerical threads and an explicitly chosen six-CPU rate.
The PID allowance must be separately observed and selected; it is not six by
definition. The improvement allowance is below either historical full author
inference arm and is not demonstrated training capacity.

The original pair cutoffs are 173,760 and 22,560 seconds. The parent commits the
original clock before activation; all work, cleanup and recovery retain it.
Persistent producer cgroups are created only after the corresponding owner
intent is fsynced. Their observed identities and zero initial counters are
published before acknowledgement. A fixed worker release barrier prevents
candidate imports before actual producer PID/cgroup attachment is acknowledged.
The trusted worker and release helper count toward the producer aggregate.

The parent meters the entire producer subtree while the controller waits.
CPU overrun, excess peak memory, or OOM-kill events refuse success. Successful
reclaim and handled memory/PID denials remain recorded observations under
`measured_caps_and_oom_kill_v1`. Polling, stop and final refusal are not a claim
of zero CPU overshoot. Actual overrun and failed costs remain chargeable.

After natural producer retirement, complete final counters are collected
between empty observations before output capture. Cgroups remain owned until
the controller and all acknowledged CLI processes have closed. Failure cleanup
then stops exact observed producer hierarchies, retains their counters, invokes
the transport's separate Docker recovery, and removes only exact empty groups
with authenticated resource-closure receipts. Unknown birth/counters/creation
outcomes remain failures.

Nonfatal metadata-write errors also trigger an independently attempted,
original-deadline-bounded emergency stop after real controller/CLI absence is
reobserved. That path cannot create resources, remove unknown groups, authorize
recovery, or yield a passing result. Fatal loss of the outer parent is a
separate unqualified deployment requirement.
