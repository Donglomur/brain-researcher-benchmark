# Restricted VALID inference ownership

This source contribution closes the ownership interface for a development reference on the original MC_Maze 20 ms task. It is not a new benchmark registration, a trained candidate, or a reported scientific result. The existing TEST route and accepted restricted VALID projection and grading sources remain immutable.

## Required inference boundary

The worker receives the projected VALID observations: 574 trials, 35 observed bins and 137 held-in neurons. Hidden neurons and future observations are physically absent, rather than zero-filled as observed data. The original noncausal author method generates the ten future bins using 192 particles and 32 trajectory averages, seed 20261118. Those averages are not independent training or biological replicates.

The separate TRAIN route has 1,721 trials, 45 bins and 182 neurons for original decoder-rate inference. These full-observation rates are not restricted-input gain-calibration predictions. Neither the old TEST train_rates nor their VALID subset may substitute for restricted VALID inference.

The ownership contract requires exact immutable source/material/method/resource joins before constructing a worker invocation. Only the selected ordinary read-only leaf files may be exposed. Raw original input and target files, their parent directories, unrelated checkpoints and output aliases must be refused. A correct mount list alone does not demonstrate a physical runtime enforced it.

The maintained attachment protocol must complete before the worker is released: create and authenticate the selected scope, attach the worker, observe its acknowledgement, and release exactly once. A missing or failed acknowledgement is a failure, not permission to proceed. Custody of outputs becomes eligible only after all required owned process/container/cgroup closure is established. An exception before launch may establish a never-launched result only when the exact absence of side effects is known; it must not suppress unresolved cleanup after launch.

## Resource contract

The original reference resource profile remains 8 GiB for the producer, six threads and a 10,800-second wall envelope, with a positively selected integral CPU budget. The previous restricted caller admits an explicit value from 1 to 64,800 CPU seconds; there is no default 7,200-second reference allowance. The upper endpoint is a finite envelope, not a completion estimate. Historical noncausal TEST inference required about 29,393 CPU seconds and cannot establish this VALID job's completion time.

Retained controller/holder/outer-owner requirements must be bound separately. The previous production proposal used a 10 GiB/eight-thread whole-operation allowance; this document allocates none of it. Fresh host/VM/image/source admission and a complete exact operation are required before any original-data inference. No live memory, disk, process or container qualification is supplied by generated tests.

## Claims and limitations

A future successful run can establish operational use of the selected released checkpoint on the correctly restricted VALID inputs, with preserved output custody and known cleanup. It cannot establish that VALID was unseen during checkpoint training or selection: the actual historical checkpoint-fit cohort remains unresolved. Exact checkpoint-to-Table-2 and original dataset-revision joins also remain unproved. These provenance limits do not prevent operational qualification, but they limit scientific claims.

A later improvement comparison requires an independently frozen candidate, the original four metrics and a predeclared selection rule. The typed bounded VALID scorer already preserves the original canonical evaluator and TRAIN decoder fit, freezing both complete predictions before target access. Its source proof is distinct from a real numerical qualification. Improving this released SMC reference alone does not establish SOTA, and publicly released TEST targets are not a fresh hidden holdout.

This phase selects source construction and one ownership-focused generated control campaign only. It carries previous projection/grader controls without replay and does not open original arrays, targets or checkpoint bodies, execute a model, perform numerical grading or calibration, or change Git. Every future actual operation remains disabled until separately selected with genuine operands and resources.

## Portable entry and dependency identities

The component lives beside `restricted-validation-v1`; it does not modify that component or the maintained TEST owner. Supply immutable descriptors for the accepted restricted source, prepared reference, grade source, retained facade, VALID transport, runtime and genuine deployment qualification. The supplied repository must contain the exact retained aggregate-owner and aggregate-episode manifests. Descriptors are trusted operator operands, not participant evidence or self-attested runtime qualification.

`validation_owner.py` provides four commands, using the selected Python interpreter:

```text
python -I -S -B validation_owner.py prepare --request REQUEST.json --sha256 REQUEST_SHA
python -I -S -B validation_owner.py command --operation execute --prepared PREPARED.json --sha256 PREPARED_SHA --output EXECUTION --owner OWNER --recovery-read-bytes READ_BYTES --recovery-write-bytes WRITE_BYTES
python -I -S -B validation_owner.py execute --prepared PREPARED.json --sha256 PREPARED_SHA --output EXECUTION --owner OWNER --recovery-read-bytes READ_BYTES --recovery-write-bytes WRITE_BYTES
python -I -S -B validation_owner.py custody --prepared PREPARED.json --sha256 PREPARED_SHA --output FRESH_CUSTODY --owner OWNER --result-sha256 RESULT_SHA
```

These are interface examples, not an authorized run. `prepare` creates only source/metadata outputs. `command` returns the bound maintained runner command. `execute` replaces its interpreter with that authenticated runner; it does not add a second process manager. `custody` invokes the retained saved-result and aggregate-closure gate before admitting a final frozen prediction. This owner refuses numerical grading. The separate accepted bounded VALID grader can consume the eventual reference and independently frozen candidate.

The original owner selects exposure before creating its request. This adapter therefore constructs the exact pre-request read-only leaf roster using the accepted source/material/profile validators; the maintained Provider owns the request, output and work locations. It does not invent an intermediate request or success receipt to break that ordering.

The controller's provider-completion callback writes an unadmitted capture only. Final custody requires natural controller/CLI closure and the genuine saved aggregate completion joins. The newly frozen snapshot must also have the same byte count and SHA-256 as the captured output. A changed quarantine file cannot become a different admitted freeze merely because it has valid dimensions.

The transport is a deliberate, narrowly bound derivative: only the `validation_reference` phase, `held_attempt` request and role `B`, with strict integral CPU1..64800, 10800 producer seconds, 8 GiB and six CPUs. The original TEST transport remains unchanged. Compatibility fields such as `closed_pair`, `PAIR_CLOSED.json` and `both_conditions_closed_before_private_grade` retain their schema names but apply to exactly one reference phase; they do not report a two-arm comparison.

Public source identity hashes exactly the five named owner Python files and the selected transport manifest/leaves. README and controls are not executable production dependencies. A materialized component has its exact eight-name identity, while the generated private overlay additionally requires exact physical directory membership. Do not publish private preparation, interface, funding, activation or receipt records recursively.
