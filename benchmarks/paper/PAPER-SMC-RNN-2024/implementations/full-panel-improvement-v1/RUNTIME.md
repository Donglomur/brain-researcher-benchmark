# Full-panel runtime composition

This component supplies the full-panel condition to the existing two-access-phase
SMC owner. It does not create a new process manager or expand execution into 574
separate trial processes. The original strict condition and owner source remain
unchanged.

`owner_overlay.build_overlay(repository_root, fresh_output, max_bytes=...)`
authenticates the existing owner closure, copies its ten unchanged primitives into
the same repository-relative layout, and substitutes the separately pinned
`owner_legacy.py` adapter. This is an explicit operational source copy; it runs no
process or candidate. The adapter loads the fixed `FullPanelEpisode` implementation
and its fixed continuous-interface, task, policy and worker dependencies. A changed
manifest cannot select arbitrary replacement code. The overlay's computed source
identity is separate from its component's runtime identity, avoiding a self-hash
cycle. Source materialization must have its own I/O allocation.

The episode accepts exactly two already frozen methods: `paper_data` and
`paper_data_author_code_and_weights`. It authenticates both method records and
copies both programmes and their planned declarations before releasing either
full-panel view. Actual participant exposure mounts only the method-gated released
views and the fixed candidate-derived artifact snapshots. A selected-artifacts
path may be absent when the selected set is empty. The candidate interface adds
`--selected-artifacts /selected_artifacts`; permitted files are described in the
frozen method record.

Before active owner acknowledgement, protocol admission reads bounded metadata and
programme text only. The unchanged owner then invokes the compatibility inspector
under its active custody: full pair, both methods, candidate artifacts and both
released views are authenticated before the first candidate phase. Every later
mount is bound to the same released-view inventory. Parent process/cgroup custody,
aggregate resource accounting and two-phase closure are inherited through the
unchanged owner primitives; source composition is not evidence that those controls
have run successfully on this condition.

A candidate writes exactly `offline.h5` and `actual_declaration.json`. The new
worker retains the source-authenticated original release barrier and CPU limits,
then creates its result and output manifests. The post-run declaration must join
the method-freeze hash, programme hash and condition. The compatibility adapter
checks the original planned-declaration path but passes only the separately
captured, immutable post-run declaration to prediction freezing. Descriptions of
actual adaptation remain participant claims unless supported by execution evidence.

Protected grading retains the original complete pair checks: both closed requests,
profiles, mounts, inventories, prediction freezes and hashes are checked before
calling either numerical scorer. A corrupted second condition prevents the first
condition from being scored. A one-use grading marker precedes target access.
All four original metrics and comparisons come from the continuous interface.
The report labels the permitted full-panel information condition and does not
claim fresh-trial generalization or infer that adaptation actually occurred.

`MATERIAL_BINDING.json` selects the fresh 71-file, 31,380,768-byte pair recorded
in `MATERIAL_EVIDENCE.json`. The earlier strict pair was not relabelled.
`DEPLOYMENT_BINDING.json` remains unselected. Deployment still needs a qualified
scientific image, coherent Linux controller/daemon PID and cgroup view, delegation,
PID ceiling and corresponding identity-bound evidence. A cgroup mount root of `/`
is not by itself proof of a coherent host view. The separately allocated material
export executed no container, candidate model or numerical scorer and produced
no scientific performance result.

Development delivery and programme freeze establish a defined interface order.
They do not prove that an authoring model had never encountered public test data,
nor do they establish isolation of a preceding authoring episode. These fields
remain false/unestablished in runtime protocols and reports. The inference cgroup
measures in-run training/adaptation, not earlier authoring work. Matched authoring
resources and actual delivery/custody evidence must be separately specified for a
controlled study; no extra authoring manager or fabricated receipt is supplied.
