to a durable parent owner. The previous `protected-episode-v1` public execution
refusal remains unchanged. This successor supplies an actual owned invocation,
the original clock, synchronous resource custody and a parent closure gate.

The implementation has generated controls and short macOS trusted-process
controls. **No actual Linux/Docker episode, candidate, original neural array,
model, protected scientific comparison or forced-parent-stop qualification has
been executed here.** These files establish source construction, not a finished
or scientifically qualified benchmark.

## Ownership and execution path

`process_owner.py`, `group_bootstrap.py` and `trusted_controller.py` extend the
existing `ownership-v4` launch barrier. A fixed task controller is authenticated,
an initialized session/group leader is observed, and intent and ownership are
fsynced before the activation gate. The bootstrap retains its identity after
controller completion and arms its alarm against the absolute original cutoff.
It passes one anonymous socket endpoint to the trusted controller and closes its
own copy. The public launch cannot select candidate code or the fixture route.

The controller then binds its source, invocation, actual parent/group, current
boot and original deadline. Before any original arrays are read, the parent
observes its launched PID, initialized command and parent relationship and
captures a live pidfd. The parent acknowledges each subsequent callback only
after storing the exact event in its private journal. Both prepared requests
must exist before the first Provider event. The unchanged Provider's compact
request encoding is preserved; its hashes are not replaced by pretty JSON.

The unchanged Provider starts Docker CLI processes in independent sessions.
Therefore controller-group closure alone is insufficient. Every `CLI-CHILD`
event reaches the parent while Docker exec is still gated. The parent verifies
the exact Linux boot/start token and captures its own live pidfd before
acknowledging release. Completed CLI absence is durably recorded before that
handle is retired, avoiding later numeric PID reuse. Cleanup signals every owned
pidfd first, then observes all closures. A reused or surviving group remains a
failure; no numeric PID/group signal is used for CLI cleanup.

The dedicated Linux supervisor becomes an observed child subreaper and requires
`pidfd_open`, `pidfd_send_signal`, `waitid(P_PIDFD)` and capacity for 640 bounded
CLI children. Its exact adopted controller is reaped through its pidfd before
the original group can be called absent. SIGINT/TERM/HUP requests are deferred
to a safe pump boundary; cleanup is not interrupted halfway through a handle
transfer. Unexpected cleanup errors remain failures and still close each known
handle. EOF without a complete result fails promptly rather than waiting up to
the full paired deadline.

## Recovery and costs

The parent stops the trusted controller first, closes every acknowledged CLI
authority, and publishes that observed closure. Only then may it invoke the
unchanged `Provider.recover`, using the exact original ownership/request pins and
the same deadline. It never retries a producer or interprets empty namespaces as
proof that an unknown creation outcome was safe.

Each producer retains the original v1 transport allowance. Recovery has a
separately explicit engineering read/write allocation in the invocation, not a
refreshed child allowance. Its Provider is initialized with the combined budget
and immediately charged the **full original child ceiling** before recovery can
spend the extra allocation. Unknown failed child costs are not refunded from the
size of retained files. Each recovery phase permits at most 64 CLI calls within
its share of the extra allocation.

All parent publications share one 32 MiB prospective metadata cap, including
phase events, observed absence, recovery, closure and final reports. Two MiB is
reserved for terminal evidence, and 256 KiB is conservatively charged for the
bounded process-owner records and publication overhead. Failed writes consume
their reserved charge. These are future execution bounds; no such scientific
run or storage allocation was made by constructing this source.

## Operator commands

Integrate this component alongside its pinned `protected-episode-v1` predecessor
and retained Sleep `vendor_transport`. Use an already prepared v1 protocol;
both programmes and all input/source/runtime pins must already be frozen.
The separately admitted runtime needs an existing immutable generic image and
the exact v1 Linux/image/profile qualification. This command does not install,
pull, download or authorize a campaign.

The [cached-image dependency inventory](../../docs/scientific-image-inventory-20261117.json) records six missing selected metadata entries and four version differences against the author-reference stack. Scientific-runtime qualification remains unresolved; candidate programs retain their own dependency choices.

```sh
python3 -I -B runner.py execute \
  --protocol /operator/protocol/PROTOCOL.json \
  --protocol-sha256 "$PROTOCOL_SHA256" \
  --output /operator/new-execution \
  --owner /operator/new-owner \
  --recovery-read-bytes "$ADDITIONAL_RECOVERY_READ_BYTES" \
  --recovery-write-bytes "$ADDITIONAL_RECOVERY_WRITE_BYTES"
```

Owner, execution, public material and protocol roots must be disjoint. The owner
holds an exclusive invocation lock. Existing destinations cannot be reused;
there is **no execute-resume command** and no clock renewal. Recovery utilities
retain boot/start identity, but fatal supervisor loss does not have an automated
recovery command in this component.

The successor's public grade entry requires `RESULT.json` with an independently
selected hash, the matching invocation and actual parent closure. A controller's
intermediate `PAIR_CLOSED.json` alone is insufficient.

```sh
python3 -I -B runner.py grade \
  --owner /operator/completed-owner --result-sha256 "$RESULT_SHA256" \
  --target /operator/private-target --evaluator /operator/pinned-evaluator \
  --output /operator/new-private-report --scratch-bytes "$ADMITTED_SCRATCH_BYTES"
```

This calls the unchanged v1 numerical grader only after the owner checks. Its
continuous measurements remain distinct from a binary paper win, broader SOTA,
or verified AI attribution. Calling the old numerical helper directly is trusted
operator evaluation and does not establish this successor's protected path.
