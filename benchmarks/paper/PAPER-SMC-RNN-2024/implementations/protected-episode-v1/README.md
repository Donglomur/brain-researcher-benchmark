# SMC protected local-program construction route

This additive route connects the authenticated 71-file official-assets packet
to frozen participant programs, the existing owned Docker transport, complete
closed HDF5 predictions, and the unchanged continuous scorer. It does not change
the current task, the two primary access conditions, or the scientific metrics.

**This is source-only normal-lifecycle composition, not an executable protected
benchmark.** Authentic `execute` refuses at `unsupported_active_owner`, before
container creation or original-array inspection. No runtime/configuration
boolean can remove that refusal. The existing transport needs
a Linux operator with `pidfd_open` and `pidfd_send_signal`; native macOS is not
supported. No matching image, long-lived controller owner, or forced-stop
host/daemon custody qualification is supplied. The command refuses execution
without the missing actual active-owner integration as well as independently
qualified evidence for this exact source and image. JSON assertions do not
constitute independent qualification. No container, model,
authentic scientific scorer, or AI episode was run to build this source.

## Scope and restriction

The route is explicitly `smc_restricted_single_process_pair_v1`. Its producer has
`pids=1` and `--init=false`, so **no child processes or additional threads** are
supported. The same process installs an irreversible hard `RLIMIT_CPU` before
running the participant program. This is producer-process CPU, excluding holder,
Docker daemon, CLI and operator costs. The host retains those separate transport
costs without inventing total CPU or peak memory measurements. The hard CPU
limit is installed and read back before image site hooks or participant imports;
the interpreter starts with `-I -S -B` and enables admitted site packages later.

This restriction is stronger than one numerical thread. It is not equivalent to
the generic primary execution profile and must not replace its current task or
admission. Official random-search/Slurm entrypoints use subprocesses and are
incompatible. Even sequential author inference or training may need library
helper threads. Source inspection found sequential inference and a DataLoader
without requested workers, but actual Torch/BLAS compatibility is unproven.
Original scripts also assume writable repository-relative data/run directories;
participants must adapt paths into `/work` and the supplied read-only files.

The unchanged finite **producer** profiles are identical across access arms:

| Outcome | CPU seconds | Wall seconds | Memory | Numerical threads |
|---|---:|---:|---:|---:|
| Reproduction | 75,000 | 86,400 | 4 GiB | 1 |
| Improvement | 7,200 | 10,800 | 4 GiB | 1 |

Setup, capture and cleanup have separate explicit 60/300/60-second ceilings per
condition. The paired enclosing deadline includes both complete phases and 120
seconds of orchestration. Neither these values nor source construction grants
execution, storage, download, API or training authority. Source/host-write limits
are explicit operator inputs shared across both Provider phases. They cover
Provider transport I/O, excluding adapter protocol/manifests, full HDF5
authentication, freezes, private grading snapshots and final publications;
those need their own separately admitted whole-operation allocation. This
adapter does not claim to meter their aggregate. Training adequacy has not been
established.

## Participant program

Submit one ordinary Python file and one existing v2 typed declaration per access
condition. Each method's `source_sha256` must equal that program's exact SHA-256.
Both programs and declarations are copied and committed before the first phase.
The program runs in the admitted image, never on the host, with these arguments:

```
program.py --input /materials --out /output --outcome reproduction --declaration /declaration.json
```

For reproduction it must write exactly `causal.h5` and `noncausal.h5`, retaining
the complete original NLB output geometry and all required arrays. For
improvement it must write exactly `offline.h5`. No reduced rows, arbitrary JSON
metrics, precomputed operator predictions, or additional output artifacts are
accepted. The trusted entry adapter constructs the transport envelope; because
participant code shares that process, its envelope and `RESULT.json` remain
untrusted declarations. The host independently checks complete captured contents
and their source/declaration binding, then invokes unchanged HDF5 validation.

Each phase receives only its condition's exact manifest-listed files, its frozen
program/declaration, and the small execution contract/entry adapter. The assisted
phase alone receives the ten official assets and author code. The pair parent,
other program, host repository, Docker socket, operator targets and private
reports are never candidate mounts. Supplied validation labels and validation
selection remain allowed. Original **test** targets remain operator-only here;
their historical public exposure is unchanged. Programs producing final test
predictions must not invoke source evaluation with operator test targets.

Public program, declaration and execution-contract copies explicitly receive
mode `0444` on their exclusively created file descriptors, including under
`umask 077`. Private publications and directories retain their existing modes.
The supplied material files must separately satisfy the retained transport's
UID/GID 65534 readability check; this adapter does not change their permissions.
Generated controls set only their authenticated `/materials` fixture members
readable. The original packet and exporter remain unchanged. The retained
Provider's own request/policy publisher still needs a separate permissions
correction and qualification; this source repair does not establish native
runtime readiness.

## Operator commands

Let `ENTRY` be this directory's `episode.py`, `PAIR` the exact validated
`participant_pair-official-assets-v2/pair_manifest.json`, and `TASK` the actual
committed task with SHA `e99cf60035a156fdb7a0a3b61b539db387ae53b31f1d4be59da31f18d9346fbd`.
The current packet SHA is
`8feceeeb5738c439eef2c1e6ea01237574ff66cf167702e7b230f5c7bac7ad72`.

```sh
python -I -B "$ENTRY" instantiate \
  --pair "$PAIR" --task "$TASK" --outcome reproduction \
  --program-paper-data paper_data.py --declaration-paper-data paper_data.json \
  --program-assisted assisted.py --declaration-assisted assisted.json \
  --runtime runtime.json --runtime-sha256 "$RUNTIME_SHA" --output "$PROTOCOL_DIR"

python -I -B "$ENTRY" execute \
  --protocol "$PROTOCOL_DIR/PROTOCOL.json" --protocol-sha256 "$PROTOCOL_SHA" \
  --output "$PRIVATE_EPISODE_DIR"

python -I -B "$ENTRY" grade \
  --closed "$PRIVATE_EPISODE_DIR/PAIR_CLOSED.json" --closed-sha256 "$CLOSED_SHA" \
  --target "$ORIGINAL_TEST_TARGET" --evaluator "$ORIGINAL_EVALUATOR" \
  --scratch-bytes "$COMPLETE_SNAPSHOT_ALLOWANCE" --output "$PRIVATE_REPORT"
```

Use `--outcome improvement` for the separate offline outcome; declarations must
match. Instantiation reads current task/material manifests and program source,
not authentic arrays or checkpoints. The internal `execute` composition would
perform full input inspection only after actual owner admission and
qualification, then call the unchanged concrete provider; its current public
CLI is deliberately unavailable.
There is no supplied-prediction shortcut to `execute` and no host fallback.

`runtime.json` has exactly `schema="smc_restricted_runtime_v1"`, the immutable
existing `image`, explicit `docker_binary` and local `docker_socket`, a
`qualification` descriptor `{path,bytes,sha256}`, and finite whole-pair
`source_read_bytes`/`host_write_bytes`. The separate operator qualification must
bind this exact source descriptor, image inventory, both fixed profiles and the
restricted entry. This static evidence is separate from the unavailable actual
controller/owner integration. Its
`generic_base_image_without_task_assets_qualified` predicate means
the exact same base image contains only admitted generic dependencies: no task
paper/data, author source, official released assets, participant programs or
declarations, predictions, operator test targets or extra pretrained models.
This prevents assisted content leaking to the paper-data arm through image
layers. Exact image-inventory qualification is external evidence, not a boolean
that participant metadata may grant. No accepted qualification file is included
or inferred from prior tasks.

## Closure and grading

Within the implemented source composition, the provider journals resource intent
before creation, verifies exact image,
environment, mounts and namespace/resource settings, retires the producer before
opaque capture, closes its holder/volume, and returns a pinned receipt. The
adapter re-observes that receipt, checks complete output membership, makes rates
read-only and creates the existing v2 prediction freeze. Both phases must finish
before `PAIR_CLOSED.json` exists. A failed condition is terminal; no partial test
score is emitted and no replacement/retry is automatic.

`grade` rechecks both source commitments, both complete closed receipts and all
captured rates before the first private scorer call. An exclusive grade-start
record enforces one final grading operation. Intermediate numerical reports stay
inside a private temporary directory; only a successful complete paired report
is published, mode `0600`. Its reproduction branch retains all eight source
findings per condition and signed/absolute reference discrepancies. Improvement
retains the single offline four-vector and strongest retained SMC reference,
with LFADS/NDT and broader-SOTA interpretation separate. No arm/metric averaging,
binary tolerance, invented win, fidelity proof or AI attribution is added.

Normal provider cleanup is implemented; abrupt operator death is a separate
unqualified boundary. Its existing parent-recovery API requires independently
proven controller closure and pinned ownership. This adapter does not fabricate
that evidence or substitute a new isolation backend. Such qualification remains
required before this route can be admitted for actual episodes.

The source controls use small generated complete HDF5 files and a mocked
container/qualification boundary. They may validate dispatch, closure ordering,
freezes and the real original scorer, but cannot qualify Docker, runtime image,
CPU/PID enforcement, author compatibility, or forced-stop custody.
