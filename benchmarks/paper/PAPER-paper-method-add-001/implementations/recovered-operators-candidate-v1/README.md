# Prospective candidate comparison through recovered NoMAD grading

This self-contained successor permits one independently frozen prospective candidate alongside literal author NoMAD and the other original F3/F4 controls. It preserves both complete directed session panels: 380 isometric pairs and 132 reaching pairs. With four historical controls plus one candidate, the archive contains 2,560 query slots and 160 method-specific within-day anchors (2,720 total). The candidate contributes 512 query and 32 anchor slots.

The trusted API remains `operator_entry.run_operator(root, request_path, request_sha256, *, source_read_limit)`. It captures the pinned 19-body source closure and request, uses the existing bootstrap and actual archive/pretarget/grade path, and computes the unchanged pooled variance-weighted R². The CLI remains source inspection only. It is not a candidate-facing target service or authority issuer.

The complete generated sizing request measured 1,480,395 bytes. This successor therefore admits requests up to 2 MiB; each source member remains capped at 1 MiB and cumulative source/request capture remains capped at 16 MiB. The original v3 caps and bytes are unchanged. Any later runtime-binding refresh must fit the successor cap and receive its own recorded request pin before grading.

## Candidate selection

The existing captured fact selection may bind a prospective `candidate_arm` record with exactly:
- `schema: nomad_f3_f4_candidate_arm_v1`;
- `method`: one bounded ASCII identity distinct from every historical method label;
- `baseline_method: NoMAD`;
- `scope: [F3_F4/isometric, F3_F4/reaching]`, in that order;
- `profile_pin`: the independently selected bytes/SHA256 pin matching that method's existing `method_profiles` entry;
- `anchor_policy: candidate_scoped`.

The same captured supports must contain the candidate's query product in every original pair and all 20/12 candidate-scoped within-day anchor identities. Author and candidate product IDs remain distinct. Equal prediction bytes are permitted with truthful separate lineage; there is no automatic author-anchor alias mode. A captured declaration or checksum does not establish native production, historical authenticity or scientific authority.

The candidate is added to operational archive membership only. Historical contrast definitions, all 102 source test slots, original-mode quantile/statistical holds, and false qualification flags remain intact. Candidate products in other historical groups or collisions with historical method labels are refused. Existing complete target-array/support matching applies to every arm.

## Results and limitations

`statistical_outputs.candidate_comparisons` contains two ordered panels with every candidate/author pair, exact candidate-minus-author differences and retained unavailable values. Candidate or author anchor failures prevent a complete panel status. Original control summaries and historical tests remain separately present. No candidate p-value, aggregate superiority criterion, confidence interval, new metric or paper-win decision is introduced.

The grade path consumes supplied frozen predictions and lineage bytes. It does not run or attest a native model, prove original process custody or establish target-hidden training. The existing checkpoint consumer can bind actual supplied states/decoder artifacts under independent selection; the generated fixture makes no such native claim. Authentic source support, preprocessing, source-author replay, model/data rights, uncertainty, meaningful effect and scientific budgets remain unresolved.

The original recovered-operators-v3 package, historical files and their pins are preserved. All numerical kernels and original source_data bodies are unchanged. SOURCE_MANIFEST.json is the sole runtime body authority for this successor; there is no candidate-specific parallel manifest or new execution helper.
