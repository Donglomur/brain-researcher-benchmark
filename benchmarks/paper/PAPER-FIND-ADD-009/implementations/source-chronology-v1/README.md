# Published decoder chronology recovery

This component recovers all 14 rows of the original Supplementary Table 1 and reconciles them with the pinned author demonstration configuration. It supplies missing source evidence for both **paper reproduction** and **same-task improvement**, as separate future outcomes. It does not grade either outcome.

The executable checks the exact PDF and two author configuration hashes before invoking Poppler, captures the bytes once, parses the complete table without dropping rows, preserves its reported interval alongside the independently computed date difference, and emits a sanitized factual report. It does not load neural recordings, acoustic targets, checkpoints or historical solver answers. Existing evaluators and task contracts remain unchanged.

From the repository root, use locally retained official source files:

```sh
python3 benchmarks/paper/PAPER-FIND-ADD-009/implementations/source-chronology-v1/recover_chronology.py \
  --supplement-pdf /operator/source/supplementary-table1.pdf \
  --training-config /operator/source/config.yaml \
  --session-config /operator/source/training_data_args.yaml \
  --output /operator/output/recovered-schedule.json
```

The three `/operator` paths are examples, not distributed files. `pdftotext` must already be installed; `--pdftotext` can select its executable. The command performs no network access and will not overwrite an existing output. It needs Python 3.9 or later and the standard library. Source versions other than the recorded hashes are rejected rather than silently accepted. The committed [recovered schedule](recovered_schedule.json) was generated by this command from the authentic sources and visually checked against the table PDF.

Important findings and the remaining binding work are in [SOURCE_FINDINGS.md](SOURCE_FINDINGS.md). Source URLs, bytes and content hashes are carried in the generated report; the PDF and acquisition receipts remain outside Git.

Tests use a small numerical table fixture and modified inputs. They check full extraction, row ordering, missing rows, malformed counts, impossible future training dates, preserving the published discrepancy, and rejection of unknown bytes before process launch:

```sh
python3 -B -m unittest discover \
  -s benchmarks/paper/PAPER-FIND-ADD-009/implementations/source-chronology-v1/tests -v
```

During the parallel construction wave, run all Python, source parsing and tests through the coordinator's shared test pool. Eight controls passed; one source execution recovered all 14 rows and the 36-session author-demo roster. These are software and source-recovery results, not authentic neural-data preparation, author inference, scientific reproduction or improvement.
