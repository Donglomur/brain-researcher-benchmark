## Closed view and artifact ABI

`views.compile_views(full_document, expected_materials_identity, expected_panel_identity)` authenticates a detached snapshot of the complete selected packet before producing either view. The return value's `info` is private operator metadata and must not be mounted into a participant.

`development` contains exactly the original 534 development shards, original development labels and 8,034 events. `test` contains exactly 1,803 globally opaque single-epoch shards, no labels, no subject/run identity, and no original within-run order. The private mapping remains with the existing evaluator. Each data directory contains only:

- `view.json`, serialized as canonical JSON plus a newline;
- `positions.json`, with the existing exact original geometry pin;
- that phase's complete `signals/` membership.

`data_mount` creates a closed directory descriptor and `validate_mount` checks its exact pins and membership. These functions do not materialize directories or authenticate physical files. The existing Provider performs metered closed-tree/body authentication, including rejection of extras, symlinks and changed bytes. A full combined original packet cannot be substituted for the development directory.

Development mounts `/input`, `/paper/paper.pdf`, `/common`, `/candidate/develop.py`, plus `/official/code.tar.gz` in B. The participant writes exactly `RESULT.json`, `selected.py` and `model.bin`, declared by `OUTPUTS.json`. Development's result is:

`model.bin` is an opaque selected artifact, not necessarily a Torch file. `selected.py` must be self-contained with respect to the selected immutable image and this artifact; it receives no development workspace or common pretrained directory during inference.

The owner independently rereads the Provider receipt, checks natural exit, all three resource closures, unchanged inputs, original clock and exact output membership. The prospective full read/write charge is debited before copying and retained on failure; partial failures remove only the owned staging tree. ## Protected chronology and campaign barrier

The trusted operator constructs each `Episode` from the independently selected full-packet/panel identities, an episode ID, the original monotonic origin/deadline, profile/declaration, and separate fixed development/inference resource dictionaries. `CampaignBarrier` receives an externally adopted roster of exact episode IDs and roles that includes both A and B. This source does not adopt the earlier provisional fit schedule or authorize a campaign budget.

1. Register every planned exact Episode object before development starts. Pairing checks equal original data, views, profile and both phase resource budgets.
2. Call `develop_and_freeze` once per episode with one exact pinned Provider per episode. Ordinary execution currently refuses before dispatch because a qualified scientific GPU provider is unavailable.
3. Seal only when every planned episode has captured and frozen its selected code/model. All actual image digests must match. Provider objects and control/quarantine roots must be distinct and non-nested.
4. Run one complete `run_inference` phase per episode, using that episode's original Provider, unchanged caps and cumulative read/write counters. The independently approved held-exposure entry may be appended only after the captured artifact hashes exist; old registry mappings cannot change. The existing Provider still authenticates the exact approval body, image, mounts and resources. A registry entry is not GPU qualification.
5. Release predictions to the private evaluator only after **all** declared episodes complete. Failure prevents partial-campaign release; there is no automatic retry, development reopening, artifact replacement or JSON resume path.

The barrier covers this exact independently admitted roster. It is not evidence about all future experiments. The existing campaign owner must admit and account the sum of episode budgets; distinct per-episode Providers do not create a global compute or agent-token budget. Trusted Python state is not a sandbox for malicious operators and is never mounted into the participant.

`complete_predictions()` returns a mandatory wrapper with `release` and `predictions`. The release binds the exact prediction-file pin to the profile/declaration, artifact, design, episode, material and roster identities. Both scientific qualification and current paper-win qualification remain false. The prospective profile is explicitly marked as requiring a separate outcome binding. Downstream private restoration must preserve this release binding; discarding it is not a supported route into the current outcome. Shared outcome-binding integration is future root/integrator work.

## Finite cost and remaining execution work

For one complete held panel, the practical route creates and retires two containers and one volume, with at least 40 Docker CLI calls and two archive GETs under the existing Provider. A genuine Linux/GPU Provider and immutable scientific image remain required, with demonstrated device custody, process/resource closure, CUDA/Torch/backend parity, bounded outputs and original-clock/cumulative accounting. The reused CPU-only Provider rejects GPU exposure. The unrelated `toolchain229045` image is not a scientific GPU image. Native refits, real candidate execution, paired source/access provisioning, hardware envelope adoption and outcome qualification remain unperformed.
