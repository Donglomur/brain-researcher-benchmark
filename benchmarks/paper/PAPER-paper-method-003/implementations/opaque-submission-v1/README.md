# REVE opaque submission composition

This is a task-specific **source composition**, not a finished protected runner.
It connects the existing complete participant manifest and prediction format to
an existing owned Docker provider's request, capture and observation interfaces.
No REVE Linux/GPU installation or paired scientific budget is selected here.
The ordinary `run()` entrypoint therefore raises `RuntimeUnavailable` before
provider construction, file access or native side effects. Caller booleans and
arbitrary backend objects cannot enable it.

The previous [material exporter](../candidate-materials-v1/README.md), source
panel, private mapping, four-class scorer and scientific contracts are unchanged.
The full original cohort remains 109 people/654 recordings/9,837 epochs, split
6,300 training, 1,734 validation and 1,803 test epochs. This artifact does not add a
task, qualify a model result or resolve the historical preprocessing/checkpoint
and run-aggregation gaps.

## Implemented seam

- `packet_info` authenticates the selected material/data identities and validates
  all 2,337 public signal records, original training/validation roster and labels,
  single-epoch opaque test metadata, class order, paper and geometry declarations.
  `pair_info` requires identical data, labels and test order across both access
  conditions; the official research archive differs as declared.
- `packet_mount`, `common_mount` and `paired_requests` compile the existing
  provider ABI for roles A/B and `held_attempt`. They describe only `/input`,
  `/candidate` and `/common`. The packet descriptor lists every file; no parent
  operator directory, target file or private map is mounted. The existing
  provider, if separately qualified and invoked, authenticates every listed file
  before and after execution. Request construction itself reads no signal body.
- Both requests use one immutable image, shared usable pretrained encoder assets,
  and identical resource operands. The common package explicitly contains the
  pinned released encoder, configuration, encoder runtime and source declaration;
  providing usable common encoder support is part of the proposed access design,
  not hidden author-code access. Its actual deployment remains unselected.
- `_compose_owned_phase` is the internal, trusted operator composition seam.
  It accepts only the exact pinned provider class, invokes `execute_phase`, and
  independently re-reads the provider receipt through `observe`. Collection
  requires matching role/image/request/input/resource identities, natural exit,
  three distinct observed resource closures and successful CLI custody records.
  Its installation gate also refuses before dispatch until a real qualified
  deployment is bound. These engineering checks do not confer qualification.
- Captures contain exactly `OUTPUTS.json` and `RESULT.json`. The former uses the
  provider's generic envelope, including exact phase/request and result hash.
  The latter is the unchanged `reve-candidate-predictions-v1` object with the
  selected `materials_identity` and exactly 1,803 opaque events. Each event has
  one class 0–3 or four finite scores; duplicate, missing, extra and malformed
  rows fail. Additional collection reads debit the original provider allowance.
- `restore_private` captures the collected result once, authenticates those bytes
  against `collected.result_pin`, and passes that exact immutable snapshot into
  the shared private inverse-ID restoration kernel. It never reopens the result
  pathname after authentication. Replacing or removing that pathname after the
  completed capture cannot substitute new predictions. It reads no target labels
  and calls no scorer.
  A future admitted operator must budget and supervise this private continuation;
  it is not an alternative execution-authorization path.

The helper APIs are available for source composition and trusted metadata
construction. Both dispatch entrypoints enforce the same closed installation
gate. Synthetic receipts and test-only patches do not constitute a qualified
deployment or an authorized campaign.

## Existing provider, exact limits

The implementation reuses the complete seven-file package at
`benchmarks/neural/NEURAL-007/implementations/whole-night-programme/program/vendor_transport`.
Its source manifest is pinned to
`93df92be5b388f4b2896805c8e02f0c41f301d1c86e6b06709444c1075ade0e4`;
every member is authenticated before import. The original material module is
pinned to `42aa46b557155e1977cc614c617552738a93a63f3de39ff0d2b2569d6e27015f`.

That provider requires Linux `pidfd` signaling and `/proc` process identity. It
uses an existing immutable local image, no image pull, nonroot execution,
read-only host mounts, no network, bounded scratch/output, and capture after the
producer is removed. It expressly rejects GPU `DeviceRequests` and returns
`qualification_inherited=false`. This CPU-only source cannot represent a
qualified GPU recipe. Its exposure-selection boolean is not independent runtime
proof. A real deployment also needs a qualified sterile host Docker environment
and credential-free image; the adapter does not infer those from source hashes.

Before/after hashing of the two existing packet trees alone reads at least
16,132,519,558 bytes, plus program/common assets, source, metadata and output
reads. The provider also has a 128 MiB/one-CPU holder and private shared-memory
overheads separate from the producer. Request fields must include those
engineering costs; a preparation wall/RAM limit is not a scientific model budget.

## Scientific policy remains separate

The released PhysioNet configuration uses batch 32, a 20-epoch linear probe and
five-epoch fine tuning; its ten Optuna trials are not a historical seed roster.
The paper's 260 A100-GPUh estimate concerns pretraining. Neither specifies a
qualified downstream CPU budget or an LLM/agent budget.

The external scientific proposal keeps equal usable encoder access, full data,
validation-only selection and budgets fixed before either outcome. Its proposed
repetition/search schedule is a new design choice. Hardware, GPU/CPU/wall/RAM,
agent limits and scientific acceptance still require separate adoption. This
artifact changes neither `outcomes.v1.json` nor reproduction/improvement rules.

The minimum next runtime work is a genuine Linux/GPU provider installation with
reviewed GPU device/resource ownership, an exact image and sterile endpoint,
independent process/boundary/refusal evidence and an adopted paired budget.
Reference qualification separately requires the complete native four-class
downstream classifier, or an explicitly declared validation-only refit protocol.
The released encoder does not supply that classifier, and a refit would not
authenticate the historical Table 12 checkpoint or seed/SD lineage.

## Generated controls

From this directory:

```sh
python3 -I -B tests/test_adapter.py
python3 -I -B tests/test_captured_restore.py
```

Thirty-eight methods exercise full 9,837-event metadata, exact paired requests, access
and output refusals, a real existing-provider metadata observer, and all1,803
distinct-value inverse joins through the unchanged original restorer. Provider
execution is replaced by an explicitly inert fixture; no Docker process, array,
model, authentic target or scorer is used. Fixture clocks/resources validate the
code ABI only. They are not proposed scientific limits.

The first local suite passed 29 methods and correctly refused a fixture placing
private restored output beside its participant manifest. The fixture placement
was corrected and the affected full observation/restoration method passed.
Unchanged passing methods were retained; later metadata, read-budget and
independent-review fixes are covered by focused controls. Generated write accounting preserves
the first failure rather than erasing it.

The ten captured-restoration controls cover all 1,803 generated event IDs with
class and distinct score outputs, exact parity with the path API, replacement or
removal after the original capture context has closed, malformed/bounded JSON,
wrong pins, identity and membership refusals, and the unchanged closed runtime
entrypoints. They use no arrays, targets, models or provider dispatch. The current
release-restoration component retains its separate context and postflight checks;
this repair maintains the documented standalone helper rather than replacing it.

`SOURCE.json` and its original control history retain their construction-cutoff
identities. Current executable pins and CI bind this maintenance revision;
no earlier evidence is relabeled as validation of these changed bytes. These
controls establish source behavior, not hostile-host isolation or model quality.
