# BaRISTA six-endpoint classification scorer

This component fixes a concrete gap between the current paper-improvement contract
and the preserved classification scorer: the latter accepts `improved` predictions
only for chronological tasks and computes one four-task pooled summary. This scorer
also accepts the candidate on both main random-nonoverlap tasks and reports each of
the six original classification endpoints separately. It does not change the
registered task, existing runtime, source splits, model controls, or source files.

It is an executable classification component, not a qualified benchmark or a full
paper improvement result. Authentic arrays, exact saved source splits, competent
reference executions and reference provenance have not been supplied or run here.
The remaining reconstruction, pretraining, exposure, scaling, interpretation and
architecture branches in `improvement.v1.json` are still required. No source model
is imported or run by this component.

## What is preserved and added

The unchanged prepared `barista_public_panel_v1` fixes all 770 contexts, seven
people (1, 2, 3, 4, 6, 7, 10), source query commitments, both information arms, five
finetuning seed slots and five chronological fold slots. Slots 1–5 correspond to
the documented native training seeds 0–4; random fold 0 is the one original
partition. This scorer never generates or repairs a split.

Every context retains nine encoding/masking combinations, three random controls,
PopT/BrainBERT and Brant. Adding the candidate to all contexts gives 23,100 arrays
across both arms: 21,560 source companions and 1,540 candidate arrays. The old
22,960-array submission is deliberately insufficient because it lacks the main
candidate outputs. The 140 added arrays are source-condition candidate results,
not extra tasks or additional participants.

| Protocol | Endpoints | Cells per endpoint/model | People |
|---|---|---:|---:|
| Random nonoverlap | sentence onset; speech/non-speech | 7 × 5 = 35 | 7 |
| Chronological | sentence onset; speech/non-speech; volume; optical flow | 7 × 5 × 5 = 175 | 7 |

Per-query ROC-AUC retains the predecessor's exact pair-ranking/tie treatment and
undefined single-class behavior. All source cells and 84 companion endpoint/model
summaries per arm are returned. Each candidate endpoint includes absolute AUC,
independent-reference AUC and paired gain, both over the source 35/175 cells and
after averaging repeats within each of seven people. Individual person results
remain available for a future predeclared inference procedure. No task can hide a
regression in another task through an aggregate primary score.

The reported SEM uses the predecessor's disclosed sample-SD/sqrt(n) convention;
historical SEM implementation parity is not established. Repeated folds and seeds
are not independent people. The seven-person descriptive SEM also does not settle
shared-movie dependence. There is no confidence interval, significance claim,
minimum effect, simultaneous success rule or paper-win decision.

## Operator inputs and execution

Use a fresh dedicated interpreter with the existing NumPy dependency:

```sh
python3 -I -B score.py --public /operator/PUBLIC.json \
  --gold /operator/GOLD.json --submission /candidate/SUBMISSION.json \
  --out /operator/new-result.json
```

Paths above are illustrative. The scorer reuses five exact predecessor bodies,
with their SHA-256 hashes embedded in `score.py`. It refuses changed bodies and
foreign preloaded generic modules. These checks establish dependency identity,
not a runtime sandbox or custody of already-imported memory.

`SUBMISSION.json` contains exactly:

```json
{
  "schema": "barista_endpoint_submission_v2",
  "task_id": "PAPER-paper-method-replacement-008",
  "panel_id": "the bound public panel hash",
  "predictions": []
}
```

`predictions` is the complete order generated by `outputs(public)`: arm, original
context order, then the original fourteen models followed by `improved`. Each
entry is `{id, arm, model, query_ids_sha256, values}`. `values` has the existing
primitive NPY descriptor `{path, bytes, sha256, shape, dtype}`, a single relative
filename, and finite float32/64 class-one probabilities on every query. Byte bounds
remain 32 MB for JSON, 4 MB per array and 512 MB over declared candidate arrays.
Repeated references count toward the byte allowance. Every candidate and companion
array must pass admission before the gold manifest or private numerical inputs
are opened. Arrays are hash-checked again when used.

The operator-owned `barista_endpoint_gold_v2` manifest contains exactly
`schema,panel_id,public_sha256,baseline_model,contexts`. `public_sha256` binds the
exact bytes of PUBLIC.json, and `baseline_model` must be
`barista_parcels_channels`. Each of the 770 ordered context records contains
`id,query_ids_sha256,labels,trusted_parcels_channels,provenance`; both arrays use
the same primitive descriptors and exact query shape. Labels are complete binary
integers/bools. Provenance has exactly these SHA-256 fields per context:
`program_sha256,training_config_sha256,checkpoint_sha256,exposure_audit_sha256,execution_receipt_sha256,baseline_artifact_sha256`.
Context-level provenance can bind the different trained states, seeds and folds;
it never implies that one global checkpoint produced the entire panel.

Reference predictions must be independently produced and validated by the trusted
operator. A candidate-declared `barista_parcels_channels` companion is scored as a
companion and cannot replace this reference. Hash syntax is not execution
authentication, model identity proof or an exposure audit. The scorer marks those
claims unestablished even when the numerical output is defined. No gold converter
fabricates the missing 70 main reference contexts from the old 700-context
chronological reference. Existing participant isolation requirements still apply
across folds, seeds, protocols, related tasks and arms.

## Source basis and boundaries

- [Original manuscript](https://arxiv.org/html/2512.12135v1), Tables 1/2 and 16/17:
  distinct main/chronological tasks and 35/175-cell reporting; the local preserved
  improvement contract and source audit were read for this implementation.
- [Pinned author training code](https://github.com/ShanechiLab/BaRISTA/blob/83b27375eba60e9eba9da4e7dd8fb283baace376/barista/train.py):
  positive-class softmax ROC-AUC and validation checkpoint selection.
- [Pinned original aggregator](https://github.com/ShanechiLab/BaRISTA/blob/83b27375eba60e9eba9da4e7dd8fb283baace376/barista/utility_scripts/aggregate_runs.py):
  available-cell rounded reporting does not certify complete manuscript summaries.
- Preserved `registered-runtime/source/classification/private/design.py`,
  `metrics.py`, `score.py`, `bind_gold.py`, public task and source audit provide the
  exact existing transport, model grid and the missing-main-candidate counterexample.
- Existing metadata/localization source audits were consulted; no new raw source,
  target, checkpoint or prediction bodies were accessed. Metadata correspondence
  does not authenticate original waveform columns, complete preprocessing or saved
  folds. No prior blocked acquisition was repeated.

`test_score.py` uses only tiny invented arrays and complete generated identity grids.
Its full file-route test preserves every control, demonstrates a main-task regression
alongside five positive endpoints, and verifies independent reference use despite
perfect candidate-declared companions. Its final-array failure test supplies a
nonexistent gold path, establishing refusal before evaluator access. Additional
controls cover missing main predictions, endpoint identity/repetition, undefined
support, independent pairwise AUC, reference swaps and seven-person aggregation.
These are software controls, not model performance or native parity.

Run tests only through the shared two-slot pool specified in the work-wave policy.
No dependencies were installed, sources downloaded, models fitted, paid APIs used,
or scientific trials run for this component. Integration into a registered operator
or canonical contract is a separate centrally owned change.
