# NuCLR metadata reader with explicit source order

Canonical JSON sorts object keys. The frozen `native-inputs-v1` producer correctly preserves source row order in `projection.metadata`, `ordered_ids` and native-address lists, but its reader reconstructs the join from `label_map` dictionary iteration. Reopening the sorted JSON changes that iteration order and rejects otherwise matching documents.

This additive reader derives order from the author's explicit `projection.metadata` row list. It requires unique IDs covering the label map exactly once, restores only an in-memory mapping in that order, and compares the result of the unchanged v1 join against every stored panel. No source document, array, fold, label or published component is modified. The original E/I inductive refusal remains. Historical route/order flags and all nine panel records remain visible.

`NativeInputs(owner_root, file_sha256=...)` requires trusted expected SHA256s for `COMPLETE.json`, `native-manifest.json` and `joined-panels.json`. Exact file digests include the trailing newline; canonical document digests used inside COMPLETE are checked separately. Only these metadata files are read by construction. A complete saved-output verifier must separately authenticate the exact 257-member file inventory and content hashes, ordinary paths, the original raw archive identity and the failed attempt's provenance. Metadata validation alone does not establish that asset custody.

`validate_documents(manifest, joined, completion)` is the lower-level metadata boundary for generated controls. It does not authenticate files or elevate generated documents to authentic inputs. `restore_source_order(projection)` preserves labels and folds while restoring the explicit row order. Neither function performs model fitting, prediction or scoring. Later `native_addresses` and `read_block` operations delegate to the unchanged pinned v1 functions, including their original block hash and geometry checks.

The fixed source is commit `492095676c8b60f361c3263af8b1d7868b43d782`. Reader policy is `nuclr_source_metadata_row_order_reader_v2`. The original failed attempt and its outputs remain evidence; selecting this reader does not retroactively turn its exit code into success. Any acceptance of existing prepared inputs requires a separate verifier receipt. Current-source construction, historical paper reproduction and scientific improvement remain distinct.
