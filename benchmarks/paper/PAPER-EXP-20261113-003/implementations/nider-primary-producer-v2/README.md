This newly authored owner-side collector produces the existing 120-field representation of the three original DL model objects for Table 1 / Extended Data Figures 1–3. It is not recovered `extended_reference.R` or `author_reference_core`, and the 120 fields are not 120 values independently published in the paper. No authentic model has been fitted or numerical reference generated during this construction.

The complete selected primary still requires the source-defined forest rows/weights, original Bayesian inference, task-required sensitivity/dependence work, and independently qualified scientific agreement. This component does not establish complete-primary reproduction, same-result superiority, a model trial, native neural interpretation, or benchmark readiness. The unchanged comparator's reporting bins/counts are engineering policy, not a newly justified overall scientific acceptance rule.

## What the producer does

`replay_primary_dl.py` authenticates the original workbook, official R script and original lock, plus the unchanged sibling field schema, output interface, comparator and strict decoder. The historical eight-column delivery projection is not admitted as the original workbook. It stages exact bytes in a private temporary root, starts a fresh `Rscript --vanilla`, and validates the completed output through the existing comparator. The scientific full120 submission is capped at 65,536 bytes. Prior outputs are never overwritten.

`replay_primary_dl.R` checks R 4.3.2 and installed package versions, including every loaded non-base dependency against the original lock. Missing or different packages fail; there is no installation, restoration or network fallback. `jsonlite` 1.8.8 and `digest` 0.6.35 are serialization/custody dependencies already pinned in that lock. Package versions, locale, session information, R executable hash, caller-supplied runtime/image identity, actual settings, commands, source hashes and implementation hashes are recorded separately from the scientific output. The supplied identity is an external owner admission label; it does not itself attest to an image or authorize computation.

The unchanged official script is parsed with source references. Only 23 complete top-level expressions are evaluated: libraries 13–19; input 28–29; duplicate merge 73–75; label processing 77–82, 86–129, 131–138 and 140; mask 141; and subset/call pairs 149/153, 216/219, 262/265. The full-file and selected-expression bytes are checked. The `here` workbook resolution is verified before `readxl` reads it. The driver never sources the official file, so the participant CSV reads at 470/474 and unrelated analyses do not run.

`collector.R` only collects already-created native models. It preserves all 40 fields per contrast, native NA/NaN/infinity states and tau interval signs; applies `tanh` only to the six explicitly named correlation-scale fields; and keeps standard errors, heterogeneity measures and fractional I² on their declared scales. Native counts follow the package's missingness rule. It verifies source-order membership, model/data/subset alignment and the contrast-specific n column. Morawetz2016b retains its first ordinal and both original row ordinals. Source-row ordinals and sample-size sums do not establish independent cohorts or unique participants.

The reference producer has the official source available for either arm. `--arm A` or `--arm B` supplies interface identity; it does not create or demonstrate distinct participant information conditions. The prior full120 route supplied method assistance to both historical arms. A future unassisted paper+data condition needs its own frozen delivery boundary.

This is an owner/reference producer. Its authenticated author-script input and analysis recipe must not be shipped as a participant tool or input to the paper+data arm. Arm labels in serialization do not enforce arm isolation. This namespace makes no task packaging or admission changes.

## Future owner execution

Native execution requires separate authorization and an admitted, already installed runtime. Keep original inputs, numerical outputs, rejected output evidence and provenance outside public Git. This command has **not** been executed:

```sh
python3 -I -B replay_primary_dl.py \
  --original-workbook /private/original-studyInformation_publication.xlsx \
  --official-script /private/original-s3_RmetaAnalysis.R \
  --renv-lock /private/original-renv.lock \
  --rscript /admitted/runtime/bin/Rscript \
  --runtime-identity 'owner-admitted-runtime-or-image-identity' \
  --arm A --output /private/full120.json --provenance /private/run.json
```

The launcher removes inherited R startup/library/renv environment hooks and sets numerical thread counts to one. Packages must be discoverable in the admitted runtime's default library paths. The 180-second launcher deadline is a software bound, not scientific execution approval or an OS RAM limit. Any changed execution budget needs the owner's native protocol. It does not automatically retry.

Timeouts, launch failures, native nonzero exits and rejected output retain failure provenance. Streams and rejected native files are retained as base64 with full length/hash and explicit truncation beyond 1 MiB each; these private records can contain scientific values. No success output is published after those failures. Successful provenance is written last: consumers must verify both files and their matching output hash and `output_published` flag. If provenance publication itself fails, any retained output remains incomplete, unadmitted evidence.

The 1 MiB limit bounds each retained artifact prefix, not subprocess pipe memory or whole-file reads. This launcher is not a hostile-process memory sandbox.
