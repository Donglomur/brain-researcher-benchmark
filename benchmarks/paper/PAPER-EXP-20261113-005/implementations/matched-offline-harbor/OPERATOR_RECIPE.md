# Paired delivery operator recipe

These are future stage instructions, not an authorization or report of a native
run. Examples are deliberately unselected. Use the existing bounded owned caller
and its independently reviewed Docker/Compose/runtime admission. This component
adds no generic process executor. Keep every failed/partial outcome; use fresh
roots instead of retries into a previous namespace.

1. **Acquire and verify the exact existing inputs.** The sibling component
   `pfc-science2-package` supplies `SOURCE_MANIFEST.json` and `task/`. Its manifest
   must match the vendored 4,878-byte SHA256
   `914881559f331bf06192aebe5fd894b2a53f7ece5e8067101256c0ae637b3b97`.
   Obtain the four assets through the published release URLs in
   `TASK_PROJECTION.json`; retain the four exact notices from that release.
   `PUBLIC_INPUTS.json` preserves lineage, licenses and scientific scope.
   Do not put reference answers, private provenance or evaluator reports in the
   asset root. The materializer checks the complete namespaces and all bodies.
2. **Materialize once into a fresh root.** After selecting the complete read/write
   budget, fill a new true request from the false template and run
   `python3 -I -S -B paired_materialize.py MATERIALIZE.selected.json`.
   The fixed shared-base identity is
   `sha256:9aaf44dc64d85d0bbb0ffdd75ff5190ad94eff91d76849d14aea859c930955ff`.
   This does not create or admit any image. Four packet copies in the complete
   pair account for about 21.5 MB; authentic materialization is not included in
   the lightweight source-control run. The implementation caps managed reads at
   64 MiB and task-file retention at 32 MiB, plus bounded manifest metadata.
3. **Admit the exact complete task images and stock Harbor dependencies.** Use
   only complete `A/.../environment`, `B/.../environment` and either identical
   `.../tests` contexts. Bind all three resulting immutable configuration IDs to
   the exact materialized file manifest and accepted base. Inspect stock helper
   and egress-sidecar availability through the separately selected native stage;
   an absent image is not permission for an automatic pull or build. Do not reuse
   the base as a complete task image. Keep Docker CLI/Compose/socket/daemon and
   host Harbor interpreter identities distinct from the Linux image runtime.
4. **Qualify actual access before model use.** In fresh native environments prove
   both arms have identical common paper/data/schema/tools and limits; A lacks
   `/official/category_matching.py` and `/official/LICENSE`; B has their exact
   public bytes. Verify absence of protected solution/scorer/reference material
   and writable shared candidate state, including hidden extra mounts or image
   content. Check no public network access in both agent and verifier using the
   installed stock no-network implementation and admitted helper; do not infer
   isolation solely from TOML. Verify the clean verifier cannot run candidate
   programs. Run the same authored oracle in both conditions and require the
   unchanged complete 69-case scores to match the accepted endpoint before any
   delivery-readiness claim. These native operations remain unperformed here.
5. **Prepare one matched pair.** Select an exact agent/model configuration and a
   fresh full 64-hex nonce, complete-image IDs, pinned `PAIR_MANIFEST.json`, and
   fresh output root. Run
   `python3 -I -S -B pair_sessions.py prepare SESSIONS.selected.json`.
   Use an actual built-in model agent for experiments; an `oracle` pair is only
   authored-baseline qualification. Keep A/B model/provider version, tool support,
   time/token budget and initial prompt equal. No custom resume/MCP/environment
   kwargs are permitted by this profile. If stock default model options cannot
   support a prespecified matched study, review a source successor first.
6. **Run the two original sessions through the existing owned caller.** Each
   literal command is `harbor trials start --config <arm config_path>`. Use the
   admitted off-PATH Harbor executable; set `PYTHON_DOTENV_DISABLED=1` before
   import, independent HOME/TMPDIR from the plan, and the previously admitted
   private Docker configuration/socket. Provider credentials remain external and
   must not be written into task/config artifacts. Do not add hidden instructions,
   network overrides, mounts, retries or shared candidate history. Keep both
   `verifier.disable=true`; use no pre-verification collection hooks. Withhold
   evaluator feedback from both sessions until both original episodes physically
   close and freeze. A/B order should be preregistered or counterbalanced across
   independent pairs, not interpreted as a new case.
7. **Freeze both closed complete trials.** The existing owner must establish
   complete process/container closure before asserting `closed_arms=["A","B"]`.
   Run `python3 -I -S -B pair_sessions.py freeze FREEZE.selected.json` with the
   exact pinned plan and fresh freeze root. The source caps each consumed trial
   at 256 MiB and 512 entries, individual files at 128 MiB, streamed combined
   copy/readback at 1 GiB and metadata reads at 8 MiB. These future budgets need
   separate capacity planning; they are not selected by source publication.
   Retained transcript contents may include private material and are local
   evidence, never automatically public. Partial freeze creates no regrade
   configurations and must not be promoted.
8. **Regrade frozen copies, then report.** Only after `FROZEN_PAIR.json` is
   accepted may the existing caller execute the two emitted stock regrade
   configurations. Both use the same separate verifier and unchanged scorer.
   Preserve complete native results, process/container closure, arm failures,
   cases and family scores. Report one benchmark and two access conditions,
   followed by authentic qualification and model-study status separately.

The control suite proves source behavior on invented fixtures. None of the
native admission, isolation, artifact transport, oracle matching or model-study
claims above can be replaced by that source-only result.
