# Original fold membership and response bridge

This owner-only component connects the existing original-row scorer to all **390 source-context fit units**: thirteen original sessions, ten source-order trial folds and three training contexts. It does not use the earlier prospective held-mouse split. The complete original 117-cell error vector is preserved; no scalar paper-win rule is introduced.

`build_plan(owner_index, secret_key)` validates the full native-index export using the pinned sibling `original-row-score-v1/scorer.py`. For every fit, it records the source-context calibration row membership and every held-fold query row. All query contexts remain, including folds that contain fewer than three test contexts. Each query receives a fit-specific opaque HMAC identifier. `validate_plan` independently reconstructs the whole plan; rehashing a truncated plan cannot make it valid.

`assemble_predictions(owner_index, plan, secret_key, responses, run_receipt_sha256)` requires exactly one complete response for every fit. It rejects missing, duplicate, replayed or cross-fit row identities, different plan bindings and noninteger predictions. Response order does not affect the reconstructed original row order. The resulting artifact is checked by the existing scorer and can be passed to its unchanged `score` or `compare` functions.

Each response has `schema: structured-original-unit-response/v1`, the frozen `plan_sha256`, one `unit_id`, and a `predictions` list of `{query_id, time_bin}` records. `response_template` exposes only opaque IDs and the response binding. It contains no neural features and is **not a participant packet**. The complete plan, owner index, row positions, secret key and assembled results contain private lineage and targets and must remain with the operator, outside actor access and public Git.

The source producer's `test_model` partitions the first-occurrence trial sequence using ten `np.array_split` folds, then trains each context decoder on the remaining trials and predicts the full held fold. This bridge preserves that membership. However, the producer uses pandas `Index.difference` and `reindex` for training. The plan's calibration positions are listed in owner-index order and **do not establish native training-row-order parity**. A source-concordance runner must independently export and qualify native calibration ordering. This component supplies no feature preprocessing, feature projection, author LDA fit or candidate launcher.

The [pinned producer](https://github.com/heyslab/StructuredExperience_NatNeuro_2026/blob/8c62c1cfe91644e3030a35d3ebb45e3bee94c3c8/ms_figures/ephys_time_decoding/time_decoding_ephys.py) was inspected through GitHub's rendered source page. No new raw source was downloaded or authenticated. Existing local scorer/provenance records supply the recorded input and endpoint conventions. No author source is vendored here.

Generated tests exercise the entire thirteen-session/390-fit panel, independent non-sorted trial-fold expectations, all 117 scored cells, row/fold/context exclusion, malformed responses, cross-fit replay, secret/feature binding and mutation protection. They are software controls, not authentic-data or model results.

The original task remains source-unresolved. Complete authentic behavior/unit support and zero-event trials, native preprocessing/LDA/order parity, an independently frozen source index, file-scoped code rights, paper-only method interpretation, protected execution and budgets, fresh author baseline, animal-level uncertainty and an original-score improvement decision remain open. HMAC identifiers and receipt hashes alone establish neither authenticity, privacy nor process isolation. This module does not activate either information condition, reproduce a paper finding or demonstrate improvement.
