# Jaxley original input programme: portable generated-control entries

This component contains six unchanged prepared input modules and two portable
entries for existing generated assertions. It supplies source for future hosted
execution; preparation does not establish a new scientific or runtime pass.

Run from the repository root with scientific site packages available:

```sh
python -I -B benchmarks/paper/PAPER-paper-method-002/implementations/original-input-programme-v1/generated_boundary_controls.py --artifacts /absolute/absent-consumer-artifacts
python -I -B benchmarks/paper/PAPER-paper-method-002/implementations/original-input-programme-v1/run_generated_controls.py --artifacts /absolute/absent-bc-artifacts
```

Each artifact directory must be an entirely absent leaf under an existing
ordinary absolute parent. Symbolic-link parents, existing leaves and source
file aliases are refused. Each entry authenticates its adjacent reporting helper
and the seven unchanged source/control modules before scientific imports. The
maintained launcher must additionally authenticate all 12 owned files through
its `test_paths` and the source-ownership inventory. `SOURCE.json` lists the
other 11 members and itself by name; it does not self-authenticate or replace
the repository inventory. There is no public replacement-source, command,
fixture or roster selector. An internal result-pipe endpoint invokes only the
same fixed scientific suite.

The consumer function retains its exact 20 logical controls, including all
18,816 operator-mask cells. Its generated camera metadata context deliberately
substitutes only the historical camera version gate. It does not qualify old
pandas pickle decoding, native reference grouping or full model readiness.
The numerical function is byte-identical and retains its 15 controls, genuine
JAX CPU/x64 convolution, source ordering and exact float64 byte comparisons.
No assertion is replaced with a reporting fixture or synthetic pass.

The proposed engineering profile is `jaxley-input-cpu`: CPython 3.11.18 on
Linux x86_64/Ubuntu 24.04, JAX/JAXlib 0.4.35, NumPy 1.24.3, SciPy 1.10.1,
pandas 2.2.3, ml-dtypes 0.4.1, opt-einsum 3.4.0, python-dateutil 2.9.0.post0,
pytz 2024.1, tzdata 2024.1 and six 1.16.0. This metadata-compatible profile is
distinct from historical ARM execution/admission. Actual hosted package and
scientific observations remain required. CPU/x64 intent is explicit through
`JAX_ENABLE_X64=true`, `JAX_PLATFORMS=cpu` and
`XLA_FLAGS=--xla_cpu_multi_thread_eigen=false intra_op_parallelism_threads=1`.
The maintained launcher supplies its existing protected thread settings.

Each invocation creates exactly `RESULT.json` and `DIAGNOSTICS.log`, each at
most 65,536 bytes. A worker has a 165-second deadline, followed by at most two
seconds for TERM and two seconds for KILL/reap. It inherits the maintained outer
process group; there is no detached worker. The outer row remains bounded at
180 seconds. A prospective two-GiB, one-CPU declaration is not an RSS limit,
CPU-affinity guarantee or full scientific-library I/O sandbox. Preparation's
separate small stdlib reporting campaign does not run these scientific workers.

Success stdout is only the deterministic JSON object `{"controls": [...]}`
with the complete ordered true roster (at most 32,768 bytes), after the real
function returns, its result validates and the worker exits zero. Native stdout
and stderr are merged and retained in the bounded diagnostic file. They are
never silently filtered. Diagnostic/result overflow, malformed results,
missing/duplicate/extra/reordered IDs, timeout and worker failure cannot produce
success stdout. Overflow retains the bounded diagnostic prefix, records the
observed extent and fails. A valid partial worker result is retained on failure;
`trace_observed_check_labels` are explicitly unconfirmed observations, not
passed controls. In particular, `operator field support` is appended before
the remaining mask loop finishes. The full suite stays unconfirmed on any
exception. A forced process kill may leave an incomplete artifact; it grants no
success or admission.

No original data decode, authentic model fitting, historical numerical replay,
dependency installation or new scientific execution is performed by source
preparation. The historical private generated-admission/runtime contracts stay
unchanged and confer no authority on this new portable profile.
