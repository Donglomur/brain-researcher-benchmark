# Paired spectral smoothing

This component executes the linear-power smoothing stage in the author's spectral-fit notebook and a separately labelled grouping repair. It produces both arms on every invocation, retaining all declared participant/region/time windows and their output row positions. The literal source arm uses the original CSV row order and `uniform_filter(size=(5,3), mode="nearest")`. The prospective sensitivity sorts time within each participant/region and applies the same filter independently. Per-row lineage shows which source windows mix different participants or regions.

The source notebook explicitly comments that smoothing should be split by region/ID, but its actual filter processes the entire table. For three constant-power rows equal to 1 followed by another region's rows equal to 101, the last row of the first region becomes 41 in the literal arm and remains 1 in the grouped arm. This is an engineering counterexample to cross-group isolation, not a measured biological error or an improvement result.

The input is the author's `restingstate_spectra.csv` format: `ID,age,region,time` followed by exactly 200 ascending frequency columns, 0.5–100 Hz at 0.5-Hz spacing. Values are finite nonnegative **linear** spectral power from the author's normalized bipolar traces. No voltage calibration or logarithmic power conversion is inferred. Times are seconds, ages years. The five-row window is five overlapping spectra at 0.25-second offsets; rows are not independent participants. Original region coverage may differ by participant, and the operator must explicitly declare every expected group and its row count/time extent. Repeated identities, missing windows, gaps, changed groups, contradictory ages and reordered frequency bins fail. Public-table mode requires all thirteen declared participants; matching a count or an operator hash does not establish their authenticity.

Use an existing Python environment with NumPy and SciPy. Native data preparation requires the project's separately frozen resource protocol; the commands below describe the interface and do not authorize a native run.

```sh
python3 -B smoothing.py --spectra /operator/restingstate_spectra.csv --packet /operator/smoothing_packet.json --output-directory /operator/paired_smoothing
```

The packet contains `task_id`, `source_commit`, `table_sha256`, `assessment_kind` (`generated_engineering_control` or `unqualified_public_spectral_table`), `expected_participants` (unique string IDs), and `expected_groups`. Each group has `ID`, `region`, `row_count`, `age`, `start_time`, and `end_time`. Use the pinned source commit in [provenance.json](provenance.json). Group counts and time extents must be derived independently from the authorized source inventory, not selected after viewing results. A generated fixture may declare a smaller cohort and is always labelled engineering-only.

The new output directory contains `source_literal_smoothed.csv`, `grouped_sensitivity_smoothed.csv` and `report.json`. Each table has the same metadata, frequency headers and row ordering as the input. The report pins both outputs, records full window-neighbor lineage including duplicated edge padding, and retains all scientific limits. Existing output directories are refused. This version holds the input and both outputs in memory; no full-cohort RAM/runtime envelope has been measured.

This stage stops **before** the notebook's 58.5–61.5 Hz interpolation with buffer 5. In a future approved native replay, each table's spectral values replace only the notebook's `smoothspect` value immediately before that interpolation call. Feeding a smoothed output back into the notebook's initial `restingstate_spectra.csv` input would apply the filter twice. Do not feed these intermediate tables straight into the parameter-table evaluator: line-noise interpolation, custom FOOOF fitting and PAF/INT extraction remain necessary. The historical fitter revision, knee-to-INT convention, and paper 3–14 Hz versus notebook 2–14 Hz alpha search remain unresolved. No native ECoG, authentic spectra, target table, fitter, candidate or scientific baseline was run to build this component.

Faithful reproduction of the original thirteen-participant cross-sectional developmental findings is a first-class benchmark outcome. This component advances the preprocessing needed for that outcome; reproducing the findings still requires authentic data, resolved estimator conventions and the original descriptive analyses. Exceeding the paper is a separate outcome: the current descriptive association endpoint has no justified ordered superiority metric. Neither a smoothing repair nor higher developmental regression R² establishes more accurate biology. The original evaluator and its numerical history are unchanged; this component establishes neither completed reproduction nor superiority, current SOTA or research qualification.

Generated controls cover a concrete cross-region/cross-participant counterexample, independent direct 15-term smoothing references at boundaries, grouped order invariance, preserved source order dependence, exact metadata/coverage validation, zero power and singleton handling, and the real CLI's paired receipts and overwrite refusal.
