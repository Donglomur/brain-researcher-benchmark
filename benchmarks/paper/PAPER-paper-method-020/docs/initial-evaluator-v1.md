# Initial BOLD5000-QA construction components

The `initial-evaluator-v1` package implements the canonical task's next construction step: a complete label-blind image/person audit and explicit text/neural information boundary. It also constructs matched inference controls and scores structured NEURONA execution outputs. It does not train NEURONA, reproduce the full paper, resolve actual payload identities, or create a qualified scientific benchmark.

## Contract and primary sources

The immutable task SHA-256 is `263ea4a405bdee13a1003048c883293b224589ebce6e4816e7a3e5e4b8248182`. Its saved metadata revision is BOLD5000-QA `36c60313218c0fbf7c381294b81469f8d085ff46`; the code revision is NEURONA `8071fb42c3ddac0355f2c0b5977baa32e33f6e14`. There are 4,891 saved inventory evidence entries, 4,888 unique names including metadata, and 4,886 unique NPY paths: CSI1 train 4,802 and test 84. Duplicate evidence is deduplicated by path; trials or questions are never deduplicated.

[The source dataset generator](https://raw.githubusercontent.com/PPWangyc/neurona/8071fb42c3ddac0355f2c0b5977baa32e33f6e14/src/create_dataset/create_bold5000_fqa.py) saves enumeration indices as NPY filenames and uses `config['rep']` for the directory split. Therefore a filename is not a verified stimulus identifier. The trusted identity sidecar is required to resolve image aliases and biological persons; path disjointness alone is insufficient.

[The author loader](https://raw.githubusercontent.com/PPWangyc/neurona/8071fb42c3ddac0355f2c0b5977baa32e33f6e14/src/loader/fqa.py) returns full records and normally all queries. This package projects fields explicitly. [The model](https://raw.githubusercontent.com/PPWangyc/neurona/8071fb42c3ddac0355f2c0b5977baa32e33f6e14/src/models/fmri/simple_cnn.py) consumes `brain_region` and query programs. The paper's Appendix F/G describes five time samples and 1,024 brain regions for BOLD5000. No native files were acquired or deserialized in this work.

[The pinned training entrypoint](https://raw.githubusercontent.com/PPWangyc/neurona/8071fb42c3ddac0355f2c0b5977baa32e33f6e14/src/train_bold5000.py) constructs its symbolic domain from train and test queries, may skip untrained test concepts, and selects checkpoints using test accuracy. These remain native-source facts. The new `prospective_within_person_all_queries_v1` path instead requires train-only domain construction, training/validation-only selection, and every declared test query. It must not be reported as exact reproduction of that historical selection/denominator behavior. The canonical contract and all historical records remain unchanged.

## Runnable interface

Use Python 3.10+ with no external dependencies. From `implementations/initial-evaluator-v1`, run:

```sh
python3 evaluator.py inventory ../../task.json
python3 evaluator.py audit-identities ../../task.json identities.json
python3 evaluator.py prepare ../../task.json identities.json trusted-records.json operator-output --shuffle-seed frozen-seed --id-salt at-least-16-secret-characters
python3 evaluator.py score operator-output/protected.json runs.json vocabulary.json
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

All production commands bind the exact canonical contract and path-set digest. The library allows explicitly marked generated inventories for engineering controls; those markings remain in outputs and never establish scientific qualification.

Production scoring additionally checks the complete source-record manifest, exact 84-path test-set digest, canonical audit counts, and contiguous exhaustive question indices for every test record. Query counts come from the trusted conversion manifest and still require independent payload verification. A self-generated hash cannot authenticate data or convert a metadata declaration into an empirical result.

`identities.json` is a list covering every official NPY path exactly once. Each row contains `path`, `subject`, `person_id`, `image_id`, `image_sha256`, and `identity_evidence`. `subject` must match the source directory. `image_id` must identify the source stimulus from trusted metadata, and `image_sha256` must identify the source image bytes. Neither may be inferred solely from the NPY enumeration index. Evidence strings are declarations requiring independent checking, not attestations. Identity components join records sharing either ID or image hash, including transitive aliases. The audit reports cross-split images and persons independently; CSI1 train/test person overlap does not establish held-out-person generalization.

`trusted-records.json` is a list covering the same paths, with `path`, `queries`, `answers`, and `brain_region` from an independently authorized neutral-format conversion of native records. Every record requires at least one nonempty query, aligned answers, and finite `[5,1024]` neural values. All test questions are retained, including duplicates and questions with unknown concepts. Empty records block preparation rather than disappearing from the population. Additional raw fields are discarded: images, captions, scene graphs, stimulus filenames, configuration, and arbitrary labels never pass through to a test packet. Training labels are intentionally exposed only in the separate `training` section.

Preparation creates a new operator directory with `protected.json` and three arm files. The combined library return value is operator-only. An isolated run receives exactly one of `neural.json`, `no_neural.json`, or `shuffled_neural.json`, plus identically approved non-neural resources. It must not have filesystem access to the operator directory, another arm, or protected targets. This package prepares that boundary; it does not provide an operating-system sandbox or attest runner compliance.

Each arm has the same `training` section and an `evaluation` list. An evaluation record contains only opaque `id`, ordered `question_ids`, `queries`, and a single `brain_region` tensor shared across its questions. The training section additionally contains answers. Keep the opaque-ID salt with the operator. The assessor alone retains source paths, person/image identities, question targets, control bindings and packet digests.

## Prospective controls and scoring

The neural arm uses each record's actual approved brain tensor. The no-neural arm replaces the test tensor with all zeros, preserving its `[5,1024]` shape and the trained architecture. It measures inference sensitivity to neural input under the same trained model. It is not a separately retrained text-only/language-only comparator and may introduce a distribution shift. Queries and language priors remain available. The contract's text-only-baseline execution requirement remains open until the broader control design is frozen and run.

Shuffling uses a deterministic, label-blind whole-image group bijection inside subject, official split, and repeated-record-count strata. All questions and repeated records of an image receive the same donor image; equal repeated-record counts preserve the exact neural record marginal. No self-image or hash-alias donor is allowed. Infeasible singleton/unequal-group strata reject preparation without crossing subjects/splits, resampling, or dropping records. The operator freezes the seed before inspecting results. These are prospective choices, not author-reported controls.

`vocabulary.json` is the exact ordered vocabulary list used by the native decoder. `runs.json` maps exactly `neural`, `no_neural`, and `shuffled_neural` to run objects. Each run contains `assessment_sha256`, its exact `input_packet_sha256`, `provenance`, and `predictions`. Provenance fields are `model_sha256`, `language_model_sha256`, `prompt_sha256`, `domain_sha256`, `vocabulary_sha256`, `runtime_sha256`, `decoding_config_sha256`, `training_partition_sha256`, `non_neural_resources_sha256`, `inference_seed`, `selection_policy` (`train_validation_only`), and `domain_policy` (`train_only`). All must match across arms; the ordered vocabulary must match its canonical-JSON digest. An absent language model is represented by the digest of an explicit, frozen no-language-model resource declaration, not an unspecified checkpoint. Hash equality is a necessary binding, not independent evidence that the runtime used those objects.

Each prediction is exactly `{"id": "question-id", "execution": ...}`. Execution is null for failed/abstained execution, or `{"kind": "bool", "value": scalar}`, `{"kind": "int64", "value": scalar}`, `{"kind": "vocab", "value": ordered-score-vector}`, or `{"kind": "Object", "value": ...}`. The structured-result rules derive from [QALoss](https://raw.githubusercontent.com/PPWangyc/neurona/8071fb42c3ddac0355f2c0b5977baa32e33f6e14/src/models/left/models/losses.py): strict positive Boolean logits, ties-to-even rounded integers with integer targets, first-maximum vocabulary decoding with exact target string equality, and no correct Object answers. Null failures count incorrect and lower execution success. The scorer rejects missing/duplicate/extra IDs, unmatched arms, changed resource declarations, nonfinite logits, and protected-target digest changes. It does not implement the paper's separate generated-language baseline parser.

The primary diagnostic is QA-weighted accuracy `sum(correct)/number_of_all_declared_queries`. Image-macro and person-macro summaries are explicitly supplementary; shared stimulus aliases use the same identity component. Neural-minus-control differences are paired on the same question IDs, with corresponding image/person summaries. No p-value, confidence interval, pass threshold, tolerance, native agreement or causal interpretation is invented. Generated fixtures cannot establish learning, difficulty or neural information.

## Independent controls and remaining gates

The independently derived six-question fixture checks unequal aggregation: neural/no-neural/shuffled QA accuracy is `2/3`, `1/3`, `1/2`; image-macro accuracy is `1/2`, `4/9`, `4/9`; person-macro accuracy is `5/8`, `1/4`, `5/8`. Thus the neural-minus-shuffle difference is `1/6` for QA weighting and zero for person weighting. Separate generated transport controls verify feasible group swaps, input isolation, exhaustive IDs, null failures, duplicate/hash-alias images, repeated images, singleton rejection, nonfinite inputs and source decoder boundary cases.

The complete canonical holds and rights statements are preserved verbatim in `provenance.json`. Native payload schema/identity conversion, semantic question-content audit, genuine model/prompt/checkpoint provenance, exact native recipe, source-specific rights, reference execution, scientifically appropriate subject/stimulus independence, a broader text-only baseline, protected access enforcement, composition/category endpoints, difficulty and scientific/submission qualification remain unresolved. The public paper/data exposure is retained. This CSI1 component does not establish the four-subject or CNeuroMod results of the paper. No archive download, dependency installation, model training/inference, model API call, or native scientific campaign occurred.
