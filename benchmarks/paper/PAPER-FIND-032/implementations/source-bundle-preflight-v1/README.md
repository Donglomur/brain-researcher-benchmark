The original Pipeline1 source remains unqualified. Before an operator supplies
official code to either reproduction or improvement, this component checks that
the three source roles have consistent revision, filename and supplied hashes,
then inventories imports from the selected `base.py` without executing any source.
It accepts the singular `reproduce_and_reorder_omission.py` role. The previously
recorded plural locator is not an interchangeable filename.

`inspect_bundle` takes exactly `base`, `sound` and `omission`. Each value has
`filename`, `revision`, `body` (UTF-8 bytes), and `sha256`. It performs no file or
network access and does not repair author code. The selected revision is
`a454439aec8936ff9de2199ab255472c7d140b8c`; mixing in an older helper module is
refused. Byte hashes authenticate only the supplied bytes internally. Independent
official-source acquisition and provenance remain separate prerequisites.

The report identifies names imported from `base` but absent from its direct
module bindings. Conditional/dynamic definitions and wildcard imports are not
resolved. Even a clean static report cannot establish imports, callable behavior,
scientific compatibility or readiness. It always leaves admission, runtime and
publication qualification false.

existing scorer's unsuccessful plural-file retrieval remains historical evidence;
this component does not overwrite it or silently rewrite canonical source roles.
The original temporal support, full participant/event/fold/model joins, compatible
confusion producer and publication-output references remain unresolved. Current
source compatibility is necessary before a run, and cannot establish that a
corrected implementation reproduces or exceeds the published analysis.
