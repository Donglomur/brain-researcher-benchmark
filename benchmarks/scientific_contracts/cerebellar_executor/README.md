# Cerebellar frozen candidate executor

This source component supplies a real, inactive candidate-execution route for the NEURAL-030 scientific contract. It does not create another benchmark or qualify the existing benchmark for a scientific study. It executes a fixed procedure over all 16 sessions and four matched input conditions: context/handle, GrC, CF and joint. The result is 64 calibration selections, 64 final fits and 64 original-query inferences, in that order for each session/condition cell.

The implementation uses the existing owned-container `Provider` directly. It prepares exact mounted operands, builds the actual generic phase requests, waits for capture after producer retirement, independently observes the pinned receipt, checks all output bodies and admits the phase-specific response. A supplied receipt file is not a candidate-execution API. The production entry has no test backend, injected Provider, alternate worker or arbitrary callback argument.

The source is inactive until an independently selected operator authority, input preparation, host/runtime qualification, image review and explicit resource operands exist. No such scientific or native qualification is included. Engineering checks use an explicitly inert Provider; no candidate, model, Docker workload or authentic data was run.

## Scientific contract preserved

The endpoint remains nonnegative expected contact-onset counts in the complete 10 or 20 retrospective 100 ms bins of the planned delay after movement end. Each prediction may use its permitted full planned-window observations. This is a within-session retrospective decoding task, not forecasting or a causal experiment. The original 5/5/6 session grouping, 16 sessions, chronological training/development/query membership, all four input conditions and complete query-bin support remain mandatory. Five-mouse membership is an external operator attestation until authentic support is audited; the executor does not verify biological identity.

The same precommitted three source files and finite recipe grid are mounted for every cell. Independent legal fitting is allowed; fitted parameters and selected grid indices can differ. The source bundle is committed before input access. The calibration program sees only training and development inputs/labels and exports one integer grid index. Only the indexed precommitted JSON recipe is transferred to final fitting. Arbitrary calibration models, generated code, state vectors or new configurations cannot cross that channel. Final fitting receives training inputs/labels only. Development data and held-out query inputs are absent from that process. Original inference receives only the query packet, selected recipe and exact captured model directory from its corresponding final fit. It receives no training/development labels or private query targets. The context/handle packet has no neural arrays or neural timestamps; no synthetic zero array replaces a missing modality.

Every cell is required. A failed phase produces an owned failure record and blocks the complete result; there is no smaller cohort, automatic retry or score from partial support. All 64 validated response objects and source/model/recipe/query lineage are committed before any of the three private evaluator operands is opened. The unchanged scorer retains the fixed context/handle ridge reference as the primary anchor and the companion's additive matched-candidate comparisons. Reference producer validity and empirical baseline strength remain unqualified. Fixed-reference gain alone is not neural attribution. All evaluation rows and target-derived scores stay in the private output root and are not printed by the launcher.

Adaptive generation and mismatched-query replay are refused before Provider construction. A new container, seed, source hash or matching model file does not prove stochastic state equivalence. There is no mismatch effect, permutation test, semantic model-consumption proof, confidence interval or new SOTA claim. A future adaptive experiment requires a separate specification distinguishing a shared frozen LLM policy from identical emitted source.

## Candidate files and fixed ABI

The procedure is exact JSON with `schema: neural030_frozen_procedure_v1`, `task_id: NEURAL-030`, `source_roles: {select: select.py, fit: fit.py, infer: infer.py}`, and a nonempty finite `recipes` list of JSON objects. The committed source roles are Python text, each supplied as an exact `{path, bytes, sha256}` operand. Their combined size with the procedure is at most 1 MiB. The source is parsed for syntax but not executed on the host.

The trusted worker invokes the corresponding candidate with:

```
/usr/local/bin/python -I -B /candidate/main.py --view /view/VIEW.json --output /output/artifacts
```

Fitting and inference also receive `--recipe /recipe.json`; inference additionally receives `--model /model`. `/procedure` contains the same immutable source bundle and procedure metadata in every phase. The selected recipe object is `{recipe_index: integer, recipe: precommitted_object}`. Candidate imports and libraries must exist in the independently qualified immutable image. No packages, data or weights are downloaded.

Selection must export only `artifacts/SELECTION.json`, with exact fields `schema: neural030_selection_v1`, `session_id`, `arm` and `recipe_index`. Fitting must export only a nonempty ordinary file tree below `artifacts/model/`. Inference must export only `artifacts/PREDICTIONS.json`, using the existing `neural030_prediction_v1` complete case/arm/trial/bin schema. Links, special files, unrelated exports, incomplete prediction rosters and extra selection fields fail. The worker owns capped `STDOUT.txt`, `STDERR.txt`, `RESULT.json` and the generic `OUTPUTS.json` manifest. The parent checks that these match the observed Provider receipt after all owned resources close.

The model is opaque captured bytes. The controller neither deserializes it nor proves that the inference program used it, that fitting was honest, or that precommitted source did not contain prior knowledge. Host isolation, trusted worker integrity, immutable image contents, namespace/clock semantics and input provenance require separate native qualification. The worker's process-group operations are confined to its owned container; it is not a host process-management utility.

## Operator request and authority

The production route is:

```
python -I -B entry.py inspect
python -I -B entry.py run --request /absolute/REQUEST.json --request-pin '{"bytes": ..., "sha256": "..."}' --authority /absolute/AUTHORITY.json --authority-pin '{"bytes": ..., "sha256": "..."}'
```

The literal entry script and selected interpreter are the launcher's trust anchor. It pins and captures the closed loader, which captures all 15 component bodies before module imports. Imports use a unique closed namespace; there is no runtime dependency on an authoring directory, mutable global `candidate_views`/`score` alias, or installed shared transport. Standard-library and NumPy identities remain part of host qualification. The unchanged transport checks its own complete source identity again when used.

`REQUEST.json` has exactly the fields enforced by `controller.preflight`: schema, mode, mismatch, fresh absolute root, public, procedure, sources, commitment, private_evaluation, clock, io, native, phase_limits, stdout_bytes, stderr_bytes and public_bytes_limit. The public operand is the already prepared `neural030_cerebellar_public_v1` object, not a raw-data loader. `private_evaluation` contains exact body operands for expected, mouse_binding and fixed_reference. These are validated as descriptors during preparation and opened only after the complete prediction panel. The authority must come from the trusted launcher, outside candidate control.

The pre-data commitment binds the exact procedure and all three source bodies. Its `sealed_before_input_access` flag and externally pinned authority establish what the operator attests; this code cannot independently prove chronology. `AUTHORITY.json` binds schema `neural030_frozen_authority_v1`, request pin, source-manifest pin, commitment pin, a qualification-record pin and four true flags: authorized, native_runtime_qualified, input_preparation_admitted and capacity_qualified. False flags fail before Provider construction. A digest or a true flag does not itself establish any scientific or security fact; the final result explicitly says operator qualification authenticity is not verified by code. The runtime also refuses unsupported local platform capabilities before construction.

All resource operands must be selected explicitly. `io` specifies host read/write limits. `native` binds the exact transport manifest, local Docker executable/socket, immutable image digest, approved image inventory digest and transport read/write limits. `phase_limits` gives all 18 existing transport resource keys separately for selection, fitting and inference: setup/producer/capture/cleanup seconds; memory bytes; CPU nanoseconds; process count; scratch bytes; file/directory counts; per-file/output/manifest bytes; CLI count/bytes; inventory bytes; source-read and host-write bytes. Stream caps and public-input byte caps are additional explicit operands. Existing transport constraints apply, including its minimum memory/page alignment and producer interval greater than one second. The single original monotonic deadline must accommodate all 192 nominal phase allowances before any work. Budgets never renew on failure. This is not an empirical runtime or storage estimate; image availability and actual sufficient capacity remain operator prerequisites. Source bootstrap reads are a bounded separate source operation; the execution meter accounts for the request and authority reads once their explicit IO envelope has been authenticated.
