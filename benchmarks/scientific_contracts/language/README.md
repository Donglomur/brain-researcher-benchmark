# Language report claims and evidence

This portable, standard-library component adds a concrete post-report check for the language drive/suppress paper project. It accepts exact numeric statements—including zero and negative outcomes—without asking an expert to approve arithmetic. It separately records external scientific judgments and prevents those records from overriding contradictory numbers or known limits of the existing study.

The current assignment is the full successor-v8 scientific programme: 184 handles across six main figures and 24 supplementary families; 28 operators; 14 people and 29 sessions; eight A/B × historical/fixed/representation/offline-selection cells. Thirty scientific gates remain open. The older Figures 1–3 fixed-feature project is historical context, not the current complete assignment. `scope_contract.py` retains the exact ordered current roster; missing handles or narrowed scope refuse.

## What the implementation does

`claim_evidence.adjudicate_engine(engine, report_node, claims, expert_reviews=())` is an actual adapter to the existing Engine's collected products, node plan and independently selected reference records. It requires the existing global barrier and target-open state, then consumes the already produced O26 report. It performs no Engine run, data acquisition, fitting, inference, target opening, file access or process launch. Only the claim assertions originate with a candidate. Evidence products and selection metadata must come from the trusted operator's existing Engine; do not deserialize candidate-authored substitutes into those arguments.

Every cited product must occur in the chosen O26 handle's source-product mapping with the same recorded pin. Its actual node/operator/cell/profile is checked against the source-owned plan. A pin is an identity join, not issuer authentication or proof of scientific truth. Existing native/source/input qualification still belongs to the original programme.

Machine checks cover:

- Exact O14 correlation statements on one typed group, retaining undefined constants. Positive within-condition statements require separate positive D **and** S correlations; a pooled correlation cannot substitute. Sign alone is descriptive, not significance or practical utility.
- O27 signed gain as the selected reference's MSE minus the candidate's MSE. Complete method, cohort and participant/condition rosters, equal-cohort aggregation and reported arithmetic must agree. Three search people and two modification people cannot become hundreds of independent participants merely because there are many rows.
- Descriptive A/B gain differences using the actual frozen pair map. These numeric statements do not establish an agent/code-access causal effect.
- O28 conditional interval statements with the complete planned draw/method roster and source bounds. Missing or failed joint draws block the interval. This checker does not recompute quantiles or establish native numerical correctness or calibrated population coverage.

Explicit stronger claim types distinguish known unsupported upgrades: population generalization, causal code benefit, neural understanding, neural gain on unmeasured generated strings, a model-independent ceiling, formal significance without calibration, and meaningful improvement from a positive point estimate alone. The component also has useful supported paths; it is not a universal refusal gate.

Numerical agreement with an upstream table remains `upstream_table_agreement`. It is not scientific-task completion, central-claim support, a positive improvement or benchmark qualification. A correctly analyzed null, failed reproduction or worse extension can be reported honestly. All 184 upstream handle statuses are preserved, including unavailable dependencies and disagreements. A chosen claim subset is never presented as review of every scientific assertion in the whole paper.

## Expert judgments stay external

The existing scientific rubric supplies separate criteria for split/selection policy, measurement units, metric decomposition, historical formulas, participant/item dependence, fixed support, signed outcomes and interpretation. Records use `supported`, `unsupported`, `not_completed_with_blocker`, or `requires_adjudication`, with a reviewer reference, rationale and existing-handle citations. Their provenance, independence and substantive correctness require actual external review. They are not machine-certified scientific approval, do not overwrite numeric claim outcomes and do not create a readiness flag.

The machine checks do not infer whether an arbitrary candidate secretly refit on evaluation data, validate all native model formulas, certify pretraining exposure, or interpret unrestricted prose. Those duties remain with the original source/method-policy and scientific review. Existing 3/2-person uncertainty is conditional sensitivity; no new population calibration is supplied here.

## Use and status

Keep `claim_evidence.py` and `scope_contract.py` together on a trusted Python import path. Call the adapter only from the operator after O26 has returned and the original source/runtime boundaries are satisfied. `API.md` describes the closed claim records and current producer fields. Both modules are portable and import only the Python standard library plus their sibling scope module. They do not depend on the private 144-role implementation at import time.

This is **additive source-build work**, not an installed replacement. The existing Engine and canonical/runtime records are unchanged; they do not automatically invoke this companion. Its outputs cannot retroactively protect old report paths or authorize an empirical campaign. Wiring it into a future controlled report/publication route requires that route's explicit integration and review. No legacy numerical source, 98 MB history tree or empirical input was copied.

`test_claim_evidence.py` exercises the actual adapter on a fully invented 184-handle report with scalar source-shaped products. In a fresh copy without an existing `CONTROL_RESULT_V3.json`, `python3 -B test_claim_evidence.py` runs the controls and creates that result exclusively. No original language module, array, target, header, model, native process or scientific fit is imported or run. Hypothetical execution flags in fixtures are invented values and establish no scientific qualification.

For public consideration, the coherent portable subset is these two modules, this README, `API.md`, and the invented test script. Private source-basis records, reviews, tool histories and their absolute authoring locators are excluded.
