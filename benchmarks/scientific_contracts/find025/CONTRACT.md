# FIND025 candidate submission contract

This interface defines submissions and declared comparisons for the existing PAPER-FIND-025 assignment, *Separating cognitive and motor processes in the behaving mouse* ([paper](https://doi.org/10.1038/s41593-024-01859-1)). It covers both registered claim families: DR/WC null/potent population decomposition and projections; choice/context decoding, movement prediction and fixed/randomized-delay controls. The sixteen obligation names below are output groups, not sixteen benchmarks. This is independently authored build-only source. No authentic dataset, reference target, model, MATLAB run or paper result was used to test it.

The real pending template has no invented animal aliases, trial dictionary, fold IDs, tolerances, reference scores or repair recipe. Its empty case assignments and unresolved joins yield an incomplete report. This is useful for constructing and checking the eventual assignment; it is not an execution-ready benchmark.

## Three result lanes

- `code_reconstruction`: explicitly versioned reconstruction of Git0038351ee773c2aee8758b3d74b0c9bf2991f543 / the inspected scientific members of Zenodo13941415. Current dispatch/argument/repair, actual support and cohort joins must be declared. A selected repair is a declared method departure, not proof of original-code equivalence. Source-scoped corr² and independently computed signed VE remain different endpoints.
- `paper_reproduction`: the final-paper result identity remains held. Even if an operator fills every resolution reference, this version never emits a numeric reproduction pass or paired paper score. It can retain declared individual results for later adjudication. An authorized successor must resolve authoritative endpoint/output/cohort mapping and a scientific comparison procedure; the reported historical means cannot supply pass tolerances.
- `protected_improvement`: candidate and freshly rerun baseline are paired within each access arm on a prospectively declared protocol. Signed VE is the required primary movement-prediction metric, and `pearson_squared_paired_vector_v1` is a separately required prospective squared-correlation metric, for both choice and ramp targets. The full decomposition, decoding and randomized-delay panel is co-reported. Differences are descriptive; no p-value, effect threshold, superiority or frontier claim is manufactured.

`paper_data` and `paper_data_code` identify candidate access conditions. B may receive the official source; A may not. The plan separately declares historical rank-table and motion-threshold privileges. Granting B data-derived parameters changes that access contrast and must be reported; it is not pure algorithm access. Neither condition is granted saved reference outputs or evaluation targets. For a complete record, `historical_precomputed` rank or threshold privilege requires the corresponding used-access flag (and therefore a permitted grant). `historical_full_session` describes fitting support and does not by itself claim import of a historical table. Failed/undefined records may fail before intake. A protected plan rejects both historical parameter grants. The evaluator's baseline may use its selected source in either arm; this does not grant that source to A's candidate. Baseline algorithm identity must match across the two access arms.

## Operands and responsibilities

1. The operator supplies a `find025_plan_v1` object. It contains immutable source observations, a status/evidence reference for each known open join, all sixteen scope-matrix keys, and the exact assigned cases. Every case declares cohort, animal, session, panel and scientific identity. Every case occurs exactly once in the matrix. Fixed onset obligations require the fixed-DR cohort tag; randomized onset obligations require the randomized-delay cohort tag. Repeated endpoint identities cannot pad its denominator. Empty obligation assignments remain explicit gaps. The matrix must ultimately contain every original eligible session, condition, target, representation and time panel; this validator verifies coverage relative to that declaration, not its authenticity against unopened data.
2. Each candidate supplies one `find025_submission_v1` per assigned run, bound to the complete plan digest. The submission contains method/intervention identity, access used, execution declarations, and artifact descriptors or explicit `failed`, `undefined` or `abstained` outcomes. Missing records remain missing in every assigned denominator. A `complete` artifact declaration is not a scientifically correct result. Candidate scalar self-scores are not accepted by the schema.
3. The evaluator separately supplies operator score records bound to the exact submission digest and endpoint identity. Each has a versioned metric, finite scalar or explicit undefined/failure status, and evaluator-record reference. A string, hash, resolution or record ID is an assertion, not independent evidence of provenance, target custody, actual execution, fitting discipline or complete scientific scope. Nothing here reads artifacts or verifies their bytes/content. Production admission must independently check those properties.

The output retains every assigned case for both candidate arms; protected mode also retains both baseline runs. It includes per-family assigned denominators and missing/failure/status counts, individual values, animal/session/panel identities in comparisons, and matched descriptive differences. There is no heterogeneous aggregate score, favorable-case renormalization, pooled trial-weighted score, or significance test. Artifact-only outputs remain unscored declarations; they are never converted into numeric success. Any unresolved required join blocks all paired differences in that lane. Missing scientific identity, unequal support, unequal evaluator identity or absent paired results blocks the affected difference. Paper mode always keeps its additional adjudication hold.

## Required output groups and artifact content

The descriptor's `kind`, logical ID and SHA-256 identify a separately held payload. No path is followed by this interface. The following content is required by the scientific contract; this metadata validator does not pretend to parse or grade the arrays.

| `subspaces_and_projectors` | `bases_projectors` | Ordered unit IDs; null and potent orthonormal bases and projectors; fitted ranks; declared fitting support. Compare subspaces/projectors, allowing rotations/sign changes within a subspace. |
| `normalized_null_variance`, `normalized_potent_variance` | `covariance_variance_support` | Each required within/cross-epoch condition; covariance support and eigenvalue ordering; tested basis rank and denominator rank; unnormalized numerator and denominator; explicit undefined outcomes. Cross-epoch source denominator can differ from basis rank. |
| `population_reconstruction` | `reconstructed_activity` | Ordered unit/trial/time coordinates and null/potent reconstructions on the declared DR/WC panels, including failed panels. |

The root-selected source evidence records fixed DR25 sessions/10 source animals versus paper25/9; two-context12/7 versus paper12/6; randomized19/4 versus paper19/4. These are observations, not a selected alias table. The fixture's single symbolic mouse/session is an engineering witness only. It must never replace these unresolved original cohorts or be used to declare a completed paper claim. The operator must resolve the complete claim-to-case matrix; no default Cartesian expansion across cohorts is invented here.

## Scientific identity and metrics

Every plan case, candidate record and evaluator record carries all `IDENTITY_FIELDS` in the module. Missing operands use null; placeholders such as `R2`, `unknown` and `not_applicable` cannot silently stand for resolved identities. For an inapplicable transform, reference an explicit applicability declaration; do not fabricate a numeric setting. Identical reference strings are only equality of declarations.

Identity includes condition dictionary and selection/outcome definition; target/unit selection; paper/code version; time grid, positive bin duration, score window, orientation, smoothing and delay onset; normalization denominator; fit/development/evaluation and scored row support; target preprocessing; dispatch, argument binding and repair recipe; rank and threshold policy, fit support and historical privilege; split, missing-value and aggregation policy. These references must resolve to complete operator-held declarations, including actual animal/session/trial memberships. No helper path, condition label, rank or threshold is chosen automatically.

- `signed_variance_explained_v1` is signed 1−SSE/SST. Negative values remain negative. Constant observed support is undefined. No evaluation-set scale/intercept refit is implied.
- `pearson_squared_delay_trialmeans_git003835_v1` is the inspected delay-trial-mean squared Pearson endpoint. It discards sign/calibration information and cannot be substituted for signed VE. Source10ms/six-bin and paper5ms/six-bin identities remain separate.
- `pearson_squared_paired_vector_v1` is the protected secondary on the exact same declared target/prediction vector as signed VE. It is an independently authored prospective endpoint, not the historical delay-trial-mean result. The actual vector construction, temporal reduction and support remain required unresolved operands.
- `normalized_subspace_variance_v1` uses the declared covariance/eigenvalue denominator, not automatically total variance. A cross-epoch denominator may permit ratios greater than1; the reporter does not clip them.
- `binary_accuracy_v1` is fraction correct on the entire assigned row support, with the declared dictionary. Source SVM training-pool four-fold CV and paper ridge-logistic outer-test accuracy are distinct identities even with the same arithmetic.
- `first_strict_90pct_latency_v1` finds the first already-oriented/smoothed trace sample strictly above90% of the maximum on the declared window, then subtracts delay onset. No >=, interpolation, zero-clamping or automatic direction of improvement is applied. Negative timestamps may be legitimate declared outputs.

The copied `metric_primitives.py` is byte-identical to the accepted independently authored predecessor. It provides already-adjudicated-vector arithmetic, not cohort construction, a normalized-variance matrix scorer, preprocessing or paper grading. This reporter consumes evaluator records; it does not run those functions on candidate-provided targets. The tiny offset example distinguishes corr²≈1 from signed VE=−149. Its 14-decimal test precision is an engineering assertion, not a paper tolerance.

## Protected pairing

Before any protected result can be declared comparable, the plan must reference outer animal-held-out folds (grouping all sessions/probes), inner animal-held-out selection, same-session calibration versus reserved complete trials, whole context-block/adjacent-pair grouping, coverage of all eligible animals, randomized1.2s exclusion from CD fit, training-only transformations, a fixed common target, separate prediction/target interfaces, within-trial lag resets, a prospective freeze, baseline source and rerun, equal resource ceilings, minimum-support failure policy, and an inference/multiplicity/meaningful-effect plan.

Within each protected movement-prediction panel, exactly one signed-VE and one corr² case must describe the same target/prediction vector and support. All identity operands match except the metric ID and the explicitly metric-specific normalization-denominator, scorer-dispatch and scorer-argument references. Target preprocessing, scored rows, timing and aggregation remain shared. Each complete protected movement record names exactly one primary `activity_predictions` descriptor. The paired arithmetic cases in a run must reference identical descriptor kind, logical ID and SHA-256. Missing or conflicting paired prediction operands make the panel noncomparable. The evaluator record binds the complete submission and case ID, hence this unique declared operand; the reporter does not verify artifact bytes or that an evaluator actually consumed them. Protected mode uses the prospective paired-vector corr² ID, retaining the historical delay-trial-mean ID in code reconstruction. A pointwise signed-VE versus trial-mean corr² combination cannot masquerade as one common-vector panel. The prospective vector definition, temporal reduction, authentic trials and time window remain unsolved operands; this rule imposes no historical trial averaging. Legitimately different reductions need distinct, separately reviewed endpoints.

Candidate and baseline records must declare train-only rank and movement-threshold privileges. Per-run execution declarations must identify fitting records, frozen procedure, actual split realization, common resource ceiling and target-visibility policy; baseline additionally binds the declared rerun. Case identity equality prevents changing the target, score support or selected cohorts as the method intervention. Predictor-side method/preprocessing changes belong in `predictor_intervention_id`, with the common target fixed. Exact folds, calibration fractions, seeds, model budgets, numeric effects and inference choices remain unselected in the real template. References do not enforce the referenced partition or process isolation. Actual support disjointness, provenance and execution require a separately authorized evaluator; this module must not be advertised as such an evaluator.

## Use and boundaries

Run from this directory or import the module explicitly:

```python
from find025_contract import validate_plan, validate_submission, report
# plan, submissions and evaluator_records are ordinary decoded JSON objects.
validate_plan(plan)
validate_submission(plan, submissions[0])
result = report(plan, submissions, evaluator_records)
```

`submission.schema.json` and `operator_plan.schema.json` describe the JSON shape; Python validation additionally enforces source constants, cross-field science identities, access and assigned coverage. No external schema library is required. No file ingestion, source execution, network, unpickling, model access or shared install occurs. Malformed containers are rejected; the API is not an adversarial process-isolation boundary. Integration must admit bounded JSON before calling it.

Portable invented tests: `python -I -S -B -m unittest discover -s <directory> -p test_find025_contract.py`. The first run's one floating-point expectation failure and its original bodies remain preserved; only that affected method was rerun after correction. This source phase neither adds a benchmark ID nor establishes runtime, paper-result or scientific qualification.
