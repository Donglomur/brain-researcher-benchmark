# Portable inactive source interface

This is the complete source component for NEURAL-094. The 35-member component
contains 29 source members, runtime inventory, README, this interface, dependency
declaration, closed source manifest and inspector. SOURCE_MANIFEST.json pins the
other 34 bodies and must itself be authenticated by an external trusted pin.
The sibling tests, notice and license are outside this strict component inventory.
All 28 Python bodies are identical to the accepted installed project source,
including the eight original numerical modules. No registry or canonical is
installed or modified by publishing these files.

`operator.py inspect` is the only CLI operation. It requires explicit positive
read/output/time allowances and the externally pinned manifest length and digest.
It reads the 35 ordinary source files and checks the runtime-inventory join without
importing a benchmark module, opening data or creating a model/native authority.
The inspector retains historical installed schema/state names; these describe
the source component and do not certify registry installation in this checkout.
The minimum source-read charge is the sum of the 35 file lengths plus 35; output
serialization is separately charged. The sibling README gives this projection's
exact pinned operands. Computing a pin from an untrusted local manifest is not
independent authentication.

A separately authorized trusted dedicated serialized operator can authenticate
all source, then call `regional_runtime.materialize(source_root, inventory_raw,
inventory_pin, destination, budget)`. `source_root` is this component's source/
directory; the inventory is the exact RUNTIME_INVENTORY.json body. The absolute
destination must already be an empty, unlinked directory. The function authenticates
all 29 source members before writing the complete 33-file layout. Four transport
modules are copied both flat for container bootstrap and under host_transport/
for the trusted host loader. Numerical source stays under numerics/. A failed
partial destination is retained and must not be reused or silently cleaned.

`materialize_capsules` then copies the fixed F/I/reference wrappers and explicitly
supplied authored program, training recipe and instructions to fresh disjoint
roots. These are source-copy APIs, not process-launch or scientific authority.
The future caller must supply and authenticate the image, provider, native stack,
storage mechanism, full metadata and packet support, resources and authoring
evidence required by README.md. Programme and grade_complete retain their source-
owned closure and target-last boundaries. There is no authority factory, grading
CLI, credential, provider purchase, fitted state or scientific result here.

The numerical manifest's original_path strings are withheld-origin descriptions;
load_group uses only fixed module names and path/bytes/sha256 fields. The runtime
materializer checks the retained string schema but never opens original_path.
Public source does not include the scientific protocol canonical, anatomical map,
source catalog, cohort/input bindings or protected targets. Their exact expected
identity descriptors remain declared, so a different dataset cannot silently
substitute for them. The scientific protocol and the external task registry
canonical are distinct; this distribution supplies neither body.

Full scope is 39 sessions, 10 mice, 73 literal labels, 2,628 pairs and five seeds.
The whole-population primary, source support, F/I deployment strategy and all
negative/undefined effects remain unchanged. F has no inference-time model use;
aggregate reservations include global authoring and failures. All execution,
native/scientific qualification, registration and readiness promotion stays held.
