# Operator and qualification boundaries

Publication supplies source and contracts. It supplies no authenticated release, private mapping, key, prepared bank, model, launcher, provider credential or qualification evidence.

## Earlier trusted qualification

All three call interfaces construct `policy.Qualification`. Its exact record fields are `generation`, `source`, `gates`, `bindings`, `original_receipts`, `whole_host_memory`, and `build_only`. The record's canonical identity must match the caller's expected pin. The code refuses build-only execution and requires all nine named qualification gaps with original evidence, then joins the exact generation and source.

Those nine gaps cover atlas content/rights; two scrambled alignments; native TR and clock; source version/rights; model/tokenizer content/rights; native runtime/numerical agreement; provider price/monetary cap; whole-tree isolation/resource accounting; and setup/extraction resource profiles. They do not replace the 32 scientific gates in the complete contract.

An operator cannot create evidence merely by writing “qualified” in a record. The trusted caller must select and authenticate the actual original evidence and enforce the native boundary. This snapshot supplies no such record or authority.

## Preparation inputs

`entry.preparation` consumes a source-owned request containing the admitted release, per-scan sources, atlas, clocks and an operator key descriptor. The key body must be exactly 32 bytes. It is required input, with no default, generated example or public identity map.

Preparation requires complete source/clock support for the selected 572 scans, exact bilateral atlas content, matching audio/alignment variants and native-clock joins. The fixed extractor uses separately qualified local model/tokenizer paths and local-files-only loading. Original neural, audio, alignment, atlas and model bodies are not distributed here.

## Reference and complete-study inputs

`entry.reference` receives the original parent, staged request/input directories, context, source/generation, output namespace, worker limits and actual observer. FIT and INFER operate through the complete source-owned reference/state path. No static prediction fixture substitutes for a reference fit.

`entry.complete` requires the prepared bank, setup closure and adopted contrast pins selected by qualification. The protected target root stays operator-owned. All 10,206 prediction/cost captures must satisfy the original barrier before participant/scorer target access. Trusted preparation's earlier response access remains separately accounted.

## Native source and transport

`Runtime` materializes only explicitly selected `runtime_assets`. Each asset joins source root, source descriptor, destination descriptor and allowed roles. The launcher executable and its dependencies must occur in that roster. Reference capsules and their actual source files must match reference-role assets; participant capsules are captured submissions.

The launcher and protected observer remain external qualified dependencies. They must enforce mounts, process-tree isolation, resource limits, original waits, output capture and truthful accounting. Supplying a container label, an executable name or participant-authored JSON is insufficient.

Missing bindings, unknown costs or incomplete output/custody must not become successful completion. Publication does not relax any profile, deadline, attempt cap, missingness rule, target boundary or scientific denominator. Future qualification must bind the fresh public snapshot and exact runtime/capsule assets; old private-source receipts are not transferable.
