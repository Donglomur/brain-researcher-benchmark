# Prospective caller/API and lifecycle

This is normative design, not executable source. Old portable files are source evidence and cannot satisfy the new API by relabeling.

## Requests and finite profiles

Every request has exact schema fields: protocol/version, generation, context_id, stage_id, method_id, caller_source pin, full operative-source manifest pin, original parent request/receipt IDs, input descriptors (path, bytes, digest, dtype/shape and ordered support), output reservations, resource profile, method_prior_identity, clock_conventions_identity, historical_layer8_direct_consumer, evaluation_label and original monotonic/UTC start. Unknown/duplicate fields, aliases, stale generation, unsupported modes or cross-context inputs fail before effects. Output names are fresh exclusively owned relative paths, no links/traversal/overwrite. Metadata alone never authenticates an actual result.

Prospective participant profile P1, separately adopted before execution: per episode at most 16 provider requests, cumulative 60,000 input and 16,000 output tokens; 3,600 wall seconds and 28,800 CPU seconds across author, tools, final fit and infer; 64 GiB whole process-tree resident memory; 128 GiB acknowledged reads, 8 GiB writes, 50,000 cumulative creation attempts, 256 live FDs and 64 child-creation attempts. F and I receive the same complete allowance, not a fresh allowance at seal/infer. Parallelism cannot multiply caps. Provider price/model/decoding versions and gateway semantics must be pinned; monetary cap is a required future profile field and cannot be inferred as authorization to spend now.

Prospective reference profile R1 per outer case, including all nine final reference contexts and all inner fits: 7,200 wall seconds, 115,200 CPU seconds, 64 GiB whole-tree resident memory, 512 GiB reads, 64 GiB writes, 200,000 creation attempts, 256 FDs and 128 child attempts; no provider calls. These are proposed ceilings, not measured feasibility. Fixed-feature preparation has its own finite profile selected before any authentic operation, based on exact admitted source extents; no preparation is authorized with that field missing. If the complete job cannot fit, the programme fails resource qualification and needs prospective amendment, never a reduced test cohort.

Cumulative physical observed costs and conservative reservations are separate; uncertain effects remain explicit. Whole-host memory admission is distinct from process-tree usage, and neither follows from current free disk space. No unknown cost exemption is selected. Existing upstream acquisition-cost unknowns remain historical and cannot become a measured zero. Original opaque web-tool network overhead in this design phase is disclosed separately.

## Stage graph

S01 authenticate source census and adoption → S02 rights/version/atlas/clock admission → S03 pin complete numerical/runtime/provider/resource profiles → S04 project exact eligible scans and protected response products → S05 produce fixed audio/lexical/contextual primitive banks → S06 freeze case/family/support map and inner-fold manifests → S07 publish isolated mode/arm/response views.

For each candidate context: S08 author (allowed view as mode specifies) → S09 seal source, declared policy and original transcript → S10 actual final FIT and immutable state → S11 actual query INFER → S12 capture complete prediction and pre-score investigation → S13 close requests/processes/FDs/artifacts/costs. I may already have produced a fitted state during authoring; S10 must either join that exact actual source-owned final fit with original closure or perform a new charged fit. It cannot assert a synthetic completion.

For each independent reference context: S14 expand complete inner plan (for R2/T/A only) → S15 actual fit-local transform+FIT+validation for every config/fold → S16 choose per-parcel training-only configurations → S17 actual outer FIT → S18 publish immutable complete state → S19 fresh query INFER → S20 capture prediction and original full cost closure. R0 and Rmean explicitly bypass inner-selection stages as not_applicable and still perform outer FIT/state/INFER. No bypass is allowed for a failed required stage.

S21 all-10,206 barrier: exact candidate and reference captures, every required state/fit/inner record, all cost/FD/process closures and all pre-score declarations. S22 obtain scoped scorer target grant and read protected targets/real-training means once through the authorized reader. S23 compute full metrics and predeclared contrasts. S24 own/reserve complete report request before publishing any externally visible report. S25 publish and close report and all score costs. S26 blinded two-reviewer interpretation then S27 adjudication (when required), with separate requests/time/costs and frozen evidence. S28 final complete report and custody readback. Any absent mandatory prediction/closure blocks S22; invalid submissions may produce a target-free structural failure report.

Trusted preparation S04 already reads neural targets, and records that fact. S21 limits agent/scorer access; it is not a claim that no previous operator saw them. Reference-bank isolation is independently checked. A postscore publication error may leave a partial external effect: keep it, record its possible prefix and block completion; never replay automatically with fresh quotas.

## Information views and actual interfaces

FeatureFit receives fitting-only word occurrences and support; returns a frozen frequency state. FeatureTransform receives state and allowed word/primitive features, returns exact ordered arm arrays. ReferenceFit receives the exact train arrays, source/group/weight maps and hyperparameter specification; returns the complete state described in REFERENCE_CONTRACT.md. ReferenceInfer receives only state and query X/support; returns all rows×400. CandidateFit/CandidateInfer obey analogous manifests but permit arbitrary declared science in the adopted sandbox. All interfaces require actual original exit/wait/signal/stream identities, not harness-generated status text.

ZERO_RESPONSE has an independent view descriptor with opaque response identity and all-zero payload. No real-Y-state, source pin revealing a response value hash, mean, residual or fit diagnostic leaks through a shared directory/service. Explicitly shared train X/row geometry is the same by design. Reference states/targets remain private for both conditions.

A provider gateway owns/reserves a request before dispatch; no retrospective receipt fabrication. Callback dispatch/pipe/selector acquisition takes ownership of all resources immediately upon actual acquisition, before later initialization that may fail. Every close attempt happens independently. The primary error and later cleanup/publication failures are separately serialized even when exception string conversion fails. Interrupted/unknown write/read effects block admission; a new helper wrapper cannot retroactively certify an old unchecked caller.

Before read effects reserve allowed bytes; before writes reserve bytes and file attempt; before spawning reserve child/tree capacity. Successful acknowledgements and exact remaining reservations are joined to the same context. Unacknowledged reads/writes, open FD closure, lost child wait, missing original clock or incomplete bank/setup costs invalidate required cost closure. Attempt counters are never refunded, quota ceilings never enlarged in response to failure, and retries are explicit new charged requests under the same experiment allowance.

## Required output envelope

Each capture contains schema/version, context and complete input/source/state/support/condition joins, ordered row IDs, all 400 parcels, finite C-order little-endian float32 NPY1 prediction descriptor, original job/process/provider receipts, cost report through final publication/close, investigation declaration and immutable readback. Duplicate/extra/missing row or parcel, wrong source, silent target access, stale prediction, fake FIT, incomplete write and failed cleanup all refuse admission.

Original wait status, logs and errors survive all report generation. A reviewer may observe/fix its own test harness, but that cleanup can never be attributed to the producer. Unknown intermediate histories cannot be reconstructed as successful runs.

The layer-eight extractor is a historical Narratives-response-selected feature prior: Caucheteux et al. selected it using brain-prediction comparisons on 101 listeners, seven stories and 237 subject-story pairs from the same public corpus. The exact overlap with the current 171 listeners/486 cases is UNKNOWN. Current outer/inner transforms, coefficients and alpha/gamma selection use their fitting support only; this locality does not establish independence of the earlier global layer choice. Results are exploratory public-corpus evaluation with a disclosed shared-corpus prior, without an untouched-test or globally independent layer-selection claim. METHOD_PRIOR.json supplies the mandatory identity and disclosure.

The two design identities are mandatory through FeatureFit/Transform, candidate and reference author/FIT/state/INFER/capture, pre-score declarations, Barrier, ScoreReport and InterpretationReview. Validate exact generation identities and context applicability before admission. Every CONTEXT candidate is a potential direct C consumer; its realized declared feature use is recorded separately without deleting the available-prior disclosure. R2/CONTEXT is a direct C consumer; R0/CONTEXT is not. The barrier refuses missing/stale/cross-generation disclosures or a true global-independence/untouched-test claim. These are provenance joins, never permission to inspect protected cohort bodies. Same scalar elapsed time in all lags follows CLOCK_CONVENTIONS.json.
