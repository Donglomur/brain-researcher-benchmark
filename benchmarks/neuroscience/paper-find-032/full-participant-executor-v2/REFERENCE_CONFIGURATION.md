## Concrete metadata preparation

After completing the two templates, preserving the selected source and runtime identities and selecting the actual host/resource scope, the following **future** command only writes ordinary configuration files:

```text
<selected-python> -I -S -B <package>/configure_reference.py \
  --template <absolute-filled-reference-template.json> \
  --package <absolute-package-root> \
  --output <absolute-fresh-private-configuration-directory>
```

The utility reads the complete ordinary source graph, hashes each selected module, writes fresh REQUEST.json/SOURCES.json/INVOCATION.json (0400) and creates a root-owned empty 0550 bytecode cache. It never imports task modules, opens recordings, runs the CLI, installs software or changes an existing file. `INVOCATION.json.argv` is the exact actual callable CLI command, including all request/source-map pins, original endpoint, isolated flags and `--mode run`. Its `execution_selected=false` is a warning that metadata generation itself does not authorize scientific execution.

The trusted invoking operator must authenticate that initial interpreter/entry and issue the exact argv without shell interpolation, under the originally selected host/outer resource scope. Retain the original command request/result, exit and both streams. **Only actual natural zero and complete stream closure may be consumed.** A success-shaped directory/report left by a nonzero command is not usable support. This is normal CLI caller responsibility, not an invented success receipt. There is no automatic retry.

The captured CLI entry installs the source finder and calls `producer.run`, which internally calls `producer.invoke_reference` and returns an integer exit code. It does not return a live ReferenceExecution to a shell. For in-process trusted integration, a trusted caller using that same authenticated finder and captured request/map calls `producer.invoke_reference` directly; that function returns the ReferenceExecution carrying the actual NativeOwner/Child. Call `result.assessment_operands()` only after `result.require_closed()`. Add the separately selected tolerances and pass those operands to the existing `participant_executor.assess_closed` on its actual closed paired execution. That method still decodes both full candidates before its first protected-reference open. This new package never opens a historical private result to construct or admit the reference.
