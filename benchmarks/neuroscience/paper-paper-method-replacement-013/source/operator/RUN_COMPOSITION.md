# Neuroformer run and metric composition

This successor adds actual run and metric callers to the native input producer.
It preserves every predecessor source role and all 46 inherited case slots.
There are **39 historical/source-native condition cells, 39 separately labelled
protected/native condition cells and seven existing prospective/5ms cells**.
These 85 cells are conditions across one paper assignment, not 85 benchmarks.
All cells retain `ready=false`; source-complete and scientific qualification
remain false. All seven wider paper families remain explicit obligations.

## What now executes when a future operator binds a qualified runtime

`run_composition.build_matrix(source_root)` authenticates the complete original
26-file source roster and the exact inherited PANEL. It records source definition
positions and hashes, case-specific dependencies and holds, and method defects.
It imports no native numerical package and opens no recordings or weights.

`ReleasedCalls` implements actual model/trainer/inference calls. Runtime leaves
must bind the captured original Neuroformer, Trainer, TrainerConfig,
load_model_and_tokenizer, decode_modality, generate_spikes, set_seed, DataLoader,
all_device, NumPy and Torch in a separately qualified environment. Their presence
as callbacks is not an authenticity or containment proof. Engineering controls
replace these numerical/model leaves with explicitly named inert objects.

The TrainerConfig expression and MAX_EPOCHS/BATCH_SIZE/SHUFFLE assignments come
from the captured training entrypoint's AST. No epoch or batch flag is guessed
from its CLI. The caller retains 250 epochs, batch160 and the original training
expression. It explicitly disables W&B telemetry and selects the single-process
Trainer branch; these are disclosed apparatus amendments, not original run facts.
Neither change grants scientific execution authority. No training has been run.

`dispatch_native(matrix,cell_id,calls,job,providers)` validates the selected cell
and complete support before calling operator-owned providers. It then checks
the actual native dataset lengths, neuron/time shapes, clocks, frame context and
interval order before passing those objects to a trainer. It currently supports
only Neuroformer continuous behavior heads: two lateral historical cells and
three protected cells across the cohorts. **Other method cells are retained and
refused before provider access**, pending their genuine method/config/quantizer/
finetuning/ablation recipes. Three protected-head capabilities do not make three
scientifically runnable benchmarks.

The exact job keys are `run_id`, `seed`, `config_identity`, `run_provenance`,
`support`, `output_directory`, `original_interval_count`, `limits`, and
`historical_true_past`. Config/run identities are explicit path/bytes/SHA-256
descriptors, passed to an operator-owned configuration provider; this caller does
not certify the contents of those provenance records. The provider must capture
and authenticate the actual selected configuration and run records. No seed,
medial configuration or original run is manufactured. The released CLI default25
and notebook default69 are alternative source defaults, not recovered author
run seeds. A job's explicit seed is used for its training and inference condition.

Support has exactly `train`, `selection`, `evaluation`, each a complete ordered
list of `id`, `recording`, `end_tick`, `recording_ticks` records on the native10ms
grid. The three explicit positive limits are `max_support_rows`,
`max_prediction_rows`, `max_native_intervals`. They are checked before provider
access and again against actual dataset metadata/query batches at effect sites.
They are not measured native memory or wall-clock ceilings. Configurations must
retain current/history50ms and video150ms. Source video uses50ms frames despite
the original frames dictionary's dt=.01 field. Other native contexts require a
source-backed extension; no metadata label alone changes the overlap calculation.

Providers supply `configuration(config_identity,run_provenance)`,
`training(rows)`, `selection(rows)`, `historical_finetune(prefix_rows)` and
`protected_queries(rows)` as applicable. Configuration returns `cohort`,
`config_status`, `config`, `tokenizer`; medial protected use must explicitly say
`lateral_config_on_medial_unqualified`. Historical medial dispatch is refused:
there is no authenticated released medial configuration/run mapping. Source
dataset assembly remains the existing `native_dataset.prepare/construct` path;
it is not replaced with synthetic data here.

## Historical/source-native condition

The complete train/test order must match the actual original NumPy split draw.
Selection support equals evaluation support, explicitly recording test exposure.
No context purge is inserted. The caller replays global RNG consumption after
native preparation's isolated split draw and checks the actual dataset intervals
against that complete draw. It preserves the original pre-training dataset peek
and shuffled test demonstration forward, which consume data/RNG before fitting.

After fitting, `historical_inference` preserves the released computational order:
reseed, construct/load the selected checkpoint, replay/check the split, peek at
the train dataset, perform the shuffled two-item test forward, generate on the
first floor1% training prefix, reload the same model.pt weights, and decode all
three speed/phi/th streams. `historical_true_past` must be explicitly supplied.
Plot, CSV and pickle serialization are omitted from the in-memory producer.
The original GPU=True generation call and its failures are retained; no CPU
surrogate is silently substituted.

The original generated-history override is ineffective because get_interval
overwrites its supplied data argument. This behavior remains unchanged. The raw
generation result is retained alongside behavior output, not relabelled as a
correct autoregressive benchmark. A corrected-history component is now available through `ReleasedCalls.protected_generation`;
it is a separately labelled source amendment within protected native conditions. It does not
select any original ablation recipe. See `PROTECTED_ROLLOUT.md`.

Other source defects remain visible. Trainer reads min_eval_epoch/eval_every on
itself, although the entrypoint writes them on its config, so the ordinary path
uses defaults0/1. One best_loss is reused across total and component losses.
The mlp_only branch constructs but bypasses its MLP. gru_only is unidirectional;
gru2_only selects the bidirectional ImprovedGRU. Lasso/GLM fitting recipes,
original classification configs and quantizers, actual pretrained/scratch
finetuning and10% recipes, and precise ablation run mappings remain missing.
The entrypoint's default gru2_only_cls configuration is not among the four
captured lateral configuration files. None is silently selected in its place.

## Protected/native condition

Training receives only the selected train and validation objects. Query providers
are called after fitting/checkpoint selection. Declared roles must be disjoint
across their full neural/video context footprints; initial video windows cover
the first three frames and are not incorrectly shortened to endpoint+50ms.
Conflicting recording lengths and duplicate physical windows are refused.

`protected_behavior` accepts only bounded, ordered query batches with row IDs and
known source feature fields. It rejects target-bearing modality streams and
extra label fields, checks cumulative support before model calls, and checks
native head output shape before CPU capture. It calls model(x,None), then applies
the existing behavior projection heads to features['last_layer'].mean(dim=1).
That additional head call is necessary: the original forward only emits behavior
predictions inside its targets!=None branch. It is an explicit source-amended
inference producer, not a claim of paper/native-run parity.

This protects the inspected argument flow, **not an adversarial process boundary**.
A provider/model in the same Python process may have other references. Authentic
data identities, private staging, process/network containment and evaluation
independence remain required external gates. Neural-count cells retain original configuration/run and qualified execution gates.
The separate generated-only component supplies an explicit current-token/history producer; passing
teacher-forced x['id']/x['dt'] to model(x,None) would still expose current truth.
Those cells remain blocked. No behavior-head success retires that requirement.

## Existing prospective/5ms condition

`dispatch_prospective` calls the existing full46 `contract.query` and
`contract.submission` interfaces through the operator's bridge API. The operator
runner receives a separate copied query; the admitted query remains fixed for
validation. The runner must retain the existing `stage.py` projection and must
not expose the full private query directly to a candidate. The complete legacy
submission is required even when reporting the seven prospective rows; a new
seven-row or per-case query ABI is not invented. The native10ms pipeline does not
produce, resample or certify the existing5ms bridge.

## Actual output-to-metric producers

`run_metrics.assemble_behavior_packet` consumes the actual original decoder
DataFrames or protected native tensors. Historical outputs must match the
original float32 endpoint encoding, trial0 and one recording, in exact order;
protected outputs must match all row IDs and scalar head shapes. Lengths and
aggregate scalar counts are admitted before tensor detachment/list capture.
The decoder's embedded true column is never consumed during candidate admission.

`assess_behavior_runs` assembles the complete selected run roster, freezes scalar
predictions, and only then calls the private target loader. `grade_behavior` uses
the literal original SciPy Pearson argument order. Historical results use the
first200 rows, retaining the full admitted support count. Protected results use
all rows. Undefined r/p remain null. These are distinct profiles and are not
silently compared as the same endpoint or called a reproduced paper result.

The original generator's true tokens lack their own parallel Trial/Interval
columns. `window_truth` therefore captures each actual dataset item's own
interval/trial and original y[:T_id-pad] slice, checks the original token width,
decodes IDs, and removes named special tokens. `freeze_generation` admits only
the aligned predicted ID/dt/Trial/Interval columns before private truth access.
It never uses the generator's unaligned raw true/time arrays as a join key.

`grade_generation` validates bounded independent window truth, constructs the
two interval event tables, and calls the exact captured compute_scores and
compute_scores_scikit definitions. The former visits true-present intervals and
retains its FP==0/FN==0 shortcut. The latter visits predicted-present intervals
and uses weighted binary metrics on the ID union. Empty branch dictionaries
remain empty. Candidate event-ID population and offset-to-paper-window identities
are still unqualified: these outputs are explicitly **source-token-window
diagnostics**, not authenticated Figure6 metrics or dense-bin count F1. The
separate teacher-forced token metric is retained in provenance and not substituted
for either helper. Selecting the paper's exact metric/conversion remains open.

## Unfinished scope

All 71 run/metric predecessor roles are retained. The source amendments are indexed
in this successor; original historical source bodies remain unchanged. The exact
external primary text was inspected for this method choice; no primary body is
copied into the successor. All46 cases
and simulation, passive-control, variability, geometry, representation-probing,
CEBRA and training-curve families remain required. No benchmark registration,
qualified-count increase, model study, original observation access or publication
is justified by this source packet. The new callers reduce concrete preparation,
method-selection and metric-alignment gaps; original method recipes, authentic
full inputs/run mappings, native execution, independent reference results,
protected execution and whole-paper coverage still remain.
