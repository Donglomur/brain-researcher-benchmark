# Independent prospective resource-definition review

Recommendation: **scientifically defensible with the mandatory amendments below; not an operative selection, implementation acceptance, or native qualification.** The proposal defines a narrower resource comparison. It does not demonstrate equality of all computational work or total I/O, and the original contract remains operative until a new policy is selected prospectively.

I authenticated and read all eleven original source/contract bodies selected by RESOURCE_CONTRACT_EVIDENCE.json, together with that evidence and the proposal. The source pins are recorded in INTAKE.json. This is a bounded design review, not a whole review of the current S3 candidate. No candidate was edited or executed.

## Scientific judgment and exact scope

Equal preselected resource allowances are a legitimate experimental control even when some dimensions of resource consumption cannot be observed. The resulting question is whether the fixed-program and investigating-agent conditions differ under the specified CPU, wall, memory, process, storage, token/call and managed-host-transfer policy. Equal allowances do not imply equal consumption. Native logical I/O can differ between methods and contribute to their behavior; it is an uncontrolled, explicitly unmeasured dimension, not evidence of matching or computational efficiency.

Use this wording for the intended interpretation: **“Compared under the same prospectively selected measured resource envelopes; native cumulative logical I/O and native file churn were not measured.”** Each report must enumerate the actual matched dimensions, accounting scopes and qualification states. Do not abbreviate this to “equal resources,” “matched total resources,” “equal I/O,” or a total-cost/efficiency claim.

The amendment must apply prospectively to the entire fixed campaign: 960 cells, 1920 logical phase envelopes, 96 panels, 32 contrasts, 8520 reference fits, 48 future qualification controls and 30 gates. Preserve all existing methods, views, seeds, folds, targets, sharing restrictions and scoring equations. This review supplies no new caps, method restrictions, results, gate closures or benchmark-count increase. Existing incomplete or failed histories retain their original policy and disposition. A changed policy requires a newly identified campaign, not reinterpretation of old runs.

## Required amendment A: define measured quantities and enforcement separately

Bind a versioned resource-policy object and its digest into CampaignPlan, selected environment/profile, every phase/cell receipt, reference setup bank, collection, score request and report. The object must name units, scope, observation method, overlap rules, selected limits, reservation semantics, allocation hierarchy, and admission/qualification consequences for each quantity. No runtime choice of a more favorable definition.

At minimum distinguish:

* Managed source-owned host reads and writes: bytes actually returned or acknowledged by the selected source-owned adapters, including capture, copying, journal/control/receipt publication and failure work. State which adapters are instrumented. Do not silently claim all interpreter/library/daemon/kernel I/O is instrumented.
* Managed control-stream transport: received bytes, including provider command/capture transport. If the same payload is later written to a journal, the stream and write are different operations. Preserve separately selected stream and write limits; do not count a logical payload once and claim all transports were charged, or sum overlapping views into a fictitious unique physical total.
* Managed file operations versus live bytes/inodes: creation attempts, acknowledged creations and live extents have different units. A live-capacity reservation is not a cumulative file-churn measurement. Define the measured operation boundary before exposure.
* Original whole CPU and wall, memory, descendants/pids, live scratch/output/request/storage capacities and provider tokens/attempted calls. Preserve the original scope and limits, including source-owned control, transport, finalization, scoring and publication work. Cgroup actor/holder/provider CPU is a component; separately incurred host/control CPU must be included without double-counting provider subintervals. Actor cgroup memory alone does not establish a bound on host capture/publication buffers or Docker-daemon memory. Existing qualifications must establish precisely the original selected coverage and enforcement; do not silently narrow “whole” to what is convenient to observe.
* Native cumulative logical read bytes, write bytes and file churn: value null, status `unobserved_by_selected_observer`, with explicit scope and reason. A known lower bound, if any, is a separate field and never substitutes for a total. Block-device counters would also require their own interpretation; tmpfs/cached logical operations are not inferred from them.

Repeated writes to a bounded tmpfs are the decisive counterexample to treating its capacity as a cumulative debit. In the selected original native.py, the request-volume reservation is later added once to write_bytes with a “conservative cumulative” comment. That is not a sound cumulative native-write bound. A successor must separate its live-capacity reservation from managed-transfer counters and native-I/O unknowns. Preserve the old debit in historical records under its original meaning; do not rewrite it as an observed quantity or reset cumulative counters.

## Required amendment B: classify unknowns by quantity, not by convenience

The only new standing exemption is for the explicitly excluded native cumulative I/O/churn quantities. It does not exempt an instrumented managed-transfer operation with missing accounting; missing required CPU, wall or memory evidence; provider token/dispatch uncertainty; lost original completion; unstable output capture; or unknown resource custody/closure.

Maintain an append-only operation ledger with original identities, known actual costs, typed unknown quantities, sound selected reservations, first error and secondary errors. Retain actual costs even when final clocks, counter reads, accounting, durable publication or cleanup fail. A later successful cleanup cannot reconstruct an original natural exit or original cost. No original clock, counter or allowance restarts.

An unobserved quantity inside an enforced cumulative envelope blocks additional work dependent on its remaining allowance unless a sound, already selected conservative reservation covers the uncertainty and all remaining work within the original limit. A storage-capacity reservation is not such a bound for repeated native I/O. An invented replacement cap or a new cleanup allowance is not reconciliation. Unknowns remain reportable even when a selected bound makes continuation safe.

Keep at least five orthogonal dispositions: (1) containment/custody, (2) remaining-envelope admission, (3) prediction/numerical availability, (4) operational-mode and scientific-semantic qualification, and (5) measured-resource comparison qualification. “Prediction structurally valid” is not yet “prediction correct”; correctness requires protected scoring. A missing cost does not mathematically change a retained prediction, but can prevent further execution or a resource-qualified interpretation. Forced, late, partial, source-mismatched or unobserved-completion results retain their existing failure rules.

Every target remains closed until the existing complete-collection barrier has all 960 terminal dispositions, all required original resource closure/custody, source/input/state pins, and admission under the same remaining campaign/scorer envelope. Unknown containment anywhere blocks all target access. Expected-unobserved native I/O alone must neither mark containment unsafe nor serve as evidence that containment is safe. A known-safe closure with missing required cumulative CPU still cannot launch the scorer if original remaining headroom cannot be established. Missing cost attribution can leave a numerical result reportable only when all independent safety, execution-admission and scoring requirements remain satisfied.

## Required amendment C: setup attribution and contrast interpretation

Keep unique physical operations separate from standalone per-cell attributable cost. Each T1 consumer receives its full frozen R2 setup attribution plus its own work under the same F/I rule; the physical setup is not executed or summed again. Attributable wall is a defined standalone charge, not observed concurrent campaign elapsed time. Costs of reused banks retain their original receipt identities. A missing managed setup cost, CPU, wall or token quantity is unknown, never zero or free reuse. Qualification requires either the known selected cost or a sound preselected bound sufficient for the unchanged allowance. If unavailable, keep the affected condition/contrast unavailable under the original rule. Excluded native setup I/O is reported unknown in both physical and attributable views and does not pretend to be a measured allowance debit.

Retain all 32 contrast rows and their existing identities, estimands, hypotheses and multiplicity family. Add a per-contrast dependency record for numerical availability, semantic qualification and the resource-policy version/metrics relevant to its interpretation. In particular, C01–C02 must state the narrowed resource-conditioned F/I interpretation; C03–C04 and C05–C12 must expose tool/setup/reference attribution qualifications. Apply the same cost accounting to all C13–C28 control arms and C29–C32 assignment comparisons; none is an exemption for a failed cell or omitted ledger. Existing paired units, three-seed averaging and all scientific controls remain unchanged.

Do not drop unavailable contrasts from the fixed joint family or replace them with successful ones. Preserve the existing rule that the qualified joint 32-contrast band is unavailable when any required contrast is unavailable. Safe, fully available raw numerical effects may be retained with their actual qualification labels and existing descriptive limits; they do not become a qualified matched-resource result through this amendment. Missing resource information must not select which outcomes are highlighted as if the selection were prospective.

## Limits of this recommendation

The enclosed metadata-only decision table tests consistency of the proposed distinctions. It is not a scientific run, native observation, resource-enforcement test, benchmark result, or proof of implementation. All thirty gates remain at their existing states; this review closes none. The eleven pinned original bodies support the identified contract conflict and required definition changes, but this bounded review does not replace the later complete S3 implementation review.
