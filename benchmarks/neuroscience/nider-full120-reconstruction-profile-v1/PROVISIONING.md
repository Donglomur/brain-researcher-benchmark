# Owner provisioning and evaluator boundaries

This is a source/BYO-authorized-assets release. Public source alone is not a fully provisioned benchmark submission. No input acquisition, container build, native compatibility run or model campaign is triggered by this package.

## Standalone comparison of a frozen response

The complete `comparator/` utility can compare an owner-selected candidate file with an independently authenticated private reference. An owner must provision the original120-field reference and its evidence, bind the canonical input workbook identity, select A or B, and independently pin a private owner-lock file. Populate the example outside the candidate-visible tree. Use absolute paths without symlinks and the exact public helper-module identities from SOURCE_MANIFEST.json. The reference stays private; owner lock, report and input-binding files may expose its identity and must not be published or mounted into candidate execution.

The example's sentinel paths and hashes are intentionally invalid. Do not replace a missing accepted reference with a candidate's output, generate a self-graded reference, or let the candidate select the owner lock, arm or target. `compare_local.py` checks file/module identities; its caller remains responsible for reference provenance, owner-lock admission and isolation. The example is not a protected-runtime configuration generator.

With an admitted private lock, a separately selected owner invocation has the argument shape:

```text
python -I -S -B comparator/compare_local.py OWNER_LOCK_ABSOLUTE OWNER_LOCK_SHA256 ARM CANDIDATE_ABSOLUTE CANDIDATE_SHA256 FRESH_PRIVATE_OUTPUT_ABSOLUTE
```

The output directory's parent must already exist, and the output itself must not. The candidate and reference limits are65,536 bytes. The utility produces OWNER_REPORT.json, SUMMARY.json and INPUT_BINDING.json privately; exit0 establishes completed comparison only. Candidate code is never executed by this utility. Protect the source, owner operands and output location from candidate modification.

## Rights and release modes

1. Public source and factual task specifications can be reviewed independently of the absent assets. Preserve source attribution and the original method bytes.
2. A BYO owner supplies assets under their actual access and use terms and keeps private references separated. This does not confer redistribution permission.
3. A fully provisioned public submission additionally needs verified asset access/redistribution arrangements and an admitted executable evaluation environment. This package makes no such readiness claim.

Do not upload authentic reports, completed owner templates, private manifests, keys or runtime inspection receipts to a public repository. The broader full-paper sensitivity/independence and model-performance studies are separate scientific projects, not invented gates on the scoped local endpoint.
