# Operator design versus participant exposure

All current files are design/review metadata. No operational view has been materialized or attested. Future public instructions must be derived and independently audited, not a recursive copy of this delivery.

A public output roster may name the source-required methods and configuration labels already present in the paper and opaque output IDs. It must not disclose other cases' event/calibration rows, hidden model-state details or reference output values. Source-derived discrepancies are qualification evidence, not public clues to A. Both arms get identical common numerical libraries; audited installed dependencies must not indirectly supply REVE's author implementation or checkpoint to A. If a baseline implementation is intentionally supplied as a common participant tool in a later condition, its source/asset exposure must be symmetric and named as a changed information condition.

The common task allows arbitrary participant-written learners and predictors. It does not embed an evaluator-owned solution in a convenient wrapper. Source parity is assessed by operator-side comparison; A is not required to use hidden source conventions it could not infer from the paper. A/B methods are developed independently with no cross-arm state or conversation memory after exposure. A participant who has already inspected B source cannot subsequently produce an uncontaminated A attempt; the attempt is labeled code-exposed rather than reset by a new directory.

No test-derived feedback is released until all coupled candidate and reference collections are closed. Source historical test-exposed traces, if separately authorized later, use quarantined historical material and never protected query targets. Publication excludes whole article bodies and full-text aliases, private identifiers, data, model states and reference predictions. Current static source files and provenance hashes alone do not prove these runtime boundaries.

Before any principal BCIC label is released, independent RV-11 developer/source contexts must already be admitted as specified in EXPOSURE_DOMAINS.md. No conversation, generated source, selected preprocessing, learned state, query/person statistic, log, feedback, cache or side-channel resource outcome can cross a conflicting domain. The same condition applies to independently fixed comparator developers. Public domain handles and local structural responses do not disclose private alias edges or target-bearing paths; all argv/env/mount/source/log projections require a physical isolation audit.

The public R-paper objective uses the patch-vector definition and explicit pooling/output fields. Native denominator discrepancies remain operator/B-source information; A is not expected to reconstruct hidden F.l1_loss conventions. A prospective sample-mean condition, if selected, must disclose the same objective to both arms.
