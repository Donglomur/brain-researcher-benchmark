# Development exposure domains

This is the normative S2 repair for REVE-D01. It applies to every family RV-01–RV-13, every R-paper/R-native/I-person/I-person-montage profile, both candidate arms and every reference. These are subdivisions of the existing complete programme, not new tasks or permission to remove cases.

## Selected design: isolated development contexts

The default is a separate method-development context for each (actor role, arm, purpose, scientific profile, family, dataset, query-support policy). A domain is not just a process or directory. It includes the human/model developer's conversation and retrieval context; source generation and edits; preprocessing and architecture decisions; configuration and search decisions; build state; training and selection states; logs, errors, diagnostics, caches and feedback. A source artifact inherits the exposure of its developer and all upstream artifacts even if it contains no explicit labels.

Before ANY development labels or label-derived feedback are released, S02/S04 must establish the operator-private person/recording/session/event alias graph and the complete domain roster. A conflicting developer must not first see principal labels and then author a nominally clean few-shot method. Forks are created from an admitted clean root before the first relevant exposure; cloning an exposed transcript, model session, cache or source tree is not a clean fork. If original actor exposure cannot be authenticated, its affected output remains exposure-unqualified or historical-exposed, never clean by assertion. Existing pretrained/model/developer prior-knowledge uncertainty remains G04/G20; this design does not claim a fresh prompt proves training-data absence.

A label-naive common source scaffold, scientific plan or immutable pretraining policy may be created before label release. Within each arm it may be copied only with a frozen clean ancestor receipt. After the fork, development may inspect that domain's permitted training/validation data and improve arbitrary participant-owned source locally. No code, hyperparameter, selected checkpoint, explanation, scalar diagnostic, failure log or developer conversation from a conflicting domain may return to a clean domain. The root programme controller routes frozen objects; it cannot use another domain's feedback to rewrite a learner. There is no post-label global method-development actor combining all domain outcomes before query.

Thus the benchmark still permits iterative agent-written methods and source-owned scientific preprocessing. It does not force an evaluator learner or prohibit learning from legitimately authorized development labels. The restrictions apply to where that learned information can subsequently travel.

## Private overlap relation and compatibility

For domain d, define Q(d) as its full protected event/person/recording support under that profile, and L(d) as the labels and label-derived feedback permitted for development. The identity resolver maps alternate dataset names, event IDs, source splits, files, sessions and repeated recordings to canonical private identities; it records uncertainty and duplicate/same-person edges. Public opaque IDs never replace this identity check. Unknown alias relationships cannot be treated as proven disjointness.

There is a directed conflict d -> e if an element of L(d) or any upstream developer/artifact label dependency can resolve to Q(e). Signal-only dependencies are checked separately: access to e's protected query recordings/person statistics also violates a condition that forbids transductive exposure. Build, source and method-selection inputs participate in these relations, not only model tensors. Grouping two contexts is allowed only after a private compatibility proof that every ordered pair is safe, every unlabelled-data dependency is permitted, purposes and source-access arms are compatible, and no ancestral exposure adds an edge. A connected component of the conflict graph is NOT a compatible group. Default isolated domains remain unless such a proof is qualified.

This check spans principal, LP, ablation, sparse, soup and few-shot families, source and protected split profiles, every dataset and XFT/pretraining reuse. Membership can change roles between profiles. A training event in a retrospective source profile can be a query event in I-person; the source-trained method cannot be relabeled clean for that query. A reference developer/model-selection policy obeys the same rule. References are independent role-owned banks; they are not candidate A/B states or information supplied to participants.

## Mandatory BCIC resolution

Principal BCIC development uses people 1–5 for training and 6–7 for validation, both source sessions. Few-shot retains ALL nine people, ALL 288 left/right events per person, five shot levels, twenty draws, and PT/XFT: all 1,800 original cases remain. Principal development labels for people 1–7 overlap many few-shot query events. Consequently, the principal BCIC developer, source descendants, tuned representation/preprocessing, trained states, diagnostics and search choices cannot enter the clean RV-11 method domain.

The RV-11 common method/developer receives no BCIC event labels from any principal, LP, ablation, soup or other family. Its permitted PT producer excludes downstream BCIC recordings, and its XFT producer uses the five specified external sources with authenticated target-person/alias exclusions. PT and XFT policies, NCM/EA conventions and regularization selection are frozen without any target-person label feedback. Original unknown historical exposures remain unknown; they are not silently repaired into historical author receipts.

After S13 freezes all domain source/method/policy states, S14/S15 create a fresh child domain for each case. Its only BCIC label exception is that case's selected 2N calibration events, removed from that case's query support. They may update only its case state using the already frozen recipe. The child may not revise the common source, choose another case's hyperparameters, export calibration feedback to its developer, or supply a sibling's state/cache. Different draws can disclose events that are queries elsewhere; both directions therefore remain isolated. PT/XFT share the same private draw support, not a mutable case actor. Identical label-free feature reuse needs the clean producer/dependency proof and reveals only admitted rows, never the global feature or calibration map.

A principal-trained BCIC method may be retained in a separately tagged exposed/historical diagnostic. It never satisfies the required inductive few-shot output. The denominator still contains the missing clean output; dropping people 1–7, changing a filename or starting a fresh prediction process cannot close it.

## Products and admission order

S04 produces exposure_domain_roster, private_alias_overlap_graph, compatibility_decisions and permitted_label_grants before S05 creates development actors. Each grant names its original source policy and dependency closure, not label values in public metadata. A context_admission_receipt binds the clean ancestor, declared model/developer provenance, source-access arm, role, domain, complete permitted objects, forbidden dependencies and the physical isolation qualification. Any uncertainty is explicit; a hash is not a physical-attestation substitute.

S05/S06 bind every source/build/method/search/preprocess artifact to context_admission_receipt plus monotone exposure_receipt. Training/validation access and source generation extend that receipt before their output can be consumed. No actor may self-declare a clean receipt, reset ancestry or omit an observed failed request. The operator independently records actual grants and original process/context custody. Reuse requires a reuse_admission_receipt proving the complete producer closure is allowed for the new consumer. Failure or unknown ancestry denies clean reuse without destroying the artifact or its cost.

S13 closes all source and selection within each domain; S14–S17 enforce case and query dependencies. S18 checks source-generation context, preprocessing, fit/selection and inference lineage against the private graph, not merely case labels. S19 still closes the entire candidate/reference programme before target grading or feedback. S20/S21 report every refusal, unknown exposure and conditional estimate. Rejected reuse is not an excuse to substitute an operator model or discard its failed computation.

## Actual visible fields and side channels

Private alias edges, complete Q/L sets, target-bearing source names and cross-family calibration maps stay with the operator. The public API exposes opaque domain handles, its permitted recipe and role, local input IDs and structurally bounded errors. Paths, argv, environment, resources, source bundles, logs, caches and response metadata must be projected from the admitted domain view. No shared writable filesystem, persistent conversation, retrieval index, tool history, stdout relay, shared mutable optimizer or unreviewed feature cache may join conflicting contexts. Synchronous failure descriptions must not reveal another domain's class or outcome. Declared budgets can be public and equal; observed private outcome-dependent resource information cannot become pre-freeze method-selection feedback.

A and B receive the same domain partitions, allowed data, local development opportunities, output requirements and total resource rules. B's authenticated author source is its only intended extra code information. An actor exposed to B source cannot create a clean A descendant. Independent references receive identical scientific exposure constraints. Runtime isolation, provenance completeness and all actual data alias joins remain open gates; no physical domains or labels were materialized in this design phase.
