## Actual JSON-lines lifecycle

Write one JSON object per line to that same original process and read each response. Descriptors below are genuine selected files, not inline invented approvals.

1. `{"operation":"initialize"}` creates the finite common output directories.
2. `{"operation":"contexts","authority":DESCRIPTOR}` materializes the reviewed complete A/B contexts through the original bounded source-copy code.
3. For each of `authoring` and `campaign`, `{"operation":"paths","phase":"authoring"}` or its campaign counterpart creates the complete deterministic physical paths and records each actual original custody. The response gives the full counts and namespace receipt. The closed `FactoredPreparation.entry(ordinal)` / `iter_physical_entries()` API gives the exact paths for host qualification without expanding or inventing a job roster.
4. Once those exact paths are genuinely qualified, send `{"operation":"qualify","phase":"authoring","profiles":DESCRIPTOR,"qualifications":DESCRIPTOR,"authority":DESCRIPTOR}`, and separately the campaign message. Profiles use the unchanged `runtime_layout.PROFILE_KEYS` contract, including actual source/authority/selected-input pins and explicit process/I/O/receipt limits. The qualifications document maps every physical token to exactly `paths`, `qualification`, `storage_qualification`. The controller checks complete coverage and exact previously prepared paths, publishes actual config/mount documents and then captures the admitted immutable native table. It does not create host qualification.
5. `{"operation":"author"}` executes all 50 original F authorings using the selected finite exchange slots. Feedback is concrete syntax/static/schema feedback only. Each attempt, raw provider response, usage, emitted source and failed check is retained. No empirical data or numerical feedback is exposed. Stop occurs at valid final source or the admitted original slot/budget limit. The response identifies the pending original records, not accepted authoring.
6. Obtain the 50 genuine independent authoring reviews, then send `{"operation":"compile","author_reviews":DESCRIPTOR}`. The compiler builds all groups/cases/reference actions, binds the actual original authoring records and produces the exact acyclic programme identity.
7. Obtain the exact E01/E02/E03 and checkpoint reviews, then send `{"operation":"publish","preconditions":DESCRIPTOR,"checkpoint_reviews":DESCRIPTOR,"authority":DESCRIPTOR,"campaign_budget":SEVEN_COUNTER_LIMITS}`. The result includes the actual pinned `OPERATOR_SELECTION.json` and executable argv for the existing campaign CLI. No programme action is run by publishing that selection.

The preparation process retains original failed work and stops on EOF before a complete selection. There is no automatic retry, fresh clock or rollback. Completed authoring clocks/costs are joined by the existing `authoring.consume`; preparation costs remain separately visible rather than erased.

Run the returned command, which has this actual form:

That finite bootstrap overhead and interpreter overhead must be included in deployment provisioning; no scientific budget/deadline is silently renewed. The actual task authority, original deadlines, resources and external review pauses remain unchanged.
