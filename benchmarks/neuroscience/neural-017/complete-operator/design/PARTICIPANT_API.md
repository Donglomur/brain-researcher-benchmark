# Full participant, reference and protected-scoring API design

These interfaces are implemented by the included source modules identified below and in README.md (Source provenance section). Native operation, data/source authenticity, licensed contexts, independent evidence and deployment remain external qualifications. No generic callback, stored benchmark score or declared method name can satisfy a production stage.

## Existing operative interfaces retained

The supported complete-operator entry is `nlb_entry.py`, with the exact preparation and campaign commands in OPERATOR.md. `nlb/operator_driver.py` and `operator_compiler.py` construct the complete programme; `nlb/controller.py::Campaign` drives it through the original authority, deadlines and global target-last barrier. The older L20 interface is a separate historical profile: its 110-second outer ownership boundary does not enlarge 20 seconds of candidate work, and no qualified legacy deployment is supplied by this component.

The included `nlb/arrays.py` validates complete prediction artifacts and `nlb/metric_core.py` implements the independent co-smoothing metric; `nlb/scoring.py` applies it to the complete protected bank after the controller has admitted collection and producer absence. The metric does not run participant code or itself prove that absence. Retain the exact six-array NPZ, 32 MiB compressed AND decoded limit, Unicode axes, strictly-positive finite values and arbitrary-method acceptance. Keep `candidate_minus_condition_co_bps` and the original R1 comparison unchanged. Bank comparisons add to the original metric rather than bypassing or replacing it.

## Objects and information roles

All JSON uses a closed schema, rejects duplicate keys/nonfinite numbers, uses explicit versions and bounded strings, and binds exact byte size/SHA256 descriptors plus source/parent identities. No command is constructed from unchecked path text. Numeric payloads use non-object arrays and explicit dtype/order/shape/units; untrusted pickles are forbidden.

`ProgrammeSpec`: canonical_id=NEURAL-017; exact dataset/session/split/public fingerprint; all574caseIDs via an operator-held roster descriptor; primary four arm identities; fixed agent seeds; diagnosis roster; information-view descriptors; reference recipes R0–R8; sources/runtime images/dependencies; metric pins; resource profile; immutable tool allowlist; scoring/release policy. Pre-registered before data exposure. The spec can name historical public descriptors but cannot include target-derived statistics in participant-visible fields.

`TrainingView`: train_counts_heldin[1721,140,137], train_counts_heldout[1721,140,45], original training IDs, observed/withheld unit IDs, condition IDs,140clock leftedges, public provenance. Counts are nonnegative integral spikes/bin. `QueryPoolView`: observed counts[574,140,137], recipient IDs/conditions, complete unit/time metadata and fixed validmask[574,140,45]. No withheld query counts, evaluation means, full diagnostic PSTH, behavior trajectories, target-derived plots, original test arrays, other task packets or old prediction outputs. The exact diagnostic projections are fixed in INFORMATION_VIEWS.json. Context-only keeps training withheld counts/conditions/time but omits all observed-neuron arrays and any states fitted from them; this supports real training of R0/R1/R2. Rate-only exposes a separate RateTrainingView with withheld-unit count totals[45] and total bin opportunities, plus output unit/time/case axes; it omits all trial-resolved counts and condition IDs. These are physical projections, not labels on an otherwise full packet.

`TrainingState`: exact method-source/dependency/config/seed/training-fold identities; full candidate search table (including unsuccessful configurations), complete fit counts and all required fitted parameters/normalizers/condition profiles; fixed selection rule; no query withheld labels. The state is source-owned files, with a stable manifest describing declared arrays and dimensions. Each scientific algorithm's producing process writes it; a controller cannot fabricate it from the method name. An arbitrary participant can store its own declared non-object state, interpreted only by its own source inside its isolated execution unit. State-file hashing authenticates bytes, not statistical validity.

`AdaptationState`: parent TrainingState, original QueryPoolView identity, allowed labels (training labels and observed query counts only), full declared adaptation graph and output state. GPFA must include combined train/query observed readout and subsequent training-withheld GLM fits. A frozen programme can learn query-dependent parameters under its precommitted unsupervised/transductive procedure; frozen SOURCE does not mean every parameter must predate query observations. Final state is immutable for collection. Case-specific alternate states reference this parent and remain local to that case; they cannot become another case's inputs.

`CaseRequest`: attempt/arm/seed/caseID, full recipient140-bin observed trace reference, same readonly full QueryPoolView, TrainingView, shared states and qualified reference-tool handles, original enclosing deadlines and budget debit token. All sources/policy/prompts are pinned. The broker creates a fresh conversation, filesystem, process group/container and namespace; no previous case transcript or response enters it. Case data may be accessed via the entire pool but other case's *answers* may not. The request carries bounded descriptors and a short task prompt, not the full primary text automatically repeated574times; papers and data remain available through metered read tools. Numeric output files are returned by descriptor rather than thousands of floats repeated in an LLM message. All actual prompt/tool tokens still count. Case order is fixed by the original roster; changing completion order never changes data roles or permits feedback.

`ToolCall`: monotonically numbered call identity, parent actor+case, exact source/config/input/state hashes and an explicit read-view; one of read_public, run_python, reference_predict, inspect_state, commit_prediction. read_public has paging/byte caps, but does not choose salient neurons using targets. run_python launches the actual arbitrary captured submitted source, not a trusted numerical surrogate. reference_predict runs the pinned producer's infer path against the declared state/query input; a lookup of an old output is only an explicit cache whose exact state/input/producer execution is already joined and charged. inspect_state exposes only declared training/adaptation artifacts, never hidden score state. No scoring, network, package-install, private repository or target-inspection tool exists.

`ModelExchange`: frozen model/provider/runtime identity, full system/user/tool messages, input/output/reasoning-token counts where reported, elapsed/cached-token accounting, request and response descriptors, termination/error. Unknown provider token classes stay unknown and conservatively consume the reserved allowance; do not present unreported reasoning compute as zero. A source-owned `investigation_actor` must call the chosen model adapter, parse tool requests, run the tool process, feed the returned observation to that SAME case context, and consume its actual final answer. A scripted fabricated response is an engineering fixture, not an LLM run. The included `nlb/openai_protocol.py`, `openai_transport.py` and `openai_gateway.py` provide the concrete Responses path; a model, credential, service/host qualification and actual model execution are not supplied or qualified by that source.

`PredictionShard`: exactly one case's140×45 expected-spikes/bin, original unit/time/recipient axes, finite strictly-positive entries including every masked position, source/state/call ancestry and private resource/terminal receipts. Numeric arrays must be emitted by submitted-source processes; text saying 'use R7' is not a prediction. The broker can serialize the specified complete numeric result, but cannot fill missing outputs with a baseline without a declared separate fallback policy (none selected). F may emit all574 at once using the existing NPZ route; the collector logically partitions and rejoins it without rescaling, rounding or losing support. I may emit per-case shards; final public submission uses the same complete six-array NPZ. Float32 or float64 are allowed within the existing size/domain contract.

`AttemptTerminal`: success/invalid/timeout/resource/worker failure/unresolved containment/reference unavailable; original worker exit/status, bytes/CPU/RSS/wall counters with explicit unknown fields, all process/group identities and absence proofs, first exception with original observation custody, secondary cleanup/serialization errors, durable receipt state. A failed durable write is not a successful receipt. In-memory emergency custody cannot itself authorize scoring. No replay to recover a missing result; keep the attempt consumed. If unresolved process state or lost terminal evidence remains, halt before any private target release.

`CollectionCommit`: planned versus attempted/completed574case IDs (or one complete F panel), required reference identities, complete support, immutable copied output hashes, all original receipts and global source/prompt/state bindings. Reject duplicates/missing/extraneous IDs, wrong parent/source/view, stale cached state, contradictory unit/time mappings, or unknown containment. Preserve failures rather than filling gaps. Output union and commit serialization are charged under the original enclosing budget.

`ProtectedResult`: untouched original co-bps and R1 delta, additive complete bank comparisons, full private trial-contribution ledger, paired-mode/ablation summaries, errors/coverage, multiplicity and uncertainty descriptors, cost/exposure scope. All case-level target derivatives stay protected. The report actor gets a separately projected aggregate only after global collection. The included `nlb/reporting.py::grade_report` checks aggregate scalar/scope facts; separate scientific reasoning assessment remains required and never alters prediction scores.

## Full production graph and global barrier

1. Operator authenticates source/descriptors without opening empirical bodies during this phase. In future authorized operation S01 authenticates target-free planned roster metadata and S04 freezes the complete source/policy/roster/resource/rubric and shuffle commitments before raw activity/target-bearing reads. Later qualified acquisition/preparation reads the exact selected NWB, not a guessed related file. Included `nlb/raw_prepare.py`, `raw_counts.py` and `raw_primitives.py` preserve original trial IDs, units, masks, source clocks and complete raw-support plan; no fresh rank/quality selection based on outcomes.
2. Operator preparation necessarily handles target-bearing raw counts while constructing the isolated target artifact. This is a separately authorized, nonparticipant preparation role; no scientific method selection or target-derived summary is exposed. It is not falsely described as zero target access. Prepared targets are sealed before participant release; the campaign target-last requirement governs all subsequent assessment/scoring reads. Existing exact prepared artifacts may be reused only with qualified original preparation lineage. Sparse1ms aggregation→5ms count conservation and official trializer parity precede public projection. Select only declared official train1721 and validation574 and retain every source row. Reject overlap/missingness/nonintegral/overflow before exposure. Full conversion is an operator operation, never delegated to an unrestricted participant.
3. Project TrainingView and QueryPoolView from the allowlist; store QueryTargetView separately. The official make_eval_input_tensors('val') returns withheld labels, so handing its full dictionary to an actor is forbidden. Source/PSTH helper bodies can be read as code; invoking `_make_psth` as a public predictor is forbidden because it reloads/smooths target-bearing source.
4. Consume the already frozen S04 ProgrammeSpec. S05 qualifies native math and actual R0–R8 training/search/inner-development convergence/domain/difficulty and training-only feasibility; no574 assessment label or derivative is read. S06 creates the legal observed-query adapted bank, including GPFA final training-label GLMs after its observed readout. Only these development/production checkpoints admit agent use. Store all original selection/config/state and resource receipts; assessment competence is later S13/S14, not a pre-study callback.
5. F runs its captured arbitrary programme, including chosen training/search and allowed query adaptation. I runs a preparation actor, freezes shared state, then574fresh actual case investigations. Every scientific job is a real isolated submitted-source process. All branches use the same intended data, tool library and total caps; diagnostic projections physically remove forbidden inputs and reference states.
6. Stop and reap every owned worker/descendant; bind original first causes and final counters. Collect all outputs. Required reference families and all registered arms/seeds/diagnostics must have complete immutable planned support. If one arm fails, preserve its coverage and counterpart outputs but no complete paired claim. No partial target-release permit is selected. A missing required reference/arm/case keeps the target loader closed and produces an operational incomplete disposition. If a later post-barrier uncertainty/report step fails, valid earlier complete574 point scores may remain explicitly scoped descriptive evidence, never a completed paired/diagnostic inference.
7. After that sealed preparation boundary, the global target-last scoring barrier verifies the collection union and absence/custody/budget statements for all producers, not just the last job. This includes reference construction, case tools, adaptive cache writers and report predecessors. No target read after a superficial 'stopped' field or an unconsumed terminal.
8. A separate isolated protected worker loads the target package once, applies unchanged metric to arbitrary positive predictions, builds complete signed paired ledgers and uncertainty, and commits results. The same private mean normalizes all absolute scores. No target is passed into method dispatch or validation failure handling.
9. A distinct report actor receives only committed aggregate feedback after all predictions freeze; evaluates factual correctness and predeclared scientific interpretation rubric. Its source/responses cannot feed another primary attempt. No judge sees hidden labels or grants automatic correctness for echoing the reference conclusion.

The new outer host must propagate the original minimum(campaign,arm,actor,enclosing tool) deadline through source snapshots, input reads, state loading, case prompts, process start/wait, stream collection, all descriptor closes and final commit. A token/tool timeout is not a fresh budget. Reserve termination and final-receipt capacity before ordinary output writes. Validate final per-job CPU as well as cumulative CPU, including post-reap observations; measurement/encoding/write errors preserve first cause and explicit unknowns. Physical isolation, cancellation and current resource probes remain gates, not claims inferred from this design or historical Docker receipts.

## Included complete implementation and remaining qualifications

The included coordinator (`nlb/controller.py`), operator compiler/driver, executor and runtime source preserve the primary arms/global barrier, complete R4/R5 producers and dependency pins, state/query-adaptation lineage, model/tool broker and fresh-case actor, complete collection, terminal/resource custody, protected comparison bank and aggregate reporting. README.md (Source provenance section) and REFERENCE_METHODS.md map the actual methods; arbitrary participant code is not restricted to calling predefined reference functions. Source presence does not supply current native isolation, full source-method authenticity, real data, model/provider operation, numerical qualification or independent checkpoint evidence.

## Stage-bound evidence APIs and external evidence

`QualificationEvidence` has a closed checkpoint ID, exact ProgrammeSpec/source/config/fold/input-role descriptors, producing original process receipts, complete resource/cost lineage, declared support, result status, limitations and prohibited-lineage attestations. It cannot be an opaque passed boolean or an old score. `nlb/evidence.py::Evidence` and `nlb/controller.py::Campaign.admit_operator_evidence` consume the stage-bound evidence products in GATE_EVIDENCE_LINEAGE.json; no stage can request later evidence, and failure stops rather than selecting a replacement. The source package supplies no successful evidence descriptors or issuer. Actual original evidence and independent judgments remain external.

`DevelopmentCompetenceCertificate` (E09/S05), with the closed required-field/support contract in DEVELOPMENT_QUALIFICATION.json, joins E07/E08 and every required R0–R8 development record. It binds native source fold/search selection rules, the explicitly added R0/R1/R3 training-only qualification exercise, all counts/convergence/warnings/domain/difficulty results, fixed source/policy membership and source-specific selection optimism. Its target role is inner-development-within-TRAIN, never QueryTargetView; its recipient is the trusted admission controller, not an unmetered participant feedback channel. `TrainingFeasibilityCertificate` E10 joins original measured training/inert costs to the unchanged expert and per-arm envelopes. Neither can certify fresh574 performance.

`AssessmentQualification` (E15/E16 after S12) binds the complete barrier/CollectionCommit and exact full574 bank, all100 groups/2 tool routes, signed65 contrasts, uncertainty/diagnostics and unavailable statuses. It cannot grant an upstream development, fit, policy or reference-choice capability. `ClaimDisposition` S16 lists all24 gate/checkpoint outcomes, exact complete support or missing evidence, valid earlier point estimates where permitted, uncertainty/report failures, resource/exposure/primary gaps, and allowed/forbidden scoped claims. The incomplete abort variant contains metadata only and explicitly has no E14/E15/E16/E17 permit or score. No source/state/prediction mutation is exposed by either API.
