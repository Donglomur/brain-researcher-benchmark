## Storage is a real kernel check, not a declaration

The source-selected Linux profile requires **256 distinct stage tmpfs mounts**
(output and work for every stage), plus a separately bounded campaign tmpfs mount
for all exports, fitted-state copies and private reports. All 257 mounts initially
must be empty, ordinary, private 0700, owned by the positive real/effective host
UID that also runs the candidate container. The policy holds directory FDs,
checks exact mount IDs/devices/inodes/ownership, current mount-table aliases and
nested mounts, writable/private tmpfs status, and actual `fstatvfs` byte/inode
ceilings. It admits all roots before the first stage, rechecks the relevant roots
before every stage, then rechecks all roots and closes every held FD. It never
mounts, binds, provisions, chowns, installs or emits a qualification certificate.

The output and workspace capacities must independently equal their existing
stage ceilings. A single larger ancestor volume is insufficient. The campaign
capacity covers the entire retained candidate reserve plus the separate
premarker export, both source capsules, reference predictions/fitting records,
report and failure allowance. Its conservative capacity overlaps the separate
stage capacity reservation; configuration explicitly accounts for the sum of
all selected kernel ceilings. It does not claim that empty tmpfs capacities are
preallocated RAM or that those ceilings substitute for an aggregate host-memory
limit. External provisioning must supply and qualify sufficient memory, CPU,
FDs, namespace exclusivity and the original whole-process owner. The policy
holds 257 FDs plus transient traversal/stream FDs; no native default is assumed.
All stage artifacts remain on their original mounts for review. No teardown,
automatic deletion or retry is performed.
