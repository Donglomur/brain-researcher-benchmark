# Reproduce three NIDER meta-analysis results

Using the supplied complete paper and scientific study-summary workbook, write one R program that recomputes the three association meta-analyses. This task covers the original input and three hypothetical procedure-check inputs. It does not ask you to reproduce every analysis in the paper or discover a new biomarker.

Your arm is fixed by the task operator. In A, use the supplied paper, scientific data and common task instructions. In B, you also receive the pinned official R script and its license. Both arms have the same question, inputs and execution limits. The authoring environment is offline: use only its supplied materials and permitted local tools. In A, do not retrieve official analysis code through links in the paper or other services. Prior knowledge is not claimed to be erased by these restrictions.

This is a **method-specified reproduction profile**. The common per-case request states the scientific scale and selected author-procedure conventions, including duplicate-row handling. Those task clarifications are shared by both arms; they are not all asserted to come from the paper alone. The A/B comparison therefore concerns access to the official implementation given that common specification. It does not measure unaided inference of every method from the paper.

Submit `solution.R`. It must run as `Rscript --vanilla /candidate/solution.R` in the supplied R 4.3.2 / meta 7.0-0 environment. It reads `/input/request.json` and `/input/study.xlsx`. The complete article is at `/paper/article.pdf`. B additionally has `/input/official_source.R` and `/input/LICENSE_NIDER_CODE.txt`; A has neither. See `DATA_SCHEMA.md` and `OUTPUT_INTERFACE.json` for the data and response contract.

Write exactly one JSON response to stdout. Use the supplied case identifier and workbook digest. Return all three contrasts and all four numeric quantities per contrast. Compute the response from the current input rather than copying original-paper values. Diagnostic text belongs on stderr. Do not add explanations, target paths or execution-certification flags to the response.

The evaluator freezes your submitted program and runs the same bytes on all four cases in separate environments. You may inspect the original input during authoring. The hypothetical inputs are available only to the frozen program in their assessment invocations; their expected answers and generation parameters are not supplied. No intermediate score is returned. Scratch files do not carry between cases.

Each assessment case has one CPU, 2 GiB RAM, no network, a read-only root filesystem, private `/work` and `/tmp` scratch areas, and a 30-second execution allowance. The output limit is 64 KiB per stream. Complete valid output and successful process closure are required. Original-paper reporting agreement and the three procedure-check results are reported separately. The fixed reporting resolution is 0.01 for Pearson r and 0.001 for p. Agreement uses open nearest-reporting bins: exact boundaries or unresolved reference-boundary cases are indeterminate, not automatically accepted. Counts must agree exactly. Return computed quantities rather than truncating them to match printed values. This profile does not score R print formatting, heterogeneity diagnostics or confidence intervals.

Include a brief `DEVIATIONS.md` with the submitted source, describing material assumptions, interpretation differences and any failure to reproduce the requested procedure. This is review provenance, not a runtime JSON field or a scored metric.
