## Closed submissions and rounding diagnostics

The fixture-only FixtureControllerInterface in [closed_interface.py](closed_interface.py) accepts a complete 2232-byte packet or an operator-selected ordinary file after the operator has ended candidate execution. It returns only an ingestion receipt: schema, ordinal, byte length, hash and the caller's closed-packet designation. Full requests, scores or refusals, and rounding diagnostics go to the operator's supplied private writer. A coherent but wrong source-category mask receives the same receipt shape as a valid packet; its refusal stays in the private outcome.

This adapter does not execute or isolate candidate code, prove candidate closure, protect Python memory from an untrusted caller, or establish authentic reference provenance. The writer and fixture reference must remain outside candidate-controlled code. Reference bytes are immutable, mutable pin/context inputs are copied before use, and all admission/file failures consume the fixed six-submission allowance. Ingestion is not successful scoring.

The existing kernel, certificate parser and continuous scorer are unchanged. The new rounding module reuses the accepted exact binary64 cell and tie-to-even expressions. Its fixture schema explicitly reports authentic_source=false and production_authority_claimed=false; it tells the caller to handle diagnostics privately rather than claiming it can enforce privacy. Production admission still refuses every fixture.
