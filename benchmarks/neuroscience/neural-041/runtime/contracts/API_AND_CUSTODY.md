# Actual source composition and remaining external producers

The original terminal entry is runtime/source/bootstrap.py; the outer operator bridge is ../../run.py. An independently selected future operator supplies exact profile/signature/trust-key pins, original monotonic origin/deadline and required --host-read-bytes. There is no default or inferred capacity. Bootstrap admits the whole known profile/signature/key read group before any capture, verifies the signed profile, requires its host_read_bytes to equal the original supplied cap, then validates and admits the entire finite source group before any source capture. Its original argument Namespace retains a live owner before I/O, independently of exception attachment. The account retains admitted reservations, exact attempted/returned member and byte prefixes, failed admission and unknown effects without refund. Entry carries that already admitted debit into its remaining whole-invocation Budget; it does not retrospectively authorize it. No trust key, signature, deployment image or qualifying evidence has been issued or inspected here. A locally manufactured profile is not independent authority. Bootstrap/native/Python startup physical costs remain an explicit external measurement requirement.

The concrete chain is bootstrap.run → entry.run → admission.verify_signed/source_capture → transport.prepare_native → Engine.execute → launcher.main → preparation_worker.run → preparation.run/Native → captured private epochs. Entry then calls projection.build to copy one actor-safe pool in opaque-ID order with normalized file times and construct complete held-patient views. Original source-order epoch inodes are never mounted. Campaign.run calls schedule, Transport.run, Engine.execute, launcher.main and worker.run for every investigate/fit/predict phase. The worker's actual API calls epoch_io.load_epoch, reference.features/fit_state/predict_state or the captured participant method. Model pickles are opaque on the host and load only inside the same isolated participant prediction namespace; no host model deserialization occurs.

Preparation consumes a future authenticated full 44-asset roster, complete clinical/exclusion map, private identity key, exact output plan and native-format/resource limits. The clinical/output-plan producer is external and currently missing. Source/asset descriptors are not measurements and cannot generate clinical authority. A new or absent asset, unknown region, incompatible unit-electrode schema, malformed clock, unresolved source preprocessing or incomplete trial mask is a hold. The documentary source and exact external roster do not close those input gates; see ../../EXTERNAL_INPUTS.json.

The task uses the existing N042 concrete Docker Engine v1.47 source. Its N041 derivative isolates ownership labels, retires the exact immutable container ID before producer-output reads, and retains original operation/retirement Attempt owners before lossy metadata conversion. Engine.execute propagates the raw first retirement exception after a natural body return; an earlier body failure stays first, with every later retirement/publication occurrence retained even when the same exception object recurs. The actual outer Entry/Campaign owns that Engine and its live child owners. Retirement is marked attempted before its setup/call and is never retried after uncertain effects. It performs real HTTP create/inspect/start/stats/delete/absence-confirmation calls when later executed, with readonly per-file mounts, no network, nonprivileged identity, readonly rootfs, CPU/memory/PID limits, bounded scratch, finite response/log/output extents and hard-quota/enforcement-lag qualification requirements. A dictionary or callback is not an alternate native implementation. Source-level checks do not establish real daemon/host enforcement. Unknown create/remove/HTTP effects remain unresolved and are not retried as successful capture.

Transport authenticates every source, request, view, method, epoch and model descriptor, binds worker receipt to original request/source/clock and independently captured output hashes, and retains the original result object. Barrier accepts only an object retained by that actual Transport, not a matching external dictionary. Every fixed/adaptive/reference prediction must close before the protected targets are re-opened for score.run. All expected cells and exact query IDs are required. References cannot feed target metrics to actors. Scorer/checker run in the trusted evaluator parent under the original budget; whole-parent native resource enclosure/physical accounting remains a deployment gate, not an inferred property of Python timers.

Campaign's original Attempt owns the engine, transport, barrier, raw first failure and each later occurrence. Method lookup, cleanup, final cost observation and failure publication are independently protected; exception stringification is not used. Entry retains the earlier invocation owner across preparation, projection and scoring. The original error is rethrown, with the owner attached when possible; attachment failure is retained. Output files after a failure are prefixes, never a valid result. A consumer must require normal original invocation return plus complete records and no failure; a REPORT.json or COMPLETE.json file by itself is not sufficient. No central consumer/registration/installation adapter has been activated.

The exact signed profile fixes source image, source manifest, protocol, private inputs, roots, native output plans, resource limits, method slots and all24 qualification evidence rows. Numerical resource values have intentionally not been invented from a small trial: full 44-session/36-patient scientific feasibility remains unmeasured. Actual preparation and all cells share a prospective aggregate native CPU/output cap; the actor's two or three phases share one episode CPU/wall cap. Adaptive authoring/tool calls consume that envelope. Fixed/adaptive source preparation, view construction, model serialization, prediction capture, protected scoring and publication remain in the original invocation timeline. Physical HDF5/daemon I/O and interpreter startup are not claimed measured by logical byte reservations.

The existing daemon transport bounds its local logging driver, but this source does not retrieve and retain daemon stdout/stderr prefixes before removal. It does retain original host exceptions, operation/config/source identity, the known resource prefix and unknown effects. Full native log observability and whole-parent physical resource accounting therefore remain concrete missing deployment/observer joins, not completed assurance. They must be resolved before runtime qualification. The preparation output-plan producer likewise remains external; no source-only count or dictionary manufactures an issued plan.

Required external producers remain: archive/rights verifier; full patient/session/asset joins; blinded clinical bundle/anatomy/artifact adjudication; preprocessing/clock support evidence; complete preparation-output plan; actual immutable source/image and signed operator selection; native isolation/quota/descendant and host observer deployment; competent references and independent numerical agreement; real strategy/provider/model/cost accounting; full-scale feasibility and independent scientific qualification. These gaps are explicit source input/deployment gates, not placeholders returning success. No authentic body, reference output, held target or model has been opened in this construction.
