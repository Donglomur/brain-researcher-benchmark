# Figure2B paired operator

This additive component preserves all 15 accepted V4 numerical files. The original README describes that unchanged numerical component; this document describes the new task-local operator. The installed behavioral route, canonical record and runtime manifest are not modified here.

`python operator_entry.py --inspect` reads bounded source and hashes only. It does not import the candidate/Harbor/scientific modules, read data, run Docker, obtain a credential or contact a model. Its fixed 4 MiB source-body cap, 2,048-entry inventory cap (including directories), depth64 bound and cooperative 10-second deadline are not a runtime grant. No scientific readiness or completed-study count follows from source inspection.

The direct runtime actions are `stage`, `run-pair` and `grade-pair`. Runtime startup requires `python -I -B -X pycache_prefix=/explicit/operator-owned-empty-cache operator_entry.py ...`; the explicit prefix must be outside the source tree, empty, owned by the operator UID and mode0500. The runtime entry verifies this before any project import and adds only the admitted package root. The three-token `python operator_entry.py --inspect` remains source-only and does not import project code. Each requires an exact request JSON body pin and explicit cumulative read/write/seconds/max-output operands. The CLI's closed request schemas are visible in operator_entry.py. There are no default datasets, models, production capacities, authority objects, provider keys or grading thresholds.

This pinned Harbor profile requires a positive integer CPU count. A fractional value is refused rather than rounded or replaced with an informational default; the same selected integer governs actual Docker/cgroup limits.

`stage` uses the existing source-exact view constructor and full derivative identity. A receives the complete paper+data+contract view; B receives identical common bytes plus the three accepted code-view additions. It authenticates operator source, runtime/capsule/qualification descriptors and full input selections; stages the exact pinned bodies; and writes the pre-release execution plan. It does not execute an agent. Both future arms are frozen to the same Responses capsule, prompt, model/settings, terminal tools and resource ceilings. The code exposure is the intended treatment difference.

The selected host GID receives traversal of only the fresh stage/view parent directories 0710 and read access to the four exact operand files 0440. Private records/captures/grade remain 0700; no ancestor or unrelated directory is changed. The operator must provision ancestor access and any external qualification reports for the selected host identity. Instructions are refused if Harbor's exact universal-newline/leading-canary handling would change them; the operator never silently normalizes a selected prompt.

`run-pair` invokes a fixed captured Harbor agent/trial/environment successor under the selected Linux cgroup-v2 host. The host validates exact Python/Docker/framework source and image/daemon identity, real preprovisioned per-arm tmpfs capacity, selected UID/GID and limits. The accounting parent contains a distinct host process leaf and the Docker child subtree. A process group alone is not complete descendant containment. Normal and recovery framework copying is suppressed; actual bounded terminal transport replaces Harbor's otherwise unbounded complete-line accumulation. Timeout/output-overrun aborts the entire arm and requires actual container/descendant cleanup. Candidate tools never receive the host Docker socket, model credential, other arm or protected grading directory.

The exact Linux runtime operand schema and lifecycle are documented in HOST_PROFILE.md.

The Responses adapter has one fixed official endpoint and one terminal function. Model identity, sampling/reasoning configuration, opaque credential-file metadata, finite request/response extents and resource reservations are explicit. It carries full raw response items, encrypted reasoning and tool-call ancestry; there is no hosted tool, retry, redirect, automatic truncation or hidden conversation. Tool calls execute only through the fixed Harbor environment source. A failed, incomplete or unknown provider outcome cannot become a grading success even if its reservation is charged. Successful admission checks terminal provider status, full usage arithmetic, request/response/history/tool joins, local transport closure and independent host/container closure.

Each dispatched maximum input/output reservation is charged without refund; observed usage is reported separately. Reasoning tokens are a subset of output, cached tokens a subset of input. Reservations and byte caps do not by themselves prove pre-billing input-token bounds for an arbitrary selected model. Input-token estimation/provider semantics require the selected independent transport/model qualification; an observed excess is retained and refused, not retroactively clipped. Each HTTP dispatch also reserves the full capped response plus probe and its immutable failure-prefix copy before touching the transport. Failure publication uses the independently precharged child receipt Budget; the original error/prefix/state and secondary publication failures remain distinct even when actor accounting is exhausted. Missing durable evidence is explicitly failure, never successful closure. Local socket/process termination is not proof of remote cancellation. No native or provider qualification was performed during this source build.

After every producer is closed, the collector streams the exact 37 output members into private custody, authenticates shape/dtype/hash/identity and calls the unchanged complete field validator. It retains partial failures and never turns them into scores. The source retains all 15 participants, four conditions, 36 output fields, actual source window/reduction/missingness semantics and complete support masks. Nothing is thinned to fit storage.

Only after both captures close does the operator produce the existing final grade plan and observations, bound to the earlier execution plan. `program` means the frozen agent/capsule identity, not a falsely pre-known generated solution. `grade-pair` reauthenticates this binding and the actual host evidence, then consumes a separately supplied operator grant and calls the unchanged V4 protected grader. There is no authority factory or private-reference shortcut. The final comparison preserves signed residuals, exact discrete/undefined support, operator-selected numerical tolerance and all original holds. It is numerical reproduction, not significance, causal inference, a new cluster endpoint or a frontier-improvement reward.

Production storage/transfer sizing is separate from the full-shape invented construction checks. A source-only extent calculation retains full nominal 36-field geometry and both-arm sizes before staging; runtime hard limits must cover complete output plus the bounded JSON manifest. The operator-selected allocations must also cover work/logs, staged input copies, private captures, reference and residual files. Inspecting an existing tmpfs mount validates its actual hard capacity; an ordinary bind path or a flag saying quota exists is refused. Later unmount ownership stays with the external provisioner after the retained captures no longer require it.

A clean checkout supplies source, dependency identities, schemas, inspection and the actual future call path. It does not supply authentic data, qualified Linux/rootfs/Harbor/model/image/storage installations, credentials, scientific execution authority or MATLAB/FieldTrip parity. These remain explicit, separately admitted operands. This public package contains authored source and synthetic generators only. It contains no original MAT files, derived authentic answers, credentials or operator grants. Rights to distribute authentic data and supplied paper/code views remain external release gates.
