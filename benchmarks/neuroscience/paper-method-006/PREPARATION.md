# Exact external source preparation

The public package is incomplete until all35 required ordinary upstream members are actually present and verified. UPSTREAM_SOURCE_MANIFEST.json is expected content, never evidence of possession. There are no automatic fetches or installs. A separately authorized source-only preparation uses:

    python prepare_upstream.py prepare --destination /absolute/private-parent/new-kilosort-tree --timeout-seconds 30 --wall-seconds 600
    python prepare_upstream.py verify --destination /absolute/private-parent/new-kilosort-tree

The numbers above are explicit examples, not scientific policies. The caller must choose finite request and operation time bounds. The preparer accepts only the embedded exact manifest and immutable official raw.githubusercontent.com URLs, with redirects, proxies, changed encodings, wrong lengths/hashes/Git blobs and unexpected members refused. All35 paths, aliases and LICENSE are required. It streams at most64KiB, limits each member and total source to1MiB, directories to64 and file count to35. It performs no upstream code import or execution. Python/SSL/filesystem native libraries are ordinary implementation dependencies, not benchmark native qualification.

Use a user-owned parent with no group/world write and no symlink path component. No existing destination is reused, repaired or overwritten. An owned staging tree is built through retained no-follow directory FDs with exclusive member creation, complete write loops and independent stream/file cleanup. Every member is authenticated, synced, sealed read-only and independently read back before publication. Atomic no-overwrite publication uses Linux renameat2(RENAME_NOREPLACE) or Darwin renameatx_np(RENAME_EXCL); other hosts/filesystems refuse without an overwriting fallback.

Darwin requires the moved root to remain writable. Only that owned root stays0700 through atomic rename; children and files are read-only and already verified. The retained root FD is then sealed0555 and synced, followed by parent fsync. Verification rejects a writable root. A post-rename failure reports published=true with the exact pending seal/durability stage and raises the original error; it does not delete the visible tree, overwrite it or retry. A prepublication failure attempts each owned cleanup independently and retains secondary errors and any partial stage. Inspect such a result explicitly. A verify success establishes current byte possession, not completion of a previously failed durability operation.

The operator API is run(catalog, plan, output_root, *, limits, upstream_root). It verifies the actual tree before programme import, requires a fresh worker with no preloaded kilosort modules, then provides the external root to the original import route. Scientific source, catalog/plan rules and16 operations are unchanged. Same-owner mutation after verification, OS/network stalls, physical CPU/peak allocation, dependency installation and whole native mount/isolation/source-issuer custody remain unqualified. Bounded extent and timeout checks are not a kernel resource guarantee. The fixed legacy native/source paths remain genuine deployment obligations, not claims that this CLI creates mounts or issuers.

The invented local engineering tests exercise publication, identity refusal, partial writes, symlink/refusal and cleanup failures; no actual upstream dependency fetch or scientific/native benchmark execution was performed. Source and rights/native qualification remain held even after successful future source preparation.
