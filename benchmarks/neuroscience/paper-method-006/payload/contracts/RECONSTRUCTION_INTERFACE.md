## Failure, cost and isolation boundaries

All planned jobs receive returned-unqualified, required-unscorable or failed
dispositions. Dependencies of failed jobs remain unavailable; later independent
jobs still run. Missing outputs never become zero scores or a reduced average.
First raw exceptions are retained before cleanup; distinct actual catches of the
same raw object remain distinct occurrences. Explicit occurrence propagation
does not add a duplicate catch. Input/output buffers and descriptors retire
independently. Partial files and library effects may exist after failure and are
reported as unknown pending outer capture.

The local Budget tracks logical reads/writes, admitted array extent and selected
work counters. It is not a physical CPU/RSS/descendant/FD/allocator observer.
Numerical libraries, sorter subprocesses, GPU work, figure internals and raw
recording readers require a genuine outer native owner. No such deployment is
qualified here. The complete inherited native/source contracts remain required.

The terminal report file is a pre-publication snapshot. The returned original
owner and cost map include the publication tail and any publication failure.
No recursive second publication is attempted. An ordinary report can describe
unknown physical work but cannot make it zero or authorize a retry.
