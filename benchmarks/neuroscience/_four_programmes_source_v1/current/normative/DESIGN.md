## Trust boundary and actual earlier occurrence

The trusted external harness launches the installed operator entry before any participant, model, scientific worker or task request is admitted. This is the trust boundary. Its selected installed executable/source closure, dependency environment, native deployment and qualification-issuer identities are part of the installed operator profile. A source author, participant request, ordinary root-owned filename or incoming JSON record cannot choose or replace that profile.

The installed entry is a fixed source-owned route. Its one fixed invocation operand is a canonical InstalledOperatorLaunchAnchorV1, at most 8192 UTF8 bytes, chosen by the trusted harness for this original launch. It contains the expected complete selection extent/SHA256 and the exact original reservation, origin/deadline, attempt/nonce, launcher/source and launch identity. All bounds are therefore available before any FD/body effect and intersect the immutable installed profile maxima. They are accepted only in that externally qualified installed-entry launch domain. They are not a public participant API or a later worker argument. The expected digest contains no claim of qualification by itself. The implementation must also authenticate the actual installed source and environment, original launcher/current process and protected inherited occurrence, and semantically validate all required earlier qualification reports. A launch outside the qualified entry domain refuses even if its bytes and digest match.

The single intake occurrence is fixed FD197: a readonly, immutable, sealed memfd created and supplied by the external harness. It is distinct from later worker FD198 and FD199. The actual inherited FD enters the bootstrap custodian immediately, before fstat, flag, seal, offset, clock, read, parse or validation operations. Its complete declared extent is at most 1,048,576 bytes and also fits every stricter installed original reservation. The reader checks actual regular-memfd identity, readonly access, all four write/grow/shrink/seal seals, original zero offset and exact extent. The fixed complete-body read and separate positive EOF read retain every returned prefix before later validation. This is not the future RootChannel or RootAuthorityFiles; both of those already require the qualification that Q1 supplies.

The original FD is closed once, with the local slot cleared before close. Unknown close prevents a successful admission and never retries a reused integer. No duplicate or reopened alias is necessary. FD197 is closed before Q1 returns and before any later child launch; it is never included in worker pass_fds. A genuine installed platform must qualify this inherited occurrence, source isolation, readonly sealing, process lineage and exclusion from participant access. Those real tests are not replaced by structural controls. If a selected platform cannot supply this exact transport under its existing descriptor and resource limits, admission refuses. No inherited FD, root cap, clock or child keep-set is silently enlarged.
