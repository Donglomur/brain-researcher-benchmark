# Linux engineering verification

This additive CI route checks the unchanged Horrocks constructor and 42 synthetic controls. The original eight construction files remain byte-identical. This addendum supplies the Linux verification route anticipated by their README; it changes no paper endpoint, LDA policy, scientific input gate, task count or readiness claim.

The proposed job uses Ubuntu 24.04 and exact CPython 3.11.18 through the workflow's existing pinned checkout/setup actions. No package or dataset is installed by the harness. Root must observe the actual PR run before claiming Linux compatibility. Earlier local Python 3.11.5 results establish only that earlier platform.

The trusted CI setup creates a fresh network and PID namespace, mounts its private proc view, drops to the fixed non-root UID65534/GID65534, clears supplementary groups and all capabilities, enables no-new-privileges and reinstates the parent-death SIGKILL after the credential change. Python receives a cleared environment with only explicit PATH, LANG and the selected interpreter's canonical lib directory. The pinned setup-python action configures that Linux library path; the wrapper does not inherit an ambient search path. Preparation and namespace admission bind the loaded libpython file by canonical path, size and SHA256 (a separate runtime operand capped at64MiB per check, three checks and192MiB total). No runtime binary is downloaded or inspected during source preparation. The setup uses existing sudo, GNU timeout, unshare and setpriv; their actual availability and behavior are checked by CI, with no fallback that weakens isolation.

The original absolute 30-second attempt starts before namespace entry. A separately bounded 40-second outer GNU timeout forces failure cleanup. The inner owner is PID1, verifies namespace/credential state, invokes the exact pinned harness once, and retains complete bounded stdout/stderr, the result, its source identities and exit/reap observations. No retry is performed. Terminating namespace PID1 terminates its descendants. The outer command's actual status and elapsed time are admitted separately; late, forced, incomplete or malformed results fail.

The artifact contains all invented fixture files, their one deliberate symlink, bounded streams and JSON records; total retained bytes must remain below 2 MiB. It contains no authentic MAT data, model responses, keys or reference labels. Upload occurs on both success and failure. If a complete duplicate artifact would exceed the aggregate cap, a failed, explicitly incomplete admission record is retained instead; a passing record is written only after complete byte admission. Symlinks are inventoried without following them; the artifact upload receives only regular files, and their exact-byte inventory plus synthetic symlink description is retained. A complete file inventory prevents a partial artifact from being presented as full evidence.

This is a fixed trusted-source engineering job, not an arbitrary candidate sandbox. Filesystem isolation from the checkout and full production scientific CPU/RSS/fit ownership are not claimed. It makes no MATLAB, LDA, provider, model or authentic-data call. The Linux namespace and source/fixture checks do not qualify real inputs, reference reproduction, scientific performance or submission readiness.

The source-level ownership rationale follows the primary [unshare](https://man7.org/linux/man-pages/man1/unshare.1.html), [setpriv](https://man7.org/linux/man-pages/man1/setpriv.1.html) and [PID namespace](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html) documentation. The workflow and ci_owner.py contain the exact prospective command, source selection and admission rules. Only the new horrocks-construction-controls job is added; all 19 preceding jobs remain unchanged.
