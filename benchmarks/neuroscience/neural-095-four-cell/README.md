# NEURAL-095: pre-Set DMFC prediction, four-cell scoring component

At observed Set, do strictly pre-Set spikes improve prediction of the released behavioral `tp` relative to the same declared procedure using already-known cues and elapsed session clock?

This directory provides a public task definition, bounded prediction validator and trusted offline scorer for the existing NEURAL-095 task. It is separate from the legacy single-output adapter. It contains no recordings, target arrays, reference predictions, candidate program, private execution graph or machine-specific runtime configuration. It does not add another benchmark to the task count.

The original development panel has 748 TRAIN trials and all 258 query trials from Haydn, session 20161211. Neural input is 40 held-in units in four 50 ms bins in `[Set-0.2 s, Set)`. Prediction occurs at observed Set. The target is released behavioral `tp` in milliseconds, which is not replaced with Go-minus-Set. This is one historical public animal/session, with no secret-test, population-generalization or online spike-sorting claim.

Each view supplies `train.npz`, `query.npz`, `schema.json`, `units.json` and `contract.json`. The cue-only view has case ID, condition, context, nominal sample interval and elapsed clock; TRAIN additionally has `tp_ms` and fixed chronological folds. The neural view adds `uint32 counts[case,4,40]`. Common fields, rows, folds and targets must agree exactly; counts must be absent from the cue-only packet. Query targets must remain inaccessible to producers. These provisioned input packets are not distributed here.

The four submitted artifacts are `frozen_program__cue_only`, `frozen_program__neural`, `case_adaptive__cue_only` and `case_adaptive__neural`. Each NPZ contains exactly `case_id` (Unicode U11) and `prediction_ms` (finite float32 or float64), one for every original query case. IDs may be ordered differently; the scorer aligns them to the pinned public identity. Missing, extra, duplicated, object-typed, nonfinite or oversized submissions fail the complete operation. Finite negative predictions remain scoreable without clipping or silently dropping cases.

Producers must use the same predeclared fitting/selection procedure across the two views, with only reviewed view-specific feature changes. Training targets alone may inform fitting, preprocessing or selection. Query transduction requires a separately declared and reviewed rule; the default prohibits fitting preprocessing or selection parameters on query rows. Declare estimator family, cue and neural feature maps, training preprocessing, hyperparameter candidates, selection folds/loss, tie rule, missing-group policy, random seed, allowed view-specific changes and query-transduction policy before release. A common program hash or numerical score is not proof of matchedness.

An external generation system must enforce both mode protocols, freeze relevant source/method declarations, isolate all four cells, stop producers, commit all four outputs and validate them before any private scoring or feedback. This component checks completed artifacts and arithmetic. It does not implement those generation protocols or verify producer absence, candidate fitting history, tool accounting, isolation or arbitrary-candidate matchedness. Mode labels are not evidence of an interactive reasoning advantage.

The primary per-arm metric is mean absolute error in milliseconds, lower being better. The scorer also reports RMSE, the unweighted mean of eight context MAEs, all 40 condition MAEs and all eight context MAEs. Every arm is compared against the same five fixed references: nominal sample interval, exact-condition training median, cue-clock ridge, cue-clock plus total-spike ridge and cue-clock plus temporal-spike ridge. These are authored fixed comparators, not a SOTA claim. Candidate-minus-reference error is negative when better.

Within each mode, the paired increment is the mean of per-trial cue-only absolute error minus neural absolute error, with condition/context breakdowns and equal-context macro increment. Positive means lower neural error on this exact panel. Zero or negative increments are valid. No scientific pass floor, population confidence interval, p-value or standalone neural-understanding/RL reward is defined. Weakening the cue procedure does not establish a meaningful neural benefit.

With Python 3.11 and NumPy available, `python -I score.py --data-dir DATA_DIRECTORY --submission frozen_program__cue_only=CUE.npz --submission frozen_program__neural=NEURAL.npz --submission case_adaptive__cue_only=ADAPTIVE_CUE.npz --submission case_adaptive__neural=ADAPTIVE_NEURAL.npz` scores already completed artifacts. The data directory must contain the five exact separately provisioned files named in `artifacts.json`. All four predictions are captured and publicly validated before loading references or targets. No candidate code runs. The JSON result retains explicit false/unverified fields for scientific matching and execution claims.

Run `python -I test_score.py` for small invented controls. These tests do not use the original data and do not qualify a portable end-to-end benchmark run. See `PROVISIONING.md` for the precise data-availability boundary and `ATTRIBUTION.md` for code/data attribution.
