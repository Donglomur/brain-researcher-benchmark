## Portable conversion source

Run `python -I -B provision.py --source ORIGINAL.nwb --out NEW_DIRECTORY --reference-grade REFERENCE_GRADE.json --reference-commit REFERENCE_COMMIT.json --reference-audit REFERENCE_AUDIT.json` in an operator-controlled environment with Python 3.11, NumPy and h5py. The output must not exist. No source download or model fitting occurs. The command authenticates the complete source and requires byte-for-byte equality with all seven registered deterministic conversion artifacts and all ten logical view files. Library or serialization differences that change those identities are a failure, not automatic equivalence or a new split.

The output contains `packet/` (the complete original conversion), `views/cue_only/` and `views/neural/` (five candidate input files each), and `evaluator/` (the five exact scorer operands). Mount only the relevant five view files into a candidate; never expose the parent output tree, original NWB, private targets or reference metadata to candidate code. `DATA_NOTICE.md` supplies the dataset attribution, data license and derivative-change notice. A final `PROVISIONING_RECEIPT.json` is written only after every exact output check succeeds. Failure preserves incomplete owned output for diagnosis and never silently retries, truncates or repairs values.

The provisioner reserves at most 4 MiB of generated output, excluding the retained input recording; the exact base/view/evaluator payloads total about 1.66 MB before receipts and notices. It does not implement an OS process owner or candidate sandbox. An operator must apply a finite whole-operation deadline and resource allocation and verify process completion. The protected candidate generation and scientific review obligations described in the task README remain unchanged. The historical `contract.json` status text is preserved byte-exact; it is not a claim about current portable readiness.
