# Submitted programme ABI

The protected operator consumes a JSON submission descriptor with `conditions` entries for A-F, A-I, B-F and B-I at seeds 97097, 97098 and 97099, using keys such as `B-F-97097`. Each entry provides an ordinary `source_root` and a manifest. The manifest schema is `n097-submitted-program-v1`, with `files` (relative path, bytes, SHA-256), `entrypoints`, `family_policy`, `campaign_agent_policy`, and `dependencies`. Source files are captured and authenticated by the controller; self-written receipts are not trusted evidence.

F entrypoints are `train` and `predict`; I entrypoints are `investigate` and `query_analysis`. Each programme receives `--request /inputs/worker_request.json --output-dir /work/results`. The worker request contains the public contract, access/mode/seed, permitted policy, neutral capability paths, one opaque episode nonce, and a query nonce only for query operations. It omits original identities, global fold/half mappings, target joins and protected operator paths. Python code must arrange its own imports within its sealed `/programme` source tree; no candidate module is imported by the grader.

Training capabilities point to `training_view.json`, `features.npy`, `rows.json`, and `inner.json`. Features are exact-EOF NPY1 little-endian float64 C-order. Training rows provide opaque case/person/image/session/run groups, `yface`, and `validation_stratum` ordered relevance/duration/orientation. The latter fields may support training weights and validation; they are not extra prediction features. `feature_columns` gives the exact channel-major ten-bin or nuisance indicator order. The query capability supplies only the opaque episode/query nonce and `x_numeric_vector`. No pooled query batch or previous-query state is supplied.

All successful operations write `PRODUCTS.json` with exactly `schema`, `status`, `products`, and `failure_reasons`; schema is `n097-worker-products-v1`. Allowed statuses are complete, failed and abstain. Training/investigation returns `training_state` containing a nonempty `files` list with relative `path` and `format`. Formats are strict JSON, exact-EOF NPY1 little-endian float64, or raw whole float64 bytes; the trusted collector does not unpickle candidate state. Architecture, training context and provenance must be represented in this state and the separately reviewed policy. The actual captured member identities become the frozen state; future queries receive its member descriptors and read-only `/state` root.

Prediction returns `prediction: {path: ...}`. Its JSON is exactly `schema=neural097-query-prediction-v2`, `opaque_episode_nonce`, `opaque_query_nonce`, `status`, and `p_face` for complete, or a bounded `reason` for abstain/failed. A complete probability is a finite plain number in [0,1]; booleans are invalid. Failed/abstained cases make the complete condition unavailable and retain original artifacts. The current campaign assembly accepts only complete predictions for scoring; noncomplete products remain failure evidence.

I `query_analysis` returns `query_program`, with captured `files` and an `entrypoint`; the controller launches those actual bytes in a fresh query-execution process against the same one-query/frozen-state inputs. Optional investigation `training_program` is retained as a declared generated-source artifact; it is not proof that every in-memory code string executed was captured. Complete dynamic-source/tool accounting is a separate open requirement.

Interpretation uses `n097-submitted-interpretation-v1` and a sole `interpret` entrypoint. Its product is `interpretation: {path: ...}`. The report envelope is `n097-interpretation-report-v1`, `condition`, `contract`, and `report`, containing all ten requested fields from the aggregate interpretation request. Expert rubric records are private separate inputs, never participant success flags.

Per fold-arm-setting-seed ceilings are 1,800 total descendant CPU seconds, 3,600 wall seconds, 8 GiB memory, one numerical thread, 100,000 training rows, 20,000 query cases, 100 MB aggregate input views, 2 GiB scratch, 256 MiB trained state, 16 MB outcomes and 8 MB per full stdout/stderr stream. Original authoring, training, investigation, failures and every query clone share this budget. Three seeds and the five arms do not create free retries. Current physical source adds explicit 10,000-file/inode bounds and requires a fresh independently qualified runtime profile. Those source limits do not authorize dropping cases.

Deployment is disabled. There is no provider/API/credential integration in this source candidate. Actual model/tool accounting and the scientific no-query-fit/family-conformity rules require separately reviewed implementation or programme-specific evidence before scientific execution can be qualified.
