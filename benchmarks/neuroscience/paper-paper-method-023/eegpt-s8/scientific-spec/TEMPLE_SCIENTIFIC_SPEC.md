# Temple source implementation specification, S5

This specification was written before the adapter implementation. It covers the full nine-method union on both TUAB and TUEV. It supplies executable scientific source, not scientific execution or historical parity. Original EEGPT-Tiny identity is outside these nine methods and must not be inferred from the LaBraM names.

## Authenticated original sources

BIOT author repository `ycq091044/BIOT`, revision `d138e32634e52ae9fa6ec98ac9c4087b14ca869a`, supplies the literal six model implementations, binary/multiclass training scripts, dataset preparation scripts and MIT license. LaBraM author repository `935963004/LaBraM`, revision `c431221e6cfd23dbfa9950e0180682fb322b0548`, supplies the literal finetuning model, optimizer/engine, channel positions, two preparation scripts and MIT license. Selected file Git blobs and SHA256 digests were checked against the finite official tree metadata. Private acquisition history is excluded from this inspection-source package.

## Architecture and objective

The six BIOT repository classes are SPaRCNet (DenseNet1D), ContraWR (STFT/residual CNN), CNNTransformer (five temporal segments, STFT/residual CNN, four Transformer layers), FFCL (STFT/residual CNN plus LSTM), STTransformer (channel attention, temporal convolutions, four Transformer layers), and BIOTClassifier (channel-token STFT embedding and four linear-attention layers). Constructor arguments are taken literally from both supervised scripts: 16 bipolar channels, 200 Hz, 200-point FFT, 100-sample BIOT hop, 20 STFT steps, 256-dimensional transformer features. TUAB has 2000 samples and one binary logit; TUEV has 1000 samples and six logits. The original STTransformer channel-attention einsum and default 2000-based scaling are retained, including their potential scientific defect; they are not silently repaired.

LaBraM Base/Large/Huge are the exact author's `labram_base_patch200_200`, `labram_large_patch200_200`, `labram_huge_patch200_200`: respectively embedding dimensions 200/400/800, depths 12/24/48, heads 10/16/16, temporal-convolution widths 8/16/32, one-second 200-point patches. Their identities are resolved independently of the EEGPT appendix's rounded 5.8M summary row. The forward pass uses ordered channel-position indices, microvolts divided by 100, mean pooling, source LayerScale 0.1, absolute positions, no relative positions, no qkv bias, head init scale 0.001 and stochastic depth 0.1. Published rounded parameter counts do not replace actual model census.

All methods optimize binary cross entropy with logits for TUAB and multiclass cross entropy for TUEV. BIOT-suite models use Adam, learning rate 0.001, weight decay 0.00001, batch 512, maximum 100 epochs, validation-monitor patience 5. LaBraM uses AdamW with layerwise decay, per-step warmup/cosine learning rates and no decay on biases, one-dimensional parameters or declared positional parameters. TUAB uses the README example: 50 epochs, layer decay 0.65. TUEV uses the source CLI defaults: 30 epochs, layer decay 0.9. Both use batch 64, learning rate 0.0005, weight decay 0.05, five warmup epochs and minimum/warmup rates 0.000001. These defaults are explicit prospective reconstructions, not recovered original three-run settings. Full original recipe qualification remains separate.

## Data and complete support

The provider supplies a concrete continuous-recording operation, preserving source ordering: select the 23 named referential channels; for BIOT-suite, resample to 200 Hz, construct the exact 16 bipolar differences, and retain volts; for LaBraM, bandpass 0.1–75 Hz, notch 50 Hz, resample to 200 Hz, retain 23 referential channels in microvolts. TUAB epochs are every full consecutive ten seconds. TUEV epochs use source event start/end timestamps and two-second context with source wrap-padding; events must have an exact one-second duration and semantic labels must already be qualified. Exclusions and event identities belong to the parent complete-support manifest and cannot be discarded here.

The future worker loader consumes precisely these qualified 200-Hz epochs, validates per-row units/channel names/shape and preprocessing identity, and reads only signal capabilities. BIOT suite applies per-channel 95th-percentile absolute-amplitude normalization with `method='linear'` and epsilon 1e-8 in volts. LaBraM reshapes 23×2000/1000 into channel×time-patch×200 and divides microvolts by 100. No fitted normalization or query labels enter inference. A source TUEV inconsistency (250-Hz event extraction but loader declaration 256 Hz in BIOT) is retained as a historical-parity uncertainty; this prospective path explicitly uses true 200-Hz event time.

## Initialization, selection, state and query

The five non-BIOT suite methods initialize from the declared FIT seed. BIOT accepts exactly two named scientific policies: source scratch, or an externally authenticated encoder-only BIOT state. LaBraM requires an externally authenticated matching-variant state and loads exact `student.` pretraining encoder keys, permitting only missing classifier head keys. It does not silently initialize an absent encoder or accept an incomplete encoder. No download occurs in any adapter. Checkpoint bytes, SHA256, variant, source recipe, corpus ancestry and qualification are parent capability obligations.

Protected changes are explicit: train all complete rows including the final partial batch; use one process and float32; choose the earliest strictly best complete-validation AUROC (TUAB) or kappa (TUEV); no test-derived tuning, split recreation or refit. Persist every completed epoch model and optimizer state, row count, full validation metrics and best-state choice. Source historical native scripts use test evaluation, distributed/AMP paths and drop-last choices; the protected implementation makes no claim of equality to those historical runs. FIT seed is retained in STATE and reconstruction uses that original seed, never the PREDICT stream. All prediction rows retain input order and use semantic sigmoid/softmax probabilities.

## API and open qualification

`registry()` and `admit_recipe(recipe, dataset, method)` are metadata only. `fit(worker, recipe)`, `predict(worker, state_root, state, document)` and `reconstruct(worker, state_root, state)` implement actual model operations with lazy numerical imports. The first publishes original fitted-state evidence and family training products. The second returns all semantic probabilities. The third reconstructs and checks the exact selected checkpoint pin. Constructors are a closed fixed registry and cannot accept an arbitrary module, function, command or callback.

Actual data/weights, dependencies/native version qualification, original corpus rights/ancestry, native numerical validation, historical seeds/splits/checkpoint identity, whole-source independent review and actual benchmark performance remain unobserved. Missing external artifacts are distinct from missing algorithm source. This helper performs only ordinary source inspection and inert/AST controls; no numerical/model/science execution is authorized or claimed.
