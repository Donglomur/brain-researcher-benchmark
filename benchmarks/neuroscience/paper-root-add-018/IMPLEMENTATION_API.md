# Complete OFC operator API — S3

`operator_api.py --program PROGRAM.json --output FRESH_DIR --review REVIEW.json --other-reserve-bytes N [--condition all|I_A|I_B|R_A|R_B]` is the ordinary-file ABI. The output parent must exist. A fresh output root and sufficient declared storage/closure reservation are required. The public source interface exposes that existing CLI directly; its source-only manifest does not register or authorize a scientific run.

The submission schema remains `ofc-submission-v1`: task/method IDs, ordinary source root and exact files, build/investigate/fit/predict/analyze argv, dependency lock, seed policy and all 74 declared obligations. The host executes those source entrypoints. It does not replace the method with a fixed reference or accept result-file replay as learned-method evidence.

The plan remains `ofc-plan-v1`: exact experiment/condition/scope, budget, public inputs, six prospective query universes, all 74 native requests, protected commitment, dependency environment, seeds, qualification identity, independent reference definitions and policy. Accepted design files define full biological support, units, estimator and disposition semantics. Each neural stream binds one session and one held target; current peer observations are allowed but the entire target test stream is excluded. Every original prospective key remains required, including privately unscored waiting trials. All 200 simulation keys remain present.

The review remains `ofc-operator-review-v1`, binding current runtime identity, exact plan/private-target/reference-program descriptors, selected conditions, resource limits and qualification. Engineering mode requires explicitly allowed inert source IDs and scientific_authorized=false. Qualified science still requires all ten gates plus independently qualified isolation and physical quotas. No current packet supplies that qualification.

Campaign time starts at operator entry, including admission work. Each condition receives `min(original campaign deadline, condition entry + plan budget.wall_seconds)`. Each supervised phase receives `min(original parent deadline, phase entry + phase_seconds)`. Source/input copies, mount sealing, launch, stream I/O, EOF/wait, collection, protected joins/target reads, evaluation returns, report publication and terminal-closure admission use those original clocks. No retry gets a fresh campaign or condition allowance. Cleanup is bounded termination/custody after failure, never a new participant/scientific execution allowance. Pure numerical calls are guarded before/after; this source phase does not claim instruction-level preemption inside an unqualified numerical library.

`custody/` is outside every participant mount. Complete stage IDs are derived from the fixed plan before workers start. Campaign and condition slots reserve three writes; attempt slots reserve four. Every slot is 8 KiB. Its size and all permitted rewrites are charged inside the original cumulative cap. Impossible closure reservations refuse before root creation or child launch. Ordinary observations and detailed failure records may fail while the supervisor still attempts the precharged bounded first-cause/attempt record. If the reserved write itself fails, the original attempt is explicitly not durably saved: strong in-memory original exception/status custody survives, the actual host prohibits collection and later work, and the operator fails. A failed durable write is never called a receipt. Long exception messages carry a bounded prefix, original length and SHA-256; a digest does not claim the full message body was saved.

Trusted writes/copies/appends use the same ledger. Worker leases charge full output+scratch+log ceilings before launch, with no cumulative credit recycling. Retained and cumulative counters are distinct; per-stage file/byte limits and full-root logical admission both apply. Child leases do not measure repeated physical overwrites. Qualified hard OS/filesystem quotas remain a separate open gate. Observed overshoot, absent containment proof and ordinary publication errors retain their original dispositions; none becomes a successful empty attempt list.

The prefix protocol still sends one query, accepts one exact keyed response, durably commits it, then sends the next. No future projection asset is mounted for a whole stream. Source, investigation and model bundles are sealed read-only. The protected collector preserves finite and tagged nonfinite native vectors in full, all axes/components/roles, missing rows and candidate failures. The grader uses fixed target/mask/reference support and qualified baseline requirements; missing baselines yield null gains. Censoring, five-class reward support, ATI undefinedness and all scientific estimators are unchanged.

Waiting offer events now have one canonical normalization: ordered unique prior-trial offers, followed by exactly one current offer. An identical current offer in the prefix is validated and not repeated. Conflicting/duplicate/current-future/order errors fail. Both waiting comparator calls consume that same sequence. Session reset and allowed-history provenance remain required original input bindings.

The report carries campaign identity and a resource snapshot explicitly taken before report publication. `custody/campaign.json` binds identity and the counters observed before its own publication and descriptor close. It cannot attest to events that occur later. `Campaign.finish` consumes the original clock after every descriptor close, preserves every observed closure error, and returns the original in-memory completion object. The actual operator checks that exact object after all closes and again after its final output callback. The CLI print/flush runs inside that callback; original zero exit is mandatory. A printed report location is provisional and explicitly carries `requires_original_zero_exit=true`. No callback, descriptor error or late original deadline can be accepted as successful completion. No post-close durable amendment is fabricated.

Every registered original worker retains its first exception object, exit status, wait/reap result and containment status through cleanup. Failures in writable census, log stat, ledger settlement/snapshot, clocks, output seal or ordinary observation publication are secondary when a worker cause already exists. Unknown observed quantities are null with observation flags, not zero. Unknown or incomplete storage measurements do not refund the original child reservation. Strong original exception objects remain distinct from bounded serialized records; an exception whose message rendering fails is recorded with unknown message fields and the rendering error type.

The original attempt terminal path has a final guarded attempt even when measurement fails. At most one corrective metadata write uses the existing four-write attempt-slot reservation (initial reserve, launch, terminal, correction). A bounded fallback can preserve original first cause/status when optional detail cannot be encoded or fit; it explicitly marks incomplete detail and unknown measurements. The worker never reruns. A successful reserved write is distinguished from in-memory custody when both writes fail. The host checks this distinction before collection, the next stage and target access. The controller records pre-stage and initial START failures before any fallible condition or FAILED publication, so those secondary failures cannot become the first cause.

The trusted Python entrypoint adds a keyword-only `on_complete` callback for the actual CLI emitter; it is not a participant-configurable hook. With or without that callback, `execute` checks the unchanged original campaign deadline at the final return boundary. Bounded records label their earlier timestamp boundary, and actual completion consumes subsequent failures. These source guarantees and inert controls do not qualify scientific correctness, numerical kernels, hard OS limits or containment.
