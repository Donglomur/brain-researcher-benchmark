This operator command exercises one fixed synthetic fork/allocation fixture and its owned container/cgroup closure. It does not read EEG, annotations, predictions, models or credentials. No fixture is executed during source construction. It does not grant Helsinki runtime admission or change the always-refusing production gate. The full scientific contract remains 79 infants, five folds, three controls, 15 B workers and 30 A/B sessions.

Four lifecycle/observer modules and fixture/input are byte-identical accepted source. common.py removes one redundant terminal LF only; its AST and behavior are unchanged. Only `diagnostic.py` supplies portable authentication, explicit input binding, read-only prerequisites and closed fixture-output interpretation. This package is a prospective synthetic interface, not the full scientific 91-member source graph. The bootstrap itself must be obtained from a trusted, reviewed source; its manifest check authenticates every member before helper loading. Run from a fresh Python process with bytecode disabled. Do not add files to the package directory.

## Required external operands

The owner supplies a reviewed request, literal SHA256 of that request, literal SHA256 of SOURCE.json and a fresh absolute output path below an existing owner-only directory. REQUEST.template.json is deliberately inert and refuses before imports or native calls. A configured runner or a 64-character authority string does not prove ownership. Independent external review must bind the operation selection and provisioning evidence before execution.

The request has exactly these fields:

- `schema`: `helsinki-zero-case-request/v1`.
- `selection`: operation_id (lowercase letters/digits/hyphen, at most 80 characters), mode (`check` or `run`), authority_sha256, exact output path, parent_device and parent_inode (exact integers).
- `target`: python and docker descriptors, each containing absolute non-symlink path, bytes and sha256; socket path and socket_guard with exact dev/inode/mode/uid/gid/nlink integers; image_id and architecture (`amd64`) matching SYNTHETIC_IMAGE.json.
- `provision`: schema `helsinki_persistent_parent_observer_v1`, boot_id, kernel_release, mount_id, cgroup_namespace_inode, delegation_path, delegation_device, delegation_inode, daemon_id, daemon_version, cgroup_driver (`cgroupfs`), cgroup_version (`2`). The non-root delegation must already exist on the same full cgroup-v2 hierarchy, be owned exclusively by this owner, have no processes or children and have cpu/memory/pids enabled for children.
- `provisioning_authority_sha256`: identity of the independently reviewed same-kernel, exclusive-delegation and daemon binding. It is an external trust operand, not a kernel observation or a qualification flag.

The Python and Docker executables are rehashed as ordinary single-link files, each at most 64 MiB, combined at most 112 MiB; group/world-writable binaries are refused. The running interpreter must resolve to the selected Python path. Linux x86_64/LP64, a local ordinary UNIX Docker socket owned by the invoking UID, the selected boot/namespace/full hierarchy and delegation identity are checked. Running a trusted owner as root may be required for the selected socket/delegation; the candidate always runs as UID/GID 65534 without capabilities or network. This tool does not use sudo, elevate, delegate, enable parent controllers, change trust, restart Docker or create a privileged container.

## Invocation

On a separately selected and provisioned Linux owner, use literal reviewed hashes and an external request. The following placeholders are intentionally not runnable selections:

```sh
python3 -I -B /absolute/package/diagnostic.py check \
  --source-sha256 REVIEWED_SOURCE_SHA256 \
  --request /absolute/private/check-request.json \
  --request-sha256 REVIEWED_REQUEST_SHA256 \
  --output /absolute/private/fresh-check
```

`check` authenticates all source, request and executable bytes; reads the same-kernel and delegation interfaces; invokes only `docker info` and `docker image inspect` through the inherited owned-client collector. It creates private local evidence only. It performs no container or cgroup mutation. Wrong driver, missing delegation/controller, wrong image/architecture or incomplete command closure produces a refusal. A successful report establishes conditional observed prerequisites, not exclusive ownership or runtime qualification.

`run` uses the same arguments with a separately selected `run` request and fresh output. It repeats those prerequisites, copies the fixed authenticated fixture to `candidate/solution.py` and the empty descriptor to `input/EMPTY_INPUT.json`, and calls the unchanged `run_candidate`. There is no arbitrary program/output input. The inherited owner creates only its unique child parent and container, verifies exact mounts/image/limits, captures stdout, waits for empty cgroup accounting, removes only admitted owned resources, then requires complete closure. Exact fixture output plus at least 0.1 CPU second and 8 MiB peak descendant memory are necessary for the synthetic positive report. These are falsifiable observations, not proof of every future workload.

All output remains private. REPORT.json preserves a refusal and points to retained lower-level evidence. Bootstrap/static refusals print bounded JSON before an operation directory exists. A failed metadata command is not converted to success by transport closure. The task-local CLI guard converts SIGTERM/SIGINT to an exception during preflight and candidate work, ignores those signals during owned closeout, and independently restores both previous handlers. Partial handler installation and restoration failures refuse; the nested donor handler lifecycle remains unchanged. This adds no alarm or general controller. A REPORT describes the operation body; successful CLI return is additionally required, because outer handler restoration may fail after that report. Failure records and incomplete files are retained. Never delete evidence to make a rerun appear fresh. No automatic retry, image pull or fallback target exists.

## Image and platform limits

SYNTHETIC_IMAGE.json pins the official `library/python:3.11.18-slim-bookworm` Linux amd64 platform manifest and its published config digest. The config-body metadata GET was refused on redirect and was not retried; no config body or image layer was downloaded. A future local inspection must confirm image ID, OS, architecture and absence of declared volumes/build hooks. Docker creation uses `--pull=never` and the config ID, with an explicit python3 entrypoint. Prior image acquisition is an external operation and is not selected here. The 47,616,215 compressed layer bytes are a registry declaration, not disk occupancy or RAM. This fixture image is distinct from every benchmark runtime and confers no compatibility with old385454 or any replacement.

Standard GitHub Ubuntu VMs are only a possible host class. Docker commonly defaults to systemd on cgroup v2; this observer requires cgroupfs. A default runner may therefore refuse. No workflow or CI dispatch is supplied. Provisioning or a different driver would require an explicit separately reviewed successor. Native macOS and an unprivileged Ubuntu slim container do not satisfy the same-kernel owner contract.

## Accounting and remaining holds

The CLI uses one original 240-second cooperative deadline: prerequisites before 60 seconds, candidate work before 180, cleanup within 240. Existing bounded client operations and original group closure are reused. Managed read ceiling is 128 MiB; attempted managed-write ceiling is 16 MiB. Source/request and current executable hash bytes count toward reads. Two inherited journals each reserve a 2 MiB logical extent and up to 4 MiB managed writes; these are ceilings, not measured physical storage. Parent controller writes are counted by the existing observer. Output, daemon/kernel cache, internal OS I/O and image acquisition are distinct costs; physical storage and full host peaks remain unmeasured. Source tests do not establish these future bounds on a real runner.
