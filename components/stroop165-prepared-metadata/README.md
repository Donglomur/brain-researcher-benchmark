# Complete Stroop prepared-metadata contract

This is a source component for the existing `NEURAL-SCOPE-20261114-STROOP`
benchmark. It validates all165 independently regenerated recording reports,
joins55 internal source groups across three sessions, and builds an owner-only
metadata/window ledger. It is not a new benchmark, an authentic data release,
a participant packet, a completed reproduction or a qualified runtime.

The consumer, its two dependency modules and its15 generated test methods are
byte-identical to the accepted implementation. The public runner adds three
relocation/private-input checks. Python3.11 standard-library modules suffice;
there is no install, download, scientific-library import or model call.

For every condition onset the consumer retains all integer offsets satisfying
`-5 <= k*T < 20`, using the exact `Fraction(T)` of the saved numeric period.
The first offset is `ceil(-5/T)`; the stop is exclusive at `ceil(20/T)`. The
nominal period yields640 samples, while its adjacent representable floats can
yield639 or641. This is conditional window geometry, not a uniform-clock or
stimulus-alignment claim. No epsilon, fitted clock or resampling is introduced.

All165 reports and every declared11/12/13 condition onset are required. Five
marker-code comparisons must satisfy the same exact count bounds and all31
nonempty subset/position-union checks. These are necessary metadata consistency
checks, not a reconstruction or proof of every possible underlying onset vector.
Feasible marker mismatches, unknown codes, recording boundaries, overlapping
onsets and simultaneous conditions remain explicit. **No event is discarded,
declared eligible or silently excluded.** Unknown-code positions are not invented.

Recorded15/5,15/15, other-literal and unresolved crop forms remain distinct.
Recorded processing strings are never executed, and removed sample counts and
historical execution remain unverified.55 internal IDs do not establish55
distinct biological people. Physical Hb units, original clocks, exposure and
identity, signal finiteness, event eligibility, the proposed40-row transform,
competent reference results and protected evaluation remain unqualified.
Historical64% binary within-person pooled-session results,768-sample windows
and random regrouping differ from the prospective three-class held-person/
session benchmark.

## Interface

The callable is `metadata_contract_v2.compile_metadata(contract, audit, reports)`.
The CLI is:

```text
python3 -I -S -B metadata_contract_v2.py --audit ACCEPTED_AUDIT.json --audit-sha256 EXTERNAL_SHA256 --contract PRIVATE_CONTRACT.json --output FRESH_ABSOLUTE_PRIVATE_LEDGER.json
```

Authentic use requires the independently accepted complete165 audit and exact
private inspection contract, plus separately admitted owner/runtime/resources.
The retained contract digest and221135-byte extent are identity commitments;
its body, authentic reports, source IDs, marker values, private paths and any
launch bindings are absent from this package. A failed/partial audit or generated
replacement contract is refused. There is no public fallback dataset. Generated
tests temporarily substitute only invented contract identities in test memory;
production source constants are unchanged.

The metadata CLI reads bounded JSON: audit8MiB, exact contract extent, at most
1MiB per report; output is capped at8MiB, create-only0600 and fsynced. These are
application bounds, not hard aggregate OS quotas. An interruption can leave a
partial output, which is not successful completion. The real output contains
internal identities and conditions and must stay owner-only. No full165 authentic
ledger or scientific readiness is established by these source checks.

`inspect_prepared_v2.py` is included unchanged for its roster/scalar/preprocessing
functions; the consumer does not invoke its MAT decoder. `stroop.py` is included
unchanged for strict JSON/hash loading; the consumer does not invoke its scorer.
These unused dependency APIs do not create an additional qualified capability.

## Source checks

CI pins `SOURCE_MANIFEST.json`, checks the entire ordinary-file namespace and
authenticates every member before executing `run_public_checks.py`. It then runs
all15 inherited generated methods and three public-boundary methods from this
relocated package. The bootstrap is inline in the reviewed CI job, avoiding a
self-authentication claim for a script loaded before its own check.

From an already trusted checkout, `python3 -I -S -B run_public_checks.py` runs the
same generated checks; that direct command does not independently authenticate
itself. Complete namespace authentication intentionally refuses extra provisioning
files or cache directories. No authenticated source hash proves biological
validity, empirical accuracy, protection from answer leakage or submission readiness.
