# Reconstruct the released Figure 3C context-decoding panel

Implement one program that reconstructs the declared analysis for all 17 released Figure 3C recording sessions and both Laser OFF and Laser ON conditions. Start from the supplied preprocessed neural workspace and the paper. Return the source trial partition, feature order and Randomised-class probabilities for every source test row. The evaluator derives the panel metrics from those predictions and compares them with a fixed reconstruction.

This is a finite reconstruction task, not an improvement challenge. The released workspace exposes all context labels. AUC 1, a copied label vector or the paper's P=.008 does not earn a better reconstruction score merely because it looks more accurate or significant. The primary score measures agreement with the fixed reference probabilities. The exact historical author settings and published AUC vector are not known; the conventions below define this task.

## Inputs and execution

The common authoring materials are this task, its schemas, public session manifest, the official article/supplement and the exact Figure3C_data.RData. The optional source-assisted condition adds only the original Figure 3C R analysis script. Both conditions receive the same data, conventions, software, budgets and scorer. Reference predictions, reference worker, grader and operator records are excluded.

Submit one UTF-8 `program.py` of at most 65,536 bytes. It may invoke the installed Rscript inside the offline container. The program is frozen once and invoked separately for each session with fresh writable state. `/input/session.json` selects the session. The input paths and full visible workspace schema are in `INPUT_SCHEMA.json`. Write only `/output/submission.json` in the format specified by `OUTPUT_SCHEMA.json`. No installation or network is available. The same source must handle all 17 sessions; no grader feedback is returned between them.

The proposed work window is 300 seconds per session pair, with 3 GiB candidate memory and 1.75 CPU cores; these are draft limits pending runtime review and root adoption. They are not an execution grant. A successful result requires all 17 outcomes, not a subset selected after seeing scores.

## Declared reconstruction conventions

1. The input is the released preprocessed workspace, not raw spikes. It contains `.Random.seed` and the ten-column `raw_pred_db` described in `INPUT_SCHEMA.json`. Preserve source row order. Derive each experiment ID from the first three underscore-separated `uuid` tokens; sessions follow first appearance, as fixed in `SESSION_MANIFEST.json`. Do not infer animal identity from those tokens.
2. Process Laser_OFF then Laser_ON separately within each session. Select `t_num`, `tone`, `context`, `laser_block`, `spk.st` and `uuid_tb`. Pivot `uuid_tb` into `uuid_`-prefixed neural columns using `spk.st`, with the four other fields forming trial identity. Preserve first-appearance row and feature order. An absent trial/feature slot is filled with zero; an observed NA remains NA. Do not infer biological silence or redo binning/window alignment from feature suffixes.
3. Factor context in the order Randomised, Regular. Restore the supplied workspace RNG state in the declared R environment. Immediately before partitioning each condition, set seed 101 and use `caret::createDataPartition(context, p=0.7, list=FALSE, times=1)`. Train rows retain that function's order; test rows are the increasing complement. Use native class-count rounding. The last session's OFF condition has 477 trial rows and 143 test rows; do not pad it to 480/144.
4. Only the neural `uuid_` columns are decoder predictors. Tone, trial identifiers, context, laser condition and the other visible metadata columns are not predictors. The reference retains the released dense missing-value semantics. The output feature order describes the complete reconstructed input roster, not a candidate's internal feature-selection decision.
5. The reference uses R 4.3.1, caret 6.0-94, xgboost 1.7.5.1 and pROC 1.18.0. Before training each condition it resets seed 101. Its xgbTree recipe is adaptive_cv, 10 folds, 3 repeats, random search, tuneLength 3, Accuracy selection, GLS futility with min 5/alpha .05/complete TRUE. The reference uses sequential foreach and xgboost nthread 2. These are explicit reconstruction conventions, including implementation-derived defaults; they are not all specified by the paper or a claim of recovered historical binaries. Alternative implementations are allowed and receive continuous agreement scores. No particular library calls or internal fit count are required in your submission.
6. Submit finite probabilities of Randomised. Regular probability is one minus that value; the declared class threshold is Randomised at p>=0.5. The evaluator independently computes accuracy and tie-aware fixed Randomised-positive AUC. It separately reproduces source pROC automatic orientation with levels Randomised/Regular: direction `<` when the Randomised-score median is no larger than the Regular-score median, otherwise `>`. This is not a rule taking max(AUC,1−AUC), and source-auto AUC may be below .5.
7. Panel contrasts are Laser_ON minus Laser_OFF in the original 17-session order. The declared nominal paired test uses two-sided `wilcox.test(ON, OFF, paired=TRUE, mu=0, exact=NULL, correct=TRUE, conf.int=FALSE)` on source-auto AUC. The evaluator reports the fixed exact/asymptotic/orientation sensitivities described in `PUBLIC_SCORING.md`; it does not select a variant to match the published annotation. Your submission contains only the fields in `OUTPUT_SCHEMA.json`. Accuracy is descriptive only.

The paper describes a 1.5-second/20-ms preprocessing procedure, while the released scripts start from the preprocessed workspace. This task preserves that released representation; correspondence of its feature construction to all upstream paper details is not established. Pointwise intervals and paired-session p-values do not account for model tuning, automatic direction selection, temporal dependence or correlated sessions. The legend's four animals and seven Table S1 Figure 3C IDs have not been reconciled. This task does not establish animal-level significance, Figure 3G, Figure 3F/SHAP, whole-paper reproduction or protected predictive improvement.

Each pair is a separately authorized 390-second stage (360 work, 30 cleanup), including a reserved 300-second candidate window. All17 stages use the same committed program with no private grading between pairs. A separate60-second stage (45 work,15 cleanup) grades all17 outputs. These are prospective maximum allowances, not measured expected compute or permission to run.

Output JSON is strict UTF-8. Duplicate keys, unpaired Unicode surrogates, nonfinite numbers, and nonzero numeric literals that underflow to zero are invalid. If a valid nonzero discrepancy cannot be represented after division in binary64, its metric is explicitly unavailable rather than rounded to exact agreement.

Primary-document caveat: Table S1 explicitly names the four observed second UUID tokens as mice and lists three additional names for Figure3C; the main legend says four animals. These sources do not fully reconcile the per-session map or explain the extra names. Keep the17-session reconstruction unchanged and do not infer independent animal replication.
