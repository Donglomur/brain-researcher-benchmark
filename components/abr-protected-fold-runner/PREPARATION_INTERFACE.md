# Maintainer preparation interface

The operator owns the packet and all evaluator metadata. Only fold-specific inputs are mounted for a participant. A complete opaque packet root has `animals/`, plus `evaluator/PRIVATE_MANIFEST.json`, `evaluator/PACKET_COMPLETION.json` and `evaluator/PREPARATION_RECEIPT.json`. A pinned receipt is a trusted maintainer assertion supported by independent private evidence, not a cryptographic proof generated by this component.

The private preparer must first apply the original deterministic validator to the exact selected private manifest. It preserves each opaque animal ID, label, outer assignment, animal order, outer and inner partitions, and state policy. It removes release identities and private source metadata. It projects completion metadata to the fixed opaque schema while retaining the complete animal-file inventory, profile and sample count unchanged, and binds the new canonical manifest digest. It must retain the old/new pins and complete correspondence evidence privately.

The receipt schema and required exact fields are defined in `runtime/prepared_manifest.py`. The selected render request carries a `preparation` locator alongside `manifest`, `completion` and the method pair. Each locator contains an absolute operator-local path, complete byte length and SHA-256. Rendering does not open these operands. The generated source binds every locator, and the future root selection must repeat them exactly. Before any actor starts, the owner reads the exact receipt and confirms its opaque-manifest and completion pins against the selected complete bytes. All correspondence flags must be true and counts complete. The private maintainer must validate those assertions before selecting their hash.

The public opaque validator enforces the full 104-animal roster, 54/50 class totals, five stratified outer folds, four stratified training-only inner folds per outer fold, canonical order and state policy. It cannot reconstruct source-identity-derived assignments. An otherwise structurally valid altered assignment remains inadmissible because it differs from the maintainer-selected manifest/preparation pins.

Standalone pure scorer or validator calls provide mathematical/structural behavior only. They are not the authorized authentic runner path, a valid preparation receipt or a source-authentication shortcut. No private preparation artifact or authentic operation is selected by this release.
