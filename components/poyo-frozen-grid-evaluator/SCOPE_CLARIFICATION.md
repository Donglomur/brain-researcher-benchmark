# Mandatory scope clarification

This consumer evaluates one submitted method/budget grid in one access condition.
It does not provide paired A/B authoring, a both-arms-before-target barrier, matched
provider budgets, cross-arm history isolation, or an execution-to-output binding.
Those are separate parts of the unchanged registered paper task.

All four method tables are supplied in the public prediction artifact. The private
loader authenticates targets only. Thus `contrasts` are **submitted-method contrasts**,
not certified gains against independently authenticated, competent fixed references.
A submitted table can misrepresent its named method or deliberately weaken a baseline.
The consumer cannot detect that from numerical predictions alone. The exact architecture
declaration, scientific-authority hash and source descriptors also do not prove method
execution, full authentic membership, contamination exclusion, or reference competence.

The independently target-scored pretrained, scratch, ridge and recurrent outputs are
useful numerical artifacts once an external trusted producer and scientific review
establish those obligations. Until then, every report's qualification/provenance flags
remain false, and neither an improvement claim nor a finished paired benchmark follows.

This clarification changes no source, input ABI, arithmetic, result values or generated
control. It is a mandatory part of the public component documentation and must accompany
any later documentation or public projection of this component.
