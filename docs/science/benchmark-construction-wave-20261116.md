# Authentic delivery and prospective freezing

This construction wave develops four existing endpoints after the
[difficulty pilot](difficulty-pilot-20261117.md). It adds candidate delivery,
identity checks and prospective execution controls. It does not add task IDs,
run a new solver study or establish scientific qualification. The 234 source
registrations and their canonical definitions are unchanged.

The paper track's success objective is surpassing the source paper on the same
task. These reproduction delivery components are calibration/preparation only,
never active improvement success. They establish neither improvement over the
paper nor current best performance. Such claims require the source paper's exact performance-bearing endpoint
and comparison conditions, an authentic author baseline, frozen metric/split
and protected evaluation; a
current-best comparison additionally needs independently verified current sources.
The cardiac association and optogenetic descriptive endpoints do not by
themselves define a defensible better-than-paper ordering.

## Cardiac six-model reconstruction

The [candidate delivery package](../../benchmarks/paper/PAPER-ROOT-ADD-016/implementations/candidate-delivery-v1/README.md)
uses the exact 655-person source table and preserves the six separate inference
models. Both conditions receive the paper, data and shared source-derived
specification; one additionally receives official code. This remains
method-assisted reconstruction. Candidate submission admission and freezing do not
qualify the historical reference as an oracle.

The available staged fitting runtime contains Linux-only wheels; the construction
host lacks the required Bambi, PyMC and ArviZ stack. No posterior draws are fabricated
and no replacement model is fitted. Native fitting and independent reference
qualification remain explicit blockers.

## Optogenetic contact timing

The [authentic delivery package](../../benchmarks/paper/PAPER-FIND-REP-003/implementations/authentic-delivery-v1/README.md)
uses all 3,304 released trials from two mice across eight sessions. Its endpoint
is the Figure 1H contact-time distribution produced by the pinned author code
from `grabTimeC / 1000`. Its physical time origin is unresolved: the source
`loadEventTimes.m` subtracts `waterTime`, so these released timestamps must not
be treated as independently validated cue-relative measurements. The prior
evaluator's additional equal-mouse mean-delay statistic is not presented as the
paper result.

The complete release contains the article's 495 stimulation trials; the
Figure 1H success filter retains 318, so those counts describe different
populations. Applying the unshifted released timestamp threshold does not recover
the article's reported 86.5%/5.1% within-three-second contact fractions.
Cue-relative reconciliation remains unresolved; this is not evidence of an
article/release discrepancy under a validated common clock. Release-native
reconstruction and reproduction of the article's quantitative intervention claim
remain distinct.

## Complete EEG direct-response comparison

The [complete direct-condition package](../../benchmarks/neural/NEURAL-077/implementations/complete-direct-condition-v1/README.md)
provides all 400 development trials under explicit signal representations and
response identities. A matched waveform programme condition receives the same
four labeled demonstrations and Cz/Pz waveform samples as the no-tools condition.
The feature-programme route remains a separate comparison with a different
representation and 1,200 labeled training trials; its results cannot isolate a
tool-use effect. A trained feature programme is not evidence of native LLM signal
understanding.

No model executed either condition in this wave. No-tools compliance and fresh
query contexts depend on the model transport and authoring policy; candidate
packet construction alone cannot enforce them on a shared host.

## Freeze before development execution

The [shared lifecycle controller](../../benchmarks/shared/frozen-neural-lifecycle-v1/README.md)
implements source/method commitment before development execution, separate
candidate processes per person, complete submission freezing before private
grading, and preservation of failures for NEURAL-007 and NEURAL-077.

The registered private scorers require a four-GiB request. This construction
wave's two-GiB process budget does not authorize those native grading runs; their
admission requirements remain unchanged. Generated lifecycle controls exercise
order, tampering and coverage failures without becoming scientific evidence.
Shared-host programme lifecycle enforcement is not an authoring security sandbox.

Raw inputs, private targets, candidate predictions and local operator receipts
remain outside the public source tree. Package documentation describes the exact
commands, source pins, evidence scope and remaining qualification gates.

## Companion source integration

Three reviewed companions extend these preparations without adding benchmark IDs.
The [EEG portable grader](../../benchmarks/neural/NEURAL-077/implementations/portable-grading/README.md)
accepts explicit external artifact/runtime locations and validates all 400 IDs
before permitting the unchanged private scoring stage. Admission of a completed
NPZ does not establish that its method was frozen before development execution.
The [sleep attempt audit](../../benchmarks/neural/NEURAL-007/implementations/finite-attempt-audit/README.md)
uses independently retained commitment/completion pins to verify the existing
lifecycle's complete source, input, per-person process and 5,450-epoch submission
history. It stops before grading and remains trusted operator orchestration.

The [native optogenetic clock audit](../../benchmarks/paper/PAPER-FIND-REP-003/docs/initial-evaluator-v1.md)
checks the exact complete released file and event-minus-`waterTime` identities.
It neither shifts the source histogram's values nor resolves its cue-relative
interpretation. It is a calibration/provenance component, never active paper
improvement success. Existing native control receipts are retained as earlier
engineering evidence; this integration performs no new authentic candidate or
private grading execution.
