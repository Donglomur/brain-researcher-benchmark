# GCaMP8 recovery component: published source scope

This source component implements process and container cleanup around the GCaMP8 paper-reproduction programme. It encloses the complete controller and its host descendants in an owned Linux cgroup, records each resource before creation, waits for the controller to stop, and recovers only the exact remaining resources. A successful cleanup cannot turn a failed scientific run into a successful one.

The public copy is **source-only and inactive**. It does not make the GCaMP8 assignment a standalone runnable benchmark, supply a scientific result, or add a task. Its 37 component files are unchanged from the reviewed implementation. The separate discovery sidecar also leaves the registered entry unchanged.

## What is implemented

The declared programme uses all 117 released neuron files, two tracks (pooled and variant), and two access conditions (A and B): 468 train/query/capture outcomes. The complete producer barrier precedes all 468 protected grades and both arm aggregates. These are declared source cardinalities; this release does not authenticate the original neural files or establish independent biological replication.

The surviving parent owns 2,808 resource identities and the fixed 12,169-event lifecycle. It retains attempted creation even if acknowledgement is lost, checks original returned resource identities, and refuses further work after uncertain ownership. Recovery closes containers before volumes and remains under the original deadline. Failed native commands preserve their original stream prefixes and later cleanup failures. Missing observations remain unavailable.

The implementation entry is [operator.py](../../../benchmarks/neuroscience/gcamp8/transitive-recovery/operator.py). The [component README](../../../benchmarks/neuroscience/gcamp8/transitive-recovery/README.md), [resource API](../../../benchmarks/neuroscience/gcamp8/transitive-recovery/REGISTRY_API.md), and [candidate interface](../../../benchmarks/neuroscience/gcamp8/transitive-recovery/controller/CANDIDATE_ABI.md) describe the exact future invocation and boundaries. Do not invoke it as a smoke test: its real route can launch scientific and native work after the external gates are satisfied.

## Dependency boundary

The public component includes its controller, native ownership machinery, resource protocol, recovery worker, failure evidence support, backend, and inherited adapter. The [source manifest](../../../benchmarks/neuroscience/gcamp8/transitive-recovery/SOURCE_MANIFEST.json) authenticates 36 payloads; with the manifest, the component totals 37 files and 340,571 bytes.

The component is not the complete scientific dependency closure. Its unchanged [controller bindings](../../../benchmarks/neuroscience/gcamp8/transitive-recovery/controller/BINDINGS.json) and [adapter bindings](../../../benchmarks/neuroscience/gcamp8/transitive-recovery/legacy/BINDINGS.json) still describe original repository-relative operands:

| Required outside these 37 files | Role in the actual caller |
| --- | --- |
| Original delivery manifest, transport module, transport lock, and view-file catalogue | `adapter.sources` captures all four exact pinned bodies; the controller loads the transport and its lock. |
| Original `aggregate.py`, `grade.py`, `interface.py`, `metric_core.py`, and `stage_view.py` | `adapter.sources` captures all five exact pinned scientific source bodies. The controller uses the original exported staging and protected scoring route. |
| Original complete scientific export | The transport catalogue, staged inputs and protected numerical targets remain outside this recovery package. |
| Explicit paired programs and current review, authoring, runtime and host selections | The original independent author contexts, allowed information, immutable source, native runtime and full resource limits require real external evidence. Template flags and content hashes alone do not provide it. |
| Qualified Linux x86-64 cgroup-v2/Docker environment and selected existing image | These are runtime prerequisites, not provisioned by publishing the source. |

This projection does not include or inspect those external scientific operands, historical private receipts, raw control fixtures, neural arrays, headers, targets, credentials or acquisition links. Whether a separate public checkout already contains any original dependencies was not audited here. No new source pins or authority documents are invented to make an incomplete checkout appear runnable. A later standalone release must deliberately include or supply the missing scientific source and qualified operands, update its bindings coherently, and validate the complete route.

The `baseline` descriptor in the inherited adapter bindings is provenance metadata; the inspected GCaMP8 caller does not open it. The inherited `CompositeCapacity` helper has a lazy `.supervision` import outside this package. The selected GCaMP8 route uses `Capacity` directly; no call to `CompositeCapacity` or `charged_directory` is present in this component. That dormant helper is not advertised as a public standalone API.

## Evidence and remaining qualifications

The earlier finite engineering batch used ten invented cases, including the full declared lifecycle, with scientific and native leaves inert. It did not authenticate a dataset, execute the real Docker/cgroup programme, reproduce a paper result, or qualify model performance. One structural exception projection remained incomplete and explicitly retained an unresolved object; successful lifecycle checks do not erase that limitation. Raw invented fixtures and private build history are excluded from this source projection.

Scientific questions remain open: released 117 versus historical 105 neurons, animal grouping, smoothing/frame conventions, original checkpoint provenance, method parity and author exposure. Native process/daemon behavior, whole-host accounting, source immutability and the outer observer's final exit also require independent qualification. Resource counters in the source cover their stated operations; they are not a measurement of total host I/O or physical resident memory.

Registration, runnable-benchmark and scientifically-qualified counts are unchanged by this publication. The release provides reviewable recovery source and an explicit dependency boundary.
