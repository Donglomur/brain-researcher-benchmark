# Repository quality and remaining delivery gaps

This assessment covers the public integration tree at
`98fab693e651faef1cfb86147bd70efe66a8c8e0` on November 16, 2026.
It is a source and metadata review, not a new native or model evaluation.

The repository is a substantial construction library with explicit scientific
contracts, source provenance, reusable scorers, controlled-access components and
generated checks. A complete, independently reproducible benchmark release has
not yet been established. The current fully qualified task total remains unknown.

These populations differ from the programme's 42 historical finite acceptances.
Neither inventory should be substituted for current full-contract qualification.
The [catalog](../../benchmarks/catalog/README.md) deliberately reports readiness
as unknown and does not traverse private qualification records.

## What must be completed

1. **Portable task delivery.** An independent user needs an exact task package,
   provisioned assets and environment, an agent-to-output command and a verifier.
   The generic public CLI currently provides navigation; its strict score/run
   routes still require separate admission. Component source and documentation
   are useful intermediate products, not proof that a task works on another host.
2. **Complete scientific scope.** Map every canonical output to its implemented
   profile and evidence. For example, [NEURAL-023's specification](../../benchmarks/manifests/neural/NEURAL-023.json)
   requires chronological sessions for Indy and Loco, while its
   [historical finite profile](../../benchmarks/neuroscience/neural-023/manifest.json)
   covers one animal and two exposed days. Preserve that useful narrower profile
   without presenting it as the entire registered programme.
3. **Executable study bindings.** The [paired-study templates](study-design-v1/README.md)
   need concrete validated assignments, matched budgets, estimands, failure
   handling and analysis before they support claims about official-code benefit
   or adaptive investigation. Source validation alone will not establish an effect.
4. **Protected evaluation and exposure accounting.** Publicly exposed examples
   remain development material. The [PFC task guide](../../components/pfc-science2-package/task/README.md)
   explicitly limits what its public-code/public-oracle profile can demonstrate.
   Improvement claims need frozen methods and a justified confirmation panel.
5. **Scientific and empirical qualification.** Review reference methods,
   biological independence, tolerances, meaningful baselines and shortcuts. Then
   qualify the complete native route and retain actual agent evidence under an
   explicitly selected execution phase. Generated assertions cannot establish
   task difficulty, scientific novelty or state-of-the-art performance.

[Harbor](https://docs.harborframework.com/tasks/overview) describes independently
runnable tasks with environments and verifiers. The
[Terminal-Bench-Science contribution process](https://github.com/harbor-framework/terminal-bench-science/blob/main/CONTRIBUTING.md)
adds oracle/no-op evidence, native validation, model trajectories and staged
review. These are task-level deliverables still to establish for this suite;
green source CI does not imply acceptance there.

The immediate construction priorities are portable component delivery and strict
study-binding validation. No new dataset acquisition or model campaign is part
of this source-only phase, and no readiness or benchmark-count increase is
claimed by its commits.
