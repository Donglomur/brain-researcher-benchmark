## Exact identities and source binding

A descriptor is an exact typed record {path,bytes,sha256}; bytes is a nonnegative exact integer (booleans refused), sha256 is64 lowercase hex, path is a canonical absolute operator path or a repository-relative source path under its declared root. Its role/schema/source generation is separate and typed. Reject duplicate JSON keys, nonfinite values, invalid UTF8, extra fields and bool/int aliases before using records. Do not normalize an untrusted traversal path into an admitted one. Physical namespace, symlink/hardlink/mount alias separation is a qualified deployment property, not established by lexical checks.

Every operation joins the whole programme source manifest, original label-free support index/protocol, immutable preparation generation, exact fold/view/query support, selected method/model state, environment/image, original clock, resource reservation and actual producer command. Before opening candidate code, output, data or private operands, the outer entry must authenticate its own source/bootstrap, the exact qualification record, the registered/default/named route and the selected operation authority. Absent qualification refuses before those operands. A source snapshot is never promoted because its fields say qualified.

Implementation must capture all required source bodies into a closed immutable module graph before data access, join actual argv/cwd/interpreter/source launch to that graph, and recheck original file pins around staging/launch. No ambient PYTHONPATH, late mutable import path, implicit latest dependency, undeclared source download or unbounded dependency closure. Libraries may be imported only in the later qualified numerical environment; their complete installed identities and image digest must be admitted, not inferred from requirements.txt.

## G3: source-owned native observation

Use an operator-owned direct container-engine API with exact image digest, unique operation nonce/labels and returned immutable container ID. Numerical workers are nonroot, readonly mounts, no network/engine socket/capabilities, no privilege escalation, fixed memory/CPU limits and bounded output/workspace. Candidate subprocess creation is disabled. The controller owns the engine socket; it is never exposed to code or provider messages.

Before start, bind the created object's exact ID/nonce/image/mount/policy record to the selected operation. During execution an independent watchdog enforces the original deadline and prospective resource reservation. On interruption it may act only through that exact engine-owned object after its identity/labels are rechecked; no PID/PGID-name guessing or signal after a reaped identifier may be reused. A state “created,” a missing status field, untyped exit value, absent EOF or a timer that fired is not successful closure. If exact object custody or stop state cannot be established, retain failed/unknown state and require separate inspection; do not claim cleanup succeeded or reuse an uncertain journal.

Successful native closure requires a strictly integer0exit, expected command and source, complete bounded stdout/stderr, natural process completion by the original normal deadline, quiescent final state, exact output/model inventory, valid resource measurements and no watchdog/cleanup uncertainty. Cleanup may bound failure but never convert it into success. Original output/wait observations must be retained before derived summaries. If a durable observation publication fails, preserve the observed outcome and publication uncertainty separately; do not overwrite, reconstruct a successful receipt or silently rerun.

Stopped-container CPU/peak-memory measurement and enforcement semantics must be demonstrated for the exact runtime. Missing measurements refuse scientific admission. A selected quota×wall reservation is a prospective CPU upper bound; it is not a measured CPU counter. Host-managed byte counters are not total native/OS I/O; each native source has separate input/output reservations and completion joins. Native code can perform broad analysis, but cannot consume an undeclared infinite physical I/O budget under an alleged source-read counter.

## G4: full independent readback and panel assembly

The independent observer captures the actual root controller invocation and original clock, not merely a subprocess.run return. It preserves bounded streams, strict typed exit, EOF/reaping and any remaining-descendant/unknown state. Numeric process-group signalling without proven custody is prohibited. It must independently replay the full source/authority/support/resource/action/artifact closure using the current complete graph, not trust controller success flags.

Each individual candidate output is joined to its one permitted query alias, canonical private support identity, mode/replication/view, exact producer/code/model state and case deadline. The observer admits all12N results, exact source/action/access and terminal-closure observations, sanitized-projection joins and their required action prefix, then assembles120complete candidate panels in canonical order. It also admits all80reference and40analytic panels and their complete upstream3,680fit/3,680inference/20selection chains. Identical counts without exact ID/source edges are not coverage.

Readback has a fixed parent processing interval anchored to the same original campaign clock. It cannot extend a child's normal scientific deadline or reinterpret late cleanup as timely success. Any permitted post-child output authentication must use its explicitly selected parent interval and check the clock after the last blocking read/fsync/close. A self-written completion marker cannot prove the outer process has naturally exited. An independently observed central natural exit and original stdout/stderr closure are final external admission conditions, separate from internal artifact validation.

G4 is the independent observer's **pre-grade producer barrier**, while the trusted controller may still be alive. It does not require the entire controller to exit before it can dispatch G5. The protected target mount/authority is issued only after that barrier, all candidate workers are closed, and their artifact identities are sealed. After G5, the observer performs the final whole-campaign/source/artifact recheck and observes the original controller exit. Any numeric grade remains provisional until that separate final external predicate passes. This prevents a circular “controller must exit before its grader runs” contract without releasing targets to an active candidate.

Only after G4's complete producer/source/artifact admission may the protected grader open the actual global assessment-target body. Before that point even a descriptor advertised as metadata must be refused if it aliases the private target root or another target-bearing object; every pretarget read must enforce the selected root/role boundary.
