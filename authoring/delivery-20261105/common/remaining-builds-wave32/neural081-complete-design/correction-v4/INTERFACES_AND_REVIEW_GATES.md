# Interface contracts and subsequent implementation acceptance

This document fixes scientific roles and required artifact edges, not a pretend runnable API. Exact future filenames may be assigned by implementation while preserving these source-bound role/schema/identity rules. Any changed scientific field, count or method requires an additive design successor and review.

## Typed metadata and complete supports

All JSON uses UTF8, no duplicate keys, finite numbers and exact field sets. Integer fields reject booleans and integral floats. Hashes are lowercase hexadecimal with exact length; array shapes contain exact nonnegative integers. A descriptor's ordinary byte/hash identity never substitutes for validating its role/content/source generation.

`support_v1` contains exactly schema,task_id,preparation_generation,protocol_source,source_inventory,people,class_ids,canonical_channels,rows andprivate_boundary_evidence. Its operator-only rows are ordered by PEOPLE then canonical_id, each containing person,canonical_id,source_event_index,source_onset_sample,processed_condition,private_label,source_file,window_descriptor andphysical_boundary_disposition. Every selected condition4event appears exactly once. This is a protected label-bearing object, not general operator metadata: only trusted G0 and the protected G5 grader may open its complete body. Before G5, campaign controllers, observers and access validators may use its authenticated descriptor but must NOT open/hash/parse its body, even for lineage. The public candidate schema is not this support object. SUPPORT_CUSTODY.md defines the separate complete label-free support_index_v3 used by all pre-grade joins, and isolated training-label views for their legitimate roles.

Operator-only `context_v4` contains schema,task_id,access_policy,mode,replication,view,context_alias,class_ids,query_descriptor,training_descriptor,training_groups_descriptor,frozen_models,tool_sources,environment,resources,original_origin,normal_endpoint andauthority. access_policy is exactly `single_query_transductive_v4` and must equal the separately issued candidate_context_v4 policy and selected authority/source. One query descriptor resolves to exactly float32[64,512] and its own32hexalias. Training contains all declared rows of exactly9people (or the reference's stated8/1 role), finite EEG, integer class labels and opaque group tokens; no held-person label or other query count. Context descriptors cannot be issued by a candidate. Counts/arrays are validated before native launch without reading the assessment object.

`training_support_v1` contains exact canonical training identities in private operator form, with public opaque aliases/group tokens in the mounted view. Inner fit and validation disjointness is checked by biological person, not row ID alone. All pre-grade complete support joins consume support_index_v3, not label-bearing support_v1; per-role training labels are read only under their separately admitted training authority. Complete source support joins must detect duplicated trials, multiple person aliases, wrong view, missing classes, wrong channel order, wrong sample extent and altered preparation generations before any producer runs.

Operator-only `model_v1` contains schema,task_id,model_role,family,configuration,outer_person,view,inner_person_or_null,source,environment,training_support,feature_definition,scaler_descriptor,parameters_descriptor,calibration_descriptor_or_null,numerical_diagnostics andproducer_closure. No executable pickle or mutable public link. Final states contain all saved moments/coefficients/kernel training features/centering statistics needed for the defined predictor. The model role distinguishes inner,selected-family andhistorical states. A final state cannot be passed off as an inner model or a model fitted with all ten people.

Operator-only `selection_v1` contains schema,task_id,outer_person,view,ordered_inner_prediction_descriptors,ordered_setting_scores,selected_per_family,selected_temperatures,temperature_scores,strongest_family,uniform_prior,laplace_prior,training_label_support,source,environment andproducer_closure. It binds exactly180inner predictions,20setting score rows,3family choices and3×7temperature scores, not merely a hash of a summary. All comparisons/reduction order come from REFERENCE_MATHEMATICS. The analytic priors are output alongside it with exact support/role descriptors.

The operator objects above are NEVER mounted or serialized into candidate/provider messages. CANDIDATE_PROJECTION.md defines the exact separate candidate context/model records, generic paths, opaque row/group handles and private bijective joins. Public projection is validated before first exposure. Full source/authority/clock/producer records remain private even if their individual values look harmless. The same projection policy applies to F and I.

## Candidate action and prediction contracts

An I request is an operator-issued ordered message bound to its context, original deadlines and previous fully observed actions. A model action is exactly either `{action:'python',code,requested_seconds}` or `{action:'predict',probabilities}`. Code is an ordinary UTF8 Python body of at most65,536 encoded bytes; requested_seconds is an exact integer1..remaining480. At most8python actions and9provider requests. There is no hidden evaluate,fetch,other-query or grade action. The trusted controller supplies the fixed current context and stamps a monotone action index; model-provided IDs cannot redirect a result to another case.

An operator Python result records exact action index, source descriptor, native closure descriptor, bounded stdout/stderr descriptors, admitted file inventory and remaining resource ledger. Only the sanitized tool-result projection in CANDIDATE_PROJECTION.md reaches the provider; original source paths, closure/clock/authority records and raw operator logs do not. Failed but fully observed actions retain the same structure and full charge; uncertain closure aborts. The provider may synthesize new code within remaining budget after an ordinary closed analytical error. Nothing automatically retries an unknown operation. Code and outputs are never silently stripped from the trace to create an apparent successful first attempt.

An F source-author request permits exactly `{action:'python',code,requested_seconds}` (data-free source testing, code<=65,536 UTF8 bytes, exact integer seconds1..min(60,remaining author-native480) for that action) or `{action:'seal_program',entrypoint:'program.py',files}`. `files` is a list of1..16 exact `{relative_path,text_utf8}` objects, ordinary unique relative `.py` paths with no empty/dot/dot-dot components, absolute paths, backslashes, NULs or symlinks. It includes program.py and totals at most524,288 UTF8 source bytes. Every file is captured, syntax/schema/dependency-validated and sealed; no supplied executable binary, pickle, unreviewed dependency fetch or later source overwrite is permitted. The author has at most8 Python actions and9 provider requests, with its final source action required by its original2,400s normal endpoint. The three sealed programmes receive no authentic data or realized models until after sealing. No automatic source repair occurs during prediction.

An F programme accepts the same sanitized single-query/training/tool context and must produce exactly one probability row through a fresh source-owned JSON output file of at most16,384 bytes. The body has exactly `{probabilities}`; the trusted caller stamps context identity. The callable entry is `predict(context)` in program.py; the trusted adapter invokes it once and serializes its return only after schema validation. No arbitrary candidate-provided output path is used. Its source identity is fixed for the replication before authentic data exposure. Programme output does not select its own source, context or case identity. F may not call the provider or create child processes during prediction.

`candidate_result_v1` contains exactly schema,task_id,mode,replication,view,context_alias,probabilities,context_descriptor,programme_or_episode_source,ordered_actions,final_resource_ledger andoriginal_terminal_closure. There is one such result per12Ncandidate case. Arbitrary explanatory text is retained only in bounded private traces and is not part of the numerical score. The benchmark does not award a separate scientific-reasoning score merely because a transcript contains a fluent explanation.

Canonical numeric prediction rows retain the original `neural081_predictions_v1` schema, exact12probabilities and canonical private-order IDs when assembled operator-side. Assembly maps context aliases back to canonical IDs through the immutable private issuer; it cannot change a candidate probability. The120candidate panels and120comparator panels each bind their exact source/results/assembly inventory. All individual candidate closures remain necessary even if panels happen to contain correct-looking counts.

Every F source bundle, I action and completed query is joined through EXECUTION_ADMISSION.md to its exact source, allowed input role, qualified physical capability, resource reservation and original terminal observations. Statistics fitted using the one allowed unlabeled query are permitted; no human/LLM statistical-semantic verdict is requested. Missing access/source/closure evidence still refuses. No universal account of every internally generated operation is claimed.

## Source/run qualification records

A qualification authority is an external operator decision bound to exact source/image/engine/provider/method/physical-root identities and a finite campaign reservation. It is not a candidate-supplied success flag. It includes source capture, complete support admissibility, original event/label/version lineage, physical namespaces, method access, numeric library behavior, provider request model and credential routing, resource enforcement, stopped-process measurement and independent external observation. No such record exists for this new programme.

Build-time/default operation must refuse before authentic key/data/model/provider/candidate operands unless the selected operation has all required specific authorities. A preparation authority permits its trusted original annotation reads; a candidate authority never inherits that permission. A grading authority is separately usable only after the complete barrier. Root installation/source publication is not any of these scientific authorities.

For provider credentials, first bind the admitted endpoint/model/secret-name descriptor and source operation using metadata only. Only the host provider adapter may read that one selected secret value from its protected channel; it is never printed, written to a receipt, placed in a numerical-worker environment or forwarded to unselected hosts. No authentication setup or paid request is authorized by this design.

## Required independent implementation evidence later

A later implementation grant must permit meaningful invented controls before running them. Required controls include:

1. Exact64×2048→64×512 transform, channel/source/event support and fixedwindow boundaries; synthetic feedback pseudo-times cannot exclude a physical trial, and unknown physical labels cannot be ignored.
2. All10people/12classes/condition4 trials survive into the correct fold/query roles; wrong-view or other-fold access refuses before operands. Both view and current-query namespaces are independently verified.
3. Analytic feature/scaler/covariance/ridge/probability controls, population versus sample variance, uniform covariance priors, source-specified AUTO shrinkage, singular/constant data, KRR intercept/alpha normalization, exact nested selection/temperature tie order and preserved failed attempts. Independently derived expectations are required; source that reproduces its own formula is insufficient evidence.
4. Complete fit→seal→infer→select→refit state/source/support edges, all grid settings and every case/panel. Validate full roster metadata without importing authentic arrays or constructing a convenient smaller scientific study.
5. Actual concrete current-query provider/tool transport and F execution wiring with inert external leaves; exact request order, broad Python source delivery, original clocks, source substitution, credentials refusal, budgets, action-error retention and no cross-query state. A mock-only port is not the final implementation.
6. All original natural-exit and stream boundaries: exact integer0, EOF/reaping/engine quiescence, late completion, failed observation publication, retained unknown survivors and no reaped numeric-PID signalling. A function returning success does not prove external terminal closure.
7. Global barrier before any assessment-target-body access, including alias/private-root attacks on pretarget metadata and the current old gold-builder's early-label-order defect. Permitted training annotation reads are separately logged rather than erased from the claim.

Additional changed-boundary controls must cover sanitized context/model/error projections, opaque training order, F source finalization/deadline, exact raw-stream versus provider projection caps, invalid UTF8, token overflow without transcript truncation, dynamic code within the fixed physical capability and absence of a per-action statistical-review dependency and calibrated near-tie metric ranking.

These are review requirements, not controls executed in this zero-fixture design phase. Full scientific qualification also requires real complete source/header verification, exact installed runtime/custody/resource observation and complete reference/candidate results under separately selected authority. A negative empirical result must remain negative; do not retrospectively redefine eligibility, reference choices or reporting to claim success.
