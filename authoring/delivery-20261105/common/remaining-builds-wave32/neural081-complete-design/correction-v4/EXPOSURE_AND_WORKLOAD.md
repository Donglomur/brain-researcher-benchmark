# Exact F/I permissions and full workload

This document selects the primary current-query comparison. Training-only LLM method choice is not a substitute I condition. One current-query context contains all allowed training evidence for that outer fold/view, the immutable trained tools and exactly one current query. No label or feedback for that query is ever returned to a candidate.

## Training/author/query separation

F receives three author episodes before access to any authentic training/query data or realized models. It may read the public scientific protocol, feature/reference definitions, tool schemas and resource profile and write unrestricted supported Python source. This source is sealed by exact byte/source/dependency identities for r0/r1/r2 before deployment. It cannot call an LLM/provider at query time. Each current-query F worker executes that frozen programme with the same numerical inputs/tools available to I; runtime decisions can depend on its current EEG, but source cannot be edited after viewing it.

I receives one fresh LLM context for each query/view/replication. It can inspect the current EEG, choose analyses, synthesize broad Python and run the code. It can inspect/probe the supplied trained models, training observations and labels, and produce intermediate numerical evidence. It is not confined to a fixed feature menu, a typed classifier router or model-vote selection. This distinction is the experiment; it is not evidence of raw signal understanding independent of tools.

The common training tools are all three selected family models, the historical model, sanitized training-only metadata/scalers/configurations and uniform/prior procedures for that fold/view. Candidate records and model envelopes are exactly CANDIDATE_PROJECTION.md; full operator records are never exposed. The protected numerical row order is the explicit opaque convention in REFERENCE_MATHEMATICS.md. All original shared reference fitted states, temperatures and strongest-family choices are sealed before either mode sees queries; subsequent private candidate adaptation does not alter those states. Return predictions/raw scores only for the **current** query when using these tools. Do not mount a table of all reference assessment predictions. All model arrays/source are readonly; no pickle/executable state loader.

Additional scratch fits and analyses **are allowed in both modes** within each current-query budget, including statistics/models fitted on the union of the nine-person labelled training data and exactly one unlabeled current query. Allowed examples include joint normalization/covariance, self-supervised or entropy-based adaptation, model-generated pseudo-labels, and a private adapted copy of a supplied frozen model. Pseudo-labels are candidate inferences, never assessment targets. Such methods can fail or worsen predictions; the protocol does not assume they help. The held person stays absent from labelled training.

No additional held-person calibration set or query batch, actual query target/correctness, cross-query writable state, shared-model mutation or online update across episodes is permitted. The original reference arrays/source remain readonly; a private scratch copy may change without changing the reference or its identity. F's sealed algorithm may perform the same adaptation classes as I, while I may synthesize source after observing this current query. All scratch/code/logs remain inside that episode and cannot become another case's input. Native action/source/resource observations and retained artifacts are recorded; a candidate's descriptions of internal fit counts are not silently treated as independently observed complete semantic traces. Scratch work is charged to the same native envelope and is not part of the fixed3,680 reference fits.

F can automate every numerical operation class available to I. Both get raw training/query64×512 arrays, not only reference features, and may read every permitted row. A supplied shared cache must be training-only, source-bound and equally available; candidate-created transductive cache/state is restricted to its one episode. Both use the same exact offline Python/numerical image and the same logical-read, write, CPU, memory and allowed-process limits for a query. Provider reasoning time/tokens are separately reported for I, not disguised as numerical equivalence. Primary provider messages are text/tool-result messages; arbitrary external retrieval, unselected remote models and additional provider calls from native code are prohibited. If a future study adds image-bearing tool messages, it is an explicitly named exposure change requiring a reviewed successor, not an unnoticed implementation option.

## Provider/tool protocol and seeds

I's allowed actions are (a) one Python source execution over the existing private episode workspace/current allowed mounts, or (b) one final12-probability prediction. There is no action that asks the grader for correctness, reads another case, acquires new data or changes the model/tool inventory. Broad Python remains possible inside action(a); the operation boundary is transport/custody, not an analytical menu. All responses, code, images/files created incidentally, errors and model choices are retained operator-side and counted. No hidden automatically repeated tool or provider action is allowed after failure.

At most K=8 Python invocations and Q=9 provider requests per I episode are selected: an initial request, at most eight requested Python runs and final prediction. A provider request may end the episode early with a final prediction. Each Python action starts a fresh native process with the same episode workspace; scratch files may persist inside that episode only. A failed action remains an attempted slot and its charges remain. The provider may continue within the remaining allowance only if the failure has a fully observed closed outcome and policy permits ordinary analytical recovery; uncertain process/custody failure aborts the entire episode. This is not retrying the same producer after an unknown outcome.

F has one isolated prediction process per query and may use the same total Python numerical budget internally; it may not launch child processes, access provider network or delegate hidden work. The common numerical image exposes NumPy/SciPy/scikit-learn and source-bound reference readers, plus supported Python standard-library operations. The runtime must actively enforce the process/network/filesystem restrictions. Both modes may compute more than eight internal mathematical operations; K counts I's separate tool transports, not an analytical-expression cap.

F-author exact actions/final bundle are fixed in INTERFACES_AND_REVIEW_GATES.md. Both author and I provider messages use the exact bounded stream projection and token-overflow rule in CANDIDATE_PROJECTION.md and RESOURCE_CONTRACT.md. Original transcript history is never implicitly summarized or dropped to fit a prompt.

Three replication IDs are exactly r0,r1,r2. The provider model, endpoint/schema/version, public sampling configuration and tokenization accounting must be selected before authentic exposure. Request seed = first8 bytes big-endian of SHA256(UTF8('NEURAL081-provider-v1|'+mode+'|'+rep+'|'+view+'|'+context_alias+'|'+decimal_request_index)), reduced modulo2^31. F data-free author contexts use view='AUTHOR', context_alias='GLOBAL' and the same domain; I uses its exact private-issued32hex alias and selected view. No seed is a privacy key. If the provider ignores/does not support seed determinism, record that fact and the returned request/model identity; do not claim deterministic replicated reasoning. References have no RNG. Candidate Python may request a documented generator derived from the same episode seed; all candidate nondeterminism remains recorded and bounded.

The model may already know this public retrospective source. No model-exposure exclusion is claimed. Provider sessions must be fresh, with no retrieval memory, shared mutable tools or previous query conversation. An API request ID does not itself prove those conditions; exact provider/interface qualification is required later.

## Deterministic complete scheduling

All source support and reference state selection precede candidate queries. The canonical queue order is mode F then I, replication r0,r1,r2, view EEG then ZERO, fixed PEOPLE order, and canonical support-ID order inside person; candidate aliases differ and other queries are inaccessible. This fixed order is a reproducibility convention, not randomization. No online learning or performance feedback is allowed, so condition order cannot legitimately update candidate state. Report any provider version/drift during the campaign and invalidate comparability if the selected model/interface changes. The full design does not silently combine runs across a provider upgrade.

Within each outer fold/view, inner-validation order is fixed training-person order; configuration order is the exact mathematical grid. Each fit seals before its inference. All180 inner predictions close before its selection worker. All80 final/historical models and all20 selection records close before the candidate campaign begins. Operator-side reference assessment inference may then occur, but its complete tables remain private. All12N candidate episodes close before any assessment-target operand read, followed by independent global admission and protected grading.
