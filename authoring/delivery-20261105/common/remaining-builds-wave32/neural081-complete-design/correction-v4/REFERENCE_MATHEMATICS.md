# Exact fixed inductive reference mathematics

This document defines the fixed reference procedures only. Their training-only fitted statistics, complete grids, selection, calibration and model states are unchanged by V4. Candidates may adapt private state with their one unlabeled query under EXPOSURE_AND_WORKLOAD.md; that does not alter these definitions. Candidate superiority over these inductive procedures is not a reasoning-only attribution.

C=12 in the declared class order. T=512. Feature matrices and learned calculations use finite binary64. Source EEG packets are finite binary32; conversion to binary64 is exact. No padding, missing-value imputation, observation deletion, approximate kernel, outcome-based refit or jitter is selected. ## Trial-local feature families

For each trial and channel c, let m_c=(1/T)sum_t x_ct and u_ct=x_ct-m_c. Hann weights h_t=(1-cos(2*pi*t/(T-1)))/2, t=0..511. The unnormalized forward DFT is a_ck=sum_t h_t*u_ct*exp(-2*pi*i*k*t/T), k=0..256; power P_ck=|a_ck|²/T. Frequencies are k/4 Hz. Band sets are k=4..15,16..31,32..51,52..79,80..119, respectively[1,4),[4,8),[8,13),[13,20),[20,30). Feature f_(5c+b)=ln(max(mean_{k in band_b} P_ck,1e-24)), yielding320 values in channel-major/band-minor order. This is not a density-normalized spectrum or a square of average amplitude. The floor is in the stated numerical power units and is applied only here.

The temporal family has g_(16c+b)=(1/32)sum_{t=32b}^{32b+31}u_ct, b=0..15, yielding1,024 channel-major/bin-minor values. Demeaning is trial-local and identical at training/query time. It is not a learned filter. References use no EOG or source metadata.

Both families are constant across trials in ZERO. Cache these unlearned features operator-side once per view/person if useful, but a fitted scaler or a feature cache supplied to candidates must be the same admitted tool class for both modes. Candidate I retains raw64×512 access and broad Python, not merely this feature menu.

## Global train-only scaling

For a training matrix F of n rows and d features, each row has weight1/n. For each feature j, mu_j=mean_i F_ij and v_j=mean_i(F_ij-mu_j)² (population variance, ddof0). Let eps=2^-52 and b_j=n*eps*v_j+(n*mu_j*eps)². Scale s_j=1 if v_j<=b_j, otherwise sqrt(v_j). Standardized z_ij=(F_ij-mu_j)/s_j. Query and validation use only this saved mu/s. All classes must be present. No NaN is allowed even though the library's generic scaler can permit NaNs.

The near-constant threshold is the exact rule in held scikit-learn1.6.1 _is_constant_feature. The historical baseline's StandardScaler uses its actual corrected two-pass/incremental accumulation implementation. For a fresh finite, unweighted fit it accumulates T=sum(x)/n, residual sum c=sum(x-T), and population variance [sum((x-T)^2)-c^2/n]/n in binary64; the immediate extmath source confirms this normalization. Empirical covariance likewise uses bias=1 (population covariance), not n-1. Prospective independent numeric checks must compare mathematical population moments and tolerated floating error, not claim bitwise equality of all accumulation paths.

Training rows are equally weighted. Biological-person/class equality is in validation and final metrics; do not silently add person weighting to covariance or kernel fitting. LDA class priors and covariance class weights are uniform as specified below.

## LDA, fixed and AUTO shrinkage

For each class k, let n_k be its training count, a_k the mean standardized row, and R_k rows z_i-a_k. S_k=R_k^T R_k/n_k. For fixed lambda in{0.01,0.1,0.5}, define S'_k=(1-lambda)S_k+lambda*tr(S_k)/d*I. Uniform class-prior covariance is Sigma=(1/C)sum_k S'_k. It is not the empirical class-frequency-weighted covariance.

AUTO means the **classwise standardized Ledoit-Wolf** operation in scikit-learn1.6.1 discriminant_analysis._cov, not a generic pooled shrinker and not OAS. For each class matrix Z_k, independently apply the same population StandardScaler rule using n_k to obtain W_k and class feature scales q_j. Ledoit-Wolf re-centers W_k; let V be that centered n_k×d matrix, E=V^T V/n_k, a_j=sum_i V_ij²/n_k, mu=sum_j a_j/d, D=sum_{j,l} E_jl², and B=sum_{j,l}sum_i V_ij² V_il².

Set beta0=(B/n_k-D)/(d*n_k); delta=(D-2*mu*sum_j a_j+d*mu²)/d; beta=min(beta0,delta); lambda=0 if beta==0, otherwise beta/delta. This is the held library formula (its blocked summations have block_size1000). It does not insert an extra max(0,beta) or a different degrees-of-freedom correction. Let L=(1-lambda)E+lambda*mu*I. Restore original class scales: S'_k=diag(q)L diag(q). Then Sigma=(1/C)sum_k S'_k. Record all class shrinkages and scales; nonfinite or out-of-[0,1] computed shrinkage is a numerical failure, not a reason to change formulas or silently choose fixed lambda.

Let A have the C class means as rows. The discriminant coefficients are W=Sigma^+ A^T, the minimum-norm least-squares solution. Class score l_k(z)=z^T W_:k -0.5*a_k^T W_:k +ln(1/C). A singular covariance is handled by the declared SVD cutoff, not jitter. If all input features are constant, all global z and class means are zero, W=0 and all scores equal; softmax is exactly uniform up to finite rounding. If within-class covariance is zero but class means differ, this LDA may also be uninformative: report the defined minimum-norm rule, not a convenient nearest-centroid replacement.

LDA grid order is BP-LDA(lambda.01,.1,.5,AUTO), then TM-LDA(sameorder). The fixed historical baseline is the original band-power transform plus original StandardScaler and LinearDiscriminantAnalysis(solver='lsqr',shrinkage='auto',priors=uniform) with uncalibrated softmax. It intentionally overlaps the BP-AUTO mathematical method. Keep its20 separate fit/inference executions for continuity and source/parity diagnosis; do not count it as an independent scientific family or silently deduplicate its workload.

## Nonlinear RBF kernel ridge, twelve settings

Use only the320 band-power features and the train-only scaler. gamma order is1/(4*320),1/320,4/320. alpha order is0.01,0.1,1,10. Configuration order is alpha-major then gamma-minor. K_ij=exp(-gamma*sum_l(z_il-z_jl)²); direct finite squared differences define distance. K_ii=1. Do not use clipped negative squared-distance tricks, subsampling, Nyström/random features or an approximate kernel.

For Y, the n×C one-hot training matrix, define H=I-11^T/n, Kc=H K H and Yc=H Y. Solve (Kc+alpha I)B=Yc. The objective is **sum_i ||y_i-f(z_i)||² + alpha||f_nonconstant||²_RKHS**, with an unpenalized intercept; equivalently1/n loss plus alpha/n penalty. Alpha is an absolute Gram-matrix ridge and is NOT multiplied by n in the solve. This normalization choice is part of the contract.

Let k(z)_i=K(z_i,z), r_i=mean_j K_ij, g=mean_i r_i and m(z)=mean_i k(z)_i. Define k_c(z)=k(z)-r-m(z)1+g1. Raw class scores are l(z)=mean_i Y_i + k_c(z)^T B. These scores need not be probabilities or lie in[0,1]; do not clip them. A softmax defined below supplies valid probabilities. The intercept and centering are fit solely from training rows. ZERO gives constant inputs; the model produces a constant vector per fold, not a target-person prior.

## Probabilities, nested selection and train-only calibration

For any finite score vector l, softmax at T_cal>0 is exp((l_k-max_j l_j)/T_cal) normalized by the sum. Underflow to0 is allowed; overflow/nonfinite arithmetic is not. All reference probability rows must also pass the canonical finite/range/sum admission. No hidden class reordering.

For each outer person p and view v, evaluate all20 settings on all9 inner held-person q among the nine training people. Fit on the other8 people. Each inner fit has exactly one held-person inference artifact, raw class scores and probabilities at T_cal=1. All180 inner artifacts must close before parameter selection. Inner scores use the same twelve-class recall and mean-trial log loss within person as the primary scorer; the nine inner people have equal weight.

Within each family select the setting with maximum inner mean balanced accuracy, then minimum inner mean NLL at T_cal=1, then first declared setting. Comparisons use the finite computed scores with no undeclared epsilon tie band. Preserve all180 observations and exact reduction order; near ties remain visible. Missing/numerically failed settings do not authorize choosing from survivors: the full selected reference grid is incomplete and cannot support a qualified comparison.

For each of the three selected family settings, retain its complete out-of-fold scores for all nine training people. Select one temperature from the ordered list **[1,1/4,4,1/16,16,1/64,64]** by minimum equal-inner-person NLL, ties first in that list. Use the canonical1e-12 log floor. This temperature scan uses only original outer-training labels and is not another matrix-model fit. It is explicitly included in the20 selection/calibration worker jobs. In real arithmetic positive temperature preserves score order. In binary64, exponentiation and normalization can merge distinct near-tied values; the first-class tie rule can then change the admitted prediction. Do not assume accuracy invariance. Recompute and retain balanced accuracy from the actual emitted calibrated OOF probabilities at every scanned temperature, alongside its NLL. The historical fixed comparator remains at T_cal=1.

Choose the strongest family using its recomputed calibrated OOF BA at its selected temperature, then that same calibrated OOF NLL, then family order BP-LDA,TM-LDA,RBF-KRR. Within-family configuration selection still uses the original T_cal=1 probabilities. Final assessment always scores the actual emitted admitted probabilities. Preserve both pre- and post-calibration BA; no extra matrix fit or assessment-label access is introduced. Refit each selected family configuration once on all nine outer-training people, attach its previously selected temperature, and seal all three states. The strongest identity is sealed before held queries. These validation values are model-selection evidence, not an unbiased final performance estimate. No calibration, family selection or temperature is re-chosen using assessment outputs.

Uniform probabilities are1/12. The separate Laplace prior for outer fold p is (count_k in its nine training people +1)/(n_train+12), reused unchanged for all queries in that fold/view. ## Exact metric reduction and finite comparison

Use the declared twelve-class order and fixed PEOPLE order (restricted to the nine training people for inner selection). Prediction is the index of the first largest *emitted probability*, not the first largest pre-softmax score. No probability renormalization is performed by a scorer. Each probability is nonboolean finite binary64 in [0,1]; require abs(math.fsum(row)-1)<=1e-6. Integers may be converted only after excluding bool, and conversion must remain finite.

For each person/class, count exact integer successes and total observations, then perform binary64 correct/total. Every class has positive support. Person BA is math.fsum(the twelve recalls in class order)/12. Inner or assessment macro BA is math.fsum(person BAs in fixed person order)/number_of_people. For NLL, each row contributes -math.log(max(p_true,1e-12)); aggregate rows with math.fsum in that person's canonical private support-ID order, divide by its exact row count, then macro-average person losses with math.fsum in fixed person order. The log floor applies only inside log. Nonfinite contributions/reductions fail.

Configuration ranks use (-BA_at_T1,NLL_at_T1,declared_grid_index); temperature ranks use (NLL_at_T,declared_temperature_index); strongest-family ranks use (-BA_at_selected_T,NLL_at_selected_T,declared_family_index). All metrics in these tuples are computed by the rules above from actual admitted probabilities. Comparison is the exact finite computed float comparison, with no epsilon tie band. Selected-temperature BA is not inherited from T=1. No signed-zero convention changes probability classes; zero loss and negative zero compare equally under ordinary finite comparisons.

Report replication means using math.fsum in r0,r1,r2 order/3. Paired mode/view contrasts first subtract the actual paired binary64 person scores, then math.fsum in the stated person/replication order and divide. These conventions close ranking ambiguity but do not claim correctly rounded library transcendental/linear-algebra operations or cross-platform bitwise invariance.

## Opaque training-row layout

Every reference fit has an operator-only canonical support record. Its numerical training-row order is instead a label-independent opaque permutation fixed before fitting. For each canonical training trial, the protected issuer computes a 32-hex token using the existing truncated HMAC-SHA256 identity mechanism with the UTF8 domain `NEURAL081-model-row-v2|generation|role|view|outer_person|inner_person_or_FINAL|canonical_id`; every field is the exact source-owned identifier, delimiter-containing values are rejected, and the private key never enters candidate space. Sort these tokens lexicographically; a collision refuses rather than dropping a row. The same outer/split/view order is used across family/configuration fits; role is INNER or FINAL, with the historical model using FINAL. This exposes neither canonical person names nor physical source order. It is not a claim that biological identity cannot be inferred from the allowed numerical training data.

Feature rows, labels, group tokens, kernel training features, B and all row-indexed centering quantities use that same order. The operator joins each to the complete canonical support privately. The token/permutation does not depend on labels, query values, mode, replication, validation outcomes or runtime state. Once fitted, no query-specific permutation or refit is performed. Exact frozen arrays and inference source are common to F/I and to the corresponding operator reference inference. Candidate per-context training-view aliases may be different, but remain privately bijective to the same full rows. This is an explicit prospective finite-precision layout choice; permutation equivalence in real arithmetic is not claimed to be bitwise invariance of the old library pipeline. Historical continuity uses its literal original feature/scaler/auto-LDA library recipe with this disclosed protected training-row layout. It does not promise numerical/byte parity with the old stage_fold concatenation order. No authentic historical result has been executed or superseded in this source-design phase.
