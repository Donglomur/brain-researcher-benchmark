NEURAL035 complete fixed-block program source
===========================================

This adds one complete program condition to NEURAL-035: predict later within-session
astrocytic peak order from earlier public fluorescence blocks. It retains all 14
sessions, seven paired mice, 1,012 session-local cells and 28 query blocks. It is
the selected fixed 30-second retrospective task. It is not the original paper's
event-specific statistic, a causal-memory result, new-animal generalization, or
whole-paper reproduction. Its cohort overlaps NEURAL-034 and PAPER-FIND-NEW-001.

One frozen program is authored before numerical access. Candidate authoring receives
the public task/schema/API specification; execution supplies the exact early public
package. This is a fixed-program condition, not an interactive investigator condition.
The public four calibration blocks support development, the public validation block
supports selection, and final refit may use all five public blocks. The same selected
procedure must cover all 14 sessions. A separate root method attestation records
chronology, prior exposure and the absence of query/full-trace/related-task access.
Hashes alone cannot establish this history, and the historically public original
traces preclude a global unseen-data claim. Whole-session processing and ROI selection
are inherited; this is not a strictly causal forecast.

The candidate ABI is an ordinary UTF-8 Python program, at most 131,072 bytes:

    python -I -B /submission/program.py --input /input --output /output/predictions.json

Only the 21 exact public files from the selected export are mounted. They total
11,648,181 bytes and include the public loader, schemas, 14 NPZs and opaque manifest.
The wrapper does not expose PROTOCOL, SOURCE_BINDING, mouse/context identities,
private query arrays/peaks/flat masks/surrogates, original whole-session observations,
or other tasks' packets. Cell correspondence is within each session only. The
public contract verifies all 14/1,012/28 identities at execution, after program freeze.
Public-loader NumPy 2.2.6 and the complete immutable image must be separately qualified.

The candidate writes the original one-document prediction schema, capped at
2,000,000 bytes. All 28 queries require a finite nonboolean score in [0,1] for every
public cell in its original order. Ties are permitted. No cell/window/animal fallback,
partial cohort or convenient subset is accepted. The legacy artifact-only interface
is unchanged. The 128 KiB program cap is a declared new program transport limit,
not a restriction retrospectively imposed on legacy prediction documents.

The controller freezes that program and a distinct fixed operator program globally
before copying public input. It runs the candidate, then the operator, in separate
networkless containers with one complete read-only public view, an output-only
bounded volume and no candidate access to the operator code/output or private data.
The operator uses the exact source `need`, `ranks` and `baseline` functions: first
exact maximum and exact constant-cell detection in each of five public blocks,
normalized midranks per block, then mean rank across blocks. Flat/degenerate public
blocks contribute 0.5. It does not average peak times before ranking. This analytic
reference is not fitted. It produces both queries for all 14 sessions independently
of query targets. No operator prediction was generated during construction.

Each phase requires typed natural-zero container state, producer removal before
capture, all three owned resources closed and 11-field CLI closure records. The
holder's fresh private 4 KiB readiness mount is separate from the candidate volume;
PID1 publication follows empty-volume admission and requires explicit `--init=false`.
Only then can the producer start. At most 16 readiness probes use the original
30-second interval. All 64 CLI calls are bounded; the larger original 2 MB report
requires a 2.7 MB maximum encoded capture response and a 24 MB per-phase response
reservation. Candidate stdout/stderr are deliberately not retained (`log-driver none`).

After both complete outputs pass the original public admission, the wrapper durably
retires its owned public copy, retains both reports and original native receipts,
and publishes COMPLETE. The outer observer owns the worker process, requires natural
exit/group absence/EOF, independently authenticates both original native receipts,
all closure records, exact selected candidate and fixed operator hashes, complete
source-bound view identity and both complete reports before publishing its result.
All source capture, imports, argparse, runtime checks and publication use one original
clock. Startup and final cleanup independently attempt timer cancellation and each
handler restoration; cleanup failures cannot return successful status. Completion
is checked again after cleanup at the original deadline. Adapter handoff uses explicit
ADAPTER_ORIGIN and ADAPTER_STARTUP_GUARD, with no new origin or unguarded timer reset.

The owned host worker process group does not cover independently launched CLI groups
or Docker daemon resources after a forced outer stop. Failure receipts/intent names
must be retained for separate recovery. There is no automatic retry or qualification
on forced termination. Receipt existence alone does not prove successful invocation.
External root supervision must observe final adapter/interpreter exit and original
deadline; a source review is not that observation.

Private grading remains a separately authorized action. `deferred_grade.py` is not
imported by the worker/observer and is not a standalone runtime CLI. A trusted caller
must authenticate successful complete collection/outer custody before supplying its
captured documents. Both full reports are validated before its private callback. It
then checks independent operator vectors against the original five-public-block
reference and calls the exact original scalar grader. Original active-subset reranking,
equal blocks → sessions → paired contexts → seven mice, all 99 phase-shift diagnostics
and undefined propagation remain intact. No threshold, p-value, scientific novelty
or performance claim is added. Candidate-minus-baseline keeps its original meaning.

Prospective resources are finite caps, not measured requirements. The complete public
array payload is 1,012 × 1,500 × 8 = 12,144,000 bytes; ZIP headers are separately bounded
by the original loader. No compressed-size inference is needed for that payload.
The same 11.65 MB immutable public view is reused read-only across the two isolated
phases and then removed. Host retention is capped at 64 MiB: at most 12 MiB public view,
4,000,000 bytes of reports, 2 MiB source/program/selection custody, 2 MiB journals and
manifests, an 8 KiB external slot, with the remainder reserved for filesystem allocation
and conservative directory overhead. Allocation is checked using st_blocks and bounded
inventories before writes; no retention credit reduces lifetime counters. The input
copy is never duplicated per session or per query. A 2 GiB free floor plus current OTHER
plus remaining 64 MiB custody is required; this source does not reserve that space now.

Controller cumulative managed reads are capped at 256 MiB, including five full public
passes (~58.25 MB), two 24 MB CLI-response reservations, source/program, reports and
metadata. The observer has a separate 16 MiB read cap; controller writes are 64 MiB
plus 16 KiB external-slot writes. These are managed host byte budgets, not physical
disk I/O measurements. Native tmpfs output is 8 MiB, scratch is 32 MiB, shared memory
16 MiB, and holder readiness 4 KiB; they are distinct native memory allocations.
Candidate memory is selected in 1 MiB steps from 512 MiB to 4 GiB; holder memory is
128 MiB. The host Python live set is not independently RSS-qualified. Standard-library
JSON reads can allocate more than their encoded byte extent, so no 64 MiB RSS claim
is made. No model artifact is exported or retained by this whole-analysis ABI.

Candidate time is selected from 1–7,200 seconds; the fixed operator gets 300 seconds.
Two phase intervals add at most 300 seconds of lifecycle overhead, plus original
startup/postflight allowance: whole = candidate_seconds + 900, worker endpoint 20
seconds earlier, failure outer endpoint 60 seconds later. These are prospective timeout
choices, not measured full-scope performance. Capacity/time refusal never permits
cropping the cohort. Actual image/dependency compatibility, full-phase speed, isolation,
peak memory and failure recovery all require future independent qualification.

The reviewed NEURAL031 wave12 source supplies custody/native transport patterns;
its 40 matched views, whole-mouse tuning constraints, scientific data and historical
qualification are not inherited. Source tests use invented JSON/values and mocked
process/clock/filesystem seams only. No authentic numeric packet, private target/key,
model, native process, reference or scorer run occurs in this build. Runtime and
scientific qualification remain false. Root alone can select/install the proposed
central route; this adds no canonical task IDs.
