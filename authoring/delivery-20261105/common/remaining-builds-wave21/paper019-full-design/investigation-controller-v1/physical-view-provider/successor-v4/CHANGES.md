send_https owns both the HTTP response and connection. Response and connection closures are independently attempted. An original provider error stays the cause of ProviderFailure; the existing bounded consumed-prefix and full attempted token/cost receipt survive. No extra retries, refunds or zero-cost inference are introduced. Whole-program max_calls semantics stay unchanged.

Supervisor owns accepted connections explicitly. The listener inode is captured immediately after bind and before chmod. Cleanup independently attempts listener.close and exact-inode-guarded unlink. If the pathname identifies a replacement, unlink refuses; it never removes the replacement. If bind succeeds but the first identity capture fails, the unknown pathname is not deleted: closure fails without fabricating owned-inode evidence. Directory fsync and descriptor close preserve original errors; every enumerated output directory receives an independent sync attempt. Failure-journal file close and parent fsync are independently attempted even after an earlier write/fsync failure, without reporting durability success.
