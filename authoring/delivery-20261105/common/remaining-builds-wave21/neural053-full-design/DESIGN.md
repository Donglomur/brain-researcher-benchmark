# NEURAL-053: complete THINGS-MEG study design

This is a design of the existing canonical task, not an implemented, acquired, run or qualified benchmark. It preserves the four-person, 48-session, 480-run cohort and the fixed 100 <= t < 300 ms summary. The task measures supervised object-category decoding and the value of training-data investigation. It does not test native waveform understanding, unseen-class recognition, online decoding or a literal reproduction of the source paper.

Root selected the investigation unit on this design turn: **one outer person fold and one feature arm**, containing all 3,708 query rows. The mode names are **fixed-program** and **training-investigation**. Query rows are predictions within a case, not independent LLM authorings. This choice is recorded explicitly because it differs from an agent independently investigating each query waveform.

## Scientific question and scope

Can an LLM's investigation of the permitted training set produce a more accurate and defensible decoder than a program it writes before seeing numerical data, under the same eventual training inputs, query inputs, tools and declared resource envelope? Does performance depend on the neural summary beyond ocular and missingness information? The principal alternative is that competent conventional fitting, acquisition patterns, or eye information explains apparent gains. Neither a high score nor an improvement over a weak centroid proves neural understanding.

All four participants and all selected experimental observations remain. The original 108,192 recorded rows consist of 88,992 experimental rows, 9,600 repeat-test presentations and 9,600 catch trials. Test and catch rows are outside this already declared experimental-image endpoint by source role; they are not removed using responses or model results. Each person has 22,248 experimental images: 1,854 concepts with 12 images each. Ten images per concept are global training images, and two are global query images. Thus the retained experimental observations divide into 74,160 training-image rows and 14,832 query-image rows. Original input membership is broader than the rows used to fit one fold.

The primary paper is Hebart et al., *THINGS-data*, eLife 12:e82580 (2023), https://elifesciences.org/articles/82580. The pinned data release is OpenNeuro ds004212 v2.0.1, commit `5405e3ef6478cd55da62d14c9340b4f95f620b03`; author code is `5e0eccac51eac78b57045f5b90b4f53814f56c32`. This neural-data selection does not turn the 2023 source into a recent paper-reproduction project.

## Representation, clocks and source limitations

The existing source-defined neural view has exactly 271 processed MEG channels in the frozen public order. The expected full processed grid is -100..1300 ms at 200 Hz, 281 samples. Select ticks 20..59: 40 samples with 100 <= t < 300 ms. Per channel retain the finite mean and finite-sample fraction. A wholly missing channel has mean zero and fraction zero; this is not an observed zero.

The ocular view uses UADC009-2104, UADC010-2104 and UADC013-2104, from the original processed x, y and pupil channels. Pinned author source resolves the vertical-channel suffix discrepancy in prose. Author eye preprocessing includes conversion, invalid-sample removal and run-wide detrending; do not label the stored derived x/y values as untouched voltages or EOG. The complete CSV epoch has 1,681 source samples at 1,200 Hz. Rounded millisecond timestamps validate order; ordinal samples 240..479 select 100..300 ms. Validate all metadata and ordinal joins before summarizing. Means and finite fractions are retained, with no new interpolation or eye-quality row removal.

Canonical arms remain neural (271 means + 271 fractions = 542 columns), ocular (three means + three fractions = six), and joint (548). Add one explicitly secondary diagnostic arm, **neural-availability**, containing only the 271 neural fractions. It receives the same rows, class order, grouping and allowed pipeline interfaces; it cannot expose means. It is a condition of this task, not a new benchmark. No new waveform or time-window access is introduced. Neural minus availability and neural minus ocular are complementary diagnostics, not causal decompositions of cortical contribution.

Source zero-phase/run-wide filtering, median replacement of two short dropout intervals, per-epoch baseline normalization and run-wide eye processing precede this benchmark. They prevent a strict causal-latency claim. The design does not repeat or undo those operations. ## Outer split and equal training-group interface

Keep the canonical stimulus-only outer partition. For each class, sort its 12 global image IDs by raw SHA256 digest of UTF-8 `neural053-v1:<integer image ID>`, then by integer ID, and assign the first two to the global query set. The partition is fixed before neural values. For each held-out person, training is the other three people with all ten training images per class: 55,620 rows. Queries are the held-out person's two query images per class: 3,708 rows. Query image identities are absent from every training fold; a held person's training-image signals are also absent from its fold. No mode or trained tool may pool fold views.

Current `prepare.py::packet_arrays` exports only classes, fold, training IDs and query IDs; the public input schema has no participant or repeated-image grouping field. The private roster supports groups, but the current public interface does not make them usable for candidate validation. This design therefore adds an explicit **training-only grouping contract**, equally available to both modes and every reference. This is a prospective interface amendment, not a claim that the current package already provides it.

For each training ID, the new sidecar supplies a fold-local opaque `person_group`, `image_group`, and `image_block` (0..4). It must contain exactly 55,620 entries; three person groups; 18,540 image groups, each present once per training person; and one training class per image group. Each class has ten image groups, two per block. The operator assigns blocks by a frozen stimulus-only deterministic hash rank among the ten training image identities, independent of values and query labels. Opaque group aliases are generated with an operator-held key and domain separation; do not publish source image IDs, raw participant/session/run names, or a mapping to external event tables. No grouping row describes a query. The scientific split membership is identical across paired modes, feature arms and replications; aliases are paired within a comparison and separated across fold/context boundaries.

The canonical inner split is the product of three held training-person groups and five held image blocks: 15 splits. An inner fit uses the other two people and eight image groups per class (29,664 rows). Validation uses the held training person and that block's two images per class (3,708 rows). All copies of validation images are excluded from inner fitting, and no held inner person's other images enter fitting. Across the 15 validation sets each outer-training row appears once. This prevents apparent validation gains from sharing a participant or another person's copy of the same image. Every class has complete support in every split.

Training transforms, normalization, feature selection, probability calibration, early stopping and hyperparameter selection use only the relevant inner-fit/validation support. Final refits use the full 55,620 outer-training rows. Merely masking validation labels while calculating scaling, PCA, imputation or covariance on the whole outer training set would leak across the inner split and is not allowed.

## Agent modes, sealing and query semantics

Use three independently initialized authoring replications per model/mode, declared before numerical access. Four outer folds and four arms give 16 cases per replication. There are 48 fixed-program and 48 training-investigation author contexts, 96 total. The three canonical arms still determine six complete model/mode/replication prediction panels; availability is a separately named diagnostic panel. Replications, arms, folds and rows do not increase the canonical benchmark count.

In fixed-program mode, an isolated author sees only the task/specification, source knowledge and allowed tool APIs, then seals its complete program before seeing numerical training data. The sealed program receives the same one-fold/one-arm training data and group interface as its paired investigation, may perform its own admissible training-only analyses and selection, and seals the resulting model/prediction pipeline before query admission.

In training-investigation mode, a fresh author context may inspect that case's allowed training values, labels and opaque groups, use Python, run allowed training-only models and inspect their validation behavior. It must freeze the selected transform, model, calibration, prediction code and state before any query matrix or query tool output is admitted. This explicitly tests training-data investigation rather than direct per-query LLM interpretation. Neither mode is permitted an extra query-adaptation phase.

After sealing, both receive the complete canonical query matrix under the same interface. Prediction must be row-separable given the sealed state: `p_i = f_theta(x_i)`. Vectorized batches are allowed, but fitting to query distributions, query normalization, clustering, global assignment constraints, use of known two-per-class balance to reassign labels, batch-rank rules and changes to theta are prohibited. No cross-query persistent learning or inspection-driven revision is allowed. The operator's query aliases/order are paired across modes and randomized independently of source order; original sequence/session/image metadata stays private.

These semantic restrictions are stronger than a file hash or a read-only mount. Future method admission must inspect the selected computation, enforce model immutability and test batch partition/permutation consistency on the actual submitted path. Such tests give bounded evidence, not a proof about arbitrary adversarial code. Until the selected runtime/method boundary is independently qualified, these remain unqualified scientific execution paths. The design does not claim that the current package enforces them.

All tools/models exposed during training must be derived only from the case's permitted training support, with exact source, fit-set and state provenance. If operator-trained models are exposed as tools, both modes receive the same interface and availability; that access condition is named separately, and a tool-only comparator is reported. No external image, text embedding, pretrained THINGS-specific model, event-table lookup or other-fold state is silently available. General LLM pretraining contamination is an acknowledged limitation of public data, not eliminated by opaque IDs.

## Competent independent reference programme

The existing standardized class-centroid softmax is retained as a weak historical continuity comparator. It is not the primary competence standard. The native author `step3e_validation_pairwise_decoding1854.m` is relevant source context: all experimental concepts, session chunks and pairwise time-resolved CoSMoMVPA LDA. The native `step3d...200` uses repeat-test stimuli. Neither answers the new multiclass, held-person/unseen-image, fixed-summary question, so their reported scores cannot be compared as if they were the same endpoint.

Before candidate execution, independently freeze and review three prospective reference families on exactly the same data and 15 inner splits:

* Multiclass least-squares ridge with training-only standardization, an unpenalized intercept and four penalties `{1e-4, 1e-2, 1, 100}` for the mean-squared one-hot objective. Fit via class sums/linear algebra without requiring a full dense one-hot training matrix.
* Shared-covariance LDA with shrinkage fractions `{0.1, 0.5, 1}` toward a scaled identity, training-only standardization and equal class priors. Constant-feature/all-constant fallbacks and covariance normalization are fixed explicitly in implementation review; none may be selected using queries.
* Nonlinear random-Fourier-feature ridge with 1,024 features, RBF length scales `{0.5, 1, 2} * sqrt(D)` after training-only standardization, and penalties `{0.01, 1, 100}`. The exact Gaussian frequencies, phase distribution, normalization, seed derivation and ridge objective are predeclared. These are prospective nonlinear comparisons, not a claimed SOTA baseline.

For each candidate setting, evaluate softmax temperatures `{0.1, 1, 10}` using inner predictions; temperature affects log loss and not class ordering. Select settings by equal-inner-person class-balanced Top-1, then lower natural-log loss, then a frozen deterministic configuration order. Select the primary reference family by the same inner criterion. Refit the selected setting of each family once on the full outer-training set; freeze all before queries. Report the training-selected primary reference plus all three family scores, never the best held-out family score as if it had been selected in advance.

There are 16 base model settings per inner split: four ridge, three LDA, nine Fourier-ridge. That is 240 inner fits plus three final family refits per fold/arm, and one separate historical centroid fit: 244. Across 16 fold/arm cases the reference programme therefore has 3,904 fitting operations. Temperature candidates entail additional validation scoring, not additional model fits. These are source-level prospective counts, not measured operations or resource estimates. Complete final reference predictions comprise 64 matrices (three families plus centroid over 16 cases). Full validation predictions can be processed in bounded chunks and retired after authenticated training-only metric/selection records; retain their exact computation/source/fit-set/seed lineage and explicitly record discarded transient artifacts rather than claiming they remain recoverable.

Uniform and training-frequency priors are computed independently for reporting. Under the exact balanced full split, every class has 30 training rows, so these priors coincide; report that fact rather than presenting them as two independent strong controls. The availability-only reference and candidate analyses use the same training-group/selection rules as neural/ocular/joint. No numerical reference competence has been demonstrated; meaningful actual comparison still requires an authorized complete qualification run.

## Outputs, grading and uncertainty

A public solver need not know the original BIGMEG fold name; the operator packager maps its opaque case to the canonical private submission identity. Source names, output filenames or provider history must not bypass the intended isolation.

Validate every canonical and required diagnostic candidate/reference panel, manifest, identity, finite probability, row sum, source/model lineage and full support before opening protected query labels. Preserve exact probabilities; no grader-side renormalization, clipping or favorable class/person removal. Ties favor lower class ID; zero true-class probability yields positive-infinite natural-log loss with a JSON-safe representation. Missing class support makes a primary unscorable. Invalid submissions, operator errors, valid-but-unscorable support and low scientific performance are different outcomes.

Primary for each replication is the mean across four held people of class-balanced Top-1 accuracy in the neural arm. Each person contributes equally; each of its 1,854 classes contributes equally. Report all four person values and all replications. The model/mode summary averages its three complete replication scores without selecting a favorable seed. Top-5 and log loss are separate secondary outcomes. Report paired training-investigation minus fixed-program, candidate minus the training-selected reference, neural minus ocular, joint minus ocular, and neural minus availability on the same support. Do not combine unlike metrics into a synthetic reward or call a neural-versus-ocular contrast causal.

Keep the existing enumeration of all 4^4 paired-person resamples as a descriptive interval diagnostic. Three agent replications are computational replications; they do not turn four biological people into twelve or thousands. Correlation among classes/images and fixed public source exposure limit population/generalization claims. No numerical pass threshold or improvement margin is selected from the query results. Actual scientific qualification must predeclare how a practically meaningful gain will be judged and preserve negative results.

## Resource accounting and practical execution gates

No acquisition, candidate/reference fitting or API spending is selected here. Source sizes and numerical extents are lower-level planning quantities, not a promise that this fits the current Mac.

The existing full preparation hashes 66,179,063,749 source bytes before and after parsing; those checks alone read 132,358,127,498 logical bytes, in addition to library parsing. Preserve this cost unless a separately reviewed immutable-source contract replaces the redundant traversal. All original payloads, prepared summaries, copies/views, headers, key material, future temporaries and filesystem overhead remain distinct storage requirements. No source-body hash was recomputed in this design.

For float32 data, an arm's complete four-fold matrices require `4 * (55620 + 3708) * D * 4` bytes before archive/header/ID overhead. The three canonical D values sum to 1,096; the availability diagnostic adds 271. One query probability matrix is `3708 * 1854 * 4 = 27,498,528` bytes. One complete canonical panel has 12 matrices = 329,982,336 bytes; adding four availability matrices gives 439,976,448 bytes. Six candidate panels require 2,639,858,688 probability bytes before metadata; the four-reference-family panels add 1,759,905,792 probability bytes if all are retained float32. Complete validation outputs, transient models and scratch are additional, and need not all coexist.

Reference fitting can avoid an N by 1,854 one-hot materialization and chunk probability evaluation. An N by 1,024 Fourier feature array at float64 alone is 455,639,040 bytes for N=55,620; transformation caches, factorization buffers, class sufficient statistics, Python/library memory and workers add to it. Caching or reuse must be source-bound and charged; it does not erase the logical fitting/selection operations. Numeric array extents are not empirical RSS, wall time, FLOPs, physical disk allocation or complete host memory limits.

A future selected execution profile must state model/token/tool/API budgets, full candidate and reference wall/CPU/GPU limits, memory, encoded/decoded I/O, scratch/retained bytes, all validation fits, all three replications, and independent process/daemon/final-durability observation. Both modes get the same total per-case resource ceiling and tool availability; the investigation does not receive an unreported budget for its exploratory fitting. Fixed-program runtime includes its own automatic search. Report training, exploration and inference costs separately, with common reference preparation identifiable. Budget exhaustion is failure with retained evidence; no shortening the cohort, post hoc window changes, deadline reset, automatic retry or partial panel promotion.

No universal process-cleanup guarantee is assumed. Exact future sources and runtime ownership must be reviewed, including failure disposition and uncertainty for surviving resources. Source construction alone cannot establish actual isolation, resource retirement, method compliance or scientific validity.
