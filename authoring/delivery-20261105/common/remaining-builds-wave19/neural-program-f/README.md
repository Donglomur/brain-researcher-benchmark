# NEURAL-026 complete selected program construction

This package adds concrete execution and protected-grading source for the
existing NEURAL-026 controlled calcium-analysis task. It does not install a
registry, download recordings, run models, calculate a scientific score, or
establish qualification. The central counts do not change from these files.

The scientific scope is all five paired mice, ten M1/S1 imaging sessions,
five folds per session and 24 native joint angles. Fifty cases are one task
with five independent biological units. No cohort, target, time-bin or ROI
subset is substituted. The numerical procedure and the primary reconstruction
MAE over all 240 pooled DeltaEV values are preserved. Negative and null effects
remain valid; the benchmark never rewards a larger positive neural story.

The initial design exposed the complete answer-producing reference code.
Root review identified that as a tool-access control, not independent
reconstruction. The preserved initial design/review and accepted access
revision document this correction. The successor has two matched conditions:

- `specification_only_reconstruction_v2`: implement the fixed analysis from
  the complete mathematical and input/output specification.
- `reference_code_control_v2`: receive the same specification and data plus
  the original `protocol.py` and `reference_program.py` implementations.

Two programs and their distinct authoring contexts are frozen before any case
input. The first context excludes the task-specific oracle during authoring
and runtime, including image modules, caches, helper APIs, prior conversations
and cross-condition feedback. Generic numerical tools and declared maxima
are matched. Technical exclusion cannot prove absence from pretraining.
The interpretation is analytical implementation/reconstruction; no native
neural-understanding claim follows.

The controller executes 50 cases per candidate condition and one separately
frozen, independently executed 50-case reference: **150 producers**, not 200.
Each receives one fresh public packet and its exact permitted documents.
Overlapping-fold training labels make global packet access a direct leak.
The reference panel is computed once and reused, with identical authenticated
lineage, in both unchanged grades. It is never counted as 100 independent
reference executions. This is still one canonical task and one source cohort.

`program/observe.py` authenticates the selected runtime and launches a captured
worker under the original clock. `controller.py` freezes and authenticates all
programs/context records, stages one-case views, invokes the native producer,
and captures complete panel manifests. The native implementation uses fresh
offline containers, bounded output volumes, explicit selected resources and
owned-resource closure. The producer is naturally closed and destroyed before
the trusted holder captures its opaque output. The independent observer joins
all 150 receipts, exact sources/inputs/contexts and both output copies.

`comparison.py` requires separately authenticated operator authority and outer
process closure. It captures all four original scoring dependencies before
executing any definition, restores legacy module state, and instruments file
reads with the original caps plus explicit budgets/clock checks. All three
complete panels pass original schema, ID and finite-value admission before
the first protected callback. Every reference body is reauthenticated again
before the corresponding target read. Every candidate/reference NPZ reread
also remains bound to its independently closed pin during the original
scorer's repeated admission; a later self-consistent replacement is refused.
The original scorer runs twice; reused
reference and target reads and work count twice. The retained NEURAL025 common
module supplies only the original scorer's needed helpers; its old cohort or
split logic is not used for NEURAL026.

Actual ten-source preparation and numeric packet/support admission remain
missing. The ten recordings total 12,707,357,935 bytes. At the original trial
guard and an illustrative eight-byte representation, three-panel staged input
components total 72,254,423,040 bytes and output numeric fields total
3,610,705,920 bytes. The encoded output format permits up to 6 GiB across
three panels; captured attempt and panel copies add retained storage. These
are cumulative components, not resident data size, allocations or observed
spending. Actual raw/expanded extents, copying, readbacks, native replies,
SVD/ridge memory and both scoring calls require whole-workload admission.

Source construction and invented engineering controls are the only completed
activities here. No authentic data, key, target, numerical model, original
scorer or native container has been executed. The disabled routing entry
preserves the preparation, exposure, image/runtime, resource, reference and
scientific holds. Actual source registration, activation and qualification
remain root-owned separate steps.
