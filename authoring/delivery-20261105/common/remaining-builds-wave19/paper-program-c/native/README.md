# Native empirical capture and assembly

This source implements typed observation capture and complete ordered output assembly for the six selected historical OSL empirical scripts. It runs no scientific computation during construction. The author implementation is revision `cded3b2ea95efef7b6c089c5e111fd565b716922` (1.2.dev12), not the later 1.2.11 release. `SOURCE_BINDINGS.json` pins all six original scripts and their exact historical wrapper. `source-audit/SOURCE_AUDIT.json` supplies file hashes and source-line evidence for the numerical contracts. The final program review belongs to `/root/paper_c`.

## Future operator API

1. `capture.build(source_root, fresh_output, bindings)` emits six script derivatives plus an instrumented historical `osl_dynamics/config_api/wrappers.py`. It never imports or executes them. `instrument(body, relative_path)` independently proves that stripping exactly the inserted import and observation calls recovers the entire original AST. The proof retains source lines, original/derivative hashes, and every capture expression. Other library bodies remain the pinned historical source. A fresh approved B/operator image must resolve this exact wrapper and `native.sink`; A must never receive the historical/current OSL implementation or these source derivatives.
2. In the same separately authorized trusted interpreter, install `native.sink.install_sink(CaptureSink(DirectoryStore(empty_capture_root, explicit_write_cap), trusted_context))` before running the appropriate derivative. After the original script returns successfully, call `sink.finish()`. The enclosing executor must separately authenticate process isolation, all mounts/source/dependencies, attempt/seed lineage, natural exit and original clocks. The sink does not manufacture those receipts. Failed observations and partial directories remain failed attempts.
3. `assemble.assemble(capture_root, branch, trusted_context, max_total_bytes=...)` reads only JSON and bounded-header primitive C-order NPY. It admits every required field in declared order, checks exact body/shape/dtype pins, preserves NaN and signed-infinity support patterns, and returns `ordered_fields`, native axes, full run context and `coordinate_signature`. Missing fields, truncated/extra data, changed pins, incompatible shapes, absent runs or source-weight changes fail admission. No pickle body is read or deserialized.
4. For CTF/Elekta TDE, `assemble_nnmf_derivations(literal, read_bytes, output_store, max_input_bytes=...)` produces both per-run NNMF component power and coherence maps using the exact held weighted-frequency-average arithmetic. These are explicitly additional assembly derivations. They are not renamed original files: the original scripts retain full spectra and both group components, while the CTF age callbacks select component zero and Elekta has no per-run map callback. `output_store` supplies its own future write cap. Literal arrays remain untouched.
5. The enclosing program computes the separately documented training-covariance RV correspondence. `comparison_view(literal, reference, order, validated_operator_correspondence_receipt)` requires equal coordinate signatures and records a separate view. `comparison_array(array, field_schema, order)` applies that single permutation on every declared state axis. It changes neither raw files nor NNMF component order. `state_axes`, `run_axis`, `run_index`, `panel`, `aggregation`, units and complete shapes are explicit for every field.
6. Complete ordered numeric Keras weights are exported as primitive arrays with variable names, shapes, dtypes and trainability. `restore_model_state(approved_native_model, literal, read_bytes, max_input_bytes=...)` checks that exact architecture and installs the weights, HMM transition/initial state and the source non-weight static-loss batch count. The caller constructs the approved original model from `structured.training.config_constructor` in its private runtime. No author model is imported or constructed by this helper. Weight fields have `comparison_role=operator_reconstruction_only_not_an_observable_score`; their internal axes must not be guessed from matching dimensions or included in a state-observable average.

The preceding original-model capture/reconstruction route is mandatory auxiliary evidence for B and `reference`, and optional for A. Arm A may submit every original scientific observable and exact coordinate/run identity without historical Keras variable names, constructor configuration, training histories or self-reported free energy. Its HMM operator evaluation uses the framework-neutral `selection.native_hmm_parameters` route with ordinary means, covariances, transition probabilities and literal initial probabilities. The legacy exact-network reconstruction route remains available for optional operator diagnostics. A DyNeMo observable output is also admissible without historical internals; this does not resolve its original training-trajectory selector. Post-fit free energy is never substituted for that statistic.

Absent A `structured`/`model_state`/`model.free_energy` auxiliaries yield empty training/weight arrays and no invented values. If A supplies any auxiliary block, the complete typed block and all referenced primitive arrays must validate. An optional candidate-reported scalar never attests training selection. B/reference continue to require full native auxiliary captures. These role differences do not remove any original scientific observable, person, run, coordinate or spectral axis. The externally authenticated roles are exactly `A`, `B` and `reference`.

The trusted context has `branch`, historical `revision`, `attempt_id`, role/seed provenance, and a 64-hex `preparation_binding` for the same canonical original preparation lineage. That preparation digest binds original input identities, retained sample/annotation maps, channels/lag/component semantics and transformations; it must exclude model role, attempt, seed and workspace paths. It cannot be a candidate assertion or a role-specific execution-manifest hash.

`runs` contains ordered dictionaries with `person_id`, decimal-string `run_id`, unique original `input_id`, and literal `source_input`. The default order is CTF `subject00`…`subject64`, each run `1`, or Elekta `sub01`…`sub19`, each run `1`…`6`. If authenticated source sorting differs, `source_order_bijection` is a complete permutation of that canonical roster and `source_order_binding` is its external evidence digest. Arbitrary equal-sized cohorts are rejected. `source_input` must exactly match `Data.inputs` and Elekta’s sorted event-file sequence. Its workspace spelling is retained as provenance but excluded from correspondence identity.

## Preserved scientific distinctions

- Native coordinates are hashes of the actual complete `Data.arrays` and raw arrays, with shape/dtype, ordered canonical input/run identities, sampling frequency, window/embedding settings, PCA identity and preparation binding. This snapshot occurs before model fitting and before burst plotting re-prepares data. It does not use `get_training_time_series`, which would crop prepared arrays again. Native source sequence support is taken from the prepared run prefixes (2,000 for HMM; 200 for DyNeMo). The separately captured raw spectral trims must match the inferred alpha lengths. No native/prospective representation equivalence is asserted.
- All model means, covariances, HMM initial probabilities and both transition axes, original free-energy selection statistic, every uncollapsed alpha run, source configuration and complete training/initialization history trees are captured from live source objects. HMM initial probabilities are literal `state_probs_t0`, not a stationary replacement. HMM free energy and DyNeMo final history loss remain distinct source definitions. Unsupported nonprimitive history/config objects fail visibly; they are never pickled or converted with `repr`.
- Source config strategies are runtime objects. Following historical `ModelBase.save_config`, the reconstruction config sets strategy/regularizer fields to `None`; the capture separately preserves their type descriptors. Complete native weights include tracked trainable and nontrainable variables (including the KL annealing variable). The additional `static_loss_scaling_factor.n_batches` is not a model weight and is explicitly retained. Optimizer/RNG trajectories are not exported, and this ABI does not claim exact training replay.
- DyNeMo’s literal selector is final training `history['loss'][-1]`. The source explicitly states that post-fit `free_energy` uses posterior means instead of training samples and can have a smaller KL term. Neither means/covariances/alpha nor the complete final network weights reconstruct that original trajectory statistic. Only externally trusted original training can attest it here. Candidate A’s independently reported final training loss remains insufficient for original native selection, and post-fit free energy is never substituted silently.
- Multitaper preserves complete frequency/PSD/coherence arrays. Burst PSD is `[65,3,1,F]`, but its literal coherence is `[65,3,F]`: inner `coherence_spectra` squeezes the singleton channel pair before the outer `keepdims=True`. No channel axes are invented. DyNeMo PSD has `[65,2,7,38,F]` coefficient/intercept support; coherence is `[65,7,38,38,F]` without that extra axis.
- Both NNMF spectra and both group power/coherence components are retained in source peak-frequency order. Peak ties are recorded. Source-thresholded group coherence is captured separately from its full unthresholded value because thresholding mutates its input. The wrappers do not request `return_weights=True`. Their absent `w.npy` means equal group averaging; raw/prepared/trimmed lengths are recorded separately and never injected as weights.
- Every temporal summary is retained. DyNeMo mean/std/correlation use covariance-trace-reweighted alpha; raw alpha remains separate. `alp_corr` is `[65,7,7]` after the source zeroes its diagonal. Burst envelope correlations use all source-aligned concatenated samples. Undefined source outputs are retained rather than zero-filled or dropped.
- Elekta captures all 114 hard-argmax state sequences, every run’s found/retained events and complete trial arrays, original event codes and uncorrected epoch axis, baseline-corrected run responses, minus-34-ms time axis and native `[time,state]` p-values. The source pools nine event codes within each run and averages runs equally; these are not posterior-alpha event curves or already aggregated 19-person responses. Corrected event sensitivities belong to a separate program layer.
- CTF dynamic age assignments are group 1 for age≤34 and group 2 for age>34 despite reversed display labels. Static uses group 1 age≥34 and group 2 age<34. Raw effects, p-values and source-masked maps remain separate. Static is one no-model-fit analysis but includes two 1,000-permutation inferences; it is not deterministic. Native GLM helpers can drop NaN-containing observations internally; their literal outputs do not establish complete inferential support or a corrected sensitivity.

## Evidence and remaining execution limits

Engineering checks parse source ASTs and use invented arrays/metadata in memory only. They check all real schema rosters, the burst shape exception, both NNMF components, DyNeMo axes, every Elekta run, primitive decoding/object-header refusal, a miniature complete assembly, undefined support, changed/missing artifacts and both-axis state permutation. The miniature fixture changes dimensions only inside a test and restores them; it is not a reduced benchmark endpoint. Failed attempt 001 remains recorded alongside the corrected result.

Attempts 001/002 advertised a 900,000-byte fixture bound without instrumenting recursive metadata size. They may have retained consecutive Elekta schemas concurrently; individually measured components were 649,791 and 659,001 bytes, and the earlier transient peak was not measured. No retroactive cap-compliance claim is made. Root prospectively expanded the helper live invented-object allowance to 8 MiB before further fixture runs. The corrected loop releases each schema before constructing the next and records recursive-size component checks separately from stored numeric fixture bytes. These checks exclude interpreter, allocator/dependency overhead and source-AST analysis; they are not host-RSS measurements. No numeric fixture file is written to disk.

Original CTF content lineage, full Elekta Giles-38 inputs/annotations, preparation mappings and external native environment closure remain unresolved. Source pins and generated engineering checks do not establish runtime compatibility, complete native references, scientific equivalence, whole-paper Figures 7–12 coverage, independence of fitted comparisons or qualification. No benchmark ID, registry, preferred interface, canonical manifest, input hold, clock or shared Git state is changed here.
