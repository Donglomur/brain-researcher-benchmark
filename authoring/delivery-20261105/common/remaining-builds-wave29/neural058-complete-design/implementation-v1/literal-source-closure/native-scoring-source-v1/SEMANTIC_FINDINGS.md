# NEURAL-058 native scoring source boundary

This additive source review identifies the original absolute-speed TS1 scoring path at BWB commit `6fbd666fe8170a2165f5198c1f490911424a654d`. It does not change the protected NEURAL-058 animal-centered float64 R² contract. The two estimands, numerical procedures and aggregation levels must remain separately named. No model, metric, dataset, serialization reader or recovered source was executed or imported.

## Literal source recovered

Exactly three files were fetched once through their official GitHub blob API, authenticated against the previously held exact-commit tree by byte length and Git blob SHA1, saved byte-identically, and parsed as syntax only: `src/ibl_bwb_eval/predictions.py` (6,160 bytes), `scoring/ts1.py` (8,507), and `scoring/aggregation.py` (19,967). The first contains the prediction writer; the second the saved-file reader and metric-update callsite; the third the cross-session/seed reporting and ranking rules. Exact SHA256, request provenance and older supporting source pins are in the adjacent JSON files. The original 63-member source proposal and five-alias package are unchanged.

## Dtype and serialization

* `predictions.py:113–125,154–162`: the writer accepts only Torch tensors, detaches them and moves them to CPU. Every floating field is cast by `.float()` unless the caller explicitly supplies `dtype`; nonfloating fields retain their type. Thus the default applies to timestamps as well as predictions. There is no cast back to float64 at this boundary, and widening later cannot recover discarded precision.
* `predictions.py:130–148`: chunks are concatenated along dimension zero, constants appended, and one safetensors file written. Rank other than zero or no data produces no file. This writer contains no distributed gather, uniqueness check, finite-value check or trial-coverage check. Multiple calls for a streamed key append; `set`/`add` collisions refuse. The writer stamps a package version, but its `version_of` documentation explicitly says scorers do not yet branch on it.
* Held `ts1_test_mixin.py:110–146`: model prediction is made under configured CUDA autocast. Before metric reshaping, saved prediction is explicitly `pred.cpu().float()`. In-memory metric prediction is not replaced with that saved float32 tensor. The target is `y["values"]`; the mixin does not force the metric path to float64. Consequently live metric and saved-file scoring must not be assumed numerically identical.
* Held `ts1_dataset.py:130–148`: wheel_speed skips the non-wheel normalization branch; an input target with NumPy float64 dtype is cast to float32. This is a dataset transformation rule, not proof of the dtype of any actual ground-truth file. Its exporter/collate chain and authentic file headers have not been acquired here.
* `scoring/ts1.py:46–88`: prediction and ground-truth tensors are read with `safetensors.torch.load_file`, indexed, reshaped and sent to `metric.update`. There is no explicit float64 conversion or general dtype validation in this callsite. The only `.long()` branch is for classification; continuous wheel_speed does not take it. Native scoring therefore uses loaded tensor dtypes and dependency promotion/default rules, not a declared all-float64 accumulation contract.
* Held exact dependency declarations pin NumPy 2.2.6, safetensors 0.8.0, Torch 2.10.0 and TorchMetrics 1.9.0. These are source declarations, not an observation of an installed execution environment. Literal NumPy/safetensors/Torch implementation and all global dtype/autocast/distributed behavior are not closed by this three-file recovery.

## Alignment, flattening, masking and duplicates

`scoring/ts1.py:50–56` calls `np.intersect1d(pred["trial_id"].numpy(), gt["trial_id"].numpy(), return_indices=True)` without `assume_unique=True`, then selects rows by the returned indices. Under the declared NumPy API this is a sorted unique intersection with first-occurrence indices, so unmatched IDs are dropped and duplicate IDs do not become independent repeated observations. This interpretation is distinguished from a fresh literal NumPy implementation audit; no duplicate fixture was run. The exact callsite has no duplicate refusal, complete-set equality check, expected row-count check or timestamp comparison. Prediction/ground-truth timestamp fields are never consulted by `score_file`.

For TIMESTEP targets (`scoring/ts1.py:71–88`), `(N,T,D)` is reshaped to `(N*T,D)` using the selected predictions' shape; values are reshaped to that same target extent. One metric instance is updated across those flattened points. There is no per-trial R² averaging. Sequence predictions instead squeeze dimension one. Shape errors are left to reshape/dependencies rather than a complete explicit alignment contract.

A mask is read only when the task specification declares `mask_key`; missing required mask refuses. It is aligned by ground-truth indices, flattened, and all-false masks refuse before update. Unlike the live mixin, this saved-file scorer has no explicit boolean-dtype assertion. Held wheel_speed specification has `mask_key=None`, dim=1, continuous TIMESTEP resolution and default `R2Score`, so any incidental ground-truth mask is ignored for that task. No explicit finite-value/NaN filtering is present in this scorer. Do not infer exact nonfinite-output behavior without the relevant dependency/runtime qualification.

The live mixin uses `.view(-1,dim)`, flattens an optional batch mask and asserts its dtype is bool; an all-false batch is skipped. It accumulates metric updates over batches and does not perform the file scorer's trial-ID intersection. Distributed sample coverage/synchronization and equivalence of live versus saved metrics remain unqualified.

`score_dir` processes sorted `seed_*.safetensors` paths. Its key is `(label,task,recording_id,seed)`. A later successful assignment with the same key replaces an earlier result; it does not reject duplicate-key files. Missing ground-truth files are skipped. Exceptions from `score_file` are logged and omitted; no expected complete roster is enforced. This is unsuitable as a protected completeness rule without separately specified benchmark admission.

## R² definition and aggregation levels

Held TorchMetrics 1.9.0 `regression/r2.py:109–145` constructs default scalar states with `tensor(0.0)` and `tensor(0)` and accumulates the functional sufficient statistics, with no explicit float64 cast. Its functional implementation `functional/regression/r2.py:23–44,77–118` computes target sum, squared-target sum and squared residual sum in tensor arithmetic; denominator is `sum(y*y) - sum(y)*mean(y)`. It requires at least two observations. It uses `torch.isclose(..., atol=1e-4)` to distinguish near-zero residual and target sums of squares, returning 1 by default and 0 for nonzero residual with near-constant target, with ordinary `1-RSS/TSS` for the non-near-zero case. Default adjusted=0 and multioutput uniform_average; wheel dim=1. No animal labels or animal-centered float64 computation appear in this path. This moment formula and near-constant behavior are distinct from any protected centered float64 denominator and explicit invalid-denominator policy.

The final `aggregate_metrics(metrics)` conversion/compute helper is imported by both live and file scoring, but its 1,197-byte body was not among the three newly admitted files. Therefore the metric-update and known R2Score source contract are recovered; end-to-end scalar extraction is not asserted closed. The unresolved exact locator is `src/ibl_bwb_eval/metrics/__init__.py`, Git blob `6389da498499e1b095b221836cdcd32b75c58b6b` at the same commit. No fourth file was fetched.

The native repository exposes several distinct summaries; none is an animal-centered raw R²:

1. `scoring/ts1.py:152–176` summarizes raw scores over seeds per `(label,task,recording_id)`: arithmetic mean and sample-SD/sqrt(n) SEM; one seed has SEM=None. This function does **not** clip negative R².
2. `scoring/aggregation.py:70–105` defaults to clipping each per-recording/per-seed R² at zero before averaging seeds within recording. Clipping also applies to bps and poisson_d2; callers can override the metric set and floor.
3. `aggregate_over_seeds`, lines283–324, clips each recording/seed score first, averages the available recordings **within each seed**, then computes mean and SEM over those seed means. Sessions are equally weighted within each available seed roster; n counts seeds. It does not pool all time points into a single R² or group sessions by animal, and does not enforce identical session coverage across seeds or labels.
4. `rank`, lines192–266, ranks labels separately within each recording using the selected primary metric and an anchored comparison, then averages available recording ranks. The default uses one-sided Welch comparisons with alpha=.05; a single-seed side or zero-variance unequal means is treated as an orderable difference by its helper. Missing comparisons warn for fewer than two labels but are not a completeness refusal. This is a ranking statistic, not an R² value; no biological-independence claim follows from seed SEM.

## Consequences for protected NEURAL-058 scoring

The new signed-velocity transfer task and original absolute wheel_speed readout must stay distinct. The protected scorer should apply its own admitted strict C=1 target panel, exact identity/completeness rule, animal-centered float64 metric and declared session/animal weighting, with explicit invalid cases. It must not silently inherit native ID intersection, first-duplicate selection, dropped files, float32 writer coercion or zero clipping. Conversely those stricter choices must not be described as exact native reproduction. Any separately reported native comparison needs its own pinned serialization/aggregation choice and complete qualification.

Remaining boundaries are explicit: literal `aggregate_metrics` scalar finalization; actual ground-truth exporter and stored dtypes; complete NumPy/safetensors/Torch semantics and model/autocast state; distributed sampling/gather/synchronization; real ID uniqueness/timestamp alignment/finite inputs and complete session coverage; and numerical agreement under an independently selected run. No genuine data header or array was opened, and no numerical claim was generated by this source review.
