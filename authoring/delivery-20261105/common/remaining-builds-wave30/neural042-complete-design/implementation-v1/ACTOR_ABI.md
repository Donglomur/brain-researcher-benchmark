## Explicit worker RNG and T1 capability clarification (V2)

The preliminary `prepare_provider` and final `solve` workers receive the same `packet.rng_seed`: the big-endian first four SHA256 bytes of canonical JSON `["neural042-case-rng-v2", case_phase_identity, sealed_method_source_pin]`. Their operation IDs remain distinct. Before candidate source execution, the worker initializes Python `random.seed(seed)` and NumPy 2.2.6 legacy global `np.random.seed(seed)`. This does not seed newly entropy-initialized `default_rng()`, other libraries, device RNGs or arbitrary external entropy. A method using a separate generator must explicitly initialize it from `packet.rng_seed` and preserve its predeclared consumption/feature relationship. Independent semantic admission must inspect this behavior; a shared numeric seed is not a proof that arbitrary candidate code or a provider is deterministic. The mathematical surrogate/group PCG64 seeds remain the separate normative identities above.

T1 admits only `(3,5)` and `(5,7)` theta passbands and the 30 declared `(h-l,h+l)` gamma passbands, with `l in {4,6}` and `h in {70,75,...,140}`. It uses the declared transition-adjusted lowpass difference. Analytic inputs and histogram phase/amplitude are exact NumPy float64 arrays, with finite values, nonnegative amplitude and finite phase in [-pi,pi]; boolean/integer/subclass inputs are refused. No arbitrary-band or full-condition/report service is added.
