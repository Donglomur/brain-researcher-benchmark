exact registered interpreter launch prefix, absolute entry path, argument order

`--program` names the sealed root whole-programme authority JSON, not candidate

## Origin and deadlines

Root must first obtain an actual qualified host-monotonic origin observation.
That value is inherited unchanged by review, original authority and the parent
`--original-origin`. It is not the central entry's later start timestamp. Require
original_origin <= observed entry start <= current time. Entry's initial local
120-second bootstrap timer is only a safety bound; after root-origin admission,
startup ends at original_origin + 120, never entry_start + 120. No source read
or preparation elapsed time is erased by adopting the origin.

The following absolute deadlines have distinct purposes:

| Boundary | Current source derivation | Meaning |
| --- | --- | --- |
| Original production | original authority whole_deadline | Original worker/native production must finish before this. |
| Parent closeout / caller normal | whole_deadline + original observer closeout_seconds | Parent outer observation and actual caller natural closure must finish before this. |
| Caller failure observation | caller normal + 90 seconds | Bounded observation and at most one explicit wait; no forced termination. A live or uncertain child may remain. Never validates a late parent. |
| Central readback | caller cleanup + readback_seconds | Separate independent metadata closure and central publication allowance. |

Current readback_seconds is `120 + ceil(read_bytes / 1,000,000)`, where read_bytes
is 268,435,456 + twice (original journal cap + original producer cap + 1,048,576).
This is a prospective reservation formula, not measured throughput or physical
I/O. Root selects actual host memory and free-space limits; current source
requires at least 1 GiB host address-space cap and a positive free-space floor.
Original whole-write reservation, central 2 MiB retained allowance, unrelated
holds and the free-space floor must all fit. These are not dataset-size claims
or proof that original inputs and full workload fit the machine.

Immediately before launching the captured original entry, Host.arm selects the
caller normal absolute deadline. The concrete caller observer captures both
streams under a combined 65,536-byte cap and records strict integer-zero natural
exit, reaping, EOF, local closure, group absence and timer facts. The central
caller sends no child TERM/KILL through a PID, PGID or pidfd. Its compatibility
TERM/KILL fields remain false. On failure it may make at most one explicit
Popen.wait call; internal object finalization may still poll/reap but cannot
create signal authority. Forced termination and complete failure cleanup are
not guaranteed. Unknown or surviving child state remains failed and requires
separate inspection. The current parent success policy requires both streams empty. The original parent
worker has a separate group; its closure still requires the original independent
outer journal and daemon records. If the caller is killed or lost, nested state
remains unknown and requires separately authorized inspection. No automatic
retry, deadline reset or silent cleanup-to-success promotion is permitted.

## Qualifications still unavailable

A valid original authority needs independent authentic-input/support, source,
provider, method-policy, runtime and resource/custody qualifications as required
by the original programme. This package provides no service that supplies those
qualifications. Credentials, provider connectivity, exact images/environments,
full workload feasibility and actual signal/daemon behavior are not established
by templates, source hashes, flags or inert controls. Root additionally needs
qualified central resources, caller observation and physical custody, plus the
actual clock receipt and final external durability admission.

Physical packet, protected operator and output roots must be disjoint in the
qualified host/container filesystem and daemon namespace, not merely different
path strings. Lexical/source checks do not establish arbitrary mount or namespace
isolation. Independent method admission must establish that candidate recipes
carry no learned numeric state into the supervised final fitter and that fitted
state is sealed for original/shifted replay. Adaptive investigation sees only
permitted original inputs; it cannot independently adapt the shifted arm.
Arbitrary code can violate such semantics despite readonly bytes, so source
construction alone is not method qualification. The 10-bin test-only shift is a
descriptive alignment diagnostic, not a causal effect or proof of native neural
understanding. No contribution or SOTA claim follows without actual qualified
protected evaluation.
