# Independent H host supervisor

`host.supervisor.run(operation_path, operation_pin, output, origin=BOOT)` executes the concrete immutable controller and independently closes it under the original global clock. `BOOT` is recorded at module initialization before operation admission. No process runs at import. The CLI requires `--operation`, `--operation-bytes`, `--operation-sha256` and `--output`; launch it through an externally pinned Python interpreter with H's root in the module search path. The owned source manifest must include this host module, all owner modules and the seven-file transport manifest.

The parent implements `operation.validate_operation`, `core.planned_jobs`, `budget.Budget`, `safe_io` and `staging`; these are concrete source dependencies, not caller execution callbacks. `planned_jobs()` yields unique `{id, action, role, ...}` records with deterministic 64-hex IDs. The complete roster has 19,102 phases: one original preparation, 616 fold preparations, three full native-role programs, 7,392 trained models, 1,848 analytic priors, 9,240 model evaluations, one private grade and one report. The H controller and supervisor must bind the same roster. No assertion of feasibility follows from these counts.

The operation supplies `limits` (global wall/read/write/retained), explicit disjoint `outer_read_bytes`, `outer_write_bytes`, `outer_retained_bytes`, `outer_cleanup_seconds`, `controller_grace_seconds`, `controller_log_bytes`, `host_memory_bytes`, `host_python:{path,pin}`, `docker:{binary,socket,binary_pin}`, `source_manifest:{path,bytes,sha256}`, `engine_source_pin`, `recovery_limits`, and `phase_resources`. Additional scientific fields are validated by the parent operation module. Recovery limits contain `max_records,max_record_bytes,max_metadata_bytes,max_cli_calls,max_cli_bytes,source_read_bytes,host_write_bytes`. The outer partition must cover complete controller source copying and verification, logs, full phase history and attempt ledger, closure reports, all necessary phase recovery and durable source retirement. It cannot reclaim unknown costs or use inner allocation implicitly.

The executable source manifest schema is `h_complete_executable_source_v1` with a `files` list containing exact path/bytes/SHA256 descriptors. Peer/history bodies do not enter the controller image. The supervisor makes a private exact immutable source copy before launching the gated controller. Its actual argv invokes copied `controller.py --operation ... --operation-sha256 ... --output ... --origin ...` through the pinned host interpreter. The controller must preserve original global deadline and stop its work before the separately reserved terminal window.

The controller writes durable `work/journal/NNNNNNN.json` records through `Budget.event`. Each record has immutable `index` and `ledger_clock:{origin,deadline,observed}`. Every phase has `attempt_start` with `{job,request_id}` and exactly one `attempt_disposition` with `{job,request_id,status,reason,capture_pin,cost,outputs}` or `unadmitted_external_attempt` with `{job,request_id,error_type,returned_closure}`. Status is completed or failed. Unadmitted returned closure and cost/output evidence are retained. A terminal event must match the exact start request. Missing, duplicate, gapped or corrupt history never manufactures completion; all source-planned rows remain in the independent ledger as not started, started without closure or unknown history.

Per-phase files are `work/phases/<id>/REQUEST.json`, `EXPOSURE.json`, `control/<id>/OWNERSHIP.json`, durable transport events and `quarantine/<id>/...`. Only exact source-planned phase IDs/actions/roles are eligible for recovery. The controller must publish `INNER_RETURN.json` with a strictly Boolean `numerical_complete`; its entire extent is bounded by `recovery_limits.max_metadata_bytes`. The outer receipt additionally requires complete successful phase dispositions, natural controller exit, independent terminal absence/custody, no publication errors and durable owned host-source retirement. It does not infer empirical correctness from these engineering conditions.

The supervisor controls the child through a bootstrap gate and captured pidfd, drains bounded metadata logs, establishes reaping and independent group absence, closes each durable CLI identity, and recovers only exact declared daemon resources. A failed final log or controller-close publication does not skip recovery. An invalid phase inventory leaves uncertainty and allows only the validated prefix to be recovered. The independently observed in-memory close can authorize cleanup after receipt publication fails, but never becomes an invented durable success receipt. Source-view removal happens only after independent external closure; a failed fsync/removal retains the charge and failure evidence.

The six small source controls in this directory use only RAM metadata, fake paths and literal-source function seams. They cover the eight-action access matrix, exact output membership, request joins, failure/unknown ledger support, and retirement dispatch. They are not a full 19,102-phase run, process/provider test, numerical comparison or runtime qualification. The donor's unchanged mechanisms remain source dependencies whose actual environment still needs qualification.

Integration V2 requires the parent operation to include an explicit positive `host_setup_seconds` profile for every action. The controller fixes host staging and full transport cutoffs before that phase work and checks them again immediately before dispatch; these do not extend the original global deadline. Generated/captured mounts must be exact owned immutable readable trees. A model-file subset is materialized into its own complete tree rather than mounted with undeclared sibling files. Owner `core.TASK` and the raw controller operation-read charge now satisfy host imports and accounting. These owner deltas are separate from this directory's transport source.
