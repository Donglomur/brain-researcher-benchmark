# Access, concrete phase barrier and implementation obligations — V2, pending independent/root acceptance

This is a source design for future concrete execution, not a claim that isolation is already implemented. Every authority below is bound to immutable source/inputs, complete support, operation and original resource clocks. A filename, JSON success flag or hash alone is not evidence of physical custody or completion. No current qualification is established.

## 1. Authorities and roles

- Protected original preparer: may read authentic EDFs, source annotation bodies and the operator key only under a later explicit preparation selection. It validates all686 identities and converts target-free signals, global assessment targets, and exact fold-specific training label views. It records every real label read and provenance. This construction phase reads none of these bodies. The operator key is never logged, copied to candidate views or opened by source-review tools.
- Training and reference context: one outer held-person × method condition. It receives all22 training people's required signals/metadata/annotations, its protected inner split selectors, and a separately sealed target-free query descriptor. It never mounts another outer fold's labels/state or the global assessment target. Learned state is fit before validation/query feature reads as specified by the reference mathematics. Trusted grouping IDs are not feature values.
- Stage-1 controller: handles only exact target-free data/source/fold descriptors, complete training-context lifecycle evidence and sealed model/prediction artifacts. It does not read, hash or parse its global assessment-target operand. Training-label view provenance is explicit and distinct. It validates allfour full stream closures before authorizing any assessment access.
- Assessment release process: a separately selected protected invocation. Only after authenticating the full stage-1 seal and independently observed closure does it open the exact original assessment body once, validate complete target support and form the post-prediction analysis corpus. It cannot rerun a detector or mutate a sealed output. It verifies annotation identity against an independently trusted preparation descriptor, never obtains the expected hash from an unverified replacement file.
- Analyst: receives its selected complete post-release view, generic tools, public mathematics and exact sealed method descriptions. Assessment annotations are deliberately allowed here. It never sees the protected expected numerical report, private scorer, live detector-fitting API, other context output or hidden provider state. Full-waveform access depends only on the declared view.
- Grader: authenticates all completed12 report artifacts and their exact case/view/source/closure identities, then performs the independent reconstruction. It never provides a private expected value or reward while an author context remains open. It cannot turn a partial study into complete admission.
- Independent observer/operator: authenticates source/deployment, actual processes/streams/custody and resources. Source-level counters are logical reservations, not measured physical I/O, RSS or universal OS identity proof. Unqualified physical paths, mounts, aliases, network/provider state or process closure remain explicit blockers.

## 2. Future source modules and literal phase sequence

Implementation must provide concrete modules, commands and source manifests for the following, rather than callbacks that return scientific predictions:

1. `prepare_original`: independently selected authentic original-to-target-free signal and exact annotation/fold view preparation. Complete source alignment, calibration, metadata exclusions and identity mapping are validated; failures retain their original receipts. No current run is selected.
2. `prepare_features`: the exact fixed per-second feature extraction and montage metadata projections. It is target-free except supervised scalers, which are fit later inside each training support. Feature caches have complete support/source/calibration hashes and are mounted only according to role. The no-EEG role receives no signal sample/feature or EEG-statistic descriptor body capable of opening those bytes.
3. `fit_references`: all9706 specified logical fits with complete nested validation. Each producer has source/config/support/seed/preprocessing/state/output lineage, original timing and costs. Fit failures do not choose another setting. No cross-fold learned-state reuse is admitted in this initial schedule.
4. `infer_and_close`: all92 final held-person stream outputs, with all686 records per stream, exact one-second lengths, finite scores, source-derived model/threshold matches and independent recomputation of events. Preserve raw probabilities for the strong methods and binary decisions in the original ABI. Close all training, native and any provider contexts; collect complete original stdout/stderr and independent lifecycle evidence. No survivor/unknown cleanup or timeout is success.
5. `seal_all_streams`: validate exact four streams, their23fold partitions, source support and all nested fits/selection/input boundaries; verify runtime/resource/method admission and final immutable model/source state. Publish durable all-stream seal and phase disposition ledger. Missing last fold/arm, stale source, mismatched state or absent observer closure blocks the seal before any assessment-operand operation.
6. `release_assessment`: accept only the exact fully admitted seal. Validate all public input and output artifacts, method/source joins, namespace/access qualifications and the original whole-study deadline first. Only then invoke the private assessment reader. A target path must not be stringified, statted, opened or hashed by a rejected request. Capture target bytes once from the independent preparation pin; parse that captured body and form the immutable metadata corpus. This is the concrete repair of the old target-read-before-prediction-validation gap. Never reconstruct a seal or clean success from a partially observed prior attempt.
7. `run_analysts`: first three globally data-free author programs must already be frozen. Execute six fresh fixed-program workers and six independent adaptive contexts, two views × three replications each mode, on the one shared sealed corpus. Concrete provider HTTP/action-loop, offline code worker, view projection, output staging, controller and independent observation are required in the complete source. Parent/child failures retain costs; no sampled successful contexts replace a failed required one.
8. `grade_reports`: whole12-artifact admission before private expected reconstruction, complete historical and matched-control reports, then independent root-observed completion. The numerical primary and diagnostic remain separate. Retain actual serialized reports/source/evidence, not a synthetic success summary.

These phases are conceptual scientific units, not necessarily eight native processes. The implementation must enumerate every actual subprocess/provider session/tool invocation and all fit/infer jobs in its deployment schedule; count a batched process separately from the fits it contains. No fixed native-process count is inferred from the fit count. This design does not pretend a callback/protocol is an implemented observer or provider.

## 3. Real all-stream barrier conditions

A separate release authority must bind at least:

- Original source roster/version, canonical biological-person and recording membership, complete observed-time geometry, full montage multiset provenance, protected training-view and assessment-target preparation descriptors.
- Exact operative source closure, dependency/native image or interpreter identity, method/config/seed/feature/event schema, all21/22training-person memberships, complete inner validation support and strict selection rule.
- Exactly23outer-fold records for each of four stream names, every expected record exactly once in its outer query, complete raw probability/decision/event output identities, all fitted states and threshold policies, and independent event recomputation agreeing with those scores.
- Complete9706 logical fit dispositions and all required validation/prediction artifacts. Failure, interrupted, entered-incomplete and unentered identities remain explicit, not merely a count of successful jobs.
- Genuine source-owned original-clock observations for the controller and every actual producer. Exit code is strict integer0, not bool; successful production needs observed natural completion, complete expected streams/receipts and no unknown surviving worker. A kill or cleanup return cannot be relabeled natural scientific success.
- Preselected resource allocations, cumulative failed and successful costs, all original output/source checks under the correct original parent budget, immutable namespace custody and no cross-fold/view/replication state. Separate bounded postprocessing intervals must be selected before launch; they cannot extend scientific deadlines after an overrun.
- Full schema and strict typed membership admission before touching the private operand. Exact IDs, number of records and total seconds alone are not proof that the correct rows or complete score bodies were supplied.

Hashing whole model/output bodies is an integrity operation whose I/O must be counted, not skipped in favor of pathnames. It also does not prove semantic compliance: independent method admission must inspect exact source, transformations, model-state lineage and actual access/namespace evidence. A trusted training view cannot be inferred merely from the absence of a field named `target`.

## 4. Cross-fold leakage and observational limitations

Every person's labels are legitimate training data elsewhere. Consequently a single persistent agent/model session cannot author or fit adaptive methods successively across held-person folds while retaining prior labels. The selected stage1 references are fixed scientific source; their numerical workers are separately isolated, and even temporary/model caches cannot cross label-support boundaries. Only admitted immutable target-free source features can be shared. The global assessment artifact and future stage2 annotations are physically unavailable to stage1 contexts.

All12 analytical executions use fresh writable namespaces and fresh provider contexts; a pair of full/withheld views cannot share investigation transcripts or generated answers. The exact fixed program may be reused because it was authored data-free and is immutable. It runs separately on each view and no fitted/runtime state carries over. An adaptive program may use every permitted current-case input, including intentionally released annotations, but never private expected reports or another context's answer.

The no-EEG detector and waveform-withheld analyst are different controls. The first restricts the **training/inference inputs of a detector** and asks a predictive question. The second withdraws **direct waveforms during numerical analysis** while retaining the same neural-derived detector evidence. Treating the second as a neural-information null would be false. Neither control removes all acquisition/patient confounding or establishes a causal intervention.

## 5. Required later engineering controls, not run here

A separately granted implementation phase should use tiny invented metadata/numerical controls that test consequential boundaries: exact historical event edge behavior; class/person weights and solver scaling; no query-based scaler/threshold reads; no-EEG attempted sample access; complete held-person grouping; seed/support reproducibility; final fold/arm missing; stale source/model/threshold/score lineage; tuple bool/int confusion; exact private-reader-last sentinel; parent/child clock and unknown-survivor refusal; view-withheld paths/tool/network refusal; cross-context memory absence; original stream retention; and correct negative/null numerical reports.

No invented full686 numeric corpus, fitted model, provider run or authentic-header observation is permitted by the present zero-fixture design grant. Source mocks are not scientific qualification, and passing source tests cannot prove that arbitrary code never leaks across OS namespaces. Such limits must stay visible in the eventual interface and root admission record.


## 6. Data-free author and exact packet interface clarifications

All three fixed-author programs freeze before any authentic corpus-dependent material is exposed to their author contexts. Algorithm family/grid, public equations, fixed cohort counts and future schema are permitted; realized selected configurations/thresholds, fitted statistics, exact montage vocabulary, predictions and outcomes are prohibited at authoring. Those materials are intentionally available during the later fixed-program execution and adaptive investigation under matching view authority. No generic 'both modes receive' statement grants earlier fixed-author access.

PACKETS_AND_REPORTS.md is normative for the four-stream seal to legacy three-arm packet projection and the separate matched diagnostic. The independent reconstruction must authenticate the common master seal, exact historical packet SHA, diagnostic packet SHA and context view before invoking the unchanged historical grader. A four-arm object cannot be passed directly to the original validator. The old preparer/three-arm seal admission is not reused as the new stage barrier.
