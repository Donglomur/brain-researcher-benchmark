# NEURAL-084 sequential-v2 public source scope

This is reviewed source for the prospective OpenBMI overt-gaze SSVEP decoding task. It adds a sequential fit/infer interface alongside the previously published single-call v1 source. It adds no benchmark ID, empirical result, runtime qualification or claim of a complete executable release.

All 54 designated people, both sessions and both acquisition phases remain. Each of 54 leave-one-person-out folds contains 21,200 labeled training epochs from the other 53 people and 400 held-person queries. The complete candidate output is 21,600 predictions. Each fold has candidate fit and inference plus three independent query-only comparisons: fixed CCA, constant scores and a frequency-column permutation. The complete route therefore has 270 native phases. These phases and comparisons are not independent benchmark tasks.

The signal representation is ten posterior channels and 400 half-open block-mean samples at 100 Hz over [0,4) seconds. It is prospective and does not reproduce the author's continuous filtering/resampling and inclusive-endpoint 401-sample MATLAB pipeline. Frequency/class constants and numeric cohort positions are public protocol definitions; they are not private participant identities or query answers. The embedded CCA reference is an independent Python implementation; numerical MATLAB parity and empirical competence have not been established.

## Sequential access and storage

The candidate ABI in `program/PROGRAM_ABI.md` changes from v1's single call to `fit`, followed by `infer` with the sealed model. Fit sees training-only files. Natural fit closure, model authentication and durable training-view retirement precede query staging. Inference sees the current fold's query-only files and its sealed model. The canonical store, held-person labels and other folds are never candidate mounts. All query processes close before query/model retirement and the next fold. Training-only method selection remains required; query-batch fitting, target-person calibration, sibling-task state and adaptive policy revision remain prohibited. The separate case-adaptive agent condition is not implemented by this route. Source hashes do not prove development chronology or eliminate prior exposure.

The canonical array payload is 345,600,000 bytes in 216 phase arrays. One training view has 339,200,000 payload bytes; one query view has 6,400,000. V2 keeps one view at a time plus one model capped at 512 MiB, rather than requiring v1's 54 replicated complete fold views with 18,662,400,000 array-payload bytes. These numbers exclude metadata and original MAT archives. The 1.5 GiB owned-stage allowance is a conditional resource policy; it excludes the already-held canonical store and is not a measurement of host memory or total dataset storage. Cumulative I/O is separate from retained capacity and is not refunded after retirement.

The operator must read canonical labels to construct the allowed training subsets. That trusted staging access is distinct from candidate exposure and from grading. Source authentication and row-preserving transport do not themselves establish original-channel/onset provenance, finite values, blind development or scientific validity.

## What this snapshot contains and omits

The source export contains `adapter.py`, the 15 `program/*.py` modules, the ABI, semantic comparison, resource derivation and four invented correctness-control files. Their bytes are unchanged from the reviewed sequential-v2 source commit. The original public task/schema/helpers and the v1 source remain in the publication branch. The v1 scope and task acquisition-status text are historical snapshots; they do not establish current full-cohort acquisition or v2 qualification. Some unchanged helper functions retain the v1 packet terminology; the v2 controller uses the separately documented sequential store and fit/infer route.

This export deliberately omits local source manifests and bindings, selected operator/review records, qualification freezes, preparation receipts, private scoring, authentic arrays and labels, models, predictions and empirical results. Executing the original adapter requires those missing bindings plus complete authenticated preparation, a separately qualified operator/runtime environment, Docker with Linux cgroups/tmpfs and the selected cached image. No image download/build, data acquisition, candidate/reference execution or grading accompanies publication. The source snapshot is not a self-contained runnable benchmark.

`test_controller.py`, `test_join.py`, `test_source_controls.py` and `stream-controls/test_stream.py` contain invented structures, generated arithmetic IDs/labels, placeholder hashes and literal byte fixtures. This publication audit parsed the 20 Python files without importing or executing them. It did not rerun tests. `test_source_controls.py` depends on omitted templates, proposed registry/qualification metadata and pinned sources; stream controls also import the already published v1 common module. Inclusion does not claim that every test runs from this public checkout. Full authentic input, isolation, runtime, reference-performance and scientific qualifications remain outstanding.
