# iSTTC full100000 paired program route — proposed and unqualified

This adds the same-task `default` and `full100000_pair` program routes for
`PAPER-paper-method-add-004`. The program operand is one root-selected pinned
four-program A/B descriptor, not a single candidate file. It preserves the
selected paired paper/data versus paper/data/author-code access condition and
existing export/delivery source. No new canonical benchmark ID is introduced.
This directory is a source proposal; root alone installs the central manifest
and source preference after joining current state.

The endpoint is the complete released 100,000-unit Hawkes simulation estimator
benchmark. It is not the Allen biological cohort, a direct real-neural-signal
assessment, the full duration/trial-count grid or a whole-paper reproduction.
Both arms reproduce four methods over every unit (400,000 rows per arm) and
supply six-method improvement artifacts (600,000 rows per arm). A separate fixed
operator baseline has 400,000 rows. All five phases preserve full continuous
600,000-ms records and 40 ×1,000-ms trials per unit, failure rows and the original
CSV/statistical grading contracts. No actual scientific results are claimed.

Each arm supplies reproduction.py and improvement.py, 1 byte through 8 MiB each.
This equal program-size domain is new; the original 100 MB CSV artifact limit is
unchanged. The four programs freeze globally before numeric views. Both arms
receive the same paper, protocol, ABI, resource plan and numeric data; only B gets
the exact additional 23-file author source allowlist. Separate authoring records,
matched model/revision/tool policy/budgets/seed policy and image identities are
operator attestations. Public source exposure is acknowledged; hashes do not
prove hidden authoring history, uncontaminated training or an unseen test set.

The adapter preserves the exact frozen 24-member program closure. It captures
all source members and the selected source/export metadata before invoking the
observer, then repeats authentication after the observer returns. The genuinely
empty upstream scripts/__init__.py is allowed only as an exact pinned source
member. Adapter manifests, qualification, selection, pair descriptors and
candidate program descriptors remain nonempty. No runtime, source or native
bytes in the program directory are edited by this registration.

The observer has a different startup structure from the donor adapter. Exactly
two top-level AST nodes change reversibly in memory:

1. ORIGIN=time.monotonic() becomes ORIGIN=ADAPTER_ORIGIN.
2. The standalone `if __name__=='__main__': enter_startup()` becomes
   `CLOCK_OWNED=ADAPTER_TRANSFER_STARTUP()`.

The callback verifies the active original 120-second adapter startup alarm,
rechecks expiry immediately before transfer, arms only the positive remainder
to the same ORIGIN+900240 endpoint and returns literal True. The observer's
INITIAL_HANDLERS snapshot retains the adapter alarm handler and original TERM/INT
handlers. Its unchanged main finally uses CLOCK_OWNED to independently cancel
and restore those three handlers. The adapter requires a natural integer-zero
return, inactive timer and all three restored handlers, then rearms only the
remaining original outer interval for postflight. Its final cleanup independently
cancels and restores the true initial handlers. The original standalone
enter_startup, main, verify_collection and cleanup_clock bodies remain unchanged;
reversing the two edits must reproduce the entire original AST. The selected
observer successor also checks its original outer deadline after main cleanup;
that exact final guard remains intact, alongside the adapter post-return check.

Import and argument-parsing failures can occur outside the observer's own main
cleanup block. Adapter final cleanup remains active on both paths. A callback
failure never grants successful ownership or a result. A cooperative observer
return-to-rearm gap remains: an external controller must observe adapter natural
exit zero; a printed/persisted result alone cannot establish success. No expired
clock receives a new minimum delay. The unchanged standalone observer's timer
initialization is not invoked by this adapted route.

The original observer.verify_collection performs the actual complete scientific
structure/custody checks: all five original accepted phase receipts and requests,
exact controller/engine closure, retired input views, every full CSV and methods
artifact, full100000 support, the four committed programs, and fixed-baseline /
deferred-grading joins. The adapter requires that original observer to return
naturally and then checks bound metadata identities. It does not copy a donor's
scientific endpoint validator, read the scientific payloads again or call grades.
Private truth and both original graders remain separately protected and unused.

Execution requires two distinct authorizations: a root review selecting the
exact pair/operation and a genuine passing qualification for this exact adapter,
program source, interpreter, scope and resource profile. No passing qualification
exists in this proposal. Central qualification refusal occurs before any candidate,
output or review operand is parsed. Within the adapter, the separate runtime
qualification record is validated before pair/selection/output operands. Review
and qualification records are operator attestations, not signatures. Neither
grants scientific qualification, private grading or forced-stop custody.

The full prospective program profile remains unchanged: controller retention
3 GiB plus 16 MiB observer retention; 2 GiB free floor plus standing OTHER and
remaining whole-attempt reservation; managed controller reads/writes 64/16 GiB;
observer reads/writes 1 GiB/16 MiB. Each phase permits 8 GiB producer RAM, 4 CPUs,
512 MiB output tmpfs and 128 MiB scratch; these are limits, not measured peaks.
The derived host retention bound is 3,008,621,108 B before rounding/reservation.
The full compressed numeric input is 2,168,730,521 B; expanded size, peak memory
and runtime remain unqualified. No staging or small-cohort timeout is inherited.

Work/publication/outer endpoints are the original ORIGIN+900000/900120/900240.
All five 174,840-second phase maxima plus staging/validation fit the declared
work policy. The adapter adds at most 8 MiB of bounded source/metadata captures,
zero persistent runtime writes and a 16 KiB terminal. Its read cap covers two
adapter source passes, two complete target-source/selected-metadata passes,
qualification/selection/pair/review capture and reauthentication, and at most
64 KiB OBSERVED plus 1 MiB COLLECTION plus 1 MiB commitment metadata. These are
prospective managed bounds, not actual I/O measurements or a resource reservation.
The exact underlying resource JSON remains pinned in BINDING.json.

Normal success requires exact owned native/CLI closure before full capture and
source verification. Forced termination may leave independent host CLI groups
or daemon resources alive; observer/controller PGID absence is insufficient.
Recovery IDs remain in original journals, forced custody stays false and automatic
retry stays unauthorized. No actual data, model, baseline, scorer, Docker or
scientific operation is selected by this proposal or its RAM controls.
